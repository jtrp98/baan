# BE-043 — Supersede-target endpoint

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

endpoint สลับ/ยกเลิกเป้าหมาย — เมื่อสาขาที่เคย active ถูกแทนที่ ตั้ง `Status='superseded'`, `SupersededAt=now()` ที่แถวเดิม ห้ามลบ/แก้ไข `public."TCompassRiasecResult"` เลยแม้แต่แถวเดียว (DES-021 §3) — การ invalidate เกิดที่ชั้น gate เท่านั้น ผลเก่ายังใช้ดู/อ้างประวัติได้ตามปกติ เพียงแต่ใช้ผ่าน gate ซ้ำไม่ได้อีกหลังถูก supersede — การตัดสินใจเปลี่ยนสาขาเป็นสัญญาณให้ทบทวนใหม่ — แต่การ invalidate ต้องไม่แตะบันทึกเดิมของเด็ก เพราะผลเก่าเป็นบันทึกของวันนั้นตาม append-only

## References

REQ-017, AC-017.3, DES-021, DEC-021

## Scope

แก้เฉพาะแถวของ `public."TCompassTargetProgram"` · `SupersededAt` ตั้งเมื่อ supersede เท่านั้น · ห้าม DELETE แถว

- Security-sensitive: yes

## Out of Scope

`public."TCompassRiasecResult"` (ห้ามลบ/แก้เด็ดขาด) · gate ของ BE-041 (แต่พฤติกรรมหลัง supersede ต้องตรงกัน) · สคีมา

## Expected Output

none

## Acceptance

AC-017.3: การเปลี่ยนเป้าหมายจากสาขา A ไปสาขาอื่นทำให้แถว A เป็น superseded พร้อมเวลา และ gate ของ A ภายหลังผูกกับหน้าต่างหลัง SupersededAt — โดยแถว RIASEC เดิมไม่ถูกแตะทุกกรณี

## Dependencies

BE-041

## Handoff

ตรวจ AC-017.3 ด้วยสถานการณ์จริง: ตั้ง A → สลับไป B → ตรวจแถว A (superseded + SupersededAt) + ตรวจแถว RIASEC ของ A ยังครบทุกแถว + gate ของ A หลังจากนั้นต้องการแถวใหม่ — เก็บผลเป็นหลักฐาน
set สถานะบนตารางของตัวเอง — revert ได้ · ประวัติ supersede คงอยู่เพื่อ audit
