# BE-047 — T-Score per subject group

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

T-Score ต่อกลุ่มสาระ (สัญญา §1): `WeightedScore_s` จาก Module E (ค่าเดียว ไม่คำนวณใหม่) + `TotalCredit_s` + percentile เทียบฐานระดับชั้นเดียวกัน (`ScorePercentile_s`/`CreditPercentile_s`) → `Composite_s = 0.6×Score + 0.4×Credit` → `TScore_s = 50 + 10×(Composite_s − nationalMean)/nationalSD` — คำนวณครบ 8 กลุ่มสาระครั้งเดียวต่อคำขอ ใช้ซ้ำทุกจุดที่ต้องใช้ T-Score (ห้ามคำนวณแยกอีกชุด) — เขียนโค้ดได้แล้ว แต่รันจริงไม่ได้จนกว่า `sb-compass` DEP-F09 (คอลัมน์ `"StddevScore"`) จะเสร็จ — ห้ามผสาน T-Score เข้ากับ `TARGET_SCORE=75` ของหมวด Program Matching โดยเด็ดขาด เป็นคนละกลไกที่ผู้ใช้ยืนยันแยกกันแล้ว (สัญญา §5) — ค่า T-Score ที่คำนวณสองชุดหรือผสมกับ TARGET_SCORE ทำให้อันดับ cluster เพี้ยนแบบเงียบ และละเมิดการยืนยันของผู้ใช้ที่แยกสองกลไกไว้ชัดเจน

## Scope

อ่าน `public."TCompassLevelSubjectStat"` แบบ read-only (ของ sb-compass) · `TScore_s` คำนวณครั้งเดียวต่อคำขอแล้วใช้ซ้ำทั้ง 11 cluster · เกณฑ์ `MIN_N_FOR_STDDEV = 30` ทำให้บางกลุ่มได้ NULL — เดินตามกติกา fallback ของ BE-048 ไม่แทนค่าเดา

- Security-sensitive: yes

## Out of Scope
