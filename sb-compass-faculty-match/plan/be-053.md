# BE-053 — Module K ownership enforcement

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

บังคับความเป็นเจ้าของบนทุก endpoint ใหม่ของ Module K (BE-052 เป็นอย่างน้อย) — `SchoolID`/`SID` จาก JWT เท่านั้น กติกาเดียวกับ Module H (BE-026)/Module I-b (BE-036/BE-044) — เขียน `TCompassStudentClusterScore` คีย์ด้วย SchoolID/SID เดียวกับ Module H/I-b ตามสัญญา Database Ownership Boundary แม้ข้อมูลนำเข้า (สถิติรวมระดับชั้น) จะไม่ใช่ข้อมูลส่วนบุคคลก็ตาม — ผล cluster เป็นข้อสรุปเรื่องอนาคตรายบุคคลของผู้เยาว์ — การอ่านข้ามบัญชีผ่าน IDOR เสี่ยงเท่ากับข้อมูลอื่นของโมดูล

## References

REQ-010, AC-010.1, DES-018, DEC-018

## Scope

ครอบ endpoint อ่านผลของ Module K · ตรวจความเป็นเจ้าของใน query เดียวกับการอ่าน · fail-closed

- Security-sensitive: yes

## Out of Scope

กลไก JWT ของระบบเดิม · ตารางสถิติของ sb-compass (read-only) · payload ของ BE-052

## Expected Output

none

## Acceptance

AC-010.1: endpoint ผล cluster ยึดตัวตนจาก session เท่านั้น — การอ้าง run/score ของเด็กอื่นไม่มีทางได้ข้อมูลกลับมา

## Dependencies

BE-052

## Handoff

ตรวจ AC-010.1 ด้วยการยิง endpoint ด้วย id ของเด็กอื่น/id ปลอม (ต้องได้ผลลบ) + ยืนยันการเขียนคีย์ SchoolID/SID จาก JWT — เก็บผลเป็นหลักฐาน
ชั้นตรวจครอบ endpoint — revert ได้ทางเทคนิคแต่ห้ามปล่อย endpoint ใช้จริงโดยไม่มีชั้นนี้
ส่งต่อ reviewer
