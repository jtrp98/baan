# FE-001 — Review queue screens

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

หน้าจอคิวงาน (intake queue + pending_review queue) พร้อมตัวกรองมหาวิทยาลัยที่ **แสดง/ส่งค่าเป็น `"UniversityCode"` (text เช่น `'KMUTT'`) เสมอ ไม่ใช่ `"UniversityID"` (integer) — v9: Id เป็นค่าที่ฐานข้อมูลออกเอง ไม่เสถียรข้ามสภาพแวดล้อม ห้ามให้หน้าจอถือ/ส่ง** ต่อกับ endpoint คิวของ BE-014 — คนตรวจใช้หน้าจอนี้เป็นทางเข้างานประจำวัน — ต้องแสดงตามคิวจริงจากเซิร์ฟเวอร์ ไม่ใช่สถานะที่หน้าจอเดาเอง

## References

REQ-003, AC-003.2, DES-023, DEC-023, DES-018, DEC-018

## Scope

แสดงจาก payload ของ BE-014 อย่างเดียว · ตัวกรองมหาวิทยาลัยส่ง `"UniversityCode"` ไปที่ endpoint ไม่กรองเองฝั่ง client จนข้อมูลไม่ตรง · **ห้าม hardcode รายการมหาวิทยาลัยหรือเลข Id ในหน้าจอ — รายชื่อมาจาก payload ของเซิร์ฟเวอร์**

- Security-sensitive: yes

## Out of Scope

endpoint ฝั่ง BE · middleware SSO · หน้าจออื่นของ console

## Expected Output

none

## Acceptance

AC-003.2 (ฐานคิว): หน้าจอแสดงคิวจริงทั้งสองคิว กรองตามมหาวิทยาลัยด้วยค่า `"UniversityCode"` ได้จริง (ไม่มีเลข Id ปรากฏในคำขอ/หน้าจอ) — เป็นทางเข้าให้คนตรวจแก้ผลก่อนอนุมัติได้

## Dependencies

BE-014

## Handoff

ตรวจ AC-003.2 (ฐานคิว) ด้วยการเปิดหน้าจอเทียบกับ payload ของ BE-014 (แถว/เรียง/กรองตรงกัน) + ไม่ผ่าน SSO ไม่เห็นข้อมูล — เก็บผลเทียบเป็นหลักฐาน
หน้าจอใหม่ additive — revert ได้ไม่กระทบ endpoint
