# BE-015 — Edit AI results endpoint

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

endpoint แก้ผลของ AI — กลุ่มสาระ/น้ำหนัก/cluster/กลุ่มคณะเดิม/แกนมิติ RIASEC/ข้อความบรรยาย ทุกแถวที่คนแก้เองต้องถูกตั้ง `is_manual=true` (DES-023 §3) — **v9: ค่าที่รับเข้ามาเป็น code (`"ClusterCode"`/`"DimensionCode"`/`"FacultyGroupCode"`) แล้ว service resolve เป็น `"ClusterID"`/`"DimensionID"`/`"FacultyGroupID"` (integer) ก่อนเขียน `public."TCompassProgramCluster"`/`public."TCompassProgramRiasecProfile"`/`public."TCompassProgram"."FacultyGroupID"` · ห้ามให้ client ส่งเลข Id และห้ามให้คนพิมพ์เลข Id เอง · code ที่ resolve ไม่พบ = ปฏิเสธการแก้ ห้ามสร้างแถว master ใหม่** — แถวที่คนแก้ไว้คืองานของคน — ถ้า import รอบถัดไปเขียนทับได้ งานแก้จะหายเงียบ ๆ ทุกครั้งที่มีเอกสารใหม่

## References

REQ-003, AC-003.2, DES-023, DEC-023, DES-018, DEC-018

## Scope

ทุกการแก้ผ่าน endpoint นี้เท่านั้น · ตั้ง is_manual=true ให้แถวที่คนแก้ครบทุกแถว · ยังไม่รวมการตัดสิน resolution (BE-016) · **สัญญาฝั่งนอกเป็น code เสมอ · การแปลง code → Id อยู่ที่ชั้น service จุดเดียว ไม่กระจายไปตามที่เรียก**

- Security-sensitive: yes

## Out of Scope

เงื่อนไขก่อนอนุมัติ (BE-017) · กลไก import/validate · สคีมา

## Expected Output

none

## Acceptance

AC-003.2: คนตรวจแก้ผลของ AI (กลุ่มสาระ/น้ำหนัก/โปรไฟล์พฤติกรรม) ได้ก่อนกดอนุมัติ — และทุกค่าที่คนแก้ถูกตั้งสถานะ manual ให้ระบบรู้เสมอ

## Dependencies

BE-013

## Handoff

ตรวจ AC-003.2 ด้วยการแก้แถวจริงผ่าน endpoint (ส่งค่าเป็น code) แล้วตรวจ is_manual=true ทุกแถวที่แก้ + ค่าที่แก้ปรากฏจริงโดยคอลัมน์ในฐานเป็น Id ที่ resolve มาจาก code + กรณีส่ง code ที่ไม่มีในคลังต้องถูกปฏิเสธและไม่มีแถว master ใหม่เกิดขึ้น — เก็บผลเรียก/ตรวจแถวเป็นหลักฐาน
endpoint ใหม่ additive — revert ได้ · แถวที่แก้ไปแล้วมี is_manual กันการเขียนทับอยู่แล้ว
