# BE-041 — CanSetAsTarget gate

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

`CanSetAsTarget(SchoolID, SID, ProgramID)` — เช็คด้วยการมีอยู่ของแถวใน `public."TCompassRiasecResult"` ที่ SchoolID/SID/ProgramID ตรงกันเป๊ะทั้งสามค่าเท่านั้น (ห้ามเช็ค `"MatchPercent"`/`"Advice"` เลยแม้แต่น้อย — ผลไม่เหมาะสมก็ตั้งเป้าหมายได้) — ต้องกรองด้วย `"ProgramID"` เสมอ ห้ามใช้นิยาม "ผลล่าสุด" (คีย์แค่ school_id/s_id) ของฝั่ง RIASEC มาแทน เพราะเป็นคำถามคนละแบบ (DES-021 §2, RISK-F20) — `"ProgramID" IS NULL` ไม่นับเป็นการทำ REQ-007 ของสาขานั้นไม่ว่ากรณีใด · gate เป็นเท็จ → คืน 409/400 พร้อมพาไปหน้า RIASEC ของสาขานั้น ห้ามคืน 200 แล้วให้หน้าจอ disable ปุ่มเอง · สาขาที่เคย superseded แล้วผูกกับหน้าต่างเวลาหลัง SupersededAt ตามสูตร §3 — จุดผิดง่ายที่สุดของ endpoint นี้คือลอกนิยาม "ผลล่าสุด" มาใช้ — เขียนผิดแล้วเด็กจะตั้งเป้าหมายสาขาที่ยังไม่เคยทำแบบทดสอบได้เลย โดยไม่มีอะไรฟ้อง (RISK-F20)

## References

REQ-017, AC-017.1, AC-017.2, AC-017.3, DES-021, DEC-021

## Scope

query ของ gate เขียนเองตามสูตร §2/§3 — ห้ามเรียก/ลอก query "ผลล่าสุด" · ไม่มีเงื่อนไขคุณภาพผลเพิ่มโดยเด็ดขาด · fail-closed ที่เซิร์ฟเวอร์

- Security-sensitive: yes

## Out of Scope

แถว `public."TCompassRiasecResult"` ทุกแถว (อ่านอย่างเดียว) · นิยาม "ผลล่าสุด" ฝั่ง RIASEC (ไม่แตะไม่ลอก) · สคีมา

## Expected Output

none

## Acceptance

AC-017.1: สาขาที่ยังไม่เคยทำแบบทดสอบรอบสองของสาขานั้น → gate เป็นเท็จ → endpoint คืน 409/400 พร้อมทางไปหน้า RIASEC ของสาขานั้น
AC-017.2: สาขาที่ทำแบบทดสอบจบแล้ว (มีแถวตรงเป๊ะ 3 ค่า) → gate ผ่าน ไม่ว่าผล % / คำแนะนำจะเป็นอย่างไร — ไม่มีเงื่อนไขคุณภาพผลเพิ่ม
AC-017.3: สาขาที่เคยถูก superseded → gate ผ่านได้เฉพาะแถว RIASEC ที่เกิดหลังหน้าต่าง SupersededAt ตามสูตร §3 (ต้องทำใหม่จริง)
