# BE-016 — Resolution endpoint (new/replace/discard)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

endpoint ตัดสิน `resolution` ('new'/'replace'/'discard') — เส้นทาง 'new' ต้อง validate `dedup_key` ไม่ชนก่อนสร้างแถว `public."TCompassProgram"`, แถว `is_manual=true` ห้ามถูกเขียนทับนอกเส้นทาง 'replace' ที่คนสั่งเอง (DES-019 §8 + DES-023 §3) — การตัดสินของคนคือสิ่งที่กันสาขาซ้ำ/ข้อมูลคนถูกทับ — ทาง 'new' ที่ไม่เช็คชนจะโดน UNIQUE ตอน runtime และการเขียนทับแถว manual คือการทำลายงานคนแบบไม่มีใครรู้

## References

REQ-003, AC-003.3, DES-019, DEC-019, DES-023, DEC-023

## Scope

'type' ของ resolution ตรวจฝั่งเซิร์ฟเวอร์ · 'new' ตรวจชนก่อนสร้างเสมอ · 'replace' ให้เขียนทับแถว manual ได้เมื่อคนสั่งเองเท่านั้น · 'discard' ไม่แตะ program เก็บ intake ไว้เป็นประวัติ

- Security-sensitive: yes

## Out of Scope

กลไก swap ของ 'replace' (BE-018) · เงื่อนไขก่อนอนุมัติ (BE-017) · สคีมา

## Expected Output

none

## Acceptance

AC-003.3: การนำเอกสารใหม่มาแทนของเดิมเดินผ่านการตัดสินของคนเท่านั้น — สาขายังไม่กลับไปเปิดให้เด็กเห็นทันที และแถวที่คนแก้ไว้ไม่มีทางถูกเขียนทับโดยที่คนไม่ได้สั่ง

## Dependencies

BE-013, BE-011

## Handoff

ตรวจ AC-003.3 ด้วยการตัดสินจริงทั้งสามเส้นทาง: 'new' บนชื่อที่ชน (ต้องถูกปฏิเสธจนแก้ชื่อ), 'replace' เขียนทับแถว manual ได้เมื่อคนสั่ง, 'discard' ไม่เปลี่ยน program — เก็บผลเรียก/สถานะแถวเป็นหลักฐาน
endpoint ใหม่ additive — revert ได้ · แถว program ที่สร้างผ่าน 'new' เป็นข้อมูลปกติของคลัง
