# BE-006 — markitdown conversion pipeline (sandboxed)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

markitdown conversion pipeline — ตั้ง `conversion_status` ('ok'/'empty'/'failed') ตามเกณฑ์ข้อความหลัง trim ยาว ≥ 200 ตัวอักษร, รันการแปลงในโหมด sandbox/process แยกที่ไม่มี network ออก, จำกัดขนาดไฟล์ + timeout + ตรวจ MIME/magic bytes ฝั่งเซิร์ฟเวอร์ (DES-019 §2 + Module F Security Considerations) — PDF ที่อัปโหลดเข้ามาเชื่อไม่ได้แม้มาจากทีมภายใน — parser ที่โดนไฟล์ที่จงใจทำให้พังต้องไม่ลาก service ล้ม และความล้มเหลวเงียบ ๆ ของ PDF สแกนต้องถูกจับด้วยเกณฑ์ 200 ตัวอักษร ไม่ปล่อยข้อความว่างเข้า AI

## References

REQ-001, AC-001.1, DES-019, DEC-019

## Scope

แปลงก่อนเสมอ แล้วจึงมีทางส่งต่อ AI · 'empty'/'failed' → หยุด ห้ามเรียก AI เข้าคิวให้คนจัดการพร้อม `conversion_note` · การแปลงต้องอยู่ใน process แยกที่ตัด network ออก พร้อมขีดจำกัดขนาด/เวลาที่ชัดเจน

- Security-sensitive: yes

## Out of Scope

เกณฑ์ 200 ตัวอักษร (ค่าที่เอกสารกำหนด ไม่ใช่ค่าที่ engineer ตั้งเอง) · endpoint upload · ตาราง/สคีมา

## Expected Output

none

## Acceptance

AC-001.1: ระบบแปลง PDF เป็นข้อความ Markdown ด้วย markitdown ก่อนส่งข้อความให้ AI อ่านเสมอ — และผลแปลงที่สั้นกว่าเกณฑ์หรือล้ม ต้องถูกตั้งสถานะ 'empty'/'failed' พร้อมหยุดก่อนถึงขั้น AI ทุกครั้ง

## Dependencies

BE-004, BE-005

## Handoff

ตรวจ AC-001.1 ด้วยการรัน pipeline กับไฟล์จริง 3 กรณี (แปลงได้ / PDF สแกน / ไฟล์เสีย) และยืนยัน sandbox: process แปลงไม่มีทางออก network + จำกัดขนาด/timeout ทำงาน — เก็บผลรัน/บันทึก sandbox เป็นหลักฐาน
pipeline เป็นขั้นแยกของ service ใหม่ — revert ได้โดย upload endpoint ยังทำงานเก็บไฟล์ได้ตามปกติ
ส่งต่อ reviewer
