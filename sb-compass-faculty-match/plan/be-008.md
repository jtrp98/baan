# BE-008 — glm-5.2 integration with secret-store key

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

เชื่อมต่อ `glm-5.2` — เรียกหนึ่งครั้งต่อหนึ่งสาขา, retry ได้ไม่เกิน 2 ครั้งพร้อม backoff, คีย์จัดเก็บที่ `prod.config` กลุ่มคีย์ชื่อกลาง `ApiKey`/`Endpoint`/`Model` และ **service อ่าน prod.config ตรงเอง (v14 — ไม่มีขั้น env injection; path ปรับได้ด้วย `CURRICULUM_PROD_CONFIG_PATH`) ของ service ตอน launch (`CURRICULUM_GLM_API_KEY`) — ห้าม hardcode ในซอร์สโค้ดทุกจุด และฝั่ง ClassOnlineWeb ยังคงไม่มีโครงเรียก AI (**2026-09-16 — แก้ตามมติผู้ใช้ "รวม config ที่เดียว" design v13** ซึ่งยกเลิกข้อเดิม "ห้ามใส่ prod.config"; DES-019 §1, §7 ฉบับ v13) — การเขียน+ทดสอบจริงบล็อกที่ PRE-F01 (คีย์ยังไม่มีจริง) จนกว่าจะมีคีย์ — นี่เป็นการเรียกบริการ AI ภายนอกครั้งแรกของสายงาน — คีย์ที่หลุดเข้าซอร์ส/config ฝั่ง .NET ขยายพื้นผิวที่เปิดอยู่แล้วของระบบ และการเรียกซ้ำตอนเด็กเปิดหน้าจอผิดสัญญา REQ-002 โดยตรง

## References

REQ-002, AC-002.3, DES-019, DEC-019

## Scope

เรียกเฉพาะตอน import ต่อหนึ่งสาขา — ฝั่ง ClassOnlineWeb ต้องไม่มีโค้ดเรียก AI เกิดขึ้นเลย · ครั้งสุดท้ายยังล้มต้องเดินเส้นทางของ BE-012 (ไม่ error ให้ปลายทางเห็น) · จนกว่า PRE-F01 จะเสร็จ งานนี้เขียน+ทดสอบ integration จริงไม่ได้ (mock ได้)

- Security-sensitive: yes

## Out of Scope

`prod.config` และไฟล์ config ฝั่ง ClassOnlineWeb (ห้ามวางคีย์) · ตาราง/สคีมา · ลำดับขั้น import ก่อนหน้า

## Expected Output

none

## Acceptance

AC-002.3: AI ถูกเรียกครั้งเดียวตอนนำเอกสารเข้าระบบ (ต่อหนึ่งสาขา) แล้วเก็บผลไว้ใช้ตลอด — ไม่มีเส้นทางใดเรียก AI ใหม่เมื่อเด็กเปิดหน้าจอ และคีย์ปรากฏเฉพาะใน secret store ของ service
