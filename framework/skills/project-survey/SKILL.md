# 🔍 คู่มือปฏิบัติการ AI: การสำรวจโปรเจคและประสานความรู้ (Project Survey & Knowledge Sync)

ทักษะนี้ใช้เมื่อผู้ใช้สั่งในแชทให้ **สำรวจโปรเจค**, **ตรวจสอบโค้ดจริงเทียบกับ Knowledge**, **ประสาน Knowledge Drift (โค้ดเดินหน้าไปไกลกว่าเอกสาร)**, หรือ **สร้าง Knowledge สำหรับโปรเจคเก่า**

ผู้ใช้ต้องการคุยกับคุณผ่านแชทเป็นภาษาธรรมชาติ โดยไม่ต้องไปพิมพ์คำสั่ง CLI เองใน Terminal คุณ (AI) มีหน้าที่สแกนโค้ด วิเคราะห์เปรียบเทียบ นำเสนอทางเลือก และสร้าง/อัปเดตเอกสาร Knowledge ให้เสร็จสรรพ

---

## 3-Step Plan-First & Subagent Workflow

### ขั้นที่ 1 — สำรวจบริบทจริงด้วยเครื่องมือใน Core และ Subagent
1. เรียกใช้คำสั่งสำรวจในเครื่องเพื่อดึงข้อมูลสรุปแบบรวดเร็ว:
   ```bash
   baan survey --target <targetName> --json
   ```
   *(หรือระบุ `--cwd <path>` หากเป็นโปรเจคภายนอก)*
2. ตรวจสอบผลลัพธ์จาก JSON:
   - `stacks`: ภาษา, เฟรมเวิร์ก (.NET, Next.js, Go, Python, React, ฯลฯ)
   - `components`: รายการฟีเจอร์และเซอร์วิสในโค้ด (`frontend/features/*`, `backend/src/*`, `engines/*`)
   - `drift.unmappedCode`: โค้ดที่มีอยู่จริงแต่ยังไม่มีโมดูลใน Knowledge (โค้ดล้ำหน้าเอกสาร)
   - `drift.unmappedModules`: โมดูลใน Knowledge ที่หาโค้ดจริงไม่พบ
3. หากมี `unmappedCode` ที่น่าสนใจ ให้สั่ง Subagent ไปเปิดอ่านโค้ดในโฟลเดอร์นั้นเพื่อสรุปว่าฟีเจอร์นั้นทำงานอะไร มี API/UI เส้นทางไหนบ้าง

### ขั้นที่ 2 — ตัวหลักนำเสนอผลการสำรวจและวางแผนในแชท (`/plan`)
1. ตอบกลับผู้ใช้ในแชทด้วยภาษาไทยที่กระชับและเข้าใจง่าย:
   - สรุป Tech Stack และสภาพแวดล้อม
   - สรุปรายการโมดูลปัจจุบันที่ตรงกับโค้ด
   - ชี้แจงรายการฟีเจอร์ที่พบในโค้ดแต่ยังตกหล่นใน Knowledge (Drift)
2. นำเสนอข้อเสนอแนะการจัดโมดูล (Module Breakdown):
   - เสนอชื่อโมดูลที่ควรสร้างใหม่
   - สอบถามผู้ใช้ว่าต้องการสร้างทั้งหมด หรือเลือกรวมกับโมดูลเดิมที่มีอยู่
3. รอความเห็นชอบจากผู้ใช้ในแชท

### ขั้นที่ 3 — ลงมือสร้างและปรับปรุง Knowledge
เมื่อผู้ใช้ตอบเห็นชอบในแชท:
1. สั่งสร้างโมดูลตามที่ตกลง:
   ```bash
   baan survey --target <targetName> --scaffold-module <moduleName>
   ```
2. อัปเดตเนื้อหาในไฟล์ที่สร้างขึ้นให้มีข้อมูลจริงที่สำรวจพบ:
   - `<project>/modules/<moduleName>/INDEX.md`: ใส่ภาพรวมและลิงก์ของโค้ดจริง
   - `<project>/modules/<moduleName>/shared/requirements.md`: สรุป Business Flow และข้อกำหนดเบื้องต้นจากโค้ดจริง
   - `<project>/modules/<moduleName>/build/contract.md`: บันทึก API Endpoints / DB models ที่ตรวจพบ
3. ตรวจสอบความถูกต้องของ Knowledge:
   ```bash
   baan --index
   baan --lint-knowledge
   ```
4. รายงานผลสำเร็จให้ผู้ใช้ทราบในแชท พร้อมชี้ทางไปยังไฟล์ที่สร้างเสร็จแล้ว

---

## กฎเหล็กและความปลอดภัย
- **ห้ามแก้ไขโค้ดใน Target**: ทักษะนี้ทำหน้าที่อ่านโค้ดเพื่อนำมาบันทึกและปรับปรุง Knowledge เท่านั้น
- **เคารพสัญญา 3 ช่อง**: ทุกโมดูลต้องมี `shared/`, `design/`, `build/` และ `INDEX.md` ที่มี frontmatter ถูกต้อง
- **อัปเดตสารบัญเสมอ**: ทุกครั้งที่เพิ่มโมดูลใหม่ ตารางใน `<project>/INDEX.md` ต้องสะท้อนการเปลี่ยนแปลง
