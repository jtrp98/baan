# BE-502 — CSAT escalation hook

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

Original Task ID: `BE-crm-case-dashboard-P5-02`

## Goal

escalation hook ใน `POST /api/v1/support/crm/feedback` **หลัง insert สำเร็จ (best-effort แยก try/catch ห้าม rollback การรับคะแนน)**: ตรง rule `flag=immediate` ของ `CRM_CASE_CSAT_RULES` → push LINE หากลุ่ม Support ผ่าน env `CRM_CSAT_ESCALATION_LINE_GROUP_ID` (ไม่ตั้ง = ข้ามเงียบ ๆ) · rule repeatCount=2 นับ feedback ต่ำของ SchoolId ใน windowDays 30 — คะแนนต่ำ/ต่ำซ้ำต้องเดินเข้าทีม Support ทันที แต่ endpoint รับคะแนนเป็น no-auth เดิม — hook ต้องไม่มีทางทำให้การบันทึกคะแนนล้ม

## References

REQ-005, AC-005.2, DES-005, DEC-005

## Scope

แตะ `POST /api/v1/support/crm/feedback` หลัง insert สำเร็จเท่านั้น — best-effort แยก try/catch: push ล้ม = log อย่างเดียว — ไม่ตั้ง env = ข้ามเงียบ ๆ — นับ feedback ต่ำของ SchoolId ใน 30 วันสำหรับ rule ต่ำซ้ำ

- Security-sensitive: no

## Out of Scope

พฤติกรรมการ insert คะแนน/response เดิมของ endpoint · สิทธิ์/token ของ endpoint (known risk รับมาจากของเดิม — fix ต้องอยู่ที่ v1 crm ไม่ใช่ scope นี้) · constant rules

## Expected Output

none

## Acceptance

AC-005.2: คะแนนถูกบันทึกเหมือนเดิมทุกกรณี (hook ล้มก็ตาม) และคะแนนที่ตรง rule immediate มี LINE แจ้งกลุ่ม Support เมื่อ env ถูกตั้ง

## Dependencies

—

## Handoff

ตรวจ AC-005.2 ด้วยกรณีทดสอบ: คะแนนต่ำตรง rule / ต่ำซ้ำครบ repeatCount ใน 30 วัน / env ไม่ตั้ง / จำลอง push ล้ม — คะแนนต้อง insert สำเร็จทุกกรณี — เก็บ log/ผลเป็นหลักฐานก่อนปิด task
hook อยู่หลัง insert แยก try/catch — revert ได้โดยพฤติกรรมการรับคะแนนไม่เปลี่ยน
