# FE-001 — Premium subject-breakdown screen reading Courses

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

สร้างหน้าจอแสดง breakdown รายวิชาใน Premium (การ์ดกลุ่มสาระ + รายการรายวิชาย่อยพร้อมคะแนนดิบ/หน่วยกิต) อ่านจาก field `Courses` ของ response `calculate/score`; รูปแบบการแสดงผลได้รับการยืนยันแล้วเป็น Table in Card (แบ่งกลุ่มสาระเป็นการ์ด แต่ละการ์ดบรรจุตารางรายวิชา); แสดง "ไม่มีข้อมูลหน่วยกิต" เมื่อ `Credit` เป็น null (ห้ามแสดง 0 หรือเว้นว่าง); ฝั่งฟรี (`analyst/{sID}`) ต้องไม่เปลี่ยนแปลงใด ๆ (ปิด OQ-16 แล้ว) — REQ-016 ฝั่งแสดงผล — กติกา `Credit` null แสดงเป็น "ไม่มีข้อมูลหน่วยกิต" ไม่ใช่ 0 อยู่ในสัญญา response (DES-018 กฎ AC4); ปิด OQ-16 แล้ว (ผู้ใช้ยืนยันรูปแบบ Table in Card และข้อความ "ไม่มีข้อมูลหน่วยกิต" 2026-09-15)

## References

REQ-016, AC-016.1, AC-016.4, AC-016.6, DES-018

## Scope

อ่านข้อมูลจาก field `Courses` เท่านั้น — ห้ามคำนวณ/เดาค่าเองฝั่งหน้าจอ; รูปแบบการแสดงผลเป็น Table in Card ตามที่ OQ-16 ยืนยัน;
ค่า `Credit` null ต้องแสดงข้อความ "ไม่มีข้อมูลหน่วยกิต" ไม่ใช่เลข 0 หรือเว้นว่าง

- Security-sensitive: no

## Out of Scope

ห้ามแตะหน้าฟรี (`analyst/{sID}`) ทุกจุด; ห้ามแสดง 0 เมื่อ `Credit` เป็น null; ห้ามคำนวณค่าแทน backend;

## Expected Output

none

## Acceptance

AC-016.1: หน้า Premium แสดงรายวิชาย่อยแยกแถวพร้อมคะแนนดิบและหน่วยกิต คู่กับค่ากลุ่มสาระถ่วงน้ำหนัก
AC-016.4: วิชาที่ไม่มีหน่วยกิตยังแสดง โดยช่องหน่วยกิตแสดง "ไม่มีข้อมูลหน่วยกิต" — ไม่แสดง 0 เป็นเลขจริง ไม่เว้นว่าง และไม่ซ่อนวิชา
AC-016.6: หน้าฟรีไม่เปลี่ยนแปลง — ยังเป็นกลุ่มสาระ + ค่าเฉลี่ยดิบธรรมดา

## Dependencies

BE-019

## Handoff

ตรวจ AC-016.1, AC-016.4, AC-016.6 ด้วยข้อมูลจริงจาก `calculate/score`: กลุ่มหลายวิชา, วิชาไม่มีหน่วยกิต, และหน้าฟรีก่อน/หลัง —
บันทึกภาพ/DOM หน้าจอทุกกรณี; ยืนยันว่า request ฝั่งฟรีไม่ถูกแตะ
ถอดหน้าจอใหม่ได้เดี่ยว — หน้า Premium กลับไปแสดงระดับกลุ่มสาระอย่างเดียวเหมือนเดิม; ไม่มีการเปลี่ยน backend เมื่อถอดเฉพาะ UI
ส่งต่อ reviewer
