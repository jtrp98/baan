# BE-004 — Implement CheckEntitlement steps 1-3 (fail-closed, parameterized SQL)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

## Goal

implement ขั้นตอนที่ 1–3 ของ `CheckEntitlement(sID)`: raw parameterized SQL (`NpgsqlParameter` เท่านั้น ห้ามต่อ string) ผ่าน `ApiBaseController.GetSchoolConnection()` — query `TSubscription` เงื่อนไข `status IN ('Active','PendingCancel')` คู่กับ `expire_at >= NOW()` เสมอ (`expire_at IS NULL` = ไม่ผ่าน), join `TPlan_Feature` ⋈ `TFeatureSBPlus` ด้วย `pf.plan_id = @subscription_plan_id`, fail-closed เมื่อ query error/ไม่พบ record — ขั้นตอนที่ 4 ยืนยันค่า FeatureCode ฝั่งธุรกิจแล้วคือ `compass_premium` และ `compass_admin_ops` (ปิด OQ-15(a2) 2026-09-15) โดยโค้ด `CompassEntitlementService.cs` มีค่าคงที่รองรับแล้ว; การ query คอลัมน์ `"FeatureCode"` รอ devops/ทีม SB PLUS รันสคริปต์ PRE-06 ก่อน deploy จริง — ปิดความเสี่ยง entitlement fail-open ของ REQ-013 (Module B Security Considerations) — ขั้นตอนที่ 4 ตัดสินทิศทางแล้วด้วยคอลัมน์ `"FeatureCode"` และยืนยันรหัสจริงแล้ว แต่คอลัมน์ใน DB จริงยังต้องรอ PRE-06 (DES-016 ขั้นตอนที่ 4) — 🔴 task นี้เป็นงาน security-grade ของเฟสที่ติดป้าย 🔒

## References

REQ-013, AC-013.1, AC-013.2, DES-016

## Scope

ขั้นตอนที่ 1–3 เท่านั้น: หาแถว subscription ที่ยังมีผล (เอาแถวล่าสุดแถวเดียว — `ORDER BY subscription_id DESC LIMIT 1`),
ไม่เจอ → `{ entitled: false, features: [] }`, เจอ → ดึงรายการ feature ด้วยการ join 2 ตาราง (ห้าม join สาม) ·
คำอธิบาย (`feature_description`) เป็นข้อมูลแสดงผลล้วน ไม่มีผลต่อการอนุญาต; คอลัมน์ `display_*` ยังไม่ยืนยัน → อ่านจาก
`f.feature_description` อย่างเดียวแล้วแจ้งกลับ `system-analyst` ให้ amend · ผล CheckEntitlement cache ได้ต่อ request เท่านั้น ห้าม cache ข้าม request

- Security-sensitive: yes

## Out of Scope

ห้ามต่อ string เข้า SQL เด็ดขาด; ห้าม join `TSubcriptionPlan`; ห้ามเขียน query อ้างคอลัมน์ `"FeatureCode"` ก่อน PRE-06 ยืนยันว่าถูกสร้างจริง;
ห้ามใส่เลข `feature_id` ลงโค้ดหรือ config เพื่อ "ไปต่อก่อน"; `status` ต้องรับทั้ง `'Active'` และ `'PendingCancel'` (การออกแบบที่ตั้งใจ ห้ามแก้เป็นเฉพาะ Active);
flow ผู้ปกครอง (`type=parent`) ห้าม implement รอบนี้

AC-013.2: กรณี DB ล่ม/query throw/ไม่พบ record/`expire_at` เป็น NULL → ถือว่าไม่มีสิทธิ์ทั้งหมด (fail-closed ไม่มีเส้นทาง fail-open)

## Handoff
