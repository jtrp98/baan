# REQ-030 — ตรวจข้อมูลอัปเดตจาก Desktop

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

## ต้องการอะไร/ทำไม

ให้ผู้ใช้ทราบว่ามีเวอร์ชันใหม่สำหรับเครื่องนี้ โดยการตรวจไม่ดาวน์โหลดหรือติดตั้งไฟล์. การเตรียมและติดตั้งเป็นคำสั่งแยกที่ผู้ใช้สั่งเองตาม [มติ 036 (GAP-07: ช่องว่างการเตรียมและติดตั้งอัปเดตที่ให้คง workflow เดิม)](../../../../shared/decisions/decisions-036.md) และผู้ใช้ยืนยันเกณฑ์เตรียม ติดตั้งและกู้คืนแล้วตาม [มติ 037 (ยืนยันเกณฑ์อัปเดต ป้ายจำลอง และ performance)](../../../../shared/decisions/decisions-037.md).

API (Application Programming Interface) คือช่องทางเรียกบริการ; OS (Operating System) คือระบบปฏิบัติการ; TOCTOU (Time-of-check to time-of-use) คือความเสี่ยงที่ข้อมูลเปลี่ยนระหว่างตรวจและนำไปใช้.

## Business Rules

- BR-030-01: Desktop ปัจจุบันตรวจ stable ตาม version และ platform ของตัวเอง
- BR-030-02: available=true ไม่อนุญาตให้ติดตั้งหรือรันไฟล์อัปเดต
- BR-030-03: การตรวจล้มเหลวต้องแจ้งข้อผิดพลาดและไม่ขัดขวางงาน local
- BR-030-04: การเตรียม/ติดตั้งอัปเดตเป็นคำสั่งแยกที่ผู้ใช้สั่งเอง (explicit intent) — ไม่เกิดจากการตรวจอัตโนมัติ (ตาม [มติ 036 (GAP-07: ช่องว่างการเตรียมและติดตั้งอัปเดตที่ให้คง workflow เดิม)](../../../../shared/decisions/decisions-036.md))
- BR-030-05: Desktop เชื่อเฉพาะ artifact ที่ผ่าน trust ตาม [DES-007 (Release และ trusted update)](../../../../build/design/des-007.md)/release-trust (hash ตรง manifest ที่ขึ้น registry + publisher pin ของ OS signature)
- BR-030-06: ช่วงเตรียมถึงติดตั้งต้องกัน staging TOCTOU, กัน expiry/withdraw/downgrade และต้องหยุดงานค้าง/หุ่นก่อนติดตั้ง (stop/close guard)

## Acceptance Criteria

- AC-030-01: เมื่อไม่มี published release ใหม่กว่า ผลตรวจมี available=false, release=null และ install_supported=false
- AC-030-02: เมื่อมี release ที่เข้าเงื่อนไข ผู้ใช้เห็น metadata แต่ไม่มีไฟล์ถูกดาวน์โหลด ติดตั้ง หรือ execute จากการตรวจ
- AC-030-03: เมื่อ API เข้าไม่ได้ การตรวจแสดงข้อผิดพลาดและผู้ใช้กลับไปใช้งาน local ต่อได้
- AC-030-04: การเตรียมอัปเดตเริ่มเฉพาะเมื่อผู้ใช้สั่งเอง และตรวจ trust ครบ (hash ตรง manifest จาก registry + publisher pin ตาม DES-007) ก่อนเก็บลง staging — ตรวจไม่ผ่านต้องไม่มี artifact ถูกเก็บหรือติดตั้ง และผู้ใช้เห็นเหตุผลการปฏิเสธ
- AC-030-05: artifact ใน staging ถูกตรวจความสมบูรณ์ซ้ำ (กัน TOCTOU) ตอนสั่งติดตั้ง — ผิด/เปลี่ยน/หมดอายุ/ถูก withdraw หรือเก่ากว่าที่ติดตั้งอยู่ (downgrade) ต้องปฏิเสธพร้อมข้อความ ไม่ติดตั้ง
- AC-030-06: การติดตั้งต้องขอหยุดงานค้าง/หุ่น (stop เป็นเพียงคำขอ) และผู้ใช้ยืนยันอีกครั้งก่อนแอป restart ติดตั้ง
- AC-030-07: การติดตั้งล้มเหลวกลางทาง เครื่องกลับมาใช้งานเวอร์ชันเดิมได้ (rollback/repair ตาม [REQ-031 (ติดตั้งและดูแลแอปบน Windows)](req-031.md)) พร้อมรายงานสาเหตุ — ไม่เหลือสถานะครึ่งติดตั้งที่ใช้งานไม่ได้
- AC-030-08: ผู้ใช้ยกเลิกหรือปิดแอประหว่างเตรียม/ก่อนติดตั้ง ต้องไม่มีการติดตั้งเกิดขึ้น และ staging ถูกล้างหรือตรวจซ้ำก่อนใช้ครั้งถัดไป

## ยังไม่ยืนยัน

ไม่มีสมมติฐานเพิ่มเติมที่ระบุไว้ในข้อกำหนดฉบับเดิม; การมีข้อกำหนดไม่ใช่หลักฐานว่า implementation ผ่านการตรวจรับแล้ว
