# REQ-027 — จัดการ license ผ่าน admin API

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

## ต้องการอะไร/ทำไม

ให้จัดการ License สำหรับระบบใช้งานจริงและเก็บข้อมูลถาวรใน SchoolBotLicense ตามมติผู้ใช้. เฉพาะพนักงานที่มี session และบทบาทที่ให้สิทธิ์จัดการ License จึงใช้ admin API ได้.

API (Application Programming Interface) คือช่องทางเรียกบริการ.

## Business Rules

มติผู้ใช้ 2026-10-21 เรื่องข้อมูลถาวรและชื่อฟิลด์อยู่ใน [มติ 004 (License และมาตรฐานชื่อข้อมูล — 2026-10-21)](../../../../shared/decisions/decisions-004.md) กับ [REQ-033 (ชื่อและฟิลด์ข้อมูล SchoolBot)](req-033.md); Memory Store ในหลักฐานฐานเดิมเป็นข้อจำกัดโค้ดเดิมที่ต้องแก้

- BR-027-01: admin API ของ License อยู่ที่ `/v2/admin` ผู้เรียกต้องมี staff session (channel `staff_admin`) ของพนักงาน SchoolBright และมีบทบาท `SchoolBotStaffRole` ที่ active ซึ่งมีสิทธิ์จัดการ License; ปิด `/v1/admin` static bearer (admin key) ไม่ใช้เป็นทางเข้าอีก — ผู้ใช้ยืนยัน 2026-10-22 ([มติ 025 (มติ auth ข้ามระบบ, admin โรงเรียน, publish, สอบซ่อม และ Desktop)](../../../../shared/decisions/decisions-025.md) ข้อ 6, [มติ 026 (อนุมัติแบบข้อมูลที่ปรับใหม่)](../../../../shared/decisions/decisions-026.md)); ชื่อบทบาทที่ให้สิทธิ์ License อยู่ที่ [DES-004 (ตัวตนและสิทธิ์การใช้งาน SchoolBot)](../../../../build/design/des-004.md) และ [DES-012 (Auth ข้ามระบบสำหรับเว็บโรงเรียน, admin และ Desktop)](../../../../build/design/des-012.md) ไม่ใช่มติธุรกิจที่นี่
- BR-027-02: สร้าง License ตามข้อมูลโรงเรียนและวันหมดอายุที่ถูกต้อง จำกัด 1 เครื่องต่อ Key ตาม [มติ 006 (จำนวนเครื่องต่อ License — 2026-10-21)](../../../../shared/decisions/decisions-006.md)
- BR-027-03: รายการคืน metadata ไม่คืน key เต็ม, hash หรือ device IDs
- BR-027-04: เก็บข้อมูล License ถาวรใน `SchoolBotLicense` โดยใช้ `SchoolBotLicenseId` และฟิลด์มาตรฐานตาม REQ-033; การ restart API ต้องไม่ทำให้ข้อมูล License หาย

## Acceptance Criteria

- AC-027-01: เมื่อระบบยืนยันตัวตนพนักงานที่ `/v2/admin` ยังไม่ถูกตั้งค่า เรียก admin API ได้ 503; ไม่มี staff session หรือ session/token ไม่ถูกต้อง ได้ 401; มี session แต่ไม่มีบทบาท StaffRole ที่ active ซึ่งมีสิทธิ์จัดการ License ได้ 403; เรียก `/v1/admin` ด้วย static bearer แล้วไม่สามารถสร้างหรือดูรายการ License ได้
- AC-027-02: ผู้เรียกที่มี staff session และ StaffRole ที่มีสิทธิ์ ส่งข้อมูลถูกต้องได้ 201 พร้อม Key สำหรับ 1 เครื่อง; ชื่อว่างหรือหมดอายุแล้วถูกปฏิเสธ และไม่สามารถสร้าง Key ที่ใช้ได้หลายเครื่อง
- AC-027-03: ผู้เรียกที่มีสิทธิ์ (ตาม BR-027-01) เรียกรายการหลังสร้างแล้วเห็น metadata และจำนวน activated devices โดยไม่มี key เต็ม, hash หรือ device IDs
- AC-027-04: ผู้เรียกที่มีสิทธิ์ (ตาม BR-027-01) สร้าง License แล้ว restart API ในสภาพแวดล้อมทดสอบ เมื่อเรียกรายการอีกครั้งยังพบ License เดิมและข้อมูลสถานะเดิม

## ยังไม่ยืนยัน

รายชื่อพนักงาน staff_admin ตั้งต้นยังรอข้อมูลจากผู้รับผิดชอบสิทธิ์พนักงาน
