# REQ-029 — จัดการ release metadata

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

## ต้องการอะไร/ทำไม

ให้ผู้ดูแลเตรียมและเปิดเผยข้อมูลเวอร์ชันสำหรับการตรวจอัปเดต. การเผยแพร่ metadata ยังไม่ยืนยันว่า artifact หรือลายเซ็นเชื่อถือได้จริง.

SHA256 (Secure Hash Algorithm 256-bit) คือค่า hash สำหรับตรวจความสมบูรณ์ของข้อมูล; HTTPS (Hypertext Transfer Protocol Secure) คือ HTTP ที่เข้ารหัสการสื่อสาร.

## Business Rules

- BR-029-01: Version เป็น x.y.z; channel stable/beta; platform windows-amd64/darwin-amd64/darwin-arm64
- BR-029-02: ต้องมี HTTPS URL ไม่มี userinfo, SHA256 64 hex และ signature metadata ไม่ว่าง
- BR-029-03: Publish เปิดเผย metadata เท่านั้น ไม่ตรวจว่าดาวน์โหลดหรือลายเซ็นเชื่อถือได้จริง

## Acceptance Criteria

- AC-029-01: สร้าง metadata ถูกต้องแล้ว published=false; สร้างคู่ version/channel/platform เดิมซ้ำได้ RELEASE_EXISTS
- AC-029-02: Version ผิดรูปแบบ, platform ไม่รองรับ, URL ไม่ใช่ HTTPS, hash ผิด หรือ signature ว่าง ถูกปฏิเสธ
- AC-029-03: Update check คืนเฉพาะ published release ใหม่สุดที่ channel/platform ตรงและ version สูงกว่า โดยไม่คืน draft หรือ version เท่ากัน

## ยังไม่ยืนยัน

- เจตนาทางธุรกิจที่กลั่นจากฐานเดิมยังไม่ยืนยัน: ให้ผู้ดูแลเตรียมและเปิดเผยข้อมูลเวอร์ชันสำหรับการตรวจอัปเดต ต้องให้เจ้าของผลิตภัณฑ์ยืนยันเจตนานี้ โดยแยกจากกฎหรือเกณฑ์ที่มีมติยืนยันแล้ว
