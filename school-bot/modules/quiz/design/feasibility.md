# Quiz (บทเรียน): Feasibility (จาก role 2)

**ผล: ทำได้มีเงื่อนไข** (2026-11-01)

ตรวจใหม่รอบ 2026-11-01 ตาม requirement ที่เปลี่ยน 2026-10-31: R2, R3, R4, R5/R16, R6, R7, R8, R9, R10, R12–R18 · R1/R11 ผลเดิม (2026-10-30) ยังใช้ได้ ปรับเฉพาะที่ระบุ · ภาพอ้างอิงที่เปิดดู: Start Page, After select level will see map, Quiz game example 2 และ 8 (ไม่เปิด Map Background 2 term ตามคำสั่ง ใช้ขนาดจาก INDEX)

**สรุป:** ทำได้ทุกข้อ ไม่มี OQ ที่ block โครงหน้า · ไม่ต้องถามผู้ใช้ก่อนออกแบบ · เงื่อนไขหลัก

2. **ชนกับ brand:** Motion D-19 (วนไม่หยุดได้แค่ Attention Ring/spinner · one-time ≤ 0.2s) ชน R18 · ปุ่ม "เริ่มภารกิจ" สีส้มในภาพอ้างอิงตรงกับ `action-robot` (= กดแล้วหุ่นขยับ) ทั้งที่ Quiz ไม่ขยับหุ่น · สี accent ต่อ level ชนความหมายสี (เขียว/ส้ม/แดง) → OQ29
3. **ข้อมูล/ออฟไลน์:** ผลการเล่นเป็น log แบบเพิ่มอย่างเดียว (ห้ามใช้ "ฉบับใหม่กว่าชนะ" ของ my-work) · ภาพแผนที่ต้องแยกต่อเทอมและบีบก่อนใช้ (OQ16) · จำนวนด่านต้องผูกกับตำแหน่งในภาพ (OQ18/OQ19)
4. **OQ ใหม่รอบนี้ (ไม่ block โครงหน้า):** OQ26 จังหวะเปิดด่านเทียบ "1 ด่าน = 1 คาบ" · OQ27 level/เทอมที่ยังไม่มีเนื้อหาตอนปล่อย · OQ28 ข้อมูล phase 1 ที่ต้องเก็บ (ตัวตนนักเรียน ห้อง เทอม) · OQ29 สีส้ม/accent ชนความหมายสี
5. **ที่ต้องตอบก่อน `approved` (ผู้ใช้ยืนยัน):** แนะนำ OQ9 (เกณฑ์ปลดล็อก) · OQ11 (ตัดปุ่มข้าม) · OQ28 · OQ29 · ที่เหลือใช้ข้อสมมติ Proposed ออกแบบได้ ติดป้ายสมมติ · ก่อนส่ง dev: OQ16, OQ18, OQ19, OQ23

## R1: เมนูบทเรียน → เลือก Level → แผนที่

**ผล: ทำได้ · พร้อม: Yes** (ผลเดิม + ปรับ)
- สถานะ "ลองแล้วได้ 0 ดาว" ไม่ใช่สถานะที่ 4: ด่านปลดล็อกแล้วแต่ยังไม่ผ่าน = "กำลังเรียน" (เดิม) · ต่อไปมี "กำลังเรียน" ได้เพียง 1 ด่านต่อ level (ด่านแรกที่ยังไม่ผ่าน) ผู้เล่นซ้ำด่านที่ผ่านแล้วไม่เปลี่ยนสถานะ
- ภาพอ้างอิงแผนที่และหน้าด่านไม่มี sidebar/ปุ่ม home (เต็มจอ มีแค่ "กลับ" / ✕) ขณะที่หน้าเลือก Level มี sidebar → ต้องตัดสินตอนออกแบบ (Delegated → Designer ต้องไม่ขัด app-shell R7/R5): ทางไปหน้าหลัก/Lab อื่นจากแผนที่ (เสนอ: ผ่าน "กลับ" ไปหน้าเลือก Level หรือแถบหน้าต่าง) · ทางออกกลางด่านต้องดักทุกทาง (✕, กลับ, ปิดโปรแกรม, ปุ่ม home บนแถบ) ใช้ยืนยันเดียวกัน (H5)

## R2: เนื้อหาจาก cloud · ครูเปิด/ปิด

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ5, OQ18, OQ23, OQ22)
- ด่านต้องมี ID คงที่ (ไม่ใช้ลำดับ) · ผลเก็บตาม ID + เวอร์ชันเนื้อหา · ถ้าบริษัทแทรก/ลบ/สลับด่านภายหลัง: ด่านที่เคยผ่านเปิดตลอด (ผ่านแล้วไม่ล็อกกลับ) · จำนวน "ผ่าน x/y" นับจาก manifest ปัจจุบันเท่านั้น (ไม่ให้ x > y) · ผลของด่านที่ถูกลบเก็บไว้แต่ไม่นับในแผนที่
- ต้องมี **manifest ต่อ level** (จำนวนด่านต่อเทอม ชื่อด่าน ตำแหน่ง node) ที่ดึงตอน login/เปิดหน้าเลือก Level ให้ครบ 6 level เพื่อวาดการ์ด (ด่านที่ผ่าน/ทั้งหมด) · ใช้แคชได้ · เนื้อหาข้อสอบดึงทั้งด่านก่อนเริ่ม (ผลเดิม OQ16)
- ข้อมูลที่แผงภารกิจต้องใช้เพิ่ม (R13): ชื่อด่าน, สิ่งที่ได้เรียนรู้ (รายการ), วิธีทำ, แท็ก, ลำดับ · ยังไม่อยู่ในแหล่งเนื้อหาที่ระบุ (Course Plan มีหัวข้อรายแถว) → รวมใน OQ23 (ต้องมีฟิลด์เหล่านี้ใน cloud ไม่งั้นแผงว่าง)
- ลำดับเลข "ภารกิจที่ n": นับต่อเนื่อง 1..N ข้ามเทอม หรือเริ่มใหม่ต่อเทอม (Designer เสนอ · เสนอต่อเนื่อง เพราะเทอม 2 ต่อเนื่อง R7)
- "ครูเปิด/ปิดหน่วย" ยังไม่นิยาม → OQ22 · Proposed ตัดออกจาก phase 1 (เหตุผลล็อก "ครูปิด" จึงยังไม่ต้องมี UI ใน phase 1 แต่เผื่อที่ในแผงเหตุผล)

## R3: แบบฝึก 4 กลุ่ม 5–8 ข้อ ไม่ลองซ้ำ ไม่มีใบ้

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ11, OQ13 ก, OQ20)
- **คะแนนต่อข้อ (OQ13 ก):** แนะนำ **ถูกทั้งข้อ = 1 ข้อ ผิด = 0 ไม่ให้บางส่วน** ทุกกลุ่ม เพราะ R4 และหน้าผล ("ตอบถูก 4/5 ข้อ") ใช้จำนวนเต็ม และเกณฑ์ไม่ปัดเศษ · ข้อจับคู่ 4–5 คู่ถูกทั้งข้อเข้มสำหรับ ป.1 ไม่มีลองซ้ำ → ให้คุมจำนวนคู่ ≤ 4 ในข้อ (ข้อกำหนดเนื้อหา OQ23) · เฉลยต้องโชว์ลำดับ/คู่/ค่าที่ถูกทั้งหมด (เดิม)
- **"ข้าม" (OQ11):** เมื่อไม่ลองซ้ำและไม่มีใบ้ ปุ่มข้าม = ตอบผิดโดยไม่ได้เห็นเฉลย หรือสร้างเส้นทางที่ 2 ที่ต้องมีข้อความยืนยัน (H5) · ภาพอ้างอิงทุกภาพไม่มีปุ่มข้าม · **แนะนำตัดปุ่ม "ข้าม" ออกจาก R3** (การกระทำ: ตอบ ตรวจ ออก) · ถ้าผู้ใช้ต้องการคงไว้ ต้องบอกก่อนกดว่านับเป็นผิด + แสดงเฉลย
- **ปุ่ม "ตรวจ":** ใช้ `aria-disabled` + บอกเหตุผล (เช่น "เลือกคำตอบก่อน", "วางให้ครบทุกช่อง") จนตอบครบ (H5) · ข้อเรียง/จับคู่มี "ล้าง/เริ่มใหม่" ก่อนตรวจ (ยังไม่ใช่ลองซ้ำหลังตรวจ) · หลังตรวจแล้วล็อกคำตอบ ไม่ย้อนแก้
- **ทางเลือกแทนการลาก (WCAG 2.5.7):** เรียงบล็อก/จับคู่/ลากป้าย = แตะเลือกแล้วแตะวาง ใช้ได้ด้วยคีย์บอร์ด (โฟกัสเห็น ลูกศร/Enter/Space) และมีเสียงสถานะด้วย aria-live ("เลือกป้าย x แล้ว วางที่ช่องไหน") · ช่องวาง ≥ 44 และเว้นระยะไม่ชนกัน (2.5.8) · สไลเดอร์ลาก = มี ‹ › คู่เสมอ (R10) ครบ 2.5.7
- **สไลเดอร์ (OQ20):** (1) ก้านสไลเดอร์ในภาพอ้างอิง ~26px < R10 (44) → ขยายจุดจับ (2.5.8 ขั้นต่ำ 24) (2) ค่าเป้าต้องอยู่บนกริดของ step ของ ‹ › และสไลเดอร์ ไม่งั้นไปไม่ถึง (เช่น step 5° ต้องเป้าเป็นพหุคูณ 5 และ tolerance ≥ ครึ่ง step) (3) ข้อความ "ใกล้แล้ว! ห่างจากเงา 20°" เป็น feedback ขณะปรับ ใกล้เคียง **คำใบ้ต่อเนื่อง** ซึ่งขัด "ไม่มีคำใบ้" ตามถ้อยคำ แต่เงาที่เห็นอยู่แล้วเป็นเป้าชัด ข้อความจึงเป็นทางเลือกที่ไม่ใช้ตา (a11y) · แนะนำคงไว้และถือเป็น feedback ไม่ใช่ใบ้ → ให้ผู้ใช้ยืนยันใน OQ20 (4) แจ้งผลด้วย aria-live แบบหน่วงเมื่อหยุดปรับ ไม่อ่านทุก 1° (H1) (5) "ถูกเมื่อทุกข้อต่อพร้อมกัน" ถูกทั้งข้อ (ตาม OQ13 ก)
- โครง: แถบ progress รองรับ 5–8 ข้อ (OQ14 answered) · ความคืบหน้า x/n แสดงเสมอ · ภาพอ้างอิงเป็น 1440×900 ไม่มีแถบหน้าต่าง ของจริงสูง 840 → ตรวจ overflow ตอน +40% (ไทย/EN/中文) เลื่อนเฉพาะแผง · ไม่มีจับเวลา (เดิม)
- ภาพ/สื่อโหลดไม่สำเร็จรายภาพ: ต้องมี fallback ข้อความ + ลองใหม่ ไม่ทำให้ทั้งด่านพัง (เดิม) · เลือกตอบด้วยภาพต้องมี alt/ข้อความกำกับ

## R4: ดาว 60/80/100% กับ 5–8 ข้อ

**ผล: ทำได้ · พร้อม: Assume** (OQ12)
- **ตรวจครบทุก N แล้ว** (เทียบเลขจำนวนเต็ม `ถูก×100 ≥ 60×N` ห้ามใช้ทศนิยม): N=5 → 3/4/5 · N=6 → 4/5/6 · N=7 → 5/6/7 · N=8 → 5/7/8 ได้ครบ 3 ระดับและเรียงต่างกันทุก N (ตัวอย่างใน R4 ถูกต้อง · เพิ่ม N=7) · ถ้า cloud ส่งด่านนอกช่วง 5–8 ให้คำนวณด้วยสูตรเดียวกัน ไม่ล้ม (ข้อมูลผิดไม่ block ผู้เล่น)
- **เล่นซ้ำ (OQ12):** ผลเป็น log เพิ่มอย่างเดียว · ดาวบนแผนที่ = **สูงสุดต่อด่าน** · "ผ่านแล้ว" = เคยได้ ≥ 1 ดาวครั้งใดก็ได้ · ผลใหม่ต่ำกว่าเดิมไม่ลดดาวและไม่ล็อกกลับ · "ดาวใหม่ +n" = ส่วนเกินดาวสูงสุดเดิม · **n = 0 ต้องไม่แสดงการ์ด "+0"** แสดง "ดาวสูงสุดของด่านนี้ x/3" แทน (H1)
- **ปุ่ม "ด่านต่อไป":** 0 ดาว (ด่านถัดไปยังล็อก) → ไม่ชวนไปด่านล็อก ใช้ "เล่นอีกครั้ง" เป็นปุ่มหลัก + บอกว่าต้องได้ 60% ก่อน · ด่านสุดท้ายเทอม 1 → ไปด่านแรกเทอม 2 (ช่วงฉลอง checkpoint) · ด่านสุดท้ายเทอม 2 → กลับแผนที่ที่เส้นชัย
- ภาพอ้างอิงผลจบด่านมี 🏅 และสัญลักษณ์ ▶ ↺ (ตัดเหรียญแล้ว ที่เหลือแทนด้วย Lucide `play`, `rotate-ccw` ตาม brand §6) · ชื่อปุ่ม: ภาพใช้ "เล่นอีกครั้ง" R4 ใช้ "เล่นใหม่" → เลือกคำเดียว (Designer เสนอ ให้ตรง brand §7)
- ผลจบด่านต้องไม่รอ cloud: บันทึกลงเครื่องแล้วแสดงผลทันที ส่งขึ้น cloud เบื้องหลัง (ดู R5)

## R5 / R16: phase 1 เก็บผลที่ cloud School Bot · ออฟไลน์ sync

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ17 answered · OQ21, OQ28)
- **ข้อความขัดกัน:** "ผลบันทึกที่ cloud ก่อนเสมอ" ขัดกับ "ออฟไลน์เก็บในเครื่องแล้ว sync" และกับหน้าผลที่ไม่ควรรอเครือข่าย → ถ้อยคำที่ทำได้: **เขียนลงเครื่องทันทีแบบคงอยู่ (durable) ก่อนแสดงผลจบด่าน แล้วส่งขึ้น cloud ทันทีที่ออนไลน์** (cloud คือที่เก็บหลักที่เปลี่ยนเครื่องแล้วเห็น ไม่ใช่ลำดับการเขียน) → แก้ R5
- **my-work/app-shell ไม่ครอบคลุม Quiz ตอนนี้ (ช่องว่าง):** my-work R5–R11 ว่าด้วยงาน Arm/Block ("quiz/teacher-web: ไม่เกี่ยว" ใน INDEX ของ my-work · R7 ยังเขียน "คะแนน Quiz เข้าคิวรอส่ง" แบบ SchoolBright เก่า) · app-shell R3 แถบสถานะผูกกับ "งาน" และ "ชื่องาน" ซึ่ง Quiz ไม่มี · ต้องกำหนดว่าสถานะ sync ของแถบหน้าต่างครอบคลุมผลบทเรียนด้วยหรือไม่ และใช้ข้อความอะไร (เสนอ: ใช้ชิป ออฟไลน์/บันทึกไม่สำเร็จ ร่วมกัน ข้อความใต้ชื่องานไม่แสดงในบทเรียน) · ใช้ถ้อยคำ "บันทึกขึ้นคลาวด์" ตาม brand §7
- **ผลเป็น log เพิ่มอย่างเดียว ห้ามใช้ "ฉบับใหม่กว่าชนะ" (my-work R8):** ถ้านักเรียนเล่นบน 2 เครื่อง การแทนด้วยฉบับใหม่กว่าทำให้ผลหาย → ผลต่อการเล่น = 1 แถว มี ID ที่สร้างฝั่ง client (UUID) ทำให้ส่งซ้ำได้ไม่ซ้ำแถว (idempotent) · สถานะที่แสดงทั้งหมด (ดาวสูงสุด ผ่าน/ล็อก กำลังเรียน) **คำนวณจาก log** ผสานระหว่างเครื่องได้ไม่ชนกัน · เวลาจากนาฬิกาเครื่องเชื่อไม่ได้ตอนออฟไลน์ เก็บทั้งเวลาเครื่องและเวลาที่ server รับ
- **ข้อมูลต่อการเล่นที่ต้องเก็บ:** รหัสผลเล่น, รหัสนักเรียน (จากบัญชี), level, **เทอมของหลักสูตร (1/2)**, รหัสด่าน + เวอร์ชันเนื้อหา, จำนวนข้อ n, ข้อถูก, ดาว (เก็บไว้แม้คำนวณซ้ำได้ เผื่อเกณฑ์เปลี่ยน), เวลาเริ่ม/จบ, ผลต่อข้อ (ถูก/ผิด + คำตอบ เพื่อวิเคราะห์ภายหลัง · Proposed) · **ห้อง ณ เวลานั้น** เก็บได้ก็ต่อเมื่อ phase 1 รู้ห้อง → OQ28
- **เปลี่ยนเครื่อง (EC-04):** ต้องดึงภาพรวมความคืบหน้าจาก cloud ก่อนวาดการ์ด Level/แผนที่ · ถ้า login แล้วแต่ดึงไม่สำเร็จและไม่มีแคชของบัญชีนี้ → **ห้ามแสดงเป็นครั้งแรก (ด่าน 1 เปิด ที่เหลือล็อก)** เพราะนักเรียนที่เคยเล่นจะเห็นความคืบหน้าหาย (H1/H9) · แสดงสถานะ "ยังโหลดความคืบหน้าไม่ได้ · ลองอีกครั้ง" แยกจากโหลดเนื้อหา
- **เครื่องใช้ร่วม (ห้องคอม):** คิวและแคชผลต้องแยกตามบัญชี · logout ตอนออฟไลน์ที่ยังมีผลค้างส่ง: เตือนชัด (OQ17 Proposed) เพราะ login ต้องออนไลน์ เครื่องนั้นจะส่งให้ไม่ได้จนบัญชีนั้นกลับมา login · ผลค้างส่งไม่ควรอ่านได้ด้วยบัญชีอื่น (NFR-05)
- ผลต่อ phase 2: เก็บ log ตามนี้ตั้งแต่ phase 1 จึงส่ง SchoolBright ย้อนหลังได้ โดยกฎ (ก)/(ข) ของ OQ21 ตัดสินทีหลัง · เก็บรายละเอียด phase 2 เดิม: ส่งซ้ำ idempotent, สถานะ "รอส่งคะแนน" บนการ์ดด่านและไม่ซ้ำชิปคลาวด์ (ใช้คำต่างกัน), ล้มเหลวถาวรไม่ติดเงียบ · ตัดสินที่ OQ7, OQ8, OQ21

## R7: สถานะด่านและล็อก

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ9, OQ10, OQ22, OQ26)
- **กฎที่ใช้ได้โดยไม่กำกวม:** ด่าน k เปิด ⇔ k = ด่านแรกของ level **หรือ** ด่าน k−1 ผ่าน (≥1 ดาว) **หรือ** ด่าน k เคยผ่านแล้ว · ด่านแรกของเทอม 2 อิงด่านสุดท้ายของเทอม 1 · ทุกด่านที่ไม่ใช่ด่านแรกของ level ไม่ใช่ "เปิดเสมอ" (ข้อความ "ด่านที่ 1 เปิดเสมอ" ต้องระบุว่าเป็นด่านแรกของ level ไม่ใช่ของเทอม 2)
- **checkpoint ไม่ใช่ด่าน** (ไม่ใช่ node ที่เล่นได้) เป็นเครื่องหมายบนแผนที่ที่ปลดตามด่านสุดท้ายเทอม 1 · R7/R13/R9 ยังไม่ระบุ → เพิ่มประโยคใน R13
- **คำว่า "ทางลัด" ชนกัน:** R7 "ไม่มีทางลัดข้ามเทอม" = ห้ามข้ามความคืบหน้า · R14 "ทางลัด" = เลื่อนดูแผนที่ → แก้ให้ R14 เรียก "ปุ่มเลื่อน" · แตะ "เทอม 2" ตอนยังล็อก: เสนอ **เลื่อนไปดูได้ (แผนที่ล็อกทั้งหมด) + แสดงเหตุผลในแผง** ไม่ใช่เงียบหรือห้ามเลื่อน (H1)
- **เหตุผลล็อก:** กฎ/Logic ยังมี "ยังไม่ถึงเทอม 2" ซึ่งอ่านเป็นเวลาปฏิทินได้ → ใช้ข้อความตามความคืบหน้าเท่านั้น ("ผ่านด่านสุดท้ายของเทอม 1 ก่อน" / "ผ่านด่านที่ k−1 ก่อน" ระบุด่านจริง) · "ครูปิด" ไม่ใช้ใน phase 1 (OQ22)
- ล็อกด้วย `aria-disabled` + แตะแล้วเปิดแผงอธิบาย เข้าถึงได้ด้วยคีย์บอร์ด ลำดับ Tab ตามลำดับด่าน (เดิม)
- **OQ9:** เกณฑ์ ≥1 ดาว (60%) ตัน ป.1 ที่ได้ <60% ต้องเล่นซ้ำจนผ่าน ไม่มีใบ้ ไม่มีข้ามด่าน · ทำได้ทางเทคนิคทั้งสองแบบ (≥1 ดาว หรือแค่เล่นจบ) · Proposed คง ≥1 ดาว · ถ้าโจทย์เล่นซ้ำชุดเดียวกัน ผู้เล่นจะจำคำตอบ → สลับลำดับตัวเลือก/ข้อ (เดตาไม่เปลี่ยน) เป็นข้อเสนอ dev
- **level อิสระ:** เด็ก ป.1 เข้า Level 6 ได้ (ตั้งใจ) · ผลไม่ผูกชั้น (phase 2 → OQ21)
- **OQ26 (ใหม่):** 1 ด่าน = 1 คาบ (ปกติ 40–50 นาที) แต่แบบฝึก 5–8 ข้อทำเสร็จภายในไม่กี่นาที และ phase 1 ไม่มีครูควบคุมเวลาเปิดด่าน → เด็กทำจบทั้งเทอมในครั้งเดียวได้ · ไม่ผิดทางเทคนิค ต้องผู้ใช้ยอมรับหรือเพิ่มกลไก (เช่น ครูเปิดด่านภายหลัง = OQ22)

## R13: แผนที่ยาว 2 เทอม

**ผล: ทำได้มีเงื่อนไข · พร้อม: Assume** (OQ16, OQ18, OQ19)
- **ภาพ (OQ16):** 9388×1985 PNG 30 MB: ถอดรหัสเป็น bitmap ≈ 75 MB ต่อภาพ (×6 level) และแคชออฟไลน์ 180 MB ไม่เหมาะ · เงื่อนไข: แยกเป็น 1 ภาพต่อเทอม (≤ ~4096 px กว้าง ความสูงเผื่อจอ 2x ที่ 840 ≈ 1680 px) บีบเป็น WebP/AVIF เป้า ≤ ~1.5 MB ต่อภาพ · ใช้ภาพโหลดทีละเทอม (เทอม 2 เมื่อใกล้ถึง) · เสนอ **ใส่ภาพธีมในตัวติดตั้ง** (ไม่มีสถานะโหลด ใช้ออฟไลน์ได้) ส่วน cloud เป็นเนื้อหา/manifest
- **จำนวนด่านต่อภาพ (OQ18/OQ19):** ตำแหน่ง node วางตามภาพ (เส้นทางคดเคี้ยว ไม่ใช่เส้นตรง) · ภาพ "ช่องวาง" มีจำนวนจำกัด ถ้า ด่านใน manifest > ช่อง แผนที่ล้น/ไม่พอ · **ตำแหน่ง node ต้องส่งมาพร้อมภาพเวอร์ชันเดียวกัน** (ไม่ปล่อยให้ภาพกับ manifest คนละเวอร์ชัน) และอนุญาตจำนวนต่างกันต่อ level/เทอม (เส้นทางที่ออกแบบแยกต่อเทอม)
- node และป้ายเป็น overlay (ตำแหน่งเป็นสัดส่วนของภาพ) ไม่ฝังในภาพ → ปรับตามขนาดหน้าต่าง (ขั้นต่ำ 1440×900 ยืดได้ R11 app-shell) ภาพ scale ตามความสูง · ภาพ `After select level` เห็น node ถูกบังด้วยแผงภารกิจ (~25% ขวา) → เมื่อเปิดแผง ต้องเลื่อนให้ node ที่เลือกอยู่นอกแผง หรือยุบแผงได้ · ค่าเริ่มต้นเลือกด่านปัจจุบัน (ภาพอ้างอิงเปิดแผงของภารกิจที่ 3 ตั้งแต่เข้า)
- **การเลื่อน:** ลากเพื่อเลื่อน (ต้องมี threshold ~5px แยกจากการแตะ node), ล้อเมาส์แนวตั้งแปลงเป็นแนวนอน, ทัชแพด 2 นิ้ว, ปุ่ม ‹ ›, แถบแผนที่ย่อ, คีย์บอร์ด (Tab ตามด่าน + เลื่อนตามโฟกัส) · ลากเป็นทางเลือกเสริม มีปุ่มคู่เสมอ (2.5.7) · เลื่อนอัตโนมัติไป "ด่านปัจจุบัน" ใช้ reduced-motion = กระโดดทันที

## R17: ธีมต่อ level

## R18: micro animation

**ผล: ทำได้มีเงื่อนไข · พร้อม: Yes (ปรับตามเงื่อนไขนี้)**
- **ชนกับ `../../../design/archive/sketchbook-brand.md` §5 (D-19):** (1) "วนไม่หยุด" ได้แค่ Attention Ring และ spinner → "node ปัจจุบันเต้นเบา ๆ" ใช้ **Attention Ring สีน้ำเงิน** (กดต่อ ไม่ขยับหุ่น) ไม่ใช้การเต้นขนาดวนซ้ำแบบใหม่ (2) one-time เกิน `dur-move` 0.2s ไม่มี token: มาสคอตกระโดดข้ามแผนที่, ดาวป๊อป, ดาวระยิบ, progress เต็ม ต้องเพิ่ม token ใหม่ (DSG) ผ่านผู้ใช้ ไม่ใช่ใช้ค่าอิสระ · สั่นเมื่อแตะด่านล็อกใช้ `dur-shake` 0.45s ได้ (มีอยู่)
- **WCAG 2.2.2 (A):** การเคลื่อนไหวที่เริ่มเอง เกิน 5 วินาที ต้องหยุดได้ → Ring วนไม่หยุดบน node ปัจจุบันไม่ผ่านถ้าไม่มีตัวหยุด · เสนอจำกัดการเต้น 2 รอบ (≈ 4.8s) แล้วเป็นวงนิ่ง (ผลเดียวกับ reduced-motion ที่ brand กำหนด: วงนิ่งความเข้ม .5) · ยืนยันกับผู้ใช้ผ่านการออกแบบ (ไม่ต้อง OQ ถ้ายึดข้อเสนอนี้)
- **WCAG 2.3.1:** ดาวระยิบ ≤ 3 ดวง ครั้งเดียว ห้ามกะพริบ > 3 ครั้ง/วินาที ในพื้นที่เดียวกัน
- **reduced-motion:** ทุก animation มีแบบลดการเคลื่อนไหว (brand กำหนด "ไม่มี = ไม่ผ่าน") = เปลี่ยนค่าทันที รวมการเลื่อนอัตโนมัติ/มาสคอตกระโดด/progress · ข้อมูล (ถูก/ผิด, ดาว, ผ่าน/ล็อก) ต้องอยู่ในข้อความ/ไอคอนเสมอ
- ทำเป็น CSS ล้วนได้ (ไม่ต้องไลบรารี) · progress + มาสคอตเลื่อนตามเป็น transform ใช้ได้
