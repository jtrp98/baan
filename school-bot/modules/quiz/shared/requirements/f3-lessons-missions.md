# ระบบภารกิจบทเรียน

Rev 1 · 2026-11-05 · บันทึกโดย นายช่าง · ขอโดย ผู้ใช้

ข้อกำหนดตามคำตอบผู้ใช้ในแชต 2026-11-05 สำหรับ School Bot Desktop, Admin และเว็บครู ใช้เป็นขอบเขตของงานภารกิจจริง ส่วนข้อสอบและกระบวนการส่งเกรดเดิมใช้สัญญาเดิม

## เกณฑ์ตรวจรับ

| ID | สิ่งที่ต้องตรวจได้ |
|---|---|
| AC-01 | เมนูบทเรียนเปิดหน้าเลือก Level 1–6 ในแอปจริง ทุก Level เปิดดูได้ แผนที่แสดงจำนวนและลำดับด่านตามที่ Admin เผยแพร่สำหรับแต่ละเทอม เช่น เผยแพร่ 20 ด่าน แสดง 20 ด่าน เทอมที่ยังว่างมีสถานะอธิบายได้ |
| AC-02 | Admin ตั้ง Level เทอม ลำดับ เนื้อหา และกิจกรรมหนึ่งรายการต่อด่านได้ ด่านเลือกใช้กิจกรรมในบทเรียน แบบฝึก หรือเชื่อมกับ Arm Lab / Block Lab ได้ตามชนิดที่รองรับ มีโหมดมีคะแนนหรือไม่มีคะแนน พร้อมตรวจความเข้ากันได้ของการตั้งค่าก่อนเผยแพร่ |
| AC-03 | Admin กำหนดเงื่อนไขผ่านรายด่านได้ตามชนิดกิจกรรม เช่น ทำครบ ส่งงาน ครูอนุมัติ หรือผ่านเกณฑ์คะแนน และกำหนดได้ว่าการผ่านด่านนั้นเป็นเงื่อนไขเปิดด่านถัดไปหรือไม่ ด่านไม่มีคะแนนยังทำเสร็จและเปิดด่านถัดไปได้ตามกติกาที่ตั้ง |
| AC-04 | ครูดูสถานะและผลของนักเรียนในห้องที่มีสิทธิ์ เปิดหรือปิดได้ทั้งรายเทอมและรายด่าน ระบบกันการปิดเมื่อทราบว่ามีนักเรียนในขอบเขตนั้นเริ่มแล้ว ถ้ายังไม่มีข้อมูลการเริ่มที่ซิงก์เข้ามา ครูปิดได้ และเมื่อซิงก์พบว่านักเรียนเริ่มออฟไลน์ก่อนปิด ระบบรับผลและเปิดด่านหรือเทอมที่ถูกปิดกลับโดยอัตโนมัติในห้องนั้น ผลเดิมยังดูได้และห้องอื่นไม่ได้รับผลกระทบ |
| AC-05 | หน้านักเรียนเดินตาม D1–D4 พร้อมปรับหน้าทำกิจกรรมและผลให้ตรงชนิดด่าน เช่น เปิด Lab ที่ผูกไว้หรือแสดงรอครูตรวจ ด่านมีคะแนนแสดงผลตามที่กำหนด แบบฝึกรองรับโจทย์เลือกตอบ เรียง จับคู่ และสไลเดอร์ตาม ref รวมทางเลือกคีย์บอร์ดสำหรับการลาก |
| AC-06 | นักเรียนเริ่มด่านที่มีเนื้อหาและสิทธิ์พร้อมบนเครื่องได้ขณะออฟไลน์ เก็บเหตุการณ์เริ่มและผลในคิวแยกตามบัญชีและป้องกันการบันทึกซ้ำเมื่อส่งใหม่ หลังซิงก์เข้าเครื่องอื่นเห็นผลเดิม สถานะของเนื้อหาและผลที่โหลดไม่ได้แยกจากสถานะยังไม่เริ่ม |

Phase 1 เก็บและแสดงผลใน School Bot และใช้ SchoolBright สำหรับยืนยันตัวตน
