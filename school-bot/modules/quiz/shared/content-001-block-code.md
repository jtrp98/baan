# ร่างเนื้อหาและคู่ผ่าน–ไม่ผ่าน Block/Code

> Rev 1 · แก้ล่าสุด 2026-11-03 · แก้โดย spec · ขอโดย ผู้ใช้ (มติ 053 — ร่างเนื้อหาจาก source)

ทั้ง 4 รายการเป็น **(สมมติฐาน — ยังไม่ยืนยัน)** ชื่อ เป้าหมาย คำแนะนำ และเกณฑ์เป็นข้อเสนอจาก source ไม่ใช่บทเรียนที่อนุมัติแล้ว ดู [รายการร่างและข้อที่ต้องเซ็น](content-001.md)

## พบใน source

Block มี move_right/move_left จำนวน 1–10 ช่อง, jump และ repeat จำนวน 1–10 รอบ ส่วน Code มีตัวอย่างเดินขวา 4 ช่อง → กระโดด → เดินขวา 3 ช่อง และ parser รองรับคำสั่งรายบรรทัด ไม่มี loop syntax ผล demo คืน simulated/commands/steps ไม่ใช่ผลเรียน หน้าบทเรียน Block/Code ยังแสดง unavailable

## ร่างรายการ

### BC-001 — Block: ต่อคำสั่งเดินและกระโดด (สมมติฐาน — ยังไม่ยืนยัน)

- เป้าหมาย: เรียงเดินขวา 3 ครั้ง ครั้งละ 1 ช่อง แล้วกระโดด ตามคู่ตัวอย่างเดิม
- คำแนะนำ: ต่อ move_right(1) สามบล็อกกับ jump เป็นสายเดียว ตรวจลำดับ แล้วส่งงาน
- ภารกิจ: ส่ง trace [right(1), right(1), right(1), jump] ตรงแบบ ไม่มีคำสั่งเพิ่ม; trace คือรายการคำสั่งหลังแปลงโปรแกรม ไม่ใช่ตำแหน่งจริง
- คู่ผ่าน: ตรงทั้งสี่คำสั่ง; ไม่ผ่าน: ขาด move หนึ่งครั้ง หรือ jump ก่อน move สุดท้าย แม้รันสำเร็จ
- ยังขาด: ผู้ใช้ยืนยันตรวจลำดับแทนการวัด “ถึงเป้า” และเลือก Lesson/Activity/revision

### BC-002 — Block: ใช้ repeat (สมมติฐาน — ยังไม่ยืนยัน)

- เป้าหมาย: อธิบายว่าการทำซ้ำให้ลำดับผลลัพธ์เดียวกับคำสั่งซ้ำ
- คำแนะนำ: วาง repeat 3 รอบ ครอบ move_right(1) แล้วต่อ jump เทียบกับ BC-001
- ภารกิจ: ส่ง trace เดียวกับ BC-001; เสนอ “ใช้ repeat” เป็นกิจกรรมเสริมที่ต้องมีหลักฐานโครงสร้างบล็อกก่อนให้ดาวเพิ่ม
- คู่ผ่านขั้นต่ำ: repeat 3 รอบแล้ว jump; ไม่ผ่านขั้นต่ำ: repeat 2 รอบแล้ว jump เพราะคำสั่งไม่ครบ
- ยังขาด: โควตาบล็อก/นิยามการนับสำหรับดาว 2 และหลักฐานตรวจ repeat สำหรับดาว 3; trace ตรงกันไม่บอกว่าใช้ repeat จริง ห้ามตัดสินโควตาจาก trace อย่างเดียว

### BC-003 — Code: ลำดับคำสั่งเริ่มต้น (สมมติฐาน — ยังไม่ยืนยัน)

- เป้าหมาย: เขียนคำสั่งตามลำดับและแก้จำนวนก้าว
- คำแนะนำ: เขียน hero.move_right(4) ตามด้วย hero.jump() และ hero.move_right(3) คนละบรรทัด แล้วส่งงาน
- ภารกิจ: ได้ trace [right(4), jump, right(3)] ตรงแบบ; ไม่มีเงื่อนไขว่าตัวละครถึงธง
- คู่ผ่าน: ตามสามบรรทัด; ไม่ผ่าน: บรรทัดสุดท้ายเป็น hero.move_left(3) แม้รันได้; syntax error แสดงข้อผิดพลาด ไม่ถือเป็นผลผ่าน
- ยังขาด: ผู้ใช้เซ็นเกณฑ์ trace เพราะฉากเดิมเป็น playback ไม่ได้วัดเป้าหมายภารกิจ

### BC-004 — Code: ทำซ้ำตามแบบ (สมมติฐาน — ยังไม่ยืนยัน)

- เป้าหมาย: เข้าใจการทำซ้ำ 3 รอบ
- คำแนะนำ: สำหรับ stub เขียน hero.move_right(1) สามบรรทัด แล้ว hero.jump(); แยกแนวคิด loop จาก syntax ที่รันได้
- ภารกิจ: เสนอ trace [right(1), right(1), right(1), jump]; จำนวน 3 เป็นร่าง ไม่ใช่ค่า N ที่อนุมัติแล้ว
- คู่ผ่าน: ครบสามครั้งแล้ว jump; ไม่ผ่าน: มีสองครั้งแล้ว jump
- ยังขาด: ผู้ใช้เลือกว่าจะรับคำสั่งซ้ำเป็นเนื้อหาฉบับนี้ หรือคงภารกิจ “ใช้ loop” ซึ่งต้องส่ง arch ตรวจต่อ ห้ามอ้างว่าร่างนี้พิสูจน์การใช้ loop

## ยังไม่ยืนยัน

ทุกรายการยังขาดการอนุมัติเนื้อหา/criteria ราย revision, สื่อ, ตำแหน่ง Course Plan และโควตาดาวที่วัดได้ ไม่มีคะแนนตัวเลขที่เซ็นแล้วสำหรับชุดนี้ เกณฑ์ดาวเดิมอยู่ที่ [เกณฑ์และคู่ตัวอย่างเดิม](../../../shared/pack-content-inventory-001-criteria.md) ร่างนี้ไม่แก้เกณฑ์นั้น

คำถามส่ง arch: “เกณฑ์ใช้ repeat/loop และโควตาบล็อกใน BC-002/BC-004 จะตรวจจากหลักฐานใด เมื่อ trace แยกโปรแกรมที่ใช้ loop ออกจากคำสั่งซ้ำไม่ได้ และ Code parser ปัจจุบันไม่รองรับ loop syntax?” คำตอบทางเทคนิคไม่แทนการเลือกเนื้อหาของผู้ใช้
