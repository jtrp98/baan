# รายการร่างเนื้อหาสามโหมดจาก source

> Rev 1 · แก้ล่าสุด 2026-11-03 · แก้โดย spec · ขอโดย ผู้ใช้ (มติ 053 — ร่างเนื้อหาจาก source)

ร่างนี้แยกเนื้อหาที่พบใน source ออกจากภารกิจที่เสนอเพิ่มเติม ใช้พัฒนาบน stub ได้ตาม [มติ 053 (ร่างก่อนและให้ผู้ใช้เซ็นก่อนต่อเนื้อหาจริง)](../../../../shared/decisions/decisions-053.md) ทุกรายการเป็น **(สมมติฐาน — ยังไม่ยืนยัน)** จนผู้ใช้เซ็นราย revision ไม่ใช่ approved inventory และไม่ยืนยันว่าครบ Course Plan ทุก Level

## รายการและวิธีอ่าน

| เอกสาร | ขอบเขต |
|---|---|
| [Block/Code](content-001-block-code.md) | ร่าง 4 ภารกิจ มีเป้าหมาย คำแนะนำ และคู่ผ่าน–ไม่ผ่าน |
| [เนื้อหา Arm](content-001-arm.md) | ครบ 7 stages ของ LearnMap และ 3 sample workspaces ที่พบ; แยกแบบอ่าน/Quiz ออกจากภารกิจ Arm |
| [rubric และข้อมูลอุปกรณ์ที่ขาด](content-001-arm-rubric.md) | เกณฑ์ครู คู่ผ่าน–ไม่ผ่าน ที่มา calibration/safety และคำถาม spec Q3 |

รหัสรายการเป็นรหัสอ้างเนื้อหา ไม่ใช่ AC ใหม่หรือ ActivityKey จริง ยังขาดการจับคู่ Course/Level/Lesson/Activity และ curriculum revision ที่ผู้ใช้เลือก รวมถึงสื่อ/คำแปลจริง การสำรวจชื่อไฟล์ใต้ target ไม่พบ inventory เนื้อหาสำเร็จรูปในโฟลเดอร์แยกชื่อ lessons/curriculum/missions/samples; พบเนื้อหาตัวอย่างในไฟล์ที่ระบุท้ายเอกสารย่อย ไม่ได้ตรวจเว็บหรือ Sheet ภายนอกซ้ำ

## ข้อเสนอ ac_ids เดิมให้ผู้คุมผูกกับงาน

| งาน | ac_ids ที่เสนอ | ความเกี่ยวข้อง |
|---|---|---|
| BA-005 (เนื้อหา Block/Code) | AC-037-02, AC-037-05, AC-037-06, AC-038-01 | เป้าหมาย/คำแนะนำ; ป้องกันอ้างอนุมัติ; ตามกลับแหล่งและ revision; คู่ผลอัตโนมัติ |
| BA-006 (เนื้อหา Arm/rubric) | AC-037-02, AC-037-05, AC-037-06, AC-038-02, AC-038-03 | เนื้อหาและแหล่ง; รออนุมัติ; ส่งงานแล้วรอครู; rubric ให้ครูบันทึกผล |

AC หมายถึง Acceptance Criteria หรือเกณฑ์ตรวจรับเดิมใน [REQ-037 (หลักสูตรสามโหมด)](requirements/req-037.md) และ [REQ-038 (วิธีประเมิน)](requirements/req-038.md) ตารางนี้เป็นข้อเสนอ ไม่แก้แผนและไม่อ้างว่าร่างเอกสารพิสูจน์พฤติกรรม runtime แล้ว ส่วน AC-037-01/03/04 และ AC-038-04/05 ต้องตรวจระบบ/สิทธิ์ในงานพัฒนาที่รับผิดชอบ

## ข้อที่ผู้ใช้ต้องเซ็นก่อน BE-015/FE-013

1. **ผู้ใช้:** รับหรือแก้รายการ Block/Code 4 ภารกิจ และ Arm 10 รายการ ระบุรายการใช้จริงพร้อม Course/Level/Lesson/Activity และ revision; ยืนยันว่า inventory ของฉบับนั้นครบ รวมสื่อและคำแนะนำ
2. **ผู้ใช้:** เซ็นคู่ผ่าน–ไม่ผ่านและเกณฑ์แต่ละภารกิจ รวมการตรวจ trace แทนเป้าหมายทางฟิสิกส์, Code loop ที่ source ยังไม่รองรับ, โควตาดาว และ numeric rubric หากใช้คะแนนตัวเลข
3. **ทีมอุปกรณ์เสนอ/ผู้ใช้รับรอง:** ตอบ calibration/safety ใน [rubric Arm](content-001-arm-rubric.md) ให้ครบสำหรับภารกิจที่ใช้หุ่น ห้ามแทนข้อมูลที่ขาดด้วยค่า sample
4. **ผู้ใช้:** ระบุผู้เซ็น วันที่ และหลักฐานอนุมัติที่ชี้ถึงฉบับเนื้อหาและเกณฑ์เดียวกัน งาน BE-015 (ระบบหลักสูตร) และ FE-013 (หน้าจอบทเรียน) ต่อเนื้อหาจริงได้หลังได้หลักฐานนี้ ตามมติ 053

## ยังไม่ยืนยัน

คำถามเต็มและผู้ตอบอยู่ใน [OQ-009 (รับรองเนื้อหาราย revision)](../../../../shared/open-questions/oq-009.md) และ [OQ-008 (ข้อมูลหุ่นและความปลอดภัย)](../../../../shared/open-questions/oq-008.md) ไม่มีการอนุมัติหรือปิดคำถามแทนผู้ใช้
