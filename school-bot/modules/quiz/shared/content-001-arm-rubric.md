# ร่าง rubric Arm และช่องว่าง calibration/safety

> Rev 1 · แก้ล่าสุด 2026-11-03 · แก้โดย spec · ขอโดย ผู้ใช้ (มติ 053 — ร่างเนื้อหาจาก source)

rubric รายการในเอกสารนี้เป็น **(สมมติฐาน — ยังไม่ยืนยัน)** สำหรับ [เนื้อหา Arm](content-001-arm.md) วิธีให้ครูตรวจและดาว 1/2/3 เป็นนโยบายที่ยืนยันแล้วใน [เกณฑ์เดิม](../../../shared/pack-content-inventory-001-criteria.md) แต่ไม่ใช่การเซ็น rubric ราย revision ของร่างนี้

## ร่างเกณฑ์ครูและคู่ผ่าน–ไม่ผ่าน

ทุกภารกิจ Arm ต้องรอครูที่ได้รับมอบหมายตรวจงานของนักเรียน การส่งงาน การเขียนลง OS ภาพจำลอง หรือจบ timer ไม่ให้ผลผ่านเอง เมื่อยังไม่มีผลครูให้คงรอผล ไม่ใช่ตัดสินไม่ผ่านทันที

| รายการ (ทุกแถวเป็นสมมติฐาน — ยังไม่ยืนยัน) | หลักฐานและคู่ผ่าน | คู่ไม่ผ่าน/ยังไม่พร้อมตัดสิน |
|---|---|---|
| ARM-004 ยก S1 | ครูตรวจท่าที่บันทึกและหลักฐานว่าข้อต่อที่กำหนดยกแขนตามแบบที่ทีมอุปกรณ์รับรอง | เปลี่ยนผิดข้อต่อหรือไม่มีท่าที่บันทึก; ไม่มีช่วงมุม/ท่าอ้างอิง = ยังตรวจรับของจริงไม่ได้ |
| ARM-006 หยิบกล่อง | ครูเห็นการหยิบและวางวัตถุตามแบบที่เซ็น พร้อมงานที่บันทึก | หยิบหรือวางไม่สำเร็จ หรือท่าเกินช่วงที่อนุมัติ; รอระบุวัตถุ/ตำแหน่งและเกณฑ์สังเกต |
| ARM-008 โบกมือ | ครูตรวจลำดับยกแขน/ซ้าย/ขวา/ทักทาย/พักครบตามแบบที่เซ็น | ขาดท่าหรือสลับลำดับ; ตัวอย่าง simulator ไม่พิสูจน์การเคลื่อนไหวจริง |
| ARM-009 แยกบล็อก | ครูตรวจหยิบ/ยก/วางสีแดงครบตามแบบที่เซ็น | มีเพียงหยิบกับยก ไม่มีวาง; ยังไม่มีข้อกำหนดตรวจสีอัตโนมัติ |
| ARM-010 ส่งบอล | ครูตรวจลำดับรับ/เหวี่ยงใน simulator ตามร่าง | ขาดหนึ่งท่า; ห้ามถือเป็นผ่านการทดลองส่งบอลจริงก่อนรับรอง safety |

ARM-001 เป็นสื่ออ่าน ไม่สร้างผลผ่านภารกิจ ส่วน ARM-002/003/007 รอคำถาม/เฉลยและ policy Quiz ที่เกี่ยวข้อง ARM-005 เป็น Block และยังไม่มีภารกิจควบคุมแขนที่ประเมินได้

คู่ท่า Arm ครบ 3 ท่าในเกณฑ์เดิมยังคงเป็นแบบฝึกอีกตัวอย่างหนึ่ง ไม่ยุบรายการที่ source มี 2 หรือ 5 ท่าให้เหลือ 3 ท่าเอง ดาว 1 ต้องผ่านเกณฑ์ขั้นต่ำที่เซ็น; ดาว 2 ต้องระบุโควตาและวิธีนับ; ดาว 3 ต้องระบุภารกิจเสริม ยังไม่ใส่โควตา/คะแนนตัวเลขที่ไม่มีผู้อนุมัติ

## พบใน source: ที่มา calibration และ safety

- การตั้ง servo IDs หกตัวกับ PWM ที่ปลายช่วง UI รองรับทิศกลับด้าน แต่ค่าเริ่มต้นเป็น nominal example ไม่ใช่ calibration ที่วัดจริง
- ส่งท่าสำเร็จหมายถึง OS ส่งข้อมูล ไม่ใช่ telemetry หรือหลักฐานว่าหุ่นถึงท่า; การเล่นครบเวลาบอกเพียงส่งคำสั่งครบ
- Stop อาจส่งไม่ถึงเมื่อการสื่อสารขาด การเขียนสำเร็จไม่พิสูจน์ว่าหุ่นหยุด และต้องมี emergency stop ทางกายภาพ
- HOME/BOX/POSE0 ยังใช้ไม่ได้จนได้ calibrated presets จริง ตัวเลข timeout ใน source เป็นข้อจำกัดซอฟต์แวร์ ไม่ใช่เกณฑ์ปลอดภัยที่รับรองแล้ว

## ยังไม่ยืนยัน: spec Q3 เดิมที่ทีมอุปกรณ์ต้องตอบ

| ผู้ตอบ | คำถามเต็มและหลักฐานที่ต้องให้ |
|---|---|
| ทีมอุปกรณ์เสนอ/ผู้ใช้รับรอง | ใช้หุ่น board firmware และ servo รุ่น/ID ใดกับแต่ละรายการ? ขอ profile ที่ชี้อุปกรณ์จริง |
| ทีมอุปกรณ์ | แต่ละข้อต่อมีช่วงมุม/PWM ปลายช่วง ทิศทาง ค่าคลาดเคลื่อนและวิธี calibration อย่างไร? ใครวัด เมื่อใด ใช้หลักฐานใด และต้องตรวจซ้ำเมื่อใด? |
| ทีมอุปกรณ์เสนอ/ผู้ใช้รับรอง | ท่าเริ่ม/ปลาย วัตถุ น้ำหนัก พื้นที่/ระยะห้ามเข้า และเงื่อนไขห้ามใช้สำหรับแต่ละภารกิจคืออะไร? |
| ทีมอุปกรณ์เสนอ/ผู้ใช้รับรอง | เกณฑ์หยุดและความหน่วงที่ยอมรับได้เมื่อ stop/unplug/disconnect/emergency คือเท่าไร วัดอย่างไร และมี physical emergency stop แบบใด? |
| ผู้ใช้/ผู้รับรองที่ผู้ใช้ระบุ | ใครรับรองผลตรวจอุปกรณ์และอนุญาตทดสอบจริง เป็นขอบเขตใดและหลักฐานใด? การอนุมัติเนื้อหาไม่แทนคำสั่งทดสอบหุ่นจริง |

ช่องข้อมูลเหล่านี้ยังไม่มีค่าที่รับรอง ห้ามใช้ sample pose หรือระยะเวลา 3000 ms ของ sample เป็นคำตอบ บันทึกคำถามต่อใน [OQ-008 (ความปลอดภัยหุ่น)](../../../shared/open-questions/oq-008.md) รอผู้ใช้เซ็นตาม [รายการก่อน BE-015/FE-013](content-001.md#ข้อที่ผู้ใช้ต้องเซ็นก่อน-be-015fe-013)
