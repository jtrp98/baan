# ข้อความพร้อมส่งถึงเจ้าของ/ผู้ดูแล Master DB — ขอหลักฐาน EV-01..06

วันที่ 2026-10-24 · เตรียมโดยนายช่างตามมติผู้ใช้ (decisions-036) — ผู้ใช้เป็นคนส่ง · รายละเอียดครบที่ [db-safe-evidence-001](db-safe-evidence-001.md)

---

เรื่อง: ขอหลักฐานโครงสร้างตารางและผลนับ aggregate (ปลอดข้อมูลส่วนบุคคล) ของ Master DB — โปรเจกต์ SchoolBot

เรากำลังออกแบบการเชื่อมระบบ SchoolBot เข้ากับฐานข้อมูลเดิม (Master DB) และต้องการหลักฐาน 2 ประเภทนี้เพื่อยืนยันสัญญาการอ่านข้อมูล โดย**ไม่ขอข้อมูลรายแถว/ค่าจริงใด ๆ ที่เป็นข้อมูลส่วนบุคคล** (ไม่ขอ username, hash รายแถว, ชื่อ, เลขบัตร):

**ส่วนที่ 1 — โครงสร้างตาราง (schema-only) 3 ตาราง:** `TUser`, `TEmployees`, `TEmpSalaries`
รบกวนส่ง metadata เท่านั้น: ชื่อคอลัมน์ / ชนิดข้อมูล / NULL-able / DEFAULT / collation / index / constraint — เช่น output ของ information_schema.columns + pg_indexes + pg_constraint หรือ `\d+<ตาราง>` (ถ้าเป็น PostgreSQL) · หมายเหตุ: ก่อนส่งรบกวนตัด literal ที่อยู่ใน DEFAULT/CHECK/comment ออกก่อน และไม่ต้องส่ง raw dump ทั้งก้อน

**ส่วนที่ 2 — ผลนับแบบรวม (aggregate เท่านั้น) 3 ชุด:**
1. จำนวนแถว `TUser` แยกตามค่า `cType` · จำนวนแถวที่ `nSystemID` เป็น NULL / ไม่เป็น NULL · จำนวนแถวที่ `nSystemID` ตรงกับ `TEmployees.sEmp` / ตรงกับ `sID` ของแถวตัวเอง / ตรงทั้งคู่ / ไม่ตรงอะไรเลย (นับเป็น count รวมเท่านั้น)
2. การกระจายรูปแบบ `PasswordHash` เป็น**ป้ายประเภท** เช่น `SHA1_HEX_40` (hex 40 ตัวครบ), `V2_FORMAT` (ขึ้นต้น v2:), `NULL_OR_EMPTY`, `OTHER` — ส่งเฉพาะจำนวนต่อป้าย **ห้ามส่ง prefix/suffix จริงของ hash ไม่ว่าส่วนใด** (มีตัวอย่าง SQL CASE ในไฟล์แนบ)
3. (ถ้าสะดวก) จำนวนบัญชีกลุ่มนักเรียนโดยรวม

เงื่อนไขการส่งผลนับ: กลุ่มไหนนับได้น้อยกว่า 5 แถว รบกวนรวมเป็น "other" ก่อนส่ง และใช้กลุ่มที่ไม่ทับซ้อนกัน เพื่อไม่ให้ย้อนกลับคำนวณจำนวนของกลุ่มที่ซ่อนได้

เหตุผลและรายละเอียดครบ (พร้อมตัวอย่างรูปแบบ SQL ที่ยอมรับ) อยู่ในไฟล์แนบ `db/db-safe-evidence-001.md` — หากสะดวกให้ส่งตามลำดับ EV-01..03 ก่อน แล้วค่อยตามด้วยส่วนที่ 2 ก็ได้
