# TP-001 — แผนทดสอบ 187 AC

> แก้ล่าสุด 2026-11-02 · แก้โดย inspect · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

แผนนี้สำหรับ developer และ check ที่ตรวจ SchoolBot ครอบคลุม 44 Requirement (REQ: ข้อกำหนด) รวม 187 Acceptance Criteria (AC: เกณฑ์ตรวจรับ) ด้วย 82 cases ตั้งแต่ TP001-001 ถึง TP001-082 แต่ละ case มีระดับ เงื่อนไขก่อนตรวจ ขั้นตอน ผลที่คาด และ AC อยู่ในไฟล์รายละเอียดแห่งเดียว ทุกผลจริงยัง NOT_RUN; จำนวน coverage ไม่รับรองว่าระบบผ่านหรือปิดเงื่อนไขส่งมอบ

## วิธีใช้และกลยุทธ์

เลือก unit/static ก่อน integration ใช้ End-to-End (E2E) หรือ manual สำหรับสิ่งที่ต้องเห็นจริง เช่น หน้าต่าง installer และหุ่น ตรวจ fault/race ของ License ตัวตน คะแนน และอัปเดต อ่าน [กลยุทธ์และสิ่งที่ต้องมีจากคน](tp-001-strategy.md), [ช่องว่างและข้อจำกัด](tp-001-gaps.md) และ [กลยุทธ์ transport](index.md#กลยุทธ์-transport) ก่อนตรวจ

## Profiles

PF (Test Profile) คือสภาพแวดล้อมตรวจ: PF-UNIT สำหรับ unit/domain; PF-STATIC สำหรับเอกสาร/DDL; PF-HOST สำหรับ Desktop host กับ fake engine; PF-UI-WIN/PF-UI-MAC สำหรับ native UI; PF-PREVIEW สำหรับ browser จำลอง; PF-API สำหรับ HTTP API Gateway (sb-api-gateway) และ gRPC SchoolBot service กับ test DB; PF-LEGACY สำหรับข้อมูลบัญชีเดิม; PF-WEB สำหรับ school_web; PF-ADMIN สำหรับ staff_admin; PF-GRADE สำหรับฐานคะแนนทดสอบ; PF-CATALOG สำหรับผล catalog ที่คนรัน

PF-HW-* แยก Windows/macOS Intel/Apple Silicon และ source-built/installed; PF-INST-* ตรวจ signed installer บน Windows/macOS เครื่อง Store และเงื่อนไขของทุก profile อยู่ใน [รายละเอียด Profile](tp-001-profiles.md)
