## SEC094-001 — Minor: publish ผ่านเมื่อไม่ทราบผู้เขียน

ตำแหน่ง `CurriculumAuthorizationService.cs:95–104`: ส่ง authorPrincipalId เป็น null/empty/whitespace พร้อม active approver แล้ว Allowed เพราะตรวจ four-eyes เฉพาะเมื่อ author ไม่ว่าง พิสูจน์สามกรณี

หากต่อ publisher โดยไม่โหลดผู้เขียน อาจอนุมัติงานตนเองได้ แต่ยังไม่มี endpoint/caller ให้ client กระตุ้น จึงเป็น Minor ใน slice นี้ ไม่ใช่ Important ที่โจมตีผ่าน G→B ได้แล้ว

เสนอ BE ให้ปฏิเสธ author ที่ขาด โหลด canonical author จาก revision ฝั่ง server แล้วเทียบ approver ห้ามรับ author จาก request; regression ต้องปฏิเสธทั้งสามกรณีและ same-author ส่งเป็นรายการไม่ขวาง slice ไม่เปิด task เอง การ re-audit จำกัด finding นี้และส่วนที่แก้เปลี่ยน

## Compliance/dependencies

PrincipalId เป็นตัวระบุบุคคลเมื่อเชื่อมบัญชีจริง; SchoolId ร่วมกับ principal เชื่อม tenant; Token เป็น credential ห้าม log/serialize context ทั้งก้อน Generated ToString ของ record มี Token จริง (ทดสอบด้วยค่าจำลอง) แต่ยังไม่มี log sink/caller บันทึกข้อระวังภายใต้ SEC001-010 เดิม ไม่เปิด finding รั่วซ้ำ แนะนำตัด raw token ออกจาก policy context หรือ redact ก่อนต่อ logging

slice นี้ไม่มี store/การส่งบุคคลที่สาม/การลบใหม่ ไม่พบหลักฐานการละเมิดกฎหมายใหม่จาก delta ยังไม่รับรองฐานประมวลผล/retention/สิทธิข้อมูล/GDPR applicability; SEC001-010 คงเดิม เจ้าของข้อมูล/DPO ต้องกำหนดก่อนใช้ข้อมูลจริง ไม่สรุปว่าต้องขอ consent ทุกกรณี

แหล่งอ่าน 2026-10-29: [PDPA ม.37 ฉบับราชกิจจานุเบกษาจากหน่วยงานรัฐ](https://www.epad.go.th/fileupload/3589927270.pdf) กำหนดมาตรการป้องกันการเข้าถึงโดยมิชอบและการลบเมื่อพ้นความจำเป็น; [EUR-Lex GDPR Article 5](https://eur-lex.europa.eu/legal-content/EN/TXT/?qid=1755832889478&uri=CELEX%3A32016R0679) เรื่อง minimisation/confidentiality อ่านจากผลค้นทางการ หน้าเต็มติด JavaScript challenge ใช้เป็นเกณฑ์อ้างอิง ไม่ใช่รับรอง compliance ทั้งระบบ

อ่าน Application/Domain/API/Infrastructure/test csproj และ Directory.Build.props/global.json จริง helper เพิ่มเฉพาะ BCL ไม่มี dependency ภายนอกใหม่ใน delta ไม่รัน CVE/license audit ทั้งระบบและไม่รับรอง release dependencies
