## 1. State ของแต่ละ flow

ทุกแถวใช้ auth/conflict/unknown และ a11y ใน §2–§4 ร่วมกัน Empty แสดงข้อความอย่างเดียว ไม่มี CTA ในพื้นที่ empty

แยก loading ตาม repo: Desktop และ admin ส่วนกลางใน school-bot คงกติกาของตน; เว็บครู/Level/หน้าเกณฑ์ admin ที่อยู่ web-system ใช้ P9 ตาม AGENTS → project-policy → CLAUDE → DESIGN และ loading.md ซึ่งมีลำดับสูงกว่า skill ทั่วไป โหลดข้อมูลใช้ shared Skeleton รูปร่างตรงข้อมูลเฉพาะส่วนที่ยังโหลด ไม่บังส่วนที่พร้อมแล้ว ไม่ใช้ Spinner หรือข้อความโหลดแทนโครงข้อมูล กลุ่มใช้ SkeletonStatus (role=status, aria-busy, ข้อความ sr-only) และ shape เป็น aria-hidden; error จบ Skeleton แล้วแสดงทางแก้ ข้อมูลใหม่ใช้ sb-reveal ตาม repo; refresh หลังบันทึกในบริบทเดิมคงข้อมูลเดิม งานบันทึกปิดปุ่มซ้ำด้วย disabled; หากต้องบังพื้นที่ใช้ .sb-progress-track > .sb-progress-bar พร้อมข้อความ ไม่ใช้ Spinner ตารางด้านล่างระบุข้อความสถานะเพื่อ i18n/a11y; บน web-system ข้อความอ่านข้อมูลเป็น sr-only ของ Skeleton

## 2. Auth และ conflict ทุก flow

- 401 UNAUTHORIZED/SESSION_EXPIRED: “เซสชันหมดอายุ — เข้าสู่ระบบอีกครั้งเพื่อตรวจสอบรายการเดิม” หยุดส่งและล้างการแสดงข้อมูลที่ไม่มีสิทธิ์ ไม่เล่นคำสั่งค้างต่อหลังเปลี่ยนบัญชี
- 403: “บัญชีนี้ไม่มีสิทธิ์ทำรายการในบริบทนี้ — ตรวจสอบบัญชีหรือให้ผู้ดูแลตรวจสิทธิ์” ไม่แสดงข้อมูลคนอื่น กรณี LICENSE_REQUIRED แจ้งให้ผู้ดูแลตรวจ License; employee บน Desktop คงปุ่ม Cloud disabled และคำอธิบายเดิม
- AUTH_NOT_CONFIGURED/AUTH_UNAVAILABLE: “ระบบตรวจสอบสิทธิ์ยังไม่พร้อม — ติดต่อผู้ดูแลหรือลองตรวจอีกครั้ง” fail closed ไม่ใช้ผล local แทน Cloud
- 412 VERSION_CONFLICT / 428 PRECONDITION_REQUIRED: “ข้อมูลเปลี่ยนแล้ว — โหลดข้อมูลล่าสุดและตรวจทานอีกครั้ง” ไม่ merge/บันทึกทับอัตโนมัติ; คำขอแก้ครั้งใหม่ต้องผ่านการตรวจทาน
- 409 PROPOSAL_STALE: “รายชื่อ ผลคะแนน หรือข้อมูลเทอมเปลี่ยน — ประเมินใหม่ก่อนยืนยัน”; SUCCESSOR_EXISTS/STATE_CONFLICT อ่านผลเดิมก่อน ห้ามสร้าง successor ซ้ำ
- ATTEMPT_EXPIRED/ACTIVITY_CLOSED อ่านสถานะครั้งเดิม ไม่อ้างว่าส่งสำเร็จหรือให้เวลาเพิ่ม; GRADER_UNAVAILABLE ไม่แสดงผลตกแทนระบบล้ม

## 3. ไม่ทราบผล mutation — Q43–Q46

ใช้กับเริ่ม attempt, บันทึก/ส่งคำตอบ, ตั้งเวลา, เปิดซ่อม, น้ำหนัก, ประเมิน/confirm/decline Level และเกณฑ์ admin

ถ้าขาดการเชื่อมต่อ/timeout หลังส่งจนยืนยันผลไม่ได้: คงข้อความ “ยังยืนยันผลการทำรายการไม่ได้ — ตรวจสอบผลก่อนทำรายการใหม่” ปิดปุ่มส่งซ้ำที่เป็นคำสั่งใหม่ ไม่แสดง success จากการกดหรือ timeout

เมื่อมี resource ID ใช้ GET ที่สัญญามีเพื่อตรวจสถานะ; submit ที่อ่านกลับเป็น submitted จึงแสดงว่าส่งแล้ว หากยังไม่ตัดสินได้ การ retry ใช้คำขอเดิม body/Idempotency-Key/If-Match เดิม ไม่เพิ่มครั้งหรือกินใบซ่อมซ้ำ ไม่เปลี่ยนคำตอบในคำขอที่ยังค้าง

IDEMPOTENCY_CONFLICT ให้หยุดและตรวจรายการเดิม ไม่สร้าง key ใหม่เพื่อหลบ; IDEMPOTENCY_EXPIRED ใช้ resource_id เมื่อ server อนุญาตให้รู้ หากไม่มีทางอ่านผลให้คงสถานะไม่ทราบผลและติดต่อผู้ดูแล ไม่สรุปว่าไม่เคยบันทึก สำเร็จแล้วจึงใช้ข้อความยืนยันคงอยู่ในหน้า; toast เป็นข้อมูลเสริมเท่านั้น

## 4. SchoolBright / a11y

Desktop และ admin ส่วนกลางใน school-bot ใช้กติกาของตน: TH Sarabun New เนื้อหา 16/32px หัวข้อ 24/48px; spacing ทวีคูณ 8px, radius 12px, target ≥48×48px เว็บใช้ sidebar/header เดิมและ cyan #09C6DD; Desktop app ใช้ orange #FF7A62 ไม่สร้าง shell หรือย้าย framework

เฉพาะ web-system ยึด DESIGN/shared component เดิม: ฟอนต์จาก theme เดิม; หัวการ์ด/หัวส่วนใช้ text-xl font-bold เนื้อหา text-sm และหัวตาราง/label text-xs ตามบริบท ไม่ hardcode ค่าจาก skill; spacing ใช้ token โดย page wrapper ตาม P10 หาก PageShell/token ยังไม่ merge ให้ใช้รูปแบบเดิมที่ DESIGN ระบุ ไม่อ้างว่าตรวจสถานะ merge แล้ว ฟอร์ม/ตาราง/ปุ่มใช้ของกลางและ meaningful props ตาม P11 เช่น pending ของ Button ไม่ copy component หรือเปลี่ยน stack การอ้างนี้มาจากเอกสารกฎ ยังไม่ได้อ่าน implementation ของ component

คู่สีที่คำนวณจาก sRGB: #1F262D บน cyan 7.38:1, บน orange 5.98:1, บนขาว 15.29:1; #646464 บนขาว 5.92:1; #DA1A0C บนขาว 5.08:1 ไม่ใช้ตัวหนังสือขาวบนสีหลักอ่อน ข้อความปกติทุก state ≥4.5:1

Tab ตามลำดับงาน มี focus outline ชัดและไม่ถูกแถบคงที่บัง; radio ใช้ลูกศร/Space; dialog ระบุชื่อ กัก focus คืน focus เมื่อปิด และ Esc ยกเลิกเฉพาะกล่องที่ยังไม่ส่ง ไม่แปลว่า rollback คำสั่งที่ส่งแล้ว

สถานะใช้ aria-live polite; error บล็อกใช้ role alert, input มี label/aria-describedby และสรุปข้อผิดพลาดพร้อมพาไป field; disabled มีเหตุผลอ่านได้ข้างปุ่ม ไม่พึ่ง tooltip สี หรือ hover อย่างเดียว เวลาอ่านเป็นช่วงตาม int-004 ไม่ประกาศทุกวินาที

ตารางมี caption/th scope; ชื่อคน/คำถาม/เหตุผลยาว wrap ไม่ตัดสาระ เฉพาะ ID ย่อได้เมื่อมีทางอ่านเต็ม ตารางเลื่อนด้วยคีย์บอร์ด เว็บ <640px เรียงแผงลง; 640–1024px ลดคอลัมน์ตกแต่ง ไม่ซ่อนคะแนน/เหตุผล

ไม่มี animation ตกแต่ง เคารพ prefers-reduced-motion: web-system ใช้ shared Skeleton ที่หยุด shimmer ตามกฎ repo และให้ sb-reveal/แถบ progress เคารพ reduced-motion ตามของกลาง โดยคงสถานะที่อ่านได้; ยังไม่ได้ตรวจ implementation ส่วน Desktop/ส่วนกลางที่ใช้ Spinner คงข้อความสถานะและรูปคงที่เมื่อจำกัด motion ภาษาไทยเป็นหลัก สลับ EN ทั้งหน้า เช่น “กำลังบันทึกคำตอบ… / Saving answers…” และ “ยังยืนยันผลการส่งไม่ได้ / Submission not yet confirmed”; เนื้อหาใช้ Text locale ตามสัญญา
