# BE-001 — หลักฐานบัญชีเดิม รอบ 001

วันที่ 2026-10-23 · sys / Claude Sonnet tier t3 · ผล role: DONE

[ใบงาน](task-017.md) · [ผลต้นฉบับและ fixtures สังเคราะห์](legacy-auth-response-001.json)

ส่งหลักฐานอย่างเดียว ไม่มี task verdict และไม่มี accepted risk ใหม่ ตรวจโค้ดจริงแล้วพบเส้นทาง login 2 เส้นใน sb-api-gateway: (1) web ครู/บุคลากร `WebLoginService` (2) mobile `AuthService.LoginAsync` ซึ่งรองรับ cType '0' นักเรียน. พิสูจน์ได้: lookup ด้วย nCompany+username, ตรวจรหัสด้วย SHA-1 hex ตัวใหญ่ หรือ plaintext/วันเกิด (mobile รับ PBKDF2 'v2:' ได้ด้วย), flag ล็อกบัญชี/ลบ/โรงเรียน/WorkStatus, นักเรียน Master.SId=School TUser.SId ผ่านโค้ด mobile. พิสูจน์ไม่ได้: (a) case/collation ของ username, (b) พนักงาน SId หรือ NSystemId เป็น sEmp จริง เพราะ 2 จุดในโค้ดขัดกัน, (c) IsAdmin=1 และ TAdmin verifier เพราะ gateway ออก token ด้วย IsAdmin=0 ตายตัว และ bypassgarde/Default.aspx ต้นฉบับไม่อยู่ใน workspace, (d) ผลของ mobile birthdate th-TH ต่อ culture ของ server. Academic มีแค่ entity/EF ไม่มี verifier ตรงกับ source-review-002. ไม่อ่าน secrets/env/config, ไม่เชื่อม DB/SQL, ไม่รันระบบ, ไม่ส่ง login จริง, ไม่แก้ source/knowledge/git, ไม่เรียก role. Fixtures ทั้งหมดสังเคราะห์ ใช้ test vector สาธารณะ SHA-1('abc'). ผลทั้งหมดมาจากการอ่านโค้ด ไม่มี runtime PASS. ข้อควรระวัง: ข้อเท็จจริงที่อ้างจาก source-review-002 และ DES-012 ที่ผมไม่ได้อ่านซ้ำคือ TeacherRepository.cs:26-32 และ Academic TmasterDbuser/TUser entity ตามที่ระบุ ให้ inspect ตรวจก่อนอ้างต่อ.
