## 1. กติกากลางของ Labs (ข้อเสนอ)

- วงจรสถานะหุ่นตาม DES-006: `off → probing → connected → busy → connected | lost` — UI แสดง chip สถานะมุมบนตลอดเวลา: "ยังไม่เชื่อมต่อ / กำลังตรวจสอบบอร์ด / เชื่อมต่อแล้ว / กำลังทำงาน / การเชื่อมต่อขาด"
- **ป้ายโหมดทดลอง**: ทุกเส้นทาง preview/mock (เช่น `preview=1`) ติดป้ายคงที่ "โหมดทดลอง (จำลอง) — ผลลัพธ์ไม่ใช่คำสั่งจริง/ผลเรียนจริง" ตลอด session (BR-013-03 — ข้อเสนอที่ยังรอยืนยัน, AC-013-01..03, Q9)
- ห้าม mix: ผลจำลอง (dry-run/simulator) ไม่แสดงปะปนกับ telemetry จริง (DES-006)
- ปุ่ม "หยุด" (stop) ปรากฏคงที่ทุกสถานะ busy — เสนอขนาดใหญ่ สีแดง มุมขวาล่างของ workspace (Q8) — copy ใช้คำ "ขอหยุด" ไม่ใช่ "หยุดแล้ว" เพราะ stop เป็นเพียงคำขอ ไม่มีเกณฑ์ latency/emergency ที่รับรอง (BR-021-03/04, OQ-008)

## 2. Arm Lab

### 2.1 ค้นหาและเชื่อมต่อหุ่น — REQ-014 · DES-006

เข้า Arm Lab = เริ่มที่ "ยังไม่เชื่อมต่อ" เสมอ ไม่แสดงเชื่อมต่ออัตโนมัติ (AC-014-01)

| State | UI + คำ copy (ข้อเสนอ) |
|---|---|
| loading (กำลังค้นหา) | "กำลังค้นหาบอร์ด…" + ปุ่ม "ค้นหาใหม่" |
| empty (ไม่พบ) | "ไม่พบอุปกรณ์ — ตรวจสอบสาย USB หรือพอร์ต แล้วกดค้นหาใหม่" (การค้นพบ ≠ เชื่อมต่อ — BR-014-01) |
| พบรายการ | รายการ "ชื่ออุปกรณ์ · ชนิด: HID/Serial" (path เป็นค่าภายในของ OS — **ไม่มีช่องให้ผู้ใช้พิมพ์ path** ตาม DES-006) ต้องเลือกอุปกรณ์ก่อน (AC-014-02) |
| ยืนยันโปรไฟล์ | ต้องยืนยันโปรไฟล์ก่อนกดเชื่อมต่อ — ไม่เลือก/ไม่ยืนยัน = ปุ่มเชื่อมต่อ disabled (AC-014-02) |
| probing | "กำลังตรวจสอบบอร์ด… (ส่ง board.info อย่างเดียว ไม่มีคำสั่งเคลื่อนไหว)" (BR-014-03) |
| error: probe ไม่ตอบ | ไม่เข้าสถานะ connected: "บอร์ดไม่ตอบสนอง — ลองเสียบสายใหม่ หรือเลือกอุปกรณ์อื่น" (AC-014-03) |
| connected | เข้า workspace · chip "เชื่อมต่อแล้ว: <ชื่ออุปกรณ์>" |

### 2.2 โปรไฟล์หกข้อต่อ — REQ-015 · DES-006

ฟอร์ม: ชื่อโปรไฟล์ + ตาราง 6 แถว servo `{ID, PWM ปลายซ้าย, PWM ปลายขวา}`

| State | คำ copy/validation (ข้อเสนอ) |
|---|---|
| empty | 6 แถวว่าง + ค่าตั้งต้น nominal (ตามโค้ดเดิม engineAdapter) |
| error: ID ซ้ำ / ไม่ครบ 6 / PWM นอก 500–2500 / ปลายเท่ากัน | inline ใต้ช่อง: "ID ซ้ำกับข้อต่อที่ 3" · "ต้องมี servo ครบ 6 ตัว" · "PWM ต้องอยู่ระหว่าง 500–2500" · "ค่าปลายทางสองค่าต้องไม่เท่ากัน (กลับทิศซ้าย-ขวาได้)" — ปุ่มยืนยัน disabled จนผ่าน (AC-015-01/02) |
| abnormal: แก้หลังยืนยัน | ป้ายเหลือง "โปรไฟล์ถูกแก้ — ต้องยืนยันใหม่ก่อนเชื่อมต่อ" ปุ่มเชื่อมต่อ disabled (AC-015-03) |
| ป้ายกำกับความหมาย | ใต้ปุ่มยืนยัน: "การยืนยันโปรไฟล์เป็นการตรวจรูปแบบ ไม่ใช่การสอบเทียบจริงบนหุ่น" (BR-015-03) |

### 2.3 Workspace — ส่งท่า / ปรับข้อต่อ (REQ-016)

- แผงข้อต่อ 6 ตัว + ภาพหุ่นจำลอง (ใช้ ArmSimulator เดิม) — ภาพหลังส่งเป็น "ค่าคาดการณ์" ไม่ใช่ telemetry (BR-016-03): ป้ายเล็กใต้ภาพ "ภาพเคลื่อนตามค่าที่ส่ง ไม่ใช่ค่าที่วัดกลับ"
- disabled: disconnected หรือปลดแรงบิด → ปุ่มส่งท่า disabled + ข้อความ "ล็อกแรงบิดก่อนจึงส่งท่าได้" (AC-016-01, AC-023-02)
- ปรับถี่: แสดง "ค่าล่าสุดที่ยอมรับ" ระบบรวมคำสั่งระหว่างค้าง ทำงานครั้งละหนึ่งรายการ (BR-016-02, AC-016-03)
- error ส่งล้ม: ภาพจำลอง **ไม่เริ่มเคลื่อน** + "ส่งคำสั่งไม่สำเร็จ — ไม่มีการส่งซ้ำอัตโนมัติ" (AC-016-02, BR-024-02)

### 2.4 อ่านค่า servo (REQ-022)

- loading: "กำลังอ่านค่า 6 ข้อต่อ…" · commit เฉพาะเมื่อครบทุกข้อที่ขอ (AC-022-01/02)
- error บางส่วน: "อ่านได้ไม่ครบ (ข้อต่อที่ 4 ไม่ตอบ) — คงค่าท่าเดิมไว้ ไม่แทนที่ด้วยผลบางส่วน" (AC-022-03)

### 2.5 ปลด/ล็อกแรงบิด (REQ-023)

- ปุ่มสลับ "ปลดแรงบิด" / "ล็อกแรงบิด" — เปลี่ยนสถานะหลังได้รับผลตอบเท่านั้น
- ขณะปลด: แบนเนอร์สีเหลืองคงที่ "แรงบิดปลดอยู่ — ส่งท่า/เล่น/อัปโหลดปิดใช้งาน" + ปุ่มสามอัน disabled (AC-023-02)
- ขอหยุดขณะปลด: ลำดับ stop ก่อน relock; stop ล้ม → ไม่แสดงว่าล็อกสำเร็จ (AC-023-03)

### 2.6 เล่นลำดับจากแอป (REQ-018)

- ตั้งรอบ 1–N หรือ "วนต่อเนื่อง" (BR-018-03) · progress: "ท่า 2/4 — รอบ 1/2"
- error กลางลำดับ: ยุติทันที "ส่งท่าที่ 2 ไม่สำเร็จ — หยุดเล่นลำดับ" ไม่ส่งท่าถัดไป (AC-018-02)
- จบ: "ส่งลำดับครบแล้ว (ครบตามเวลาที่ตั้ง) — ไม่ใช่การยืนยันการเคลื่อนที่จบจากหุ่น" (AC-018-03)

### 2.7 อัปโหลดท่าไปบอร์ด (REQ-019 · DES-006: ทีละ ≤4 ท่า, 1–10,000 ท่า)

- progress เพิ่มเฉพาะหลังได้รับผลตอบของชุดย่อย: "ส่งแล้ว 4/5 ท่า" (AC-019-01/02)
- error: "อัปโหลดไม่สำเร็จ — หยุดส่งชุดถัดไป ชุดบนบอร์ดถือว่าใช้ไม่ได้ทั้ง session" (AC-019-03) · ห้ามมีสถานะ "verified บนบอร์ด" (BR-019-03)

### 2.8 เล่นชุดท่าบนบอร์ด (REQ-020)

- ต้องมีชุดอัปโหลดใน session นี้ — ยังไม่มี = ปุ่ม disabled + "อัปโหลดชุดท่าก่อนจึงสั่งเล่นจากบอร์ดได้" (AC-020-01)
- ช่องรอบ 1–9999 อย่างเดียว **ไม่มีตัวเลือกวนไม่สิ้นสุด**; ถ้าผู้ใช้พยายามใส่ ∞: "ต้องระบุจำนวนรอบ (1–9999)" (AC-020-02)
- ระหว่างเล่นบนบอร์ด: chip "กำลังเล่นบนบอร์ด" ค้างจนกว่าจะกดหยุดหรือเกิด error — ไม่ตั้งจบจากเวลา (AC-020-03)

### 2.9 หยุด / ยกเลิก / งานค้าง (REQ-021)

| State | คำ copy (ข้อเสนอ) |
|---|---|
| กดหยุดระหว่าง busy | "กำลังขอหยุด…" (ยกเลิกงานค้างให้จบก่อน แล้วจึงส่ง stop — AC-021-01) ปุ่มอื่น disabled ระหว่างนี้ ห้ามงานใหม่แทรก (DES-006) |
| stop สำเร็จ | "ส่งคำขอหยุดแล้ว" (ไม่ใช่ "หุ่นหยุดแล้ว" — BR-021-03, AC-021-03) |
| stop ล้มเหลว | "ส่งคำขอหยุดไม่สำเร็จ — ตรวจสอบสาย/บอร์ดแล้วลองอีกครั้ง" (AC-021-03) |
| คำตอบเก่า/timer เก่า มาถึงหลังหยุด | log แถว "ได้รับผลเก่าจากงานที่ยกเลิกแล้ว — ไม่นำไปส่งท่าถัดไป" ไม่มีคำสั่งใหม่ออก (AC-021-02) |
| ออกจาก workspace ขณะเชื่อมต่อ | ส่ง stop อัตโนมัติแม้ไม่มีคำสั่งรอผล (AC-021-04) — กล่องยืนยันออก: "จะขอหยุดหุ่นก่อนออก" |

### 2.10 การเชื่อมต่อขาดระหว่างใช้งาน (REQ-024)

| State | UI + คำ copy (ข้อเสนอ) |
|---|---|
| lost ขณะ idle | overlay ครอบทั้ง workspace (ใช้ NativeReconnectOverlay เดิม — Q7): "การเชื่อมต่อขาด — ตรวจสอบสาย USB แล้วกดเชื่อมต่อใหม่" (AC-024-01) |
| transport error ระหว่างส่ง | ข้อผิดพลาดตรงจุด + "ส่งคำสั่งไม่สำเร็จ — ไม่มีการส่งซ้ำอัตโนมัติ" (AC-024-02, BR-024-02) |
| เชื่อมต่อใหม่สำเร็จ | เริ่มต้นว่าง ไม่เล่นท่าเดิม/ไม่คืนสถานะอัปโหลดเดิม — ป้าย "เชื่อมต่อใหม่แล้ว ต้องอัปโหลดชุดท่าใหม่ก่อนสั่งเล่นจากบอร์ด" (AC-024-03, DES-006) |
| busy/cancelled | **ไม่แสดง overlay lost** — เป็นผลงาน ไม่ใช่สายหลุด (BR-024-03) |

### 2.11 โครงงานท่า/ลำดับ/กลุ่ม (REQ-017)

- validation inline: ท่าต้องมีค่าครบ 6 ข้อ · เวลาท่า 1,000–9,000 ms · รวมไม่เกิน 10,000 ท่า · **ID ท่าห้ามซ้ำ** (AC-017-02 — แก้ตาม check 060f: ตัวตรวจของ AC เป็น ID ซ้ำ) · ข้อเสนอเพิ่มเติม (แยกจาก AC): ชื่อท่าซ้ำ → แจ้งเตือนให้ผู้ใช้ยืนยัน แต่ไม่บล็อก (Q11)
- กลุ่ม: ต้องมีชื่อ + อ้างท่าที่มีอยู่ ≥2 รายการ — กลุ่มไม่ผ่านถูกละออกพร้อมแจ้ง "กลุ่ม 'ท่าทักษิณ' อ้างท่าที่ไม่มีอยู่ — ไม่นำไปใช้" (AC-017-01/02)
- เปิดโครงงานใหม่: ป้าย "สถานะบนบอร์ด: ยังไม่ได้อัปโหลดใน session นี้" ไม่อ้างว่าบอร์ด/หุ่นอยู่ตรงท่าบันทึก (AC-017-03, BR-017-03)

## 3. Code Lab — REQ-025

เลย์เอาต์: กล่อง editor DSL ซ้าย + ฉากจำลองขวา + แถบผล (รายการคำสั่ง จำนวน steps) · ป้ายคงที่ "ฉากจำลอง — ผลลัพธ์ไม่ได้ควบคุมแขนกลจริง" (BR-025-01)

| State | คำ copy (ข้อเสนอ) |
|---|---|
| empty | ตัวอย่างเริ่มต้น `hero.move_right(2)` + คำแนะนำคำสั่งที่ใช้ได้: `hero.move_right(n)` · `hero.move_left(n)` · `hero.jump()` (BR-025-02) |
| loading (รัน) | "กำลังรันโปรแกรม…" สั้น ๆ + ปุ่มรันกลายเป็น disabled |
| success | รายการคำสั่ง + "รวม 5 steps" + ภาพเล่นในฉาก — ไม่มีคำสั่งไปหุ่น (AC-025-01) |
| error: คำสั่งนอก DSL | "ไม่รองรับคำสั่ง 'for' — ใช้ได้เฉพาะ hero.move_right(n), hero.move_left(n), hero.jump()" (AC-025-02) |
| error: เกินขอบเขตรัน | "โปรแกรมเกินขีดจำกัดการรัน — สูงสุด 64 คำสั่ง, เดินครั้งละ 1–10 ช่อง, รวมไม่เกิน 100 ช่อง" (BR-025-03) |
| error: โหลดไฟล์ | schema ผิด/ยาวเกิน: "ไฟล์โครงงานไม่ถูกต้อง หรือโค้ดยาวเกิน 16,384 ตัวอักษร" (AC-025-03) |
| abnormal: สองหน่วยนับ 16,384 | โค้ดไทยผ่านการโหลด (นับ UTF-16) แต่ติดตอนรัน (นับ bytes): "โปรแกรมยาวเกินขีดจำกัดตัวรัน (16,384 ไบต์) — ข้อความภาษาไทยนับไบต์มากกว่าจำนวนตัวอักษร" + ข้อเสนอแสดงตัวนับความยาวใกล้ editor (BR-025-03, Q10 — การรวมหน่วยเป็นสิทธิ์ของ arch ไม่เสนอเอง) |
| บันทึก/เปิด | schema 1 — บันทึกเงียบ + toast "บันทึกแล้ว" · เปิดคืน source เดิมได้ (AC-025-03 ครึ่งแรก) |

## 4. Block Lab — REQ-026

ผืนบล็อก: move / jump / repeat (ลากวาง) + ป้าย "ผลลัพธ์เป็นการจำลอง ไม่ได้ส่งบล็อกไปหุ่นจริง" (BR-026-03)

| State | คำ copy (ข้อเสนอ) |
|---|---|
| empty | ผืนว่าง + กล่องบล็อกให้ลาก 3 ชนิด |
| abnormal: สองลำดับไม่เชื่อม | ป้ายบนผืน "โปรแกรมต้องเชื่อมเป็นลำดับเดียว" + ปุ่มรัน disabled (AC-026-02) |
| disabled block | บล็อกที่ถูกปิดแสดงจางลง ข้ามตอนรัน แจ้งในผล "ข้าม 1 บล็อกที่ปิดไว้" (BR-026-01) |
| error: เกินขอบเขต | ตรวจก่อนรัน: "โปรแกรมขยายเกิน 64 คำสั่ง" / "repeat ซ้อนกันเกิน 8 ชั้น" / "ค่า move/repeat ต้องอยู่ระหว่าง 1–10" — ไม่แสดงผลรันสำเร็จ (AC-026-03, BR-026-02) |
| success | trace คำสั่งตามลำดับ เช่น move_right → jump → jump (AC-026-01) + ภาพเดินในฉากจำลอง |
| บันทึก/เปิด | workspace schema 1 คืนบล็อก/ค่า/การเชื่อมเดิม · schema ผิด → "ไฟล์ไม่ตรงกับโปรแกรมนี้" (AC-026-04) |

## 6. a11y พื้นฐาน (int-002)

- ปุ่ม "หยุด" โฟกัสได้ตลอด ไม่เคย disabled ระหว่าง busy · มี `aria-label="ขอหยุดหุ่น"` · **visible focus** ชัดเจนทุกปุ่ม/ช่อง
- progress อัปโหลด/เล่นลำดับ ใช้ `aria-live="polite"` + `role="progressbar"` บอกค่าปัจจุบัน/รวม
- ตารางโปรไฟล์/ฟอร์ม: error ผูกกับช่องด้วย `aria-describedby` · ความคมชัดข้อความ-error ≥ 4.5:1 · ไม่ใช้สีอย่างเดียว (แบนเนอร์ปลดแรงบิดมีทั้งสีและคำ)
- คีย์บอร์ด: Tab ครบทุกบล็อก/ช่อง · Code Lab ใช้ได้เต็มด้วยคีย์บอร์ด · Esc = ยกเลิก dialog ไม่ใช่ขอหยุดหุ่น (ขอหยุดต้องกดปุ่มชัดเจน) · **การจัดบล็อกใน Block Lab ใช้คีย์บอร์ดได้จริง** (เลือกบล็อกด้วยลูกศร/Enter, ย้าย/แทรก/ลบด้วยปุ่มลัดที่ระบุในผืนงาน — ไม่พึ่งเมาส์อย่างเดียว) · เปิด dialog แล้ว focus เข้า dialog ทันที ปิดแล้วคืน focus ตำแหน่งเดิม
- reduced-motion: ปิดอนิเมชันฉากจำลอง/ภาพหุ่น เหลือแถบสถานะข้อความแทน
- ภาษา: copy ไทยหลัก ศัพท์เทคนิค/รหัส (HID/Serial, DEVICE_LIMIT) อังกฤษ
(เพิ่ม visible focus/การจัดบล็อกด้วยคีย์บอร์ด/dialog focus ตามข้อเสนอ check 060f)
