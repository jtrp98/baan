## T3. ช่องว่างส่ง arch ก่อนเชื่อมระบบ

ทุกข้อเป็น Task UX-005 ไม่ใช่คำถามเทคนิคให้ผู้ใช้ตัดสิน:

1. Reference `design/des-005.md:73–85`, `design/source-review-003.md:24–29`: ตาราง API ที่อ่านไม่มีสัญญา Sheet preview/validate/import; ยังขาดการผูกแถวกับ stable key การเก็บความหมาย D/ที่มา หน่วย atomic ผล validation/ผลสำเร็จ และการกันนำเข้าต้นทางเดิมด้วยคำขอใหม่ จึงยังยืนยัน atomic failure/duplicate outcome ไม่ได้ ห้าม front ประกอบหลายคำขอแล้วอ้าง atomic ทั้งชุด
2. Reference `design/des-005.md:73–77`: GET curricula ระบุ published summaries; ยังไม่ระบุการอ่านรายการ/รายละเอียด draft และหลักฐานผู้อนุมัติ/วันเวลา API แก้ content รับ lessons ไม่ครอบ metadata หลังสร้าง ต้องให้ arch เติม/ชี้สัญญาที่ใช้จริง ไม่เสนอ GET draft, metadata PUT หรือ audit endpoint ใหม่ใน UX
3. Reference `design/des-010.md:60–73`: มีสร้าง bank revision และ publish แต่ยังไม่ระบุอ่าน/แก้ draft ที่บันทึกแล้ว; ตัวแก้ก่อนสร้างและการสร้าง revision ใหม่ร่างได้ แต่ flow เปิดกลับมาแก้ต้องรอสัญญา ไม่สมมติ PUT bank
4. Reference `design/gateway-grpc-contract-001.md:26–38,54–60`: manifest ปัจจุบันยังไม่เปิด learning/admin-content RPC โดยปริยาย ต้องมี DTO/route/error/replay/read-back mapping ตามเจ้าของก่อนเชื่อม ไม่มี direct public B fallback (`design/gateway-integration-001.md:5–17`)

ร่างเสนอหน้าตาและทางออกของ state ที่ยังขาดได้ แต่ปุ่มที่พึ่งสัญญาเหล่านี้ยังไม่มีหลักฐานพร้อม implement แม้ภายหลังมนุษย์เซ็น UX แล้ว

## T5. Sign-off table

ทุกส่วนยังเป็นข้อเสนอ ผู้อนุมัติและวันที่อนุมัติเว้นไว้จนมีคำตอบจริง ไม่บันทึกการเซ็นแทนมนุษย์

| ส่วน | คำถาม | ผล | ผู้อนุมัติ | วันที่อนุมัติ |
|---|---|---|---|---|
| หลัก §1–§3; visual/a11y S6 | Q39 | รอเซ็น | — | — |
| หลัก §4; import states | Q40 | รอเซ็น | — | — |
| หลัก §5; bank/policy states | Q41 | รอเซ็น | — | — |
| S1–S5; ทางออกเมื่อผลค้าง/ชน | Q42 | รอเซ็น | — | — |

- **Q39:** เห็นชอบหน้าหลักสูตรที่แสดงลำดับแยกจากรหัสถาวร และให้ผู้ตรวจอีกคนเผยแพร่หลังดูสรุปหรือไม่? เช่น ย้ายบทที่ 6 ไปลำดับ 7 รหัสเดิมยังอยู่; เผยแพร่ฉบับ 4 แล้วผู้เรียนฉบับ 3 ยังเรียนและเห็นผลเดิม รวมรูปแบบ SchoolBright และ a11y ใน S6
- **Q40:** เห็นชอบหน้าตัวอย่างนำเข้าที่แสดงทุกแถว ป้าย “ตรวจแล้วจากต้นทาง — ยังไม่เผยแพร่” และหยุดให้ตรวจเมื่อพบข้อมูลผิดหรือรายการซ้ำหรือไม่? เช่น D=TRUE ยังเป็นร่าง; สื่อชุดที่ 2 อยู่ใต้บทเดิม แนะนำยืนยันทั้งชุดหลังตรวจผ่าน โดยทีมต้องทำสัญญารองรับก่อนใช้งานจริง
- **Q41:** เห็นชอบหน้าคลังข้อสอบที่แยกฉบับชัด และแสดงการตั้งค่าข้อสอบครบก่อนเผยแพร่หรือไม่? เช่น เห็นทันทีว่า Test ยังไม่ตั้งเวลา; แก้เฉลยเป็นฉบับใหม่แล้วผลสอบครั้งเก่าไม่เปลี่ยน
- **Q42:** เห็นชอบให้แสดงแถบ “ยังไม่ทราบว่าบันทึกสำเร็จหรือไม่” ค้างไว้จนตรวจผลเดิมได้ และให้ตรวจข้อมูลล่าสุดเมื่อมีคนแก้ชนหรือไม่? เช่น อินเทอร์เน็ตขาดหลังเผยแพร่จะไม่ชวนสร้างฉบับซ้ำ; คนอื่นแก้ร่างก่อนแล้วระบบไม่ทับการแก้ของเขาอัตโนมัติ
