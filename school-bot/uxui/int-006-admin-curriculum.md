# int-006 — admin หลักสูตรและคลังข้อสอบ

วันที่ 2026-10-26 · ใบงาน063 · UX-005

ทุกการจัดวาง คำบนหน้าจอ และ interaction ในชุดนี้เป็น **ข้อเสนอ (proposal) — รอเซ็น / awaiting sign-off** ไม่ใช่ signed int artifact ส่วนกฎธุรกิจอ้างมติเดิม ไม่เสนอเปลี่ยนกฎ

อ่านร่วมกับ [state/a11y](int-006-admin-states.md) และ [trace/sign-off/ข้อจำกัด](int-006-admin-trace.md) ทั้งสามไฟล์เป็นร่างชุดเดียวกัน

## 1. ผู้ใช้และขอบเขต

- ส่วนกลาง: Next.js ใน `target/school-bot/web`, session `staff_admin`; `content_author` สร้าง/แก้ร่างและนำเข้า ส่วน `content_approver` ตรวจและเผยแพร่ ต้องไม่ใช่ผู้สร้างหรือผู้แก้ร่างนั้น
- โรงเรียน: `school_web` ใน `target/sb-tech-upgrade-web-system`; admin โรงเรียนเลือก published revision เปิดใช้กับห้อง/เทอม ครูปรับเฉพาะเวลาสอบและช่วงเปิด–ปิด ไม่แก้เนื้อหากลาง
- Desktop ใช้เรียน/ทดลอง ไม่มีหน้าจัดการหรือหน้าครู ครูบน Desktop ไม่สร้าง Submission/Attempt Cloud

หลักฐาน: `requirement/req-043.md:13–17`; `design/des-005.md:14–20,86`; `design/des-012.md:63–68`; `requirement/decisions-032.md:13`; `requirement/decisions-034.md:16–18` พาธ v2 ในมติเก่าอ่านเป็น school-bot ตาม `requirement/index.md:126`

ข้อเสนอ: เมนู admin มี “หลักสูตรกลาง” และ “คลังข้อสอบ” หัวรายละเอียดแสดงชื่อ/Level/ฉบับ/สถานะ/ที่มา หน้าแก้ไขแบ่ง “ข้อมูลหลักสูตร → บทเรียนและกิจกรรม → ตรวจร่าง” ไม่เพิ่มสถานะ approved ในข้อมูล; วงจรยัง draft → มนุษย์ตรวจ → published

## 2. สร้างและจัดบทเรียน — Q39

ข้อเสนอ flow: สร้างฉบับร่าง → ใส่ชื่อ Level ชั้นแนะนำ วิชากลางและที่มา → จัด Lesson/Activity → “บันทึกฉบับร่าง” → เปิดตรวจเนื้อหาที่บันทึกแล้ว

ฟอร์มใช้เฉพาะข้อมูล DES-005: curriculum_key/revision/level_id/title/source_ref/recommended_grades/subjects และ LessonInput/ActivityInput ไม่ใช้วิชาหรือช่องคะแนนของโรงเรียนแทนวิชากลาง

รายการ Lesson แสดง **ลำดับ | ชื่อ | รหัสถาวร | กิจกรรม** รหัสอ่านอย่างเดียวแยกจากช่องลำดับ ปุ่ม “ขึ้น/ลง” ใช้ keyboard ได้ ไม่บังคับลาก ทุกกิจกรรมมีชนิดและโหมด: สื่อใช้ instruction; ภารกิจใช้ project พร้อม Block/Arm/Code; Quiz/Test ใช้ mode=null ไม่แปลงใบงานเป็นข้อสอบเอง

ตัวอย่างประกอบเท่านั้น: LessonKey `7d0b04d8-3275-469c-a1aa-3a54e9daa105` ชื่อ “How AI Learns” ย้ายลำดับ 6 → 7 รหัสเดิมคงอยู่ เลข Unit ในชื่อแผนไม่ใช้สร้างรหัส อ้างรูปปัญหาจริงใน `design/source-review-003.md:20–21`

ก่อนบันทึก ตรวจรหัส/ลำดับซ้ำ ความสัมพันธ์กิจกรรมกับ mission และ mode; submit แล้วชี้จุดผิด ไม่ล้างข้อมูล การบันทึกสำเร็จต้องมาจากผล server แล้วเปิดอ่านฉบับนั้นใหม่ได้ ไม่ถือภาพ preview ใน browser เป็นหลักฐานบันทึก

หลักฐาน: `design/des-005.md:23–48,73–86`; `design/data-contract-rules.md:18–20` การอ่านร่างกลับและแก้ metadata หลังสร้างยังมีช่องว่างตาม companion trace

## 3. ตรวจและเผยแพร่ revision — Q39

ข้อเสนอ: ฉบับ published เป็นหน้าอ่านอย่างเดียว ใช้ “สร้างฉบับแก้ไขใหม่” เพื่อเตรียม revision ใหม่ผ่านสัญญาสร้างเดิม ไม่แก้ children ของฉบับเก่าและไม่เสนอ endpoint clone

หน้าตรวจแสดงเนื้อหา/ลำดับ/รหัสถาวร/ที่มา/หลักฐานเกณฑ์ และข้อความ “ฉบับใหม่นี้ไม่เปลี่ยนบทเรียนหรือผลเดิมของผู้เรียนที่ใช้อยู่” ผู้มีสิทธิ์คนที่สองกรอกหลักฐานอ้างอิงการอนุมัติแล้วกด “ตรวจร่างและเผยแพร่” ไม่มีการอนุมัติอัตโนมัติจากการบันทึกหรือ D=TRUE

ผู้สร้าง/ผู้แก้ร่างเห็นปุ่มเผยแพร่ disabled พร้อม “ต้องให้ผู้ตรวจอีกคนเผยแพร่ฉบับนี้” ขาดหลักฐานเกณฑ์หรือเวลาของ Test ให้ชี้รายการที่ต้องเติม ไม่สร้างชื่อผู้อนุมัติจากช่องกรอกของ client

สำเร็จ: “เผยแพร่ฉบับ 4 แล้ว — ผู้เรียนเดิมยังใช้ฉบับเดิม” พร้อมที่มา ผู้อนุมัติ และวันเวลาจากหลักฐาน server ที่ตรวจย้อนกลับได้ ถ้ายังอ่านหลักฐานไม่ได้ห้ามใส่ข้อมูลสมมติแทน

ตัวอย่างประกอบ: เผยแพร่ฉบับ 4 แล้ว ห้องที่ใช้อยู่ฉบับ 3 ยังคงฉบับ 3 และผลเดิม ไม่มีปุ่มย้ายผู้เรียนทั้งหมดใน flow นี้

หลักฐาน: `requirement/req-044.md:13–25`; `design/des-005.md:60,75–86`; `design/des-010.md:44` การอนุมัติ UX นี้ไม่ใช่การอนุมัติเนื้อหาราย revision (`requirement/decisions-038.md:22`)

## 4. นำเข้า Course Plan Sheet — Q40

ข้อเสนอ flow: ระบุต้นทาง → ดูตัวอย่าง → ตรวจข้อมูล → ตรวจสรุป → ยืนยันนำเข้าเป็นร่าง → อ่านผลยืนยัน ไม่กำหนดชนิดไฟล์ ช่องเชื่อมต่อ หรือ endpoint เพิ่มเอง

ตาราง preview แสดงตำแหน่งแถวต้นทาง ชื่อ ระดับชั้น เลข C/ชื่อ Unit ที่อาจไม่ตรงกัน รหัส Lesson ถาวรที่ตรวจยืนยันได้ สื่อชุด 1/2 และความหมายของ D ค่านี้เป็นข้อมูลแสดงประกอบ ไม่ใช่ฟิลด์ใหม่ในคำขอ

- นำเข้าทุกแถวเป็น draft; D=TRUE ใช้ป้าย “ตรวจแล้วจากต้นทาง — ยังไม่เผยแพร่”; แถวอื่น “ยังไม่ยืนยันการตรวจจากต้นทาง” ไม่ตัดทิ้งเอง
- O ไม่ใช้สร้างข้อมูล รหัส หรือลำดับ เปลี่ยนเฉพาะ O ต้องไม่เปลี่ยนผลนำเข้า
- P–X อยู่ใต้ Lesson เดิมในกลุ่ม “สื่อชุดที่ 2” ไม่สร้าง Course/Level ใหม่
- ตรวจแถวหัวตาราง/ช่อง merged/ข้อความที่ไม่ใช่ URL/สื่อหาย และแยก “ไม่มีสื่อ” จาก “อ่านสื่อไม่ได้” ห้ามเติมค่าหรือเดารหัสจาก C/Unit/O

ข้อเสนอเมื่อข้อมูลผิด: สรุปจำนวนและชี้แถว “ยังนำเข้าไม่ได้ — แก้รายการที่ระบุก่อน” ไม่เขียนเฉพาะแถวที่ผ่าน เป้าหมายคือยืนยันทั้งชุดหรือไม่เปลี่ยนข้อมูลเลย แต่ **ยังไม่อ้างว่าสัญญาปัจจุบันรับประกัน atomic import** ต้องให้ arch ระบุหน่วย transaction ก่อนเชื่อม

กรณีซ้ำ: แสดงรายการที่ตรวจยืนยันว่าเคยนำเข้าแล้ว หรือ “ยังตรวจรายการซ้ำไม่ได้” ไม่เลือกข้าม/ทับ/รวม/สร้างใหม่เอง ปิดการยืนยันส่วนนี้จนสัญญากันซ้ำพร้อม การส่งคำขอเดิมซ้ำเพื่อรับผลเดิมแยกจากการนำเข้าต้นทางเดิมด้วยคำขอใหม่

หลักฐาน: `requirement/req-045.md:13–24`; `requirement/decisions-023.md:16` แทนข้อความรอ OQ-017 เดิม; `design/des-005.md:27–29`; `design/source-review-003.md:10–16,20–29`

## 5. คลังข้อสอบและ policy — Q41

ข้อเสนอ flow: เตรียม bank revision → ตรวจข้อ/ตัวเลือก/เฉลย/คะแนนเต็ม/ที่มา → บันทึกร่าง → ผู้ตรวจอีกคนเผยแพร่ แก้ฉบับ published โดยสร้าง revision ใหม่เท่านั้น ไม่แก้ประวัติ attempt

รองรับ single_choice และ boolean เท่านั้น; ข้อปรนัยมีอย่างน้อย 2 ตัวเลือก เฉลยเดียว ถูก/ผิดมี 2 ตัวเลือก เฉลยเดียว คะแนนเต็มมากกว่า 0 ตรวจ key ซ้ำและเฉลยที่ไม่มีในตัวเลือกก่อนบันทึก

แผง policy อยู่กับ Activity ที่เลือก bank/question_keys ไม่ผูก policy กับชื่อ bank แสดงจำนวนครั้ง การเลือกคะแนน เวลาเปิดเฉลย เวลาสอบ การสุ่มข้อและสุ่มตัวเลือกครบ:

| ค่าเริ่ม | Quiz | Test |
|---|---|---|
| ครั้ง/คะแนน | ไม่จำกัด/สูงสุด | 1 ครั้ง/ครั้งแรก; เมื่อมีซ่อมใช้สูงสุดรวมซ่อม |
| เวลา/เฉลย | ไม่จับเวลา/หลังส่ง | ต้องตั้งเวลา/หลังปิดสอบ |
| สุ่มข้อ/ตัวเลือก | ไม่สุ่ม/ไม่สุ่ม | สุ่มข้อ/ไม่สุ่มตัวเลือก |

แสดงค่าที่บันทึกจริงเมื่อเปลี่ยน policy ไม่สรุปจากชื่อ Quiz/Test ครูปรับได้เฉพาะเวลาและช่วงเปิด–ปิดในเว็บครู เรื่องน้ำหนักรายรอบ/สอบซ่อมส่ง UX-007 ไม่เพิ่มใน admin นี้

ข้อความก่อนเผยแพร่: “การแก้ข้อสอบนี้ใช้กับฉบับใหม่ การทำข้อสอบที่เริ่มแล้วคงคำถาม ลำดับ เกณฑ์ และ policy เดิม” ไม่สร้าง attempt ทดลองของครูบน Cloud

หลักฐาน: `design/des-010.md:17–46,53–73`; `design/learning-rules-032-034.md:16–22` การเปิด/แก้ bank draft ที่บันทึกแล้วต้องรอ arch ระบุสัญญา
