## 2. หน้าจัด mapping (admin โรงเรียน) — DES-008 · REQ-049

### 2.1 โครงหน้า (ข้อเสนอ — Q30)

- บริบทด้านบน: ปีการศึกษา/เทอม + วิชา (plan_course) + ห้อง — server resolve เป็น NYear/NTerm จริงแล้วแสดงค่าที่ resolve (DES-008: ห้ามใช้ term "1" แทน legacy NTerm) · เปลี่ยนบริบท = โหลดชุดข้อมูลใหม่ **ไม่ใช้ mapping ข้ามบริบท** (AC-049-03)
- ตารางหลัก **"รายช่องคะแนน (GradeSlot)"**: แถว = ช่อง; คอลัมน์ = ชื่อช่อง · หมวด (ก่อนกลางภาค/หลังกลางภาค/กลางภาค/ปลายภาค จากข้อมูลจริง) · คะแนนเต็ม · สถานะช่อง (ว่างให้เลือก / SchoolBot ดูแล / ล็อกโดยระบบเกรด block_code) · กิจกรรมที่ผูก · สถานะ mapping (ใช้งาน / ล็อกแล้ว-ส่งแล้ว / เกษียณ) · ปุ่ม action
- เหตุผลที่เสนอให้ "รายช่องเป็นแถวหลัก": กฎ 1 ช่อง = 1 กิจกรรม ทำให้เห็นการชนได้ตรงแถว

### 3.2 ตารางพรีวิว: นักเรียน × ช่องคะแนน

อ้างอิง: BR-050-02/03/05 · AC-050-01/03 · AC-049-04 · BR-049-04 · grade-rules ("สูตรและ skip")

- แถว = นักเรียน (รหัส + ชื่อ) · คอลัมน์ = ช่องปลายทางที่แมพ (ชื่อช่อง + หมวดจากข้อมูลจริง — **ไม่เดาหมวดจาก Quiz/Test**) · แสดงเฉพาะคู่ที่แมพเท่านั้น ไม่เพิ่มช่องเอง
- เซลล์แสดงครบทางเดียว: `8/10 → 16/20` + ค่าก่อนปัด (raw_target) 2 ตำแหน่งทศนิยมใน tooltip/แถวขยาย + ค่าเดิมของช่อง (old_score) และค่าที่ SchoolBot เคยส่งล่าสุด (last_exported_score) — Q33
- ท้ายตารางแสดงสูตรคงที่: "คะแนนช่อง = (คะแนนที่ได้ ÷ คะแนนเต็มกิจกรรม) × คะแนนเต็มช่อง แล้วปัด half-up (x.5 ขึ้น ต่ำกว่า x.5 ลง — 7.5→8, 7.4→7) คำนวณรายช่องจากต้นทางเดียวกัน ปัดครั้งเดียว"
- ตัวอย่างประกอบหน้า (ตาม AC-050-03): 8/10 → ช่องเต็ม 20 = 16 · 3/4 → ช่องเต็ม 10 = 8 (จาก 7.5 ปัดขึ้น) · 3/4 → ช่องเต็ม 12 = 9

### 3.4 ยืนยันส่ง (confirm) — receipt / idempotent

อ้างอิง: BR-050-04 · AC-050-02/04 · BR-052-01..03 · AC-052-01..03 · DES-009 (snapshot/If-Match/idempotency/receipt/outbox)

- ปุ่ม "ยืนยันส่งคะแนน" (disabled จนมีรายการพร้อมส่ง ≥1 และผ่าน gates) → dialog สรุป: จำนวน พร้อมส่ง/ข้าม/ถูกกั้น/ชน + รายวิชา-ชื่อช่อง + "เขียนเฉพาะช่องที่ SchoolBot ดูแล คงช่องอื่นทุกค่าไว้" → ยืนยัน → 202 รับ export_id
- การเขียนเป็นแบบ assignment เปลี่ยนเฉพาะ Score ของช่อง SchoolBot ใน ScoreData (owned-only merge) คงรายการอื่น/ผลพิเศษไว้ทั้งหมด ไม่ส่งผลรวมแทนค่าเดิม (DES-009)
- Receipt: รายการที่ apply สำเร็จแสดง "ส่งแล้ว — รหัสรับรอง <receipt_id>" ต่อนักเรียน (บันทึกใน PgtgradeAuditLog — BR-052-03, G-DB)
- Idempotent: ปุ่มยืนยัน disabled ระหว่างรอผล; ไม่ทราบผล (unknown) แสดง "กำลังตรวจสอบผลคำสั่งเดิม… ไม่ส่งซ้ำอัตโนมัติ" — ส่งซ้ำ/ไม่ทราบผลครั้งก่อน คะแนนไม่บวกซ้ำ ไม่เกิดผลซ้ำ (AC-052-03) · IDEMPOTENCY_CONFLICT → "คำสั่งเดิมมีเนื้อหาต่างไป — กรุณาสร้างพรีวิวใหม่"
- ข้อมูลเปลี่ยนหลังพรีวิว: 409 PREVIEW_STALE / TARGET_CHANGED → "ข้อมูลคะแนนหรือปลายทางเปลี่ยนหลังพรีวิว — กรุณาสร้างพรีวิวใหม่แล้วยืนยันอีกครั้ง" ไม่เขียนทับเงียบ (AC-050-04, AC-051-03)
- พรีวิวหมดอายุ 15 นาที: เตือนเมื่อเหลือ ≤2 นาที · หมดอายุ → "พรีวิวหมดอายุ — สร้างใหม่เพื่อใช้ค่าที่อ่านล่าสุด" (DES-009 snapshot bound)
- ออกโดยไม่ยืนยัน: ไม่มีการเขียนใด ๆ (AC-050-02) — toast "ยังไม่ได้ส่ง — พรีวิวนี้จะหมดอายุเอง"
- Release gates: แถบสถานะ 5 gate (parity/coexistence/target/authz/db จาก PreviewView); gate ใดไม่ผ่าน ปุ่มยืนยัน disabled + "ระบบยังไม่เปิดให้ส่งจริง (เช่น CALCULATOR_NOT_VERIFIED)" — environment ที่ไม่ใช่ production เห็นพรีวิวก่อนได้พร้อมสถานะ gate (DES-009) — Q36

### 3.5 คะแนนชน (conflict) → แก้ชน (resolve) — พรีวิวใหม่ / CAS / owned-only

อ้างอิง: BR-051-01..04 · AC-051-01..03 · DES-009 (resolve / xmin CAS)

| State | เงื่อนไข | UI + คำ copy (ข้อเสนอ) |
|---|---|---|
| พบชน (conflict) | ครูแก้ช่อง SchoolBot หลังรอบก่อน · ค่าปลายทางเปลี่ยนหลังพรีวิว · ระหว่าง apply เทียบ xmin ของแถวระบบเกรดกับค่าตอนพรีวิว (CAS) ไม่ตรง | แถว/เซลล์ "ชน" แสดงคู่ค่า: "ค่าปัจจุบันในระบบเกรด <X> — ค่าที่ SchoolBot เสนอ <Y>" · หยุดส่งรายการชนก่อน คงผลที่สำเร็จแล้ว (BR-051-01) |
| เลือกวิธีแก้ | รายการ conflict | radio รายคน: "คงค่าปัจจุบัน (keep_destination)" / "ใช้ค่า SchoolBot ทับ (replace_owned)" + ช่องเหตุผล · ปุ่มลัด "คงค่าปัจจุบันทั้งหมด" — **ไม่มีปุ่ม "ทับทั้งหมด"** กันพลาด (Q35) |
| ขอบเขตการทับ | replace_owned | ทับได้เฉพาะช่อง SchoolBot ที่เป็นเจ้าของ — ช่องครูกรอกเอง/ผลพิเศษ/PgtgradeEdit ยังถูกกั้นเสมอ ไม่ข้ามข้อห้าม (BR-051-03/04) |
| ส่ง resolve | กด "สร้างพรีวิวใหม่จากการเลือกนี้" | ระบบสร้าง**พรีวิวใหม่** (แทนใบเดิม — Supersedes) → "สร้างพรีวิวใหม่แล้ว กรุณาตรวจและยืนยันส่งอีกครั้ง" — resolve ไม่ใช่การส่ง (DES-009) |
| ข้อมูลเปลี่ยนอีกระหว่างแก้ | หลังเลือก/หลังพรีวิวใหม่ | ตรวจชนใหม่เสมอ → PREVIEW_STALE/TARGET_CHANGED → พรีวิวใหม่อีกครั้ง ไม่เขียนทับค่าล่าสุดเงียบ (BR-051-04, AC-051-03) |

## 7. คำถามรอเซ็น (เรียง Q30…)

- **Q30 (§1/§2)**: หน้าจัด mapping ใช้ "รายช่องคะแนนเป็นแถวหลัก" เพื่อให้กฎ "1 ช่อง = 1 กิจกรรม" ตรวจได้ตรงแถว — ตกลงโครงหน้าแบบนี้หรือไม่?

- **Q32 (§2.5)**: mapping ที่ส่งแล้ว (ล็อก) มีเพียงปุ่ม "ใช้ชุดใหม่" ที่ผูกกิจกรรมกับช่องอื่นที่ยังไม่ถูกจอง โดยไม่มีปุ่มแก้/ปลดชุดล็อกใด ๆ และคู่/คะแนนที่ส่งแล้วคงเดิมทุกกรณี — ตกลงหรือไม่?
- **Q33 (§3.2)**: เซลล์พรีวิวแสดง "8/10 → 16/20" พร้อมค่าก่อนปัดใน tooltip/แถวขยาย และแสดงสูตร + ตัวอย่าง half-up ท้ายตาราง — ตกลงรูปแบบนี้หรือไม่?
- **Q34 (§3.1)**: ตอนสร้างพรีวิว เลือกผู้เรียนครบทั้ง roster ไว้ก่อนเป็นค่าเริ่มต้น แล้วครูติ๊กเอาออกรายคนได้ — ตกลงค่าเริ่มต้นนี้หรือไม่?
- **Q35 (§3.5)**: การแก้คะแนนชนใช้ radio รายคน + ปุ่มลัด "คงค่าปัจจุบันทั้งหมด" แต่ไม่มีปุ่ม "ทับทั้งหมด" — ตกลงหรือไม่?
- **Q36 (§3.4)**: หน้าพรีวิวแสดงแถบสถานะ release gates 5 ตัว และเมื่อ gate ใดยังไม่ผ่านให้ปุ่ม "ยืนยันส่ง" disabled พร้อมรหัสเหตุผล — ตกลงหรือไม่?
- **Q37 (§3.6)**: หน้าสถานะการส่ง poll อัตโนมัติทุก 5 วินาทีเฉพาะที่ยังไม่จบ และไม่มีปุ่ม "ส่งซ้ำ" (มีแต่ "ตรวจสอบสถานะใหม่" และ "สร้างพรีวิวเฉพาะรายการค้าง") — ตกลงหรือไม่?
