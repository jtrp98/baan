## Scope

จัด traceability ครบ 44 REQ / 186 AC และ 81 cases จาก requirement index และ TP Markdown รวม Amendment003/004 แม้ associations ในต้นฉบับ task นี้ระบุเพียงบาง REQ ให้ matrix ผูกทุก AC กับ delivery task, QA task, platform/store/mode, fixture, expected/actual evidence และผู้ตรวจ แยก automated/bridge/UI/source-built hardware/signed installer ตามความสามารถพิสูจน์จริง ไม่ใช้ planner validation หรือ runner tests แทน SchoolBot QA จัดรายการ human prerequisites โดยไม่กำหนด SLA/criteria แทนคน

## Out of Scope

งานนอก outputs/AC/references ของ task นี้ การเลือกนโยบายธุรกิจหรือเซ็นอนุมัติแทนคน การเพิ่มหรือตัด frozen release scope และ speculative feature ห้ามแก้ข้ามเขต Owns ของ role ห้าม state-changing git หรือเรียก role ต่อเอง Shared SQL/deploy/publish, installer tests และการเปลี่ยนสถานะหุ่นต้องมีหลักฐานอนุญาตเฉพาะตาม gate ไม่ถือว่าได้สิทธิ์จากการรับแผน

## Expected Output

- 186-AC matrix พร้อม implementation/validation owner

ส่ง artifact จริงในเขต Owns ของ role พร้อม references ที่ตรวจย้อนกลับได้ ไม่สร้างสำเนาเอกสารข้ามหมวด หากมีไฟล์เดิมให้ amend พร้อม Change Log วันที่ 2026-10-26

## Acceptance

ครบ AC จริง186ข้อจาก44REQ; อ้าง canonical task IDs/fixture/platform/store/mode/ผู้ตรวจและ evidence; แยก script review/runtime/hardware/installer; OQ closed ไม่ทำให้ ACผ่าน

แนบตาราง criterion/AC → วิธีตรวจ → expected/actual → evidence path หรือ source:line และข้อจำกัด งานเตรียมแบบ/คำตัดสินต้องมีรายการประเด็น ผู้ตอบ และผลกระทบที่ตรวจทานได้; ถ้ายังไม่มี AC association ให้ตรวจตาม references โดยไม่สร้าง AC เอง งาน implementation ส่งคำสั่ง/exit code และผล checks ตามส่วนที่เปลี่ยน แยก automated logic, UI, hardware และ installer evidence ห้ามอ้างผ่านเมื่อไม่ได้ตรวจหรืออ้าง task นี้ปิด AC ก่อน QA ตรวจ เกินสองรอบแก้ให้หยุดส่งคนตัดสิน

## Dependencies

ไม่มีรายการในข้อเสนอ; ตรวจตามเอกสารอ้างอิงและขอบเขตงานนี้

ไม่มีรายการในข้อเสนอ; ตรวจตามเอกสารอ้างอิงและขอบเขตงานนี้

## Handoff

ให้ tp รายงาน Waiting on Human ก่อน แล้วส่งผลลัพธ์ของ TP-001, outputs/evidence paths, checks ที่ทำจริง, AC ที่เกี่ยวข้อง, ข้อจำกัดและ blockers ให้ นายช่าง ส่งต่อ role ผู้รับตาม [dispatch routing](dispatch-001.md) และงานที่ depends_on TP-001 ใน [canonical tasks](tasks-001.json) ห้ามเรียก role ต่อเองหรือถือว่า artifact ได้รับการยอมรับแล้ว ผู้ทำไม่ลง verified/blocked เอง; QA ส่ง verdict ในเขตตนให้ นายช่าง บันทึก Findings ที่ไม่บล็อก AC เสนอ PM เข้า backlog เท่านั้น
