## Scope

ดำเนินงาน ตรวจ security บน RC ภายในขอบเขต references และส่ง outputs ที่ระบุด้านล่าง รักษาพฤติกรรมที่ไม่เกี่ยวข้องและกติกา repository ผู้ลงมืออ่าน README/เอกสาร/as-built เฉพาะส่วนก่อนแก้จริง แยกข้อเท็จจริง ข้อเสนอ และสิ่งรอยืนยัน ตรวจ preconditions ตาม Dependencies และ [gates](gates-001.md) ก่อนส่วนที่พึ่งพา; ส่วนอิสระเดินต่อได้ DBA เตรียม SQL/rollback และตรวจ human-provided SQL/catalog evidence เท่านั้น ไม่รัน SQL เอง งาน robot ใช้ dry-run จนมีคำสั่งอนุญาตทดสอบอุปกรณ์จริง

## Out of Scope

งานนอก outputs/AC/references ของ task นี้ การเลือกนโยบายธุรกิจหรือเซ็นอนุมัติแทนคน การเพิ่มหรือตัด frozen release scope และ speculative feature ห้ามแก้ข้ามเขต Owns ของ role ห้าม state-changing git หรือเรียก role ต่อเอง Shared SQL/deploy/publish, installer tests และการเปลี่ยนสถานะหุ่นต้องมีหลักฐานอนุญาตเฉพาะตาม gate ไม่ถือว่าได้สิทธิ์จากการรับแผน

## Expected Output

- findings/retest evidence

ส่ง artifact จริงในเขต Owns ของ role พร้อม references ที่ตรวจย้อนกลับได้ ไม่สร้างสำเนาเอกสารข้ามหมวด หากมีไฟล์เดิมให้ amend พร้อม Change Log วันที่ 2026-10-21

## Acceptance

ขอบเขตการผูก AC: เป็น security retest; implementation อยู่ BE-003/004/005/007/008/019/025/026/027/031/032/035–039 และ QA-001/004/010–016 ตรวจตามหน้าที่เดิม; ต้องปรับ `req_ids/des_refs` ให้ตรง acceptance ที่ขยายแล้ว; IPC ต้องให้ arch ตรึง criterion

RCจริงตรวจauth/channel/tenant/teacherCloudban/import/four-eyes/v1ปิด/mapping/outbox/receipt/key/IPC/artifact; Critical/Importantแก้และretestหรือคนรับความเสี่ยงเป็นลายลักษณ์อักษร; ไม่ขยายriskacceptance025

แนบตาราง criterion/AC → วิธีตรวจ → expected/actual → evidence path หรือ source:line และข้อจำกัด งานเตรียมแบบ/คำตัดสินต้องมีรายการประเด็น ผู้ตอบ และผลกระทบที่ตรวจทานได้; ถ้ายังไม่มี AC association ให้ตรวจตาม references โดยไม่สร้าง AC เอง งาน implementation ส่งคำสั่ง/exit code และผล checks ตามส่วนที่เปลี่ยน แยก automated logic, UI, hardware และ installer evidence ห้ามอ้างผ่านเมื่อไม่ได้ตรวจหรืออ้าง task นี้ปิด AC ก่อน QA ตรวจ เกินสองรอบแก้ให้หยุดส่งคนตัดสิน
