## เงื่อนไขร่วมก่อน commit

Compare-and-set (CAS) คือการตรวจค่าที่คำขออ่านมาเทียบกับ backing store ล่าสุด แล้วเปลี่ยนข้อมูลภายใต้ lock/transaction เดียวกัน ทุก writer รวม activate เครื่องเดิม, validate, unbind และ revoke ใช้ขอบเขต `LicenseId` เดียวกัน ตาม [protocol และ setup ตรวจ](data-contract-rules-transactions.md) Rev12 การตรวจ cache ก่อน save ไม่ใช่ CAS ของ store

`License` และ `Binding` หมายถึง `SchoolBotLicense` และ `SchoolBotLicenseBinding`; ชื่อ field จริงคือ `LastCheckedAt` ไม่ใช่ `LastValidatedAt`; `LastEntitlementExpiresAt` คือเวลาสิ้นสุด lease ออฟไลน์ `BindingEpoch` เป็นรุ่นการผูก ไม่ใช่ primary key หรือ ETag

| Writer | เงื่อนไขภายในหน่วย commit | เมื่อไม่ผ่าน |
|---|---|---|
| Activate สร้าง binding | License/School/key เดิมยังมีอยู่และ active; `CurrentBindingId`/`BindingEpoch` เท่าที่อ่านมา โดย pointer ต้อง null; ไม่มี live binding; ตรวจ `AllowedNextJkt` และประวัติ detached ซ้ำ | ไม่มี key → `403 LICENSE_INVALID`; inactive → `403 LICENSE_INACTIVE`; pointer/epoch เปลี่ยน, มี live, ไม่ตรง next key หรือเป็นเครื่องเก่าที่ไม่ได้รับอนุญาต → `409 DEVICE_LIMIT`; ไม่เปลี่ยนไปใช้ epoch ใหม่แล้ว retry เอง |
| Validate และ activate เครื่องเดิม | License active; pointer/epoch เท่าที่อ่านมา; Binding ID/LicenseId/SchoolId/DeviceJkt/Epoch ตรงกับตัวที่ตรวจ proof; `Epoch=License.BindingEpoch`, `DetachedAt=null`, `IsDelete=false`; มี live เพียงแถวนี้ | inactive → `403 LICENSE_INACTIVE`; binding ไม่มี/ไม่ใช่ของ License → `403 DEVICE_NOT_ACTIVATED`; detached หรือ pointer/epoch ไม่ตรง → `403 BINDING_REVOKED`; หลาย live → `409 DEVICE_LIMIT`; ไม่อ่านใหม่เพื่อคืนสิทธิ์ให้ binding เก่า |
| Unbind | ตรวจ admin authorization ซ้ำก่อน commit; If-Match เท่า ETag จาก `License.UpdateDate` ล่าสุด; อ่าน pointer/epoch/binding ล่าสุดภายใน lock | ขาด If-Match → `428 PRECONDITION_REQUIRED`; ETag ไม่ตรง → `412 VERSION_CONFLICT`; ไม่มี License → `404 NOT_FOUND`; authorization ใช้สัญญาเดิม |
| Revoke | authorization และ If-Match เช่น unbind; ใช้ License ล่าสุดรวม pointer/epoch ปัจจุบัน | เช่น unbind; ห้ามส่ง binding snapshot เก่ากลับทับ store |

License active หมายถึง `IsDelete=false`, `RevokedAt=null`, ยังไม่ถึง ExpiresAt; ตรวจ inactive ก่อน binding และตรวจ authorization ก่อนเปิดเผย resource ฝั่ง admin ทุก failure ใช้ [error envelope เดิม](data-contract-rules-http.md) และไม่เปลี่ยน License, Binding, success audit หรือ idempotency result ไม่ออก entitlement เมื่อ CAS ไม่ผ่าน แม้ proof ผ่านแล้ว

Validate พร้อมกันใน epoch เดียวไม่ต้องเทียบ LastCheckedAt เก่าเป็น version: คำนวณเวลา/patch จากแถวล่าสุด ณ commit เพื่อไม่ให้ lease/เวลาเดินถอย คง `exp=min(checked_at+259200,License.ExpiresAt)` ไม่เพิ่ม If-Match ให้ device API

## ข้อเท็จจริงจาก source และข้อที่ต้องแก้

Adapter ปัจจุบันตรวจ detached/current/epoch และเลือก patch เฉพาะเวลาแล้ว; activation ตรวจ pointer/epoch, live และ detached history จึงแก้ทิศทางถูกต้อง แต่การตรวจยังใช้ lists ที่โหลดครั้งแรกของแต่ละ adapter แล้วส่ง lists ทั้งชุดไป store; static adapter lock ไม่ทำให้ cache ของอีก instance ใหม่ขึ้น

Memory store ล็อกเฉพาะตอนแทน lists และ load ไม่ร่วม lock; file store ล็อกตาม directory แต่ย้าย bindings กับ licenses คนละไฟล์ จึงยังขาด CAS กับ authoritative state และการเผยแพร่ทั้งหน่วยเมื่อ write ล้มเหลว Service ยังออก token จาก record/เวลาก่อน commit และเก็บ activation idempotency แยกใน instance dictionary; หน่วย commit ยังไม่มี audit/idempotency ร่วม ห้ามถือว่าชื่อ `CommitLicenseUnitAsync` เป็นหลักฐานว่าได้ครบ

นี่คือรายละเอียด protocol ภายในตาม invariant เดิม ไม่มี field/table/HTTP shape ใหม่ และคง `BINDING_REVOKED` สำหรับ detached binding การเปลี่ยน SQL/constraints ต้องส่ง vault ผ่านประตูเดิม; ดู [ข้อรอ PostgreSQL](data-contract-rules-transactions.md)

### เหตุผลและทางเลือกที่ปัดตก

เลือก CAS และ patch ภายใต้ store lock/DB transaction เพราะใช้ fields เดิมและหยุด stale writer ที่จุดบันทึก ปัดตก service semaphore อย่างเดียว (คนละ instance ไม่แชร์), เทียบ epoch จาก cache (ไม่เห็น unbind), แทนทั้ง record (ย้อน DetachedAt) และ compensation หลัง save (เผยแพร่ครึ่งหน่วย) Revoke คงประวัติ binding ตามพฤติกรรมเดิม ไม่เพิ่ม detach/epoch โดยไม่จำเป็น
