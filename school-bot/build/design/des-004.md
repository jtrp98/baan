# DES-004 — ตัวตนและสิทธิ์การใช้งาน SchoolBot

> Rev 13 · แก้ล่าสุด 2026-11-02 · แก้โดย arch · ขอโดย ผู้ใช้ (มติ 052 — อายุ Desktop session นับจากเวลา bind)

สัญญานี้กำหนดการยืนยันตัวตน การออก SchoolBot session และการตรวจสิทธิ์แยกตามช่องทาง Desktop, เว็บโรงเรียน และ admin ส่วนกลาง ระบบใช้บัญชีเดิม รับผล authentication จาก API Gateway และตรวจ directory/สิทธิ์เองก่อนออก session และก่อน commit ทุก mutation

ขอบเขต requirement และมติที่เกี่ยวข้องอยู่ใน [สารบัญอ้างอิง auth](auth-references-001.md)

## ช่องทางและความรับผิดชอบ

- `desktop`: Guest ใช้งาน local ภายใต้ License; นักเรียนและครู login เพื่อเรียน ทดลอง และจัดการ Project Cloud ของตน ไม่มีเมนูครู การตรวจงาน หรือส่งคะแนน ตาม [มติ 022 (แยกหน้าจัดการออกจาก Desktop)](../../shared/decisions/decisions-022.md) และ [มติ 025 (ช่องทางและสิทธิ์ Login)](../../shared/decisions/decisions-025.md)
- `school_web`: ครูรายวิชาและผู้ดูแลโรงเรียนทำงานผ่าน `sb-tech-upgrade-web-system` แลก token ตาม [DES-012 (auth ข้ามระบบ)](des-012.md)
- `staff_admin`: พนักงาน SchoolBright ใช้ admin Next.js ใน `school-bot/web` และสิทธิ์จาก `SchoolBotStaffRole`

Desktop → HTTP API Gateway → gRPC SchoolBot service; เว็บเพิ่ม same-origin Backend for Frontend (BFF) ก่อน API Gateway ไม่มี direct public SchoolBot fallback รายละเอียดอยู่ใน [สัญญา Gateway integration](gateway-integration-001.md)

## การยืนยันตัวตนและแหล่งข้อมูล

API Login/session อยู่ใน `school-bot/web` ตาม [มติ 010 (ใช้บัญชีเดิมและรวม API ใน SchoolBot)](../../shared/decisions/decisions-010.md) โดย reuse credential/challenge pipeline ของ API Gateway ตาม [สัญญา Login reuse](gateway-login-reuse-001.md) และ [Desktop adapter](desktop-login-adapter-001.md) SchoolBot ไม่ทำ password verifier/hash ซ้ำ ไม่คัดลอกหรือแก้ hash และไม่สร้างบัญชีหรือ mapping DB ชดเชย Local dependency injection ไม่ใช่หลักฐาน remote API

ครูใช้ Gateway web continuation; นักเรียนยังใช้ mobile ไม่ได้จนพิสูจน์ Desktop device lifecycle และ identity ครบ HTTP 200, temporary token, challenge และ `terminal_candidate` ไม่ใช่ `fully_authenticated` ก่อนครบ admission ห้ามออกแม้ unbound session สัญญา adapter เป็น Data Transfer Object (DTO) ภายใน ไม่เพิ่ม public continuation endpoint

SchoolBot ยังรับผิดชอบ `LegacyDirectory.Resolve(AccountId,SchoolId) → [{profile,roles}]` และ `Authorize(session,action,resource) → allow|deny` ต้องพิสูจน์ canonical AccountId, account↔profile/tenant, username lookup/normalization, password encoding/hash/flags ของ pipeline เดิม และ active/role/scope rules ห้ามเดา `nSystemID`/`cType` หรือถือ AccountId เท่ากับ student/employee ID

ตาราง `SchoolBotSession`, `SchoolBotLicense`, `SchoolBotStaffRole`, `SchoolBotIdempotency`, `SchoolBotAuditEvent` อยู่ SchoolBot DB (`10.0.0.128:9499`) ตาม [มติ 027 (ที่ตั้งตารางใหม่)](../../shared/decisions/decisions-027.md) ข้อมูลบัญชี/โปรไฟล์/สิทธิ์วิชาอ่านจาก Master DB และ School DB ด้วย connection แยกและบัญชี DB เดิม ไม่สร้าง role/GRANT ใหม่ ตาม [มติ 029 (สิทธิ์เข้าฐานเดิม)](../../shared/decisions/decisions-029.md) ไม่มี client DB access หรือเงื่อนไขต้องใช้ Academic Login/OpenID Connect (OIDC)

## ทางเลือกที่ไม่ใช้

ใช้ deny-by-default และแยก Channel ชัดเจน ปัดตก PIN/ชื่อเมนูเป็นสิทธิ์, เมนูครูใน Desktop, เว็บโรงเรียนที่ไม่มี License active และการห้ามครู bind บน Desktop ใช้ opaque session โดยไม่มี JWT/refresh token เพื่อลด lifecycle; หมดอายุต้อง login หรือแลกใหม่
