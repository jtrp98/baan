# มติที่ 046 — Gateway dev และระยะเวลา replay ของ License

วันที่ 2026-10-26 · ผู้ตอบ: ผู้ใช้ในแชต · ผู้บันทึก: นายช่าง

## คำตอบจริงและขอบเขต

1. ต่อคำถามอนุมัติแบบ Gateway opaque-session เฉพาะ SchoolBot, B เป็น authority ของ session/tenant/สิทธิ์, ส่งผ่าน gRPC และกรอง header ที่ปลอมสิทธิ์ ผู้ใช้ตอบ “dev ได้เลย ฉันสร้าง branch ไว้รอแล้ว”. ถือเป็นคำอนุญาตพัฒนาในขอบเขตแบบที่ถาม ไม่ใช่การอนุญาต production หรือหลักฐานว่าการ review/ทดสอบเสร็จแล้ว ตรวจแบบอ่านอย่างเดียวพบ branch ปัจจุบันของ target/sb-api-gateway คือ `dev/golf/school-bot`; ผู้ช่วยไม่ได้สร้างหรือสลับ branch
2. ผู้ใช้ตอบ “อนุมัติ 15 นาที” สำหรับ create-license replay: คำขอเดิมกู้ Key เดิมได้เฉพาะก่อน ReplayUntil ภายในเพดาน 900 วินาที; หลังหมดหน้าต่างใช้การเพิกถอนแล้วสร้างใหม่หากไม่ได้เก็บ Key โดย License ที่สร้างไว้ไม่หาย ไม่เปลี่ยนสิทธิ์ออฟไลน์ 3 วันหรือ 1 Key ต่อ 1 เครื่อง
3. เรื่องระบบเก็บกุญแจเซ็น License ผู้ใช้ตอบ “ไม่เข้าใจ อธิบายเพิ่ม”. ยังไม่มีการเลือก store/signer/custodian หรือรับความเสี่ยงเรื่อง custody ผู้ช่วยต้องอธิบายว่ากุญแจเซ็นฝั่งผู้ให้บริการต่างจาก License Key ที่แจกให้โรงเรียน

## ขอบเขตที่ยังต้องพิสูจน์

H5 env/network/TLS/peer/source-rate-limit/BFF/bootstrap และผล review ของ implementation ยังต้องได้หลักฐานตามงานที่เกี่ยวข้อง ไม่ใช้คำอนุญาต dev แทนผล runtime หรือปิด G-AUTH/G-SEC/G-RELEASE. การพัฒนาส่วนที่ไม่ต้องใช้ production signer เดินต่อได้ตามขอบเขตที่อนุญาต

บันทึกมติและปรับป้าย TTL ตาม sweep เชิงกลใน design และ fixture plan เท่านั้น ไม่สร้าง Key, ไม่รัน bootstrap, ไม่แก้ source Gateway/SQL/deploy/branch หรือเปลี่ยน task verdict ในรอบอธิบายนี้. เอกสาร review และ mitigation เดิมเป็นหลักฐานตามวันที่; สมมติฐานค่าอื่นคงเดิม
