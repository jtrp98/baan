# REQ-025 — Code Lab: เขียนและรันโปรแกรม

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

## ต้องการอะไร/ทำไม

ให้ฝึกลำดับคำสั่งพื้นฐานและดูผลเคลื่อนที่จำลอง. ผลโปรแกรมอยู่ในฉากจำลองและไม่สั่งแขนกลจริง.

UI (User Interface) คือส่วนติดต่อผู้ใช้; DSL (Domain-Specific Language) คือภาษาคำสั่งเฉพาะงาน.

## Business Rules

- BR-025-01: โปรแกรมมีผลในฉากจำลอง ไม่ใช่การควบคุมแขนกล
- BR-025-02: รองรับเฉพาะ DSL ที่ประกาศ ไม่ใช่ arbitrary Python
- BR-025-03: ขอบเขตรันปัจจุบันคือ 1–64 คำสั่ง เดินครั้งละ 1–10 ช่อง รวมไม่เกิน 100 steps และ source ไม่เกิน 16384 bytes; การโหลดฝั่ง UI ตรวจ 16384 ตัวอักษร (UTF-16 code unit ตาม `String.length`) แยกต่างหาก — สองจุดตรวจใช้หน่วยต่างกันตามที่ source เป็นจริง; ข้อความหลายไบต์ (เช่น ไทย 1 ตัวอักษร = 3 UTF-8 bytes) อาจผ่านการโหลดแต่ถูกปฏิเสธตอนรันเมื่อเกิน 16384 bytes

## Acceptance Criteria

- AC-025-01: รันชุด move_right, jump, move_left ที่ถูกต้องแล้วได้รายการคำสั่ง จำนวน steps และผลเล่นในฉาก โดยไม่มีคำสั่งไปหุ่น
- AC-025-02: ส่งคำสั่งนอก DSL แล้วแสดงข้อผิดพลาด ไม่ดำเนินเป็น Python ทั่วไป
- AC-025-03: บันทึกแล้วเปิด source เดิมได้; เมื่อโหลด schema ผิดหรือ source ยาวเกิน 16384 ตัวอักษร (หน่วยตาม BR-025-03) แสดงข้อผิดพลาด; เพดาน bytes ตอนรันอยู่ใน BR-025-03 ไม่ใช่เกณฑ์ของข้อนี้

## ยังไม่ยืนยัน

- เจตนาทางธุรกิจที่กลั่นจากฐานเดิมยังไม่ยืนยัน: ให้ฝึกลำดับคำสั่งพื้นฐานและดูผลเคลื่อนที่จำลอง ต้องให้เจ้าของผลิตภัณฑ์ยืนยันเจตนานี้ โดยแยกจากกฎหรือเกณฑ์ที่มีมติยืนยันแล้ว
- ยังไม่มีมติผู้ใช้ให้รวมหน่วยจำกัด source ตอนโหลด (UTF-16 code unit) กับตอนรัน (UTF-8 bytes) เป็นหน่วยเดียว; ต้องให้เจ้าของผลิตภัณฑ์ยืนยันก่อนเปลี่ยนข้อจำกัดเดิม
