# REQ-027 — จัดการ license ผ่าน admin API

## Purpose

ให้จัดการ License สำหรับระบบใช้งานจริง และเก็บข้อมูลถาวรใน `SchoolBotLicense` ตามมติผู้ใช้

## ข้อเท็จจริงจากไฟล์

- `web/src/SchoolBot.Api/Program.cs:96` กัน admin ด้วย Bearer key ที่ตั้งไว้อย่างน้อย 32 ตัวอักษร (as-built เดิมแบบ static bearer — ถูกแทนด้วย BR-027-01 ตาม decisions-025 ข้อ 6 และ decisions-026)
- `web/src/SchoolBot.Application/ManagementService.cs:24` สุ่ม key คืนเต็มครั้งเดียวและเก็บ hash
- `web/src/SchoolBot.Domain/Licensing/SchoolLicense.cs:8` ตรวจชื่อโรงเรียน 1–200 ตัวอักษร, limit 1–1000 และหมดอายุในอนาคต
- `web/README.md:29` ระบุ Memory Store และยังไม่มี admin website

## Business Rules

มติผู้ใช้ 2026-10-21 เรื่องข้อมูลถาวรและชื่อฟิลด์อยู่ใน [decisions-004.md](decisions-004.md) กับ REQ-033; Memory Store ข้างต้นเป็นข้อจำกัดโค้ดเดิมที่ต้องแก้

- BR-027-01: admin API ของ License อยู่ที่ `/v2/admin` ผู้เรียกต้องมี staff session (channel `staff_admin`) ของพนักงาน SchoolBright และมีบทบาท `SchoolBotStaffRole` ที่ active ซึ่งมีสิทธิ์จัดการ License; ปิด `/v1/admin` static bearer (admin key) ไม่ใช้เป็นทางเข้าอีก — ผู้ใช้ยืนยัน 2026-10-22 ([decisions-025](decisions-025.md) ข้อ 6, [decisions-026](decisions-026.md)); ชื่อบทบาทที่ให้สิทธิ์ License อยู่ที่ DES-004/DES-012 ไม่ใช่มติธุรกิจที่นี่ และรายชื่อ staff_admin ตั้งต้นยังรอข้อมูล
- BR-027-02: สร้าง License ตามข้อมูลโรงเรียนและวันหมดอายุที่ถูกต้อง จำกัด 1 เครื่องต่อ Key ตาม [มติ](decisions-006.md)
- BR-027-03: รายการคืน metadata ไม่คืน key เต็ม, hash หรือ device IDs
- BR-027-04: เก็บข้อมูล License ถาวรใน `SchoolBotLicense` โดยใช้ `SchoolBotLicenseId` และฟิลด์มาตรฐานตาม REQ-033; การ restart API ต้องไม่ทำให้ข้อมูล License หาย

## Acceptance Criteria

- AC-027-01: เมื่อระบบยืนยันตัวตนพนักงานที่ `/v2/admin` ยังไม่ถูกตั้งค่า (เดิมเรียก "ไม่ตั้ง admin key") เรียก admin API ได้ 503; ไม่มี staff session หรือ session/token ไม่ถูกต้อง (เดิมเรียก "token หายหรือผิด") ได้ 401; มี session แต่ไม่มีบทบาท StaffRole ที่ active ซึ่งมีสิทธิ์จัดการ License ได้ 403; เรียก `/v1/admin` ด้วย static bearer แล้วไม่สามารถสร้างหรือดูรายการ License ได้
- AC-027-02: ผู้เรียกที่มี staff session และ StaffRole ที่มีสิทธิ์ ส่งข้อมูลถูกต้องได้ 201 พร้อม Key สำหรับ 1 เครื่อง; ชื่อว่างหรือหมดอายุแล้วถูกปฏิเสธ และไม่สามารถสร้าง Key ที่ใช้ได้หลายเครื่อง
- AC-027-03: ผู้เรียกที่มีสิทธิ์ (ตาม BR-027-01) เรียกรายการหลังสร้างแล้วเห็น metadata และจำนวน activated devices โดยไม่มี key เต็ม, hash หรือ device IDs
- AC-027-04: ผู้เรียกที่มีสิทธิ์ (ตาม BR-027-01) สร้าง License แล้ว restart API ในสภาพแวดล้อมทดสอบ เมื่อเรียกรายการอีกครั้งยังพบ License เดิมและข้อมูลสถานะเดิม
