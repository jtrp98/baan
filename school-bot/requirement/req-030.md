# REQ-030 — ตรวจข้อมูลอัปเดตจาก Desktop

## Purpose

(สมมติฐาน — ยังไม่ยืนยัน) ให้ทราบว่ามี metadata ของเวอร์ชันใหม่สำหรับเครื่องนี้หรือไม่

## ข้อเท็จจริงจากไฟล์

- `app/desktopservice.go:109` ขอ update ด้วย appVersion, stable และ platform ของเครื่อง
- `web/src/SchoolBot.Api/Program.cs:85` คืน available, release และ install_supported=false
- `docs/API.md:95` ระบุกรณีไม่มี release และ Desktop ไม่ download/execute
- `app/desktopservice.go:182` อนุญาต HTTPS หรือ HTTP เฉพาะ loopback

## Business Rules

- BR-030-01: Desktop ปัจจุบันตรวจ stable ตาม version และ platform ของตัวเอง
- BR-030-02: available=true ไม่อนุญาตให้ติดตั้งหรือรันไฟล์อัปเดต
- BR-030-03: การตรวจล้มเหลวต้องแจ้งข้อผิดพลาดและไม่ขัดขวางงาน local
- BR-030-04: การเตรียม/ติดตั้งอัปเดตเป็นคำสั่งแยกที่ผู้ใช้สั่งเอง (explicit intent) — ไม่เกิดจากการตรวจอัตโนมัติ (ตาม [decisions-036](decisions-036.md) · GAP-07)
- BR-030-05: Desktop เชื่อเฉพาะ artifact ที่ผ่าน trust ตาม DES-007/release-trust (hash ตรง manifest ที่ขึ้น registry + publisher pin ของ OS signature)
- BR-030-06: ช่วงเตรียมถึงติดตั้งต้องกัน staging TOCTOU, กัน expiry/withdraw/downgrade และต้องหยุดงานค้าง/หุ่นก่อนติดตั้ง (stop/close guard)

## Acceptance Criteria

- AC-030-01: เมื่อไม่มี published release ใหม่กว่า ผลตรวจมี available=false, release=null และ install_supported=false
- AC-030-02: เมื่อมี release ที่เข้าเงื่อนไข ผู้ใช้เห็น metadata แต่ไม่มีไฟล์ถูกดาวน์โหลด ติดตั้ง หรือ execute จากการตรวจ
- AC-030-03: เมื่อ API เข้าไม่ได้ การตรวจแสดงข้อผิดพลาดและผู้ใช้กลับไปใช้งาน local ต่อได้
- AC-030-04: (ข้อเสนอตามมติ GAP-07 — รอผู้ใช้ตรวจรับ) การเตรียมอัปเดตเริ่มเฉพาะเมื่อผู้ใช้สั่งเอง และตรวจ trust ครบ (hash ตรง manifest จาก registry + publisher pin ตาม DES-007) ก่อนเก็บลง staging — ตรวจไม่ผ่านต้องไม่มี artifact ถูกเก็บหรือติดตั้ง และผู้ใช้เห็นเหตุผลการปฏิเสธ
- AC-030-05: (ข้อเสนอตามมติ GAP-07 — รอผู้ใช้ตรวจรับ) artifact ใน staging ถูกตรวจความสมบูรณ์ซ้ำ (กัน TOCTOU) ตอนสั่งติดตั้ง — ผิด/เปลี่ยน/หมดอายุ/ถูก withdraw หรือเก่ากว่าที่ติดตั้งอยู่ (downgrade) ต้องปฏิเสธพร้อมข้อความ ไม่ติดตั้ง
- AC-030-06: (ข้อเสนอตามมติ GAP-07 — รอผู้ใช้ตรวจรับ) การติดตั้งต้องขอหยุดงานค้าง/หุ่น (stop เป็นเพียงคำขอ) และผู้ใช้ยืนยันอีกครั้งก่อนแอป restart ติดตั้ง
- AC-030-07: (ข้อเสนอตามมติ GAP-07 — รอผู้ใช้ตรวจรับ) การติดตั้งล้มเหลวกลางทาง เครื่องกลับมาใช้งานเวอร์ชันเดิมได้ (rollback/repair ตาม REQ-031) พร้อมรายงานสาเหตุ — ไม่เหลือสถานะครึ่งติดตั้งที่ใช้งานไม่ได้
- AC-030-08: (ข้อเสนอตามมติ GAP-07 — รอผู้ใช้ตรวจรับ) ผู้ใช้ยกเลิกหรือปิดแอประหว่างเตรียม/ก่อนติดตั้ง ต้องไม่มีการติดตั้งเกิดขึ้น และ staging ถูกล้างหรือตรวจซ้ำก่อนใช้ครั้งถัดไป
