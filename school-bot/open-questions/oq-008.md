# OQ-008 — ขอบเขตหุ่นและการยอมรับความปลอดภัย

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

ทีมเสนอหุ่นรุ่นใด firmware ใด วิธี calibration และเกณฑ์หยุดหรือเหตุฉุกเฉินแบบใด และใครจะรับรองให้ใช้กับผู้เรียน?

สถานะ: ตอบแล้วบางส่วนในมติ 016 และ 038; คงสถานะ PARTIAL ตามทะเบียนเดิม

## ถามใคร

ผู้ใช้ตรวจภาพรวม; ทีมอุปกรณ์เสนอรุ่นและข้อมูลจริง พร้อมระบุผู้รับรองความปลอดภัย

## ถ้าไม่ตอบกระทบอะไร

หากยังไม่ได้ข้อมูล จะกำหนดตัวเลขตรวจรับด้านความปลอดภัยและรับรองการใช้หุ่นกับผู้เรียนไม่ได้ การอ่าน source ไม่ยืนยันความปลอดภัยทางกายภาพ

## ข้อสรุปที่ยืนยันแล้ว

ผู้ใช้ตอบเมื่อ 2026-10-21 ให้รองรับหุ่นรุ่นที่ทีมกำหนด โดยผู้ดูแลตรวจ calibration และการหยุดก่อนใช้กับผู้เรียน และมอบหมายทีมสำรวจเสนอรุ่นตาม [มติ 016 (มติผู้อนุมัติภาพรวมและการจัดทำข้อเสนอหุ่น/OS)](../requirement/decisions-016.md) มติ [มติ 038 (sign-off UX ครบทั้งสองไฟล์ + spec Q1/Q2/Q4/Q5)](../requirement/decisions-038.md) ยืนยันว่ายังไม่อนุญาตทดสอบอุปกรณ์จริง ให้ใช้ dry-run/fake bridge จนมีคำสั่งเป็นลายลักษณ์อักษร

## ข้อกำหนดที่เกี่ยวข้อง

[REQ-014 (ค้นหาและเชื่อมต่อหุ่น)](../requirement/req-014.md) ถึง [REQ-024 (การเชื่อมต่อขาดและคำสั่งล้มเหลว)](../requirement/req-024.md)

## ยังไม่ยืนยัน

รอรุ่นหุ่น/board/firmware บริบทที่อนุญาต ผู้รับผิดชอบ calibration เกณฑ์และความหน่วง stop/disconnect/unplug/emergency เงื่อนไขห้ามใช้ ผู้รับรอง และหลักฐานยอมรับที่มนุษย์กำหนด นโยบายที่ตอบแล้วไม่ใช่ผลตรวจหุ่นจริงหรือการรับความเสี่ยง
