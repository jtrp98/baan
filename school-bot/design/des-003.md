## Project document v2

`LocalProjectDocument={schema:2,project_id:U,mode:Mode,name:T200,local_revision:N,updated_at:D,content:ProjectContent}`
`CloudProjectDocument={schema:2,project_id:K,project_revision_id:K,mode:Mode,name:T200,revision:N,update_date:D,content:ProjectContent}`

UTF-8 document ≤1 MiB; ชื่อ 1–200 ตัวอักษร ไม่ใช้เป็น path. Host สร้าง Local UUID ออฟไลน์; web สร้าง Cloud K. `project_revision_id` คือ PK ของ snapshot; `revision` คือ `SchoolBotProjectRevision.Revision` ซึ่งยังคงอยู่ ไม่ใช่ concurrency token. Cloud ใช้ `ETag` จาก `SchoolBotProject.UpdateDate` คู่กับ `If-Match` ตาม decisions-030; `update_date` ใช้แสดงผล ห้าม client แปลงวันที่ไปสร้าง ETag. `local_revision` เป็น counter ไฟล์ใต้ lock ไม่ใช่คอลัมน์ Version ใน DB และไม่ใช่ cloud ETag

Host ใช้ reference `{store:"local",project_id:U}` หรือ `{store:"cloud",school_id:S,project_id:K}`; Cloud cache/recovery แยก P ตามเดิม ห้าม cast/hash UUID เป็น K หรือใช้ bare ID ข้าม store

ProjectContent เป็น tagged union:

| kind | Fields ทั้งหมด |
|---|---|
| code | `{kind:"code",source:string}`; จุดโหลด UI ตรวจ `source.length ≤16384` UTF-16 code units; ตอนรัน engine ตรวจ UTF-8 bytes ≤16384 แยกกันตาม BR-025-03/AC-025-03 |
| block | `{kind:"block",stacks:Stack[]}` |
| arm | `{kind:"arm",poses:Pose[],order:U[],groups:PoseGroup[],joint_names:T200[6],time_mode:"same"|"split",loops:integer1–9999,view:"cards"|"table"}` |

`Stack={x:number,y:number,blocks:Block[]}`; coordinates finite; รวม ≤1000 blocks
`Block` มี `id:U,enabled:B` และ union:
`{type:"move",direction:"move_right"|"move_left",tiles:integer1–10}`;
`{type:"jump"}`;
`{type:"repeat",times:integer1–10,body:Block[]}`

ID ไม่ซ้ำ ไม่มี cycle; draft บันทึกหลาย stacks ได้ แต่ run ต้องหนึ่ง stack ตาม REQ-026; nesting ≤8 และ compilation fuel ≤1000

`Pose={id:U,name:T200,values:number[6],duration_ms:integer1000–9000,joint_duration_ms:integer1000–9000[6]}`
ช่วง values: `[-180,180]`, สี่ค่า `[-135,135]`, ค่า gripper `[0,100]`
`PoseGroup={id:U,name:T20,pose_ids:U[]}`; ≥2 IDs ที่อยู่ใน order; ชื่อกลุ่มไม่ซ้ำ
order ไม่ซ้ำ อ้าง poses ครบหนึ่งครั้ง และ ≤10000; zero poses บันทึกได้แต่เล่นไม่ได้

ไม่บันทึก connection, uploaded/verified, predicted telemetry, torque หรือ executable path เป็นข้อเท็จจริงถาวร กลุ่มผิดใน legacy ถูกละพร้อม warning; document v2 ที่เขียนใหม่ต้อง valid ทั้งชุด

## State / conflict / recovery

`clean → dirty → saving → clean|conflict|save_failed`

ขณะ saving ถ้าแก้ต่อ ให้ snapshot ที่ส่งมี revision ของตัวเอง ผลตอบเก่าไม่ล้าง dirty ของการแก้ใหม่ Cloud ขาด If-Match → `428 PRECONDITION_REQUIRED`; ชน → `412 VERSION_CONFLICT` พร้อม `details.current_etag`; ให้ reload หรือ Save As ไม่มี silent last-write-wins/auto-merge. Local counter ชนใช้ VERSION_CONFLICT โดยไม่มี HTTP และคืน current_local_revision

404 รวมงานที่ไม่มีสิทธิ์เห็น; 400 PROJECT_INVALID, 413 PROJECT_TOO_LARGE, 409 PROJECT_EXISTS/STATE_CONFLICT, 503 STORE_UNAVAILABLE; local ใช้ codes เดียวกันโดยไม่มี HTTP

Guest write ใช้ per-project lock + atomic replace; index เป็นข้อมูล derive/rebuild ได้ ไม่ใช้ index สำเร็จแทนไฟล์สำเร็จ ป้องกัน traversal/symlink escape และ concurrent writer

Cloud timeout ใช้ idempotency key เดิม; ถ้าค้างไม่อ้าง saved Login ที่ offline ยังแก้ draft ในหน่วยความจำได้ ไม่สลับเป็น Guest เอง. ข้อเสนอ encrypted Cloud recovery snapshot แยก P ใช้ `base_etag` แบบ opaque; เป็นเรื่อง retention/custody ของ Cloud cache แยกจาก Guest policy ที่ยืนยันแล้ว และยังไม่อนุญาตให้เปิด Cloud cache ข้ามบัญชี. Close guard ต้องให้ retry หรือ explicit discard

Cloud create/copy retry ต้องใช้ Idempotency-Key:U และ payload เดิมจนทราบผล; ห้ามสร้าง key ใหม่เพราะ timeout

## Migration

อ่าน slot ใน SchoolBotPoC ก่อน ArmStudioPoC ตามพฤติกรรมเดิม ถ้าปลายทางใหม่มีแล้วไม่ import ต้นทางเก่าทับ ตรวจขนาด/JSON/content ก่อนแปลง

สร้าง UUID แบบ deterministic ต่อ source slot และ mode พร้อม local receipt:
`{schema:1,source_app:"SchoolBotPoC"|"ArmStudioPoC",mode,source_hash:H,project_id:U}`
เขียน project ก่อน receipt; rerun ตรวจ ID/hash แล้วไม่ overwrite งานที่ผู้ใช้แก้ ต้นฉบับคงอยู่เสมอ ไฟล์เสียแจ้งแยกและไม่ขัดขวางโครงงานอื่น

Legacy Code คงจุดโหลด UI ที่นับ UTF-16 code units ≤16384 และขนาดไฟล์รวม ≤1 MiB; ไม่เพิ่มเงื่อนไข source UTF-8 bytes ที่โหลด/บันทึกแทน REQ. เพดาน source 16384 bytes ตรวจตอนรันใน engine; source หลายไบต์อาจโหลดได้แต่รันถูกปฏิเสธ ต้องแสดงข้อผิดพลาดโดยไม่ทิ้งต้นฉบับ. Blockly adapter แปลงเฉพาะสาม block types ที่อ่านพบ; unsupported content คืน MIGRATION_UNSUPPORTED ไม่ทิ้งเงียบ

Guest→Login ใช้ explicit selection+copy เป็น Cloud ID ใหม่หลังแสดงบัญชี/โรงเรียนปลายทางตาม REQ-041; Guest policy ยืนยันแล้ว ไม่รอ OQ-007 ซ้ำ. การเลือกประวัติเป็นอีก operation ตาม [guest-history-001.md](guest-history-001.md); ครูนำเข้า Project ได้ แต่ห้ามสร้าง Submission/Attempt Cloud ตาม decisions-032

Import ไม่ส่ง Cloud project_id; Host เก็บ receipt ก่อนส่งและเติม cloud K หลัง durable response. รูปแบบ, identity, การกู้หลัง restart/คำตอบหาย และ server tombstone ตาม [guest-import-001.md](guest-import-001.md); ไม่เพิ่ม ClientId column

## ทางเลือกและการตรวจ

เลือก revision+optimistic concurrency; ปัดตกหนึ่ง slot, filename ตามชื่อ, silent sync และ overwrite หลัง conflict ทดสอบสองงานต่อสามโหมดทั้งสอง stores, restart durability, save timeout/retry, corrupt file และ migration rerun ตาม AC-011/036
