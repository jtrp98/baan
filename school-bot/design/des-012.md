## สัญญาที่ยืนยัน: C — token exchange + gateway introspection

### 1. ที่ตั้งฐานข้อมูลและการเข้าถึง DB ([decisions-027](../requirement/decisions-027.md), [decisions-029](../requirement/decisions-029.md))
- ตาราง `SchoolBotSession`, `SchoolBotStaffRole`, `SchoolBotLicense`, `SchoolBotIdempotency` และ `SchoolBotAuditEvent` อยู่บน **SchoolBot DB (`10.0.0.128:9499`)**
- การอ่านข้อมูลสถานะโรงเรียน (`TCompany`), พนักงาน (`TEmployees`) และสิทธิ์ครูรายวิชา (`TplanCourseTeacher`, `TplanCourse`, `TplanCourseTerm`, `TplanTermSubLevel2`) อ่านจาก **School DB (`JabjaiSchoolSingleDB`)** ผ่าน connection แยกด้วย**บัญชี DB เดิม**ของระบบ โดย**ไม่รัน GRANT/สร้าง role ใหม่**ใน School DB ([decisions-029](../requirement/decisions-029.md))
- เนื่องจากไม่มี transaction เดียวครอบ SchoolBot DB กับ School DB ทุกคำสั่งแก้ไขต้อง **re-check สิทธิ์จาก School DB และสถานะ session/License/StaffRole ใน SchoolBot DB ณ จุดก่อน commit**

### 2. Gateway introspection — ขอเพิ่มใน G (รอเจ้าของ G ดำเนินการตาม H1/H5)
`GET /api/school-bot/auth/web-principal`
- Authenticate ด้วย scheme `JabjaiWebLegacy` อย่างเดียว; ปฏิเสธ token ที่มี claim `purpose` หรือ `aud` (`legacy-handoff`) → `401`
- Rate limit ตาม claim `(school,user)`, `Cache-Control: no-store`, ไม่ log token/claims
- คืน `200 {school_id:I,user_id:I|null,admin_id:T64|null,is_admin:B,user_type:T16|null,expires_at:D|null}` (ต้องคืน `is_admin` ตาม [decisions-025](../requirement/decisions-025.md))

### 3. SchoolBot exchange (`POST /v2/auth/web-sessions`)
Header: `JabjaiWebKey-*: <token>`; body: `{channel:"school_web"|"staff_admin"}`
ไม่ใช้ `Idempotency-Key`/raw response cache; คืน `201 {access_token:T43,token_type:"Bearer",session:SessionView}` (`Cache-Control: no-store`)

ขั้นตรวจ (fail closed ทุกข้อ):
1. Introspection สำเร็จภายใน timeout 3 วินาที ไม่งั้น `503 AUTH_UNAVAILABLE`
2. ใช้ `school_id`/`user_id`/`admin_id`/`is_admin` จาก response เท่านั้น ไม่อ่านจากชื่อ header/body
3. **Token ที่ไม่มี `exp` (`expires_at=null` จาก bypassgarde)**: **อนุญาตให้แลกได้ตามมติผู้ใช้ [decisions-025](../requirement/decisions-025.md) (H2 — ผู้ใช้รับความเสี่ยง)** โดยจำกัดอายุ `SchoolBotSession` ตามตารางอายุ session ด้านล่าง
4. โรงเรียน active (`TCompany IsActive & !CDel`) จาก School DB
5. `P = employee(school_id, user_id)` เมื่อพบ `TEmployees` ที่ไม่ถูกลบในโรงเรียนนั้นและ `WorkStatus ∉ {2,3}`; ไม่พบ → `P=null` (ใช้ได้เฉพาะกรณี `is_admin=true` แบบ legacy admin โดยบันทึก `LegacyAdminId = admin_id`)
6. **เมื่อ `channel = "school_web"` (ยืนยันตาม decisions-025 H7 และ decisions-026)**: ต้องตรวจใน SchoolBot DB ว่าโรงเรียนมี `SchoolBotLicense` ที่ active (`RevokedAt IS NULL AND IsDelete = false AND ExpiresAt > now()`) โดย**ไม่ต้องมี device binding (`DeviceJkt=null`)**; หากไม่มี คืน `403 LICENSE_REQUIRED`
7. **เมื่อ `channel = "staff_admin"`**: ต้องมี `SchoolBotStaffRole` ที่ active (`IsDelete = false AND ValidFrom <= now() AND (ValidUntil IS NULL OR ValidUntil > now())`) ของ `(school_id, user_id)` และ `DeviceJkt=null`
8. บันทึก `SchoolBotSession` และ `SchoolBotAuditEvent` ใน **SchoolBot DB transaction เดียว** โดย `CreateBy`/`UpdateBy` = `user_id` (`sEmp`) หรือ `null` เมื่อไม่มี `user_id` ([decisions-028](../requirement/decisions-028.md))

`SessionView={session_id:K,channel:desktop|school_web|staff_admin,account_id:I|null,school_id:S,profile:P|null,legacy_admin:B,expires_at:D,update_date:D}` (+ ETag จาก `UpdateDate` ตาม [decisions-030](../requirement/decisions-030.md))

### 5. Staff endpoints (`/v2/admin/*`)
- `GET /v2/admin/staff-roles` (`staff_admin`) → `{items:[StaffRoleView],next_cursor}`
- `POST /v2/admin/staff-roles` `{school_id:I,employee_id:I,role:StaffRole,valid_until:D|null,reason:T1000}` → `201 StaffRoleView` (+ ETag)
- `DELETE /v2/admin/staff-roles/{id}` + `If-Match` (`ETag` จาก `UpdateDate`) → `200 {id:K,deleted:true,update_date:D}`
- `POST /v2/admin/sessions/revoke` `{school_id:I,profile_id:I|null,legacy_admin_id:T64|null,channel:T16|null,reason:T1000}` → `200 {revoked:integer>=0}`

### 6. CORS / Origin / CSRF / อายุ Session / Audit
- คงกฎไม่ส่ง `Access-Control-Allow-*`, ปฏิเสธ `Origin` นอก allow-list ด้วย `403 ORIGIN_NOT_ALLOWED`, เก็บ token ฝั่ง `web-system` ใน memory (Zustand) และฝั่ง `admin web` ใน `__Host-sb-admin` HttpOnly cookie
- อายุ session: `school_web` = 30 นาที absolute (และไม่เกิน `SourceTokenExpiresAt` เมื่อมีค่า); `staff_admin` = 8 ชม. absolute (และไม่เกิน `SourceTokenExpiresAt` เมื่อมีค่า); `desktop` = 8 ชม. หลัง bind

## Override ตาม decisions-035 — แหล่งสิทธิ์ is_admin (มีลำดับเหนือขอบเขต Rev5, §2–§4 และ Human Gate เดิม)
- **ข้อยุตินโยบาย ([decisions-035](../requirement/decisions-035.md))**: ผู้ใช้เลือกทาง A ให้สิทธิ์ `school_admin` (`is_admin=true` บน `channel="school_web"`) มาจาก **(1) การตรวจสมาชิกกลุ่ม `แอดมิน/ผู้บริหาร` ฝั่ง server** ตามเกณฑ์ legacy (`FingerprintPayment/Default.aspx.cs:193–240`: `TGroupPermissionUser` ที่ผูก `SchoolID==school_id`, `UserID==user_id` (`nSystemID`), `IsActive==true` join `TGroupPermissionMenu(Type=='W')` และ `TMenuPermission` ที่ `groupName=='แอดมิน/ผู้บริหาร' && isEditable==false` พร้อมมีแถวเมนูอย่างน้อย 1 แถว) คู่กับสถานะพนักงาน/โรงเรียน active ที่ตรวจแล้ว หรือ **(2) Super admin เดิม** (`FingerprintPayment/bypassgarde.aspx.cs:55–75`, `BypassAcademic.aspx.cs:43–63`: `user_id==0 && admin_id!=null` ของโรงเรียนที่ active)
- **กติกาตรวจและ fail-closed**: JWT ของพนักงานปกติที่ส่ง `IsAdmin=0` ไม่ใช่เหตุตัดสิทธิ์กลุ่มหากผลตรวจกลุ่มฝั่ง server ผ่าน; ห้ามเชื่อ `is_admin`/`school_id`/`user_id`/`admin_id` จาก request body/header/query เด็ดขาด; หากข้อมูล mapping (`TR-AUTH-03` ระหว่าง `user_id`/`nSystemID`/`sID`/`sEmp`), ตารางกลุ่มสิทธิ์ หรือ identity lookup ยังไม่พร้อม/เชื่อมไม่ได้ ต้อง **fail closed** (`503 AUTH_NOT_CONFIGURED` หรือ `503 AUTH_UNAVAILABLE`) ห้ามยกสิทธิ์จาก JWT claim อย่างเดียว
- **ขอบเขตและข้อห้าม**: สิทธิ์ที่ได้เป็น `school_admin` เฉพาะภายใน `school_id` ที่ตรวจแล้วเท่านั้น (ไม่กลายเป็น `staff_admin`, ไม่ให้สิทธิ์ครูทุกคนที่ไม่ได้อยู่กลุ่ม, ไม่ข้ามโรงเรียน) และต้อง re-check สิทธิ์กลุ่ม/สถานะก่อน commit ทุกครั้ง; ไม่สร้างตาราง/GRANT/Role ใหม่ ไม่เพิ่ม AC และไม่ระบุคอลัมน์/DB placement/query นอกเหนือที่ source ยืนยัน
- **สถานะสิ่งค้าง**: ปิดเฉพาะ policy choice แหล่ง `is_admin` (C11); ส่วน technical proof (`TR-AUTH-02-rest` ตัวตรวจ login `TAdmin`, `TR-AUTH-03..06`), implementation (`G`/`B`) และ H5 ยังค้าง ดูรายละเอียดและ test scenarios S1–S6 ที่ [gateway-integration-001](gateway-integration-001.md)

## Override Rev6 — Login reuse แยกจาก session และ transport

ใช้ [gateway-login-reuse-001](gateway-login-reuse-001.md) สำหรับจุด reuse. คง C/มติ035/อายุ session/authorization เดิม; Gateway JWT ไม่แทน SchoolBot session. `parse-legacy-token` และ `legacy-handoff` ไม่ใช่ private web-principal. Reuse validator ได้เฉพาะส่วนที่ตรงสัญญา โดยยังต้องตรวจ purpose/aud, active identity/tenant และสิทธิ์สด; ข้อยกเว้นไม่มี exp จำกัดตามมติ025. ข้อความเดิมว่า HTTP forwarder ต้อง implement ถูกลดเป็น candidate รอ G/Light review ตาม Gateway integration Rev2 ไม่ใช่ข้อสรุป transport.
