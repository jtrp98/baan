# DES-012 — Auth ข้ามระบบสำหรับเว็บโรงเรียน, admin และ Desktop

> Rev 9 · แก้ล่าสุด 2026-11-02 · แก้โดย arch · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

สัญญานี้เลือกวิธี C คือแลก token เว็บเป็น opaque SchoolBot session โดยให้ API Gateway ตรวจผ่าน private introspection แยกช่องทาง `school_web`, `staff_admin` และ `desktop` คง License, profile binding, อายุ session และการตรวจสิทธิ์สดตาม [DES-004 (ตัวตนและสิทธิ์)](des-004.md)

ขอบเขต requirement และมติที่เกี่ยวข้องอยู่ใน [สารบัญอ้างอิง auth](auth-references-001.md)

## เส้นทางและขอบเขต

Browser web-system/admin → same-origin Backend for Frontend (BFF) → HTTP API Gateway → gRPC SchoolBot service; Desktop host → HTTP API Gateway → gRPC SchoolBot service ฝั่ง SchoolBot เรียก private Gateway `web-principal` โดยไม่วนผ่าน BFF/public service-route ตาม [Gateway integration](gateway-integration-001.md) HTTP paths/status เป็นสัญญาฝั่ง client ไม่ใช่การกำหนดให้ SchoolBot expose HTTP หรือมี RPC mapping ครบแล้ว

Login HTTP เดิมของ Gateway เป็นคนละขอบเขตกับ service transport ใช้ [Login reuse](gateway-login-reuse-001.md) และ [Desktop adapter](desktop-login-adapter-001.md) โดยไม่ทำ verifier ซ้ำ Gateway JWT ไม่แทน SchoolBot session; `parse-legacy-token`, `legacy-handoff`, การ decode JWT และ `GetWebSessionPrincipal` เดิมไม่พิสูจน์ admission ครบ ข้อยกเว้น token ไม่มี exp จำกัดเฉพาะการแลก token เว็บ ไม่ขยายไป Desktop; Data Transfer Object (DTO) web-principal เดิมยังไม่พิสูจน์ canonical AccountId ของ Desktop

## เหตุผลและทางเลือก

[มติ 025 (เลือก token exchange ผ่าน Gateway)](../requirement/decisions-025.md) และ [มติ 026 (รับแบบที่ปรับแล้ว)](../requirement/decisions-026.md) เลือกวิธี C เพื่อแยก lifecycle ของ SchoolBot ไม่ใช้วิธีตรวจ JabjaiWebKey ทุก request ด้วย signing secret ร่วม เพราะแชร์ key และไม่มี revoke ส่วนวิธี D (ตรวจเองด้วย secret ร่วมเฉพาะตอนแลก) คงเป็นทางสำรองเมื่อ introspection ยังไม่เปิด การที่ระบบผ่าน Gateway เป็นมติ routing แยกจากการเลือกวิธี auth

## สิ่งที่ยังต้องพิสูจน์

H5 (เงื่อนไข route/env/network/trust ระหว่างระบบ) หมายถึงการเพิ่ม BFF route/private `GET /api/school-bot/auth/web-principal` และตั้งค่า env/network ระหว่าง web-system, Gateway และ SchoolBot ยังไม่ปิด การอนุมัติวิธี exchange, token ไม่มี exp, admin, schema, การให้คนที่สองอนุมัติ publish, License เว็บ และการยุติ admin v1 ตามมติที่ลิงก์ข้างต้น ไม่ใช่หลักฐาน implementation หรือ runtime

[มติ 035 (ตรวจกลุ่มแอดมิน/ผู้บริหารฝั่ง server และคง super admin)](../requirement/decisions-035.md) ปิดคำถามแหล่ง `is_admin` แล้ว แต่การพิสูจน์ login ของ `TAdmin`, account/profile mapping, collation, hash/culture, student login และ trust integration ยังขาด เมื่อยังไม่ตั้งค่าใช้ `503 AUTH_NOT_CONFIGURED`; แหล่งข้อมูลล่มใช้ `503 AUTH_UNAVAILABLE` ตาม [DES-004 (ตัวตนและสิทธิ์)](des-004.md) ไม่ยกสิทธิ์จาก claim อย่างเดียว
