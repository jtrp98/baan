## ข้อเสนอ: custody / identity

Host เก็บ License Key และ device private key ใน Windows protected credential store หรือ macOS Keychain แยกจาก user-login tokens; ไม่เก็บใน localStorage/project/log ไม่มี secret signer ใน Desktop

Device ใช้ P-256 key pair; `device_jkt` เป็น JWK thumbprint การคัดลอก device-id/entitlement อย่างเดียวใช้ไม่ได้ ต้องพิสูจน์ private key ด้วย OS store ทุกครั้งที่เปิดแอป Key store ใช้ไม่ได้ต้อง locked ไม่ fallback temp/plaintext

การผูกนี้พิสูจน์ installation key ไม่รับรอง physical uniqueness ต่อผู้มีสิทธิ์ administrator หรือ cloned VM ต้องยืนยันวิธี machine/shared-user custody ก่อน implementation ไม่เปลี่ยนมติหนึ่งเครื่องต่อ Key

## API และ proof

ทุก path ด้านล่างเขียนเต็มแล้ว เป็น HTTP semantics ที่ client→G; G→B ใช้ gRPC ตาม [Gateway](gateway-integration-001.md); license key ≤256 ตัวอักษร ส่ง body ผ่าน HTTPS เท่านั้น

| Method/path | Input | Result |
|---|---|---|
| POST /v2/device-challenges | `{device_jwk}` | 200 `{challenge,server_time,expires_at}` |
| POST /v2/licenses/activate | `{key,device_jwk,challenge,proof}` | 200 EntitlementResult |
| POST /v2/licenses/validate | `{key,binding_id:K,challenge,proof}` | 200 EntitlementResult |
| GET /v2/admin/licenses | pagination | LicenseView list |
| POST /v2/admin/licenses | `{school_id,school_name,expires_at}` | 201 `{license:LicenseView,key}` |
| POST /v2/admin/licenses/{id}/revoke | `{reason}` + If-Match | 200 LicenseView |
| POST /v2/admin/licenses/{id}/unbind | `{reason,next_device_jkt:H?}` + If-Match | 200 LicenseView |

`LicenseView={id:K,school_id:S,school_name,key_hint,expires_at,revoked,activated_devices:0|1,update_date:D}` ไม่คืน hash/device IDs; response ของ resource เดี่ยวส่ง `ETag` จาก `UpdateDate`; revoke/unbind ใช้ `If-Match` ตาม [กฎกลาง](data-contract-rules.md) ไม่รับ `version` จาก client
`EntitlementResult={valid:true,license_id:K,binding_id:K,entitlement,checked_at,expires_at}` เป็น host-only; UI ได้เพียงสถานะ/กำหนดอายุ

Challenge เป็น server-signed JWS ผูก device_jkt, nonce สุ่ม, issued_at และ expiry 120 วินาที Proof เป็น device-signed JWS ผูก challenge, HTTP method/path, Idempotency-Key และ SHA256 ของ canonical JSON body ที่ตัด proof ออก ใช้ JCS; ตรวจ nonce ไม่ถูกใช้กับ operation อื่น

API Cloud ใช้ device proof ผูก hash ของ access token เพิ่มด้วย และตรวจ binding ปัจจุบัน การ retry mutation ใช้ RequestKey เดิม; signed GET replay ในช่วง challenge ไม่สร้าง mutation

`/v2/admin/licenses/{id}` ใช้ K; server สร้าง License/Binding PK และคืน ID เดิมเมื่อ replay; device identity/proof ไม่ใช่ PK. Challenge nonce:U และ Idempotency-Key:U เป็น proof identifiers ไม่ใช่ table keys

License admin ใช้ staff_admin + active license_admin; 503 AUTH_NOT_CONFIGURED / 401 / 403 STAFF_ROLE_REQUIRED ตาม [role/errors/replay](license-admin-security-001.md); ไม่เปิด v1 static bearer

## Atomicity / retries

Transaction ล็อก License และตรวจ key hash, expiry, revoke, current binding, idempotency แล้วจึงเปลี่ยน binding/ออกสิทธิ์/เขียน audit/result พร้อมกัน Signer หรือ commit ล้มเหลวไม่ส่งผลสำเร็จ

- Activate เครื่องเดิมที่ยังผูก: ไม่เพิ่ม binding; ตรวจออนไลน์ใหม่ได้
- สองเครื่อง activate พร้อมกัน: สำเร็จหนึ่ง อีกเครื่อง `409 DEVICE_LIMIT`
- Validate ไม่สร้าง binding; ไม่เคย activate → `403 DEVICE_NOT_ACTIVATED`
- Unbind เพิ่ม BindingEpoch, detach เครื่องเก่า และเปิดให้เครื่องใหม่ activate ทันที ไม่รอ 3 วัน
- Fingerprint ที่เคย detached ห้าม activate กลับเอง แม้ช่วงยังไม่มีเครื่องใหม่; ผู้ดูแลระบุ `next_device_jkt` จึงอนุญาตตัวนั้นได้ หากระบุแล้วรับเฉพาะตัวนั้นจน activate
- Retry เดิมคืนผลเดิมและ expiry เดิม ไม่ถือเป็น online check ใหม่; ตรวจ authorization/current binding ก่อน replay entitlement เสมอ
- Create key replay ตาม [license admin security](license-admin-security-001.md): TTL 15 นาที (ผู้ใช้อนุมัติตาม decisions-046), ตรวจ ReplayUntil ตอนอ่านและล้าง ResultCipher/ResultKeyId เมื่อหมดอายุ; คง tombstone และไม่ลบหลังอ่านครั้งแรก
- Timeout/5xx retry key เดิม; 429 รอ Retry-After; 4xx ไม่ retry อัตโนมัติ; idempotency payload ต่าง → 409

## Signed entitlement

JWS ES256 header `{typ:"schoolbot-entitlement+jwt",alg:"ES256",kid}`; claims:
`{iss,aud:"schoolbot-desktop",jti:U,license_id:K,school_id:S,binding_id:K,binding_epoch:N,cnf:{jkt},modes:["block","arm","code"],iat,nbf,checked_at,exp,license_expires_at}`

เวลาเป็น UTC epoch seconds; `iat=nbf=checked_at`; `exp=min(checked_at+259200,license_expires_at)` ครบกำหนดเมื่อ now≥exp ไม่มี grace ต่อจากการเปิดแอป

Signer อยู่ server KMS/HSM ที่เสนอ ใช้ key แยกจาก update/content signing Desktop ฝัง public trust root; rotation keyset ต้อง root-sign และมี version/expiry; เก็บ verifier key เก่าจน entitlement สุดท้ายหมด Unknown/revoked kid ต้อง online ไม่รับ keyset จาก URL ใน token

## Local state / errors

`unactivated → valid → expired|denied|clock_untrusted`; online Active เท่านั้นกลับ valid

เก็บ token/key/clock anchor แบบ atomic generation เดียว ก่อน unlock Anchor มี server UTC, observed wall time และ max effective UTC; session ใช้ monotonic elapsed ร่วมกับ wall time ไม่ให้เวลาถอย ทุกเริ่ม session/resume ตรวจ rollback เทียบ anchor และ persist high-water mark ก่อนอนุญาตงาน; rollback หรือข้อมูลเสียต้อง online ใหม่ Clock เดินหน้าอาจหมดสิทธิ์เร็ว แต่ห้ามย้อนกลับเพื่อคืนสิทธิ์

การ rollback ทั้ง disk/OS store โดย privileged attacker ยังเป็นข้อจำกัด ไม่อ้างป้องกันสมบูรณ์

| ผลตรวจ | พฤติกรรม |
|---|---|
| 403 LICENSE_INVALID / LICENSE_INACTIVE / BINDING_REVOKED | บันทึก denied, invalidate cache, ไม่ renew |
| 403 DEVICE_NOT_ACTIVATED / DEVICE_PROOF_INVALID | ไม่ unlock/renew; ให้ recovery |
| network/5xx/429 | ใช้สิทธิ์เดิมได้เฉพาะยัง valid; ไม่เลื่อน expiry |
| malformed success / signature ผิด | ไม่รับสิทธิ์ใหม่; คืน INVALID_ENTITLEMENT |
| 403 ไม่ทราบ code | locked รอ online recovery ไม่ตีความ Active |
| credential write ล้มเหลว | CREDENTIAL_STORE_FAILED; ไม่รายงาน activated พร้อมใช้ |

เครื่องเก่าออฟไลน์หลังย้ายใช้ได้ถึง exp เดิมตามมติ; เมื่อรู้ผลปฏิเสธออนไลน์ต้องหยุดใช้ cache Login/logout ไม่ต่ออายุหรือเพิกถอน License โดยตัวมันเอง
