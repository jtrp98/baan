# DES-007 — Release และ trusted update — Rev1

อ้าง REQ-029–033; OQ-011

## ข้อเท็จจริง

`ManagementService.cs:87` publish เปลี่ยน flag; `DesktopRelease.cs:35` ตรวจรูปแบบ artifact ไม่ verify signature
`Program.cs:85` check คืน install_supported=false
`app/desktopservice.go:109` ตรวจ stable ตาม platform
`docs/INSTALLERS.md:78` อธิบาย per-user MSI; `:161` Universal Mac; `:178` ระบุยังไม่ลงนาม งานนี้ไม่ได้อ่าน scripts/artifacts เพื่อรับรองข้อความเหล่านั้น

## Actor / trigger / preconditions

Publisher สร้าง/publish metadata; ผู้ใช้กด check, download และ install เป็นคนละ operation; release ต้องมี trusted artifact ก่อนติดตั้ง ไม่ดาวน์โหลด/execute เพียงเพราะ available=true

## ข้อเสนอ manifest / API

JWS ES256 header `typ:"schoolbot-release+jws",kid`; payload:
`{release_id:U,version:string,channel,platform,url:string,sha256:H,size_bytes:positive_integer,package_kind:"windows-setup"|"windows-msi"|"macos-pkg",min_os:string,engine_hashes:[{id:"demo"|"zide",sha256:H}],issued_at:D,expires_at:D}`

Version ใช้ x.y.z ตามเดิม; HTTPS URL ≤2048 ไม่มี userinfo; hash ของ artifact **หลัง signing/notarization**; Mac สอง platform records ชี้ Universal PKG hash เดียวกันได้ ต้องตรง manifest ทั้งคู่

| Endpoint `/v2` | Input/ผล |
|---|---|
| POST /admin/releases | `{manifest}` → 201 `{id,version,lifecycle:"draft"}` |
| GET /admin/releases | pagination → summaries |
| POST /admin/releases/{id}/publish | `{evidence_ref:T2048}` + If-Match → release summary |
| POST /admin/releases/{id}/withdraw | `{reason}` + If-Match → release summary |
| GET /updates/check | version,channel,platform → `{available,release:null|{id,manifest},install_supported:false}` |

Admin ใช้ publisher scope; public check ใช้ global catalog ที่เสนอ null SchoolId แต่ audit/common fields ครบตาม data-model

Server verify manifest signature, fields, artifact identity และ evidence จาก release pipeline ก่อน publish ไม่ fetch arbitrary URL จาก request มา execute; evidence_ref ต้องมาจาก trusted pipeline registry ที่กำหนด deployment ไม่ใช่ URL ที่ client อ้างลอย ๆ

Trust key แยก License; public roots อยู่ใน host; rotation root-signed/keyset versioned ห้ามเชื่อ public key ที่แนบกับ manifest เอง

## Host workflow / states

`idle → available → downloading → verified → awaiting_close → installing → completed|failed`

`CheckUpdatesV2()` ไม่เปลี่ยนไฟล์
`PrepareUpdate({release_id}) → {download_id,state}` โหลด metadata ใหม่ ตรวจ signature/expiry/platform/version/size/allowlisted HTTPS origin แล้ว stream ลง staging; ไม่ตาม cross-origin redirects ไม่ resume partial bytes ที่ hash ยังไม่ยืนยัน

`InstallPreparedUpdate({download_id})` ต้องผู้ใช้สั่ง, verified artifact, แอปไม่มี active robot work และ close guards สำเร็จ ตรวจ hash/signature อีกครั้งทันทีที่ส่งให้ OS installer จาก protected staging ป้องกันเปลี่ยนไฟล์หลังตรวจ ไม่รับ arbitrary URL/path/arguments จาก frontend

ต้องตรวจ OS publisher signature เพิ่มจาก manifest hash; Windows setup/MSI ใช้ installer เดิม, Mac PKG ใช้ Developer ID Installer และ app/engines ใช้ Developer ID Application/notarization ไม่มี private signing key ใน payload

## Errors / recovery / invariants

400 INVALID_RELEASE/INVALID_ARTIFACT; 409 RELEASE_EXISTS/RELEASE_NOT_PUBLISHED; 403 ARTIFACT_UNTRUSTED; 409 UPDATE_NOT_APPLICABLE/APP_BUSY; local DOWNLOAD_FAILED, HASH_MISMATCH, INSTALL_FAILED

Hash/signature/expiry ผิด: ไม่ execute, ไม่ replace แอป ใช้งานเวอร์ชันเดิมต่อได้ภายใต้ License; download retry เป็นการอ่าน ไม่ใช่ install retry อัตโนมัติ Withdraw ห้ามเริ่ม download/install ใหม่ แต่ไม่อ้างถอน binary ที่ติดตั้งแล้ว

Installer จัดการ files-in-use โดยขอให้ผู้ใช้ปิด ไม่ kill process ไม่ overwrite binary ที่เปิดอยู่ Cancellation ต้องรอ installer outcome ไม่ปลอมเปอร์เซ็นต์หรือถือว่า cancel=rollback สำเร็จ

Windows ใช้ transaction/repair ของ MSI; Mac ไม่อ้างว่า PKG rollback เทียบเท่า MSI ต้องตรวจ bundle หลัง failure และเสนอ repair ด้วย signed package ที่เหมาะสม ห้าม auto-downgrade; recovery release ใช้ version ใหม่ หรือ IT procedure ที่มนุษย์อนุมัติ

เก็บ Projects/Device identity/credential store เมื่อถอนตามนโยบายเดิม การล้างข้อมูลส่วนบุคคลเป็น operation แยกที่ต้องกำหนด ไม่รวม API ใน installer

## Compatibility / ทางเลือก / การตรวจ

คง `/v1/updates/check` เป็น metadata-only และไม่เปลี่ยน AC-030-01/02 Download/install ใหม่เป็น explicit workflow ที่ต้องทบทวนก่อน build; ไม่มีการเลือกตัด scope

ปัดตก checksum อย่างเดียว, arbitrary updater script และ unsigned silent install ใช้ repository package/version/resource/notices checks เดิม เพิ่ม trust verification

ตรวจ clean Windows install/repair/uninstall/upgrade/WebView2 และ Mac Universal Intel/ARM64; ตรวจ payload ไม่มี secrets/maps/debug tools เกณฑ์ OS ขั้นต่ำและ signing owner รอ OQ-011 ไม่มีผลทดสอบในงานนี้
