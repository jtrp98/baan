## Content / criteria contract

Curriculum แต่ละ revision มี Mode เดียว, ordered Lessons และ Missions; Published content immutable เปลี่ยนเกณฑ์ต้อง revision ใหม่ ไม่มีการย้อนแก้ผลเก่าจากเกณฑ์ใหม่

`CriteriaRules` เป็น union:

- automatic: `{kind:"automatic-v1",combine:"all"|"any",rules:AutoRule[]}`
- teacher: `{kind:"teacher-v1",items:[{id:U,instruction:Text}]}`

`AutoRule` มี id และหนึ่งรูปแบบ:
`{type:"trace_equals",commands:Command[]}`;
`{type:"steps_at_most",maximum:integer1–100}`;
`{type:"uses_op",op:"move_right"|"move_left"|"jump",minimum:integer1–64}`

`Command={op:"jump"}` หรือ `{op:"move_right"|"move_left",value:integer1–10}`
rules/items 1–64, IDs ไม่ซ้ำ; combine/ค่าที่ตั้งต้องมี SourceRef และ ApprovedBy/At จากมนุษย์ก่อน publish ไม่กำหนดคะแนน ดาว หรือ threshold ของบทเรียนแทนธุรกิจ

ชุดนี้ประเมิน trace ของ bounded DSL; ไม่อ้างตรวจฟิสิกส์ใน Phaser หากหลักสูตรต้องวัด world/obstacle goals ต้องออก evaluator contract เพิ่มก่อน publish เกณฑ์นั้น ไม่ใช้ตัวตรวจ trace รับรองผลที่วัดไม่ได้

## Grading / transitions / idempotence

Code/Block:
`queued → grading → evaluated` หรือ `error`
Arm:
`awaiting_teacher → evaluated`
การเปิด/ปิดบทเรียนไม่สร้าง submission หรือ passed

Server โหลด snapshot จาก ProjectRevision เอง ไม่รับ commands/score ที่ UI อ้าง Code parse DSL ใหม่; Block compile normalized tree ใหม่ ใช้ bounds เดียวกับ DES-003 และ demo: 1–64 commands, ≤100 steps; ไม่ eval Python/JavaScript

Worker ใช้ durable GradingJob+lease; infrastructure รัน trusted bounded evaluator โดยไม่มีสิทธิ์ network/files ของ source นักเรียน ระบบต้องมี golden vectors เทียบ host/server เพื่อกัน semantics ต่างกัน ผล automatic บันทึก evaluator version และ rule results; passed ตาม combine ที่ได้รับอนุมัติ

Business validation ของโปรแกรมผิดคืน `400 PROGRAM_INVALID` ก่อนรับ submission; infrastructure grader ล้มเหลวเป็น error ไม่ใช่ not_yet เสนอ retry transient สูงสุด 3 ครั้งด้วย lease เดิม หลังนั้นให้ผู้ดูแล retry โดยไม่สร้าง submission ซ้ำ

Commit Assessment, Submission.current pointer, Job และ audit transaction เดียว; unique submission/job/result ป้องกันผลซ้ำ เมื่อ response สูญหายใช้ Idempotency-Key เดิม

Arm ไม่ใช้ telemetry/write/timer เป็นผ่าน ครูเลือก outcome พร้อม feedback และ rule_results ครบ rubric; AssessorId มาจาก auth การแก้ผลสร้าง Assessment sequence ใหม่พร้อม supersedes_id และเหตุผล ไม่ overwrite ผลเก่า

Progress derive จากผลล่าสุดของแต่ละ mission revision แสดง awaiting_teacher/error แยกจาก passed มี history ให้ตรวจย้อนกลับ ไม่รวมดาว/คะแนนหรือ carry-forward ต่าง revision โดยอัตโนมัติ

## Offline / Guest / errors

เสนอ signed published content bundle สำหรับ local lessons; local Code/Block result ระบุ `authority:"local"` ไม่เป็น Cloud assessment จน server ตรวจ snapshot ใหม่

Guest learner profile, การเก็บประวัติ และวิธีให้ครูยืนยัน/นำเข้าเป็นบัญชีจริงรอ OQ-007/009 ไม่มีการผูก Guest กับนักเรียนโดยเดา ไม่ใช้ข้อค้างนี้ตัดระบบ Cloud learning ที่ออกแบบแล้ว

## ทางเลือกและการตรวจ

เลือก immutable snapshots+server grading; ปัดตก client stars, run-success=passed และแก้เกณฑ์ย้อนหลัง ทดสอบตัวอย่างผ่าน/ไม่ผ่านที่เจ้าของเนื้อหาให้, queue restart, duplicated submit, ครูสองคนตรวจชนกัน และ isolation ตาม AC-037–039 ทุกข้อ
