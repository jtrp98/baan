## ข้อเสนอ: integration seam

มติ decisions-010/011: `school-bot-v2/web` ทำ Login/session/API เอง; Desktop เรียก HTTPS ไม่มี DB access หรือ Academic Login/OIDC dependency. ภายใน web: `LegacyCredentials.Verify(school_id,username,password)→AccountId:I`; `LegacyDirectory.Resolve(AccountId,SchoolId)→[{profile:P,roles:Role[]}]`; `Authorize(session,action,resource)→allow|deny` ตรวจ scope ณ request/commit

Ports นี้อ่าน records เดิม ต้องมีหลักฐาน password encoding/hash/flags, username lookup, account↔profile/tenant และ active/role/scope rules ก่อนเปิดใช้ ห้ามเดา nSystemID/cType หรือสร้างบัญชี/mapping DB ชดเชย; ไม่คัดลอก/แก้ password hash ของ legacy

ข้อเสนอ session: opaque token จาก CSPRNG 32 bytes, base64url 43 ตัว; DB เก็บ SHA-256 ใน SchoolBotSession เท่านั้น ส่ง raw token ครั้งเดียวตอน login; ปัดตก JWT/refresh เพื่อลด lifecycle รอบนี้ ครบอายุให้ login ใหม่

`SessionView={session_id:U,account_id:I,school_id:S,profile:P?,expires_at:D,version:N}`; roles ไม่ cache เป็น authority ใน session ต้อง resolve ใหม่

username/password ต้องไม่ว่าง; ไม่ trim/normalize password; username normalization รอ compatibility evidence

| Endpoint `/v2` | Input/ผล |
|---|---|
| POST /auth/login | `{school_id:S,username:T256,password:T1024}` → 201 `{access_token:T43,token_type:"Bearer",session:SessionView}` |
| GET /auth/session | Bearer → 200 SessionView |
| PUT /auth/session | `{profile:P}` + If-Match → 200 SessionView; bind ครั้งเดียว |
| POST /auth/logout | Bearer → 204; revoke session ปัจจุบัน |
| GET /me | Bearer → 200 `{account_id:I,display_name:T200,memberships:[{profile:P,roles:Role[]}]}` |
| GET /admin/teacher-grants | scope/pagination → grant list |
| POST /admin/teacher-grants | `{teacher_id,learner_id,mode,can_view,can_assess,valid_from,valid_until}` → 201 grant |
| DELETE /admin/teacher-grants/{id} | If-Match → 200 `{id,deleted:true,version}` |

Teacher/Learner IDs เป็น I ตาม data-model; grant result คือ input + id:U/version:N; school/common fields เป็น server-managed ตาราง/endpoints grants ใช้เฉพาะ fallback ที่อนุมัติตาม data-model

## Permissions ที่เสนอ ไม่ใช่มติขอบเขตครู

| Actor | อนุญาต |
|---|---|
| Guest + License | local projects/Labs/cached published lessons; ไม่มี Cloud learner identity |
| Student | CRUD งานตน ส่ง/อ่าน submission และผลตน |

ไม่ให้ครูเห็นทั้งโรงเรียนโดยปริยาย; administrative role ไม่ได้รับสิทธิ์อ่าน source นักเรียนอัตโนมัติ Content-author/publisher scopes แยกจาก teacher

Login ต้องมี active License entitlement/device proof และ school ตรงกัน; web ตรวจ credential แล้วสร้าง session ผูก SchoolId/DeviceJkt; ไม่รับ AccountId/role จาก client ทุก private request ตรวจ Bearer, expiry/revocation, device proof, entitlement และ active legacy account/tenant ซ้ำ; domain ต้องมี P และ scope ตรง resource

## State / invariants / failure

`guest → authenticating → authenticated_unbound → authenticated → expired|signed_out`

Login ให้ unbound session 5 นาที (ProfileKind/ProfileId=null); ใช้ได้เฉพาะ session/me/logout. Bind ต้องเป็น P ใน memberships ที่ตรวจใหม่, school ตรง session; สำเร็จตั้ง expiry=CreateDate+8 ชั่วโมง; kind/id เปลี่ยนอีกไม่ได้ (409 SESSION_ALREADY_BOUND); bind ซ้ำ P เดิมคืนค่าเดิมหลังตรวจสิทธิ์/If-Match ไม่ต่ออายุ; เปลี่ยน school/profile ต้อง login ใหม่

GET session คืน ETag; PUT ใช้ If-Match/Idempotency-Key ตามกฎกลาง; Session+idempotency+audit commit ใน School DB เดียว Login ไม่ใช้ idempotency/cache raw response; timeout ให้ login ใหม่ session ที่ไม่ได้รับจะหมดอายุ Logout ไม่ต้อง If-Match/Idempotency-Key/License: revoke+audit transaction เดียว คืน 204 แม้ token หาย/หมดอายุ/ถูกถอน; DB ล่มคืน 503 ไม่อ้างว่า revoke สำเร็จ
ไม่มี refresh; token หมดอายุ/เครือข่ายล้มเหลวไม่เปลี่ยนเป็น Guest หรืออ้าง cloud saved. Password อยู่ UI/host memory ชั่วคราว ส่ง HTTPS แล้วล้าง; ห้าม log/telemetry/local disk/OS store เก็บ password; host เก็บเฉพาะ token ใน OS credential store ไม่คืน token ให้ renderer Response auth ใช้ Cache-Control:no-store; backend ห้ามบันทึก password/raw token รวม SQL/request logs

Logout ใช้ robot drain/close guard เดิม; ล้าง token/UI แม้ offline และแจ้ง revocation ยังไม่ยืนยัน (server expiry ยังมีผล); recovery ข้ามผู้ใช้รอ OQ-007

ใช้ error envelope กลาง: 400 INVALID_INPUT; 401 UNAUTHORIZED แบบเดียวสำหรับ username/password ผิดหรือบัญชีปิด, token invalid/revoked; 401 SESSION_EXPIRED; 403 PROFILE_REQUIRED/FORBIDDEN/SCHOOL_MISMATCH; 409 SESSION_ALREADY_BOUND; 412 VERSION_CONFLICT; 429 RATE_LIMITED + Retry-After (จำกัดตาม school/account/source); 503 AUTH_NOT_CONFIGURED เมื่อ compatibility ยังไม่พร้อมทั้งระบบ, AUTH_UNAVAILABLE เมื่อ DB ล่ม ไม่ใช้ sample login หรือเปิดสิทธิ์แทน; object ที่ไม่ควรรู้คืน 404

ตรวจ grant ณ commit ของ assessment ไม่ใช่เฉพาะตอนเปิดหน้า การถอน grant ต้องมีผลกับคำขอถัดไปและไม่ปล่อย in-flight commit ที่ authorization หมดแล้ว

Static admin key เดิมเป็น adapter เฉพาะ development/compatibility ที่ระบุ deployment ชัด Production ใช้ตัวตนรายคน/บริการพร้อม audit; config หายยัง 503 และ token ผิด 401 ตาม AC-027-01 การเปลี่ยนนี้ต้อง breaking review

## ทางเลือกและการตรวจ

ปัดตก PIN/ชื่อเมนูเป็นสิทธิ์ และ role จาก client เลือก deny-by-default + explicit grants ทดสอบ cross-school IDs, teacher ไม่มี grant, grant ถูกถอนขณะตรวจ และ logout/login บัญชีใหม่ไม่รับ callback/ข้อมูลบัญชีเก่า ตาม AC-035-01, AC-038-03, AC-039-02/04
