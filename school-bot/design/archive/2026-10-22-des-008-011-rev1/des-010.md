## Question contract

ข้อเสนอชนิดรุ่นแรก:
single_choice | multiple_choice | boolean
ชนิดอื่นต้องมี evaluator contract ก่อน publish

Question={
question_key:U,kind:QuestionKind,prompt:Text,
options:[{option_key:U,text:Text}],
correct_option_keys:U[],max_score:DecimalString
}

single_choice มีเฉลยหนึ่งตัว; boolean มีตัวเลือกสองตัวและเฉลยหนึ่งตัว
multiple_choice ให้เต็มเมื่อชุดคำตอบตรงเฉลยทั้งหมด ไม่ partial credit
กฎนี้เป็นข้อเสนอ evaluator ต้องให้เจ้าของเนื้อหาอนุมัติก่อนใช้จริง
IDs ไม่ซ้ำ; correct keys ต้องอยู่ใน options; max_score > 0

PublicQuestion ตัด correct_option_keys ออก
student response ไม่คืนเฉลยหรือ hidden scoring metadata ก่อนเวลา
ที่ policy อนุญาต ไม่มีการรับ earned/score จาก client

## Activity และ policy

quiz/test อยู่ที่ Activity ไม่ใช่ Curriculum.Mode
Config={
kind:"question-v1",bank_id:K,question_keys:U[],
shuffle_questions:B,shuffle_options:B
}
question_keys เป็นชุดแน่นอน; order ที่ใช้จริงเก็บใน Attempt
ไม่สุ่มจาก bank ปัจจุบันใหม่ตอน resume

ScoringPolicy={
quiz_counts:B,
activity_weights:[{activity_id:K,weight_bps:0..10000}],
quiz:{max_attempts:N,selection:first|latest|best,
time_limit_seconds:integer>=1|null,
reveal:after_submit|after_close|never},
test:{max_attempts:N,selection:first|latest|best,
time_limit_seconds:integer>=1|null,
reveal:after_submit|after_close|never},
missing_result:block,
approval_ref:T2048
}

ไม่มี default จำนวนครั้ง/เวลาสอบ/selection/reveal
ต้องตั้งและอนุมัติก่อนเปิด scored activity
quiz_counts=false บังคับน้ำหนัก quiz เป็น 0
น้ำหนักกิจกรรมที่นับคะแนนรวม 10000
กิจกรรม type instruction ไม่มีน้ำหนัก
ผลคะแนนหลักสูตร = ผลรวม normalized score × weight
ห้ามเฉลี่ยเฉพาะคน/กิจกรรมที่ส่งแล้วโดยไม่แสดงความไม่ครบ

Policy เก็บ revision immutable; CourseRun ชี้ revision ที่ใช้
เปลี่ยน policy ต้องเป็น revision ใหม่ด้วย optimistic check
attempt/export ที่สร้างแล้วคง snapshot เดิม
preview ที่ยังไม่ยืนยันต้องสร้างใหม่เมื่อ policy ของ run เปลี่ยน

## API

ใช้ /v2, SchoolBot session และ HTTP contract ร่วม
admin content endpoints ต้อง central-author permission
teacher endpoints ตรวจสิทธิ์ CourseRun; learner ใช้ตัวตนจาก session

POST /v2/admin/question-banks
{bank_key:U,revision:N,title:Text,questions:Question[],source_ref:T2048}
201 {id:K,version:N}

POST /v2/admin/question-banks/{id}/publish
{approval_ref:T2048} + If-Match
200 {id:K,version:N,published_at:D}
approval_ref ต้อง resolve trusted human approval

POST /v2/course-runs/{id}/scoring-policies
{policy:ScoringPolicy} + If-Match ของ CourseRun
201 {id:K,revision:N,course_run_version:N}

GET /v2/course-runs/{id}/scoring-policy
200 {id:K,revision:N,policy:ScoringPolicy}

POST /v2/attempts
{course_run_id:K,activity_id:K}
201 AttemptView

GET /v2/attempts/{id}
200 AttemptView

POST /v2/attempts/{id}/submit
{answers:[{question_key:U,selected_option_keys:U[]}]} + If-Match
200 AttemptView

AttemptView={
id:K,version:N,sequence:N,
state:started|submitted|expired|voided,
activity_id:K,course_run_id:K,
started_at:D,deadline_at:D|null,submitted_at:D|null,
questions:PublicQuestion[],
earned:DecimalString|null,max_score:DecimalString,
feedback:{question_key:U,correct:B}[]|null
}

POST endpoints ใช้ Idempotency-Key เดิมเมื่อ retry
learner_id/sequence/deadline/score เป็น server-assigned
body answers ต้องไม่มีคำถามหรือตัวเลือกนอก snapshot
คำถามไม่ตอบเป็น unanswered ตาม evaluator ที่อนุมัติ
ไม่ยอมรับ submission ที่เลย deadline โดยใช้เวลาจาก client

## Transactions และผลลัพธ์

lock counter ของ learner/run/activity ตอนเริ่ม attempt
นับ started/submitted/expired ใน max_attempts
void ต้องเป็น authorized correction พร้อม audit ไม่ใช้สร้างสิทธิ์สอบเพิ่ม
หากต้องการคืนสิทธิ์สอบให้มี policy/การอนุมัติแยกก่อน implement

submit ทำ validate/evaluate/freeze answers/result/audit/idempotency
ใน School transaction เดียว
การ submit ซ้ำคืนผลเดิม ไม่เพิ่มคะแนน
ผลสำเร็จไม่เปลี่ยนด้วย policy หรือ bank revision ใหม่
การแก้ผลต้องมีเหตุผลและผล superseding ไม่ overwrite ประวัติ

project activity ใช้ Submission/Assessment เดิม โดยเพิ่ม
earned_score/max_score ที่มาจาก rubric/evaluator ที่อนุมัติ
ผลเดิมไม่มีตัวเลขให้ SOURCE_NOT_SCORABLE ไม่แปลงจาก outcome เอง

## ทางเลือกและการตรวจ
