เป็นข้อมูลรายโรงเรียน ไม่มี external physical FK ข้าม DB

## โมเดล

CourseRun = การใช้ curriculum revision หนึ่งกับห้องและเทอมหนึ่ง

GradeSlot = ช่อง PGGradeDB ที่ได้รับการยืนยันให้ SchoolBot ดูแล
ระบุ n_grade_id, assessment_id และ score_identifier แบบ exact
รวม school/year/term/plan_course/course/classroom context

ScoreMapping = GradeSlot หนึ่งกับแหล่งคะแนน Activity ตั้งแต่หนึ่งรายการ
Source={activity_id:K,indicator_key:U|null,weight_bps:0..10000}
ผลรวม weight_bps ของ source ที่นับคะแนนต้องเท่ากับ 10000

Lesson เป็นตัวเลือกกลุ่มกิจกรรม ไม่เป็นคะแนนที่สร้างขึ้นเอง
การเลือก Lesson/Indicator ในหน้า mapping ต้องขยายเป็นรายการ
activity_id ที่แน่นอนก่อนบันทึก ห้ามตามกิจกรรมเพิ่มใน revision ใหม่เอง

หนึ่ง Activity แมพได้หลาย GradeSlot ข้ามหลายวิชา
หนึ่ง GradeSlot รวมหลาย Activity ได้เมื่อกำหนดน้ำหนักครบ
ใน CourseRun หนึ่งมี active mapping ต่อ GradeSlot ได้หนึ่งชุด
ห้ามสร้าง mapping ซ้ำเพื่อส่งคะแนนไปช่องเดียวกันสองครั้ง

## การได้มาซึ่ง GradeSlot

1. อ่านช่องเดิมและ resolve context ฝั่ง server
2. ต้องพบ header/assessment/identifier ที่ไม่กำกวมและยังใช้งาน
3. ผู้มีสิทธิ์ยืนยันว่าช่องนั้นเป็นช่องเฉพาะ SchoolBot
4. ตรวจว่าไม่มีคะแนนครูหรือเจ้าของช่องอื่นอยู่ก่อนเริ่มถือครอง
5. บันทึก ownership ใน School DB พร้อม audit

ชื่อช่องที่มีคำว่า SchoolBot ไม่ใช่หลักฐาน ownership
ห้ามยึดช่องของครูด้วยการตั้งชื่อใหม่หรือเลือก force
หากไม่พบช่องว่างที่จัดสรรได้ ให้ SLOT_UNAVAILABLE
การสร้าง Pgtassessment ใหม่ต้องรอ writer contract/DBA review
ห้ามใช้ MAX(id)+1 หรือเดา ScoreIdentifier จาก ordinal

## HTTP

ใช้ headers/envelope/limits/pagination ตาม data-contract-rules
mutation มี Idempotency-Key และ X-Request-Id
update มี If-Match; body ไม่รับ Version แทน header

200 {items:[{activity_id,lesson_id,lesson_key,activity_key,
type,mode,indicator_keys,has_numeric_score}],next_cursor}

GET /v2/grade-targets
query: year:I, term:T64, classroom_id:I, plan_course_id:I,
limit,cursor
200 {items:[TargetView],next_cursor}

TargetView={
n_grade_id:I,assessment_id:I,score_identifier:T128,
course_id:I,plan_course_id:I,year:I,term:T64,
classroom_id:I,category:before_midterm|after_midterm|midterm|final,
name:T512,max_score:DecimalString,
editable:B,owned:B,block_code:T64|null,target_token:T512
}

year/term ใน query เป็นบริบทผู้ใช้ตามระบบเดิม
server resolve เป็น NYear/NTerm และบันทึกค่าที่ resolve ได้ด้วย
ห้ามใช้ term "1" แทน legacy NTerm โดยไม่ resolve

POST /v2/course-runs/{id}/grade-slots
{assessment_id:I,n_grade_id:I,plan_course_id:I,
target_token:T512,ownership_reason:T1000}

ที่ client ประกอบขึ้นเอง การเรียกนี้ไม่เขียน PGGradeDB

## Validation และสิทธิ์

ตรวจสิทธิ์ทุกวิชาที่อ่าน/เปลี่ยน ไม่รวมสิทธิ์ครูคนหนึ่งไปยังวิชาอื่น
source ต้องเป็น published Activity ใน curriculum revision ของ run
indicator ต้องถูกประกาศอยู่บน Activity นั้น
source ต้องมีผลตัวเลขที่นิยามได้ ไม่แปลง passed เป็น 100 เอง
น้ำหนักและ quiz eligibility ต้องสอดคล้อง ScoringPolicy
ค่าหายไม่ถือเป็นศูนย์
mapping ที่ใช้งานแล้วเปลี่ยนได้เฉพาะอนาคต ประวัติ export เก็บ snapshot เดิม
การแก้/retire mapping ทำให้ preview ที่ยังไม่ยืนยันหมดความใช้ได้

## ทางเลือก

เลือก explicit many-to-many และ GradeSlot ownership ใน School DB
ปัดตก FK จากหลักสูตรกลางไป Pgtassessment เพราะผูกโรงเรียน/เทอม
ปัดตกสร้างช่องอัตโนมัติจากชื่อ/เลขลำดับ เพราะยังไม่รู้ allocator เดิม
ปัดตกตั้ง quiz→คะแนนเก็บ/test→สอบเป็นกฎตายตัว เพราะมติไม่ได้ยืนยัน
mapping ต้องเลือกปลายทางอย่างชัดเจน

## เกณฑ์ตรวจ

พิสูจน์หนึ่งคาบส่งหลายวิชา, หลายกิจกรรมรวมช่องเดียว,
ครูไม่มีสิทธิ์หนึ่งวิชา, slot ซ้ำ, context ไม่ตรง,
indicator ไม่อยู่ Activity, เปลี่ยน revision แล้วไม่ remap อัตโนมัติ,
และไม่มี PGGradeDB mutation จากการบันทึก mapping
