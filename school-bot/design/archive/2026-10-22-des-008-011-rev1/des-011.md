## ขอบเขต

Level เป็นระดับหลักสูตร ไม่ใช่การเลื่อนชั้น/ย้ายห้องในทะเบียนนักเรียน
ระบบเสนอจากค่าเฉลี่ยคะแนนรวมของห้อง ครูยืนยันทั้งห้องเท่านั้น
ไม่เขียน CompassStudentLevelScore หรือทะเบียนชั้นเรียนเดิม
ไม่เลื่อนนักเรียนเป็นรายบุคคล

## Policy ที่ต้องได้รับคำตอบ

ต้องมี approved promotion policy ระบุ:
threshold:DecimalString ช่วง 0..100,
effective timing: วันที่/เทอมที่ให้เริ่ม Level ใหม่,
roster rule: ประชากรห้องที่ใช้คำนวณและการจัดการย้ายเข้า/ออก,
missing-result rule และกรณีห้องไม่ถึงเกณฑ์,
สิทธิ์ครูผู้ยืนยันเมื่อหลักสูตรเชื่อมหลายวิชา

ไม่มี default สำหรับประเด็นเหล่านี้
หาก policy ไม่ครบ ให้ POLICY_NOT_CONFIGURED
ข้อความ "สูงกว่าเกณฑ์" ใช้ strict > ไม่ใช้ >=

## การคำนวณและ snapshot

ใช้คะแนนรวม SchoolBot ตาม ScoringPolicy revision ที่ระบุ
ไม่ใช้ GetScore100 ของหลายวิชามาเฉลี่ยโดยเดา
แต่ละคนมีน้ำหนักเท่ากันในค่าเฉลี่ยห้อง
ต้องแสดง roster, ผู้มีผลครบ/ไม่ครบ และตัวหาร

proposal เก็บ roster และผลของทุกคนเป็น immutable snapshot
รวม source result refs, policy revision, current/target curriculum,
average, threshold, effective context และ hash

ห้ามเสนอเลื่อนจากค่าเฉลี่ยเฉพาะผู้ที่มีคะแนนโดยซ่อนผู้ไม่มีผล
การจัดการผลไม่ครบใช้ policy ที่เจ้าของอนุมัติเท่านั้น

## API

ใช้ SchoolBot teacher session และ HTTP contract ร่วม

POST /v2/course-runs/{id}/level-proposals
{promotion_policy_ref:T2048,target_curriculum_id:K}
201 ProposalView

GET /v2/level-proposals/{id}
200 ProposalView

ProposalView={
id:K,version:N,course_run_id:K,target_curriculum_id:K,
eligible:B,average:DecimalString|null,threshold:DecimalString,
member_count:integer>=0,complete_count:integer>=0,
snapshot_hash:H,effective_at:D,reason_codes:T64[],
state:proposed|confirmed|declined|stale,
successor_run_id:K|null
}

POST /v2/level-proposals/{id}/confirm
{snapshot_hash:H} + If-Match
201 {proposal_id:K,successor_run_id:K,version:N}

POST /v2/level-proposals/{id}/decline
{reason:T1000} + If-Match
200 {id:K,version:N,state:"declined"}

ไม่มี learner_ids ใน confirm และไม่มีคำสั่ง promote-student

## Transition

ก่อน confirm ตรวจใหม่ทั้ง roster, source results, policy,
current curriculum, target curriculum และสิทธิ์
เปลี่ยนแม้หนึ่งส่วนให้ PROPOSAL_STALE ต้องเสนอใหม่

confirm บันทึก proposal, successor CourseRun และ audit/idempotency
ใน School transaction เดียว
successor ใช้ roster เดียวกันทั้งห้องตาม snapshot ที่ยืนยัน
ไม่ย้ายผลเก่า/attempt เดิมและไม่ remap ช่อง PGGradeDB อัตโนมัติ
ถ้าเป็น future effective_at แสดง scheduled successor ตามจริง
การเริ่ม run ต้องตรวจเงื่อนไข effective context ตาม policy ที่อนุมัติ

หนึ่ง run มี confirmed successor ได้หนึ่งรายการ
target ต้องเป็น Level ถัดไปตามเส้นทางที่เผยแพร่
ห้ามข้าม Level หรือ downgrade โดยไม่มี business contract เพิ่ม

LEVEL_NOT_ELIGIBLE, ROSTER_INCOMPLETE,
SUCCESSOR_EXISTS, STATE_CONFLICT

428 PRECONDITION_REQUIRED

## ทางเลือกและการตรวจ

เลือก proposal snapshot + whole-room confirmation
ปัดตก auto-promote และเลือกเฉพาะเด็กคะแนนสูง เพราะขัดมติ
ปัดตกเปลี่ยน CurriculumId ใน run เดิมเพราะทำลายประวัติ

ตรวจคะแนนเท่ากับเกณฑ์, roster เปลี่ยน, ผลแก้ระหว่างรอยืนยัน,
ยืนยันซ้ำ, ครูสองคนยืนยันพร้อมกัน, policy ไม่ครบ
และไม่มี partial promotion
