# DES-011 — ระบบเสนอเลื่อน Level และครูยืนยันทั้งห้อง — Rev2

อ้าง REQ-048 (BR-048-01..06, AC-048-01..04); decisions-020:31, decisions-024;
DES-010 (คะแนนรวม), DES-012 (สิทธิ์); REQ-037/039 เป็นฐานเดิม

## ขอบเขต

Level เป็นระดับหลักสูตร ไม่ใช่การเลื่อนชั้น/ย้ายห้องในทะเบียนนักเรียน
ระบบเสนอจากค่าเฉลี่ยคะแนนรวมของห้อง ครูยืนยันทั้งห้องเท่านั้น
ไม่เขียน CompassStudentLevelScore หรือทะเบียนชั้นเรียนเดิม
ไม่เลื่อนนักเรียนเป็นรายบุคคล
หน้าครูอยู่ web-system (BR-048-05); หน้าตั้งเกณฑ์อยู่ admin ส่วนกลาง

## Policy (มติ decisions-024)

- เกณฑ์ (threshold) เป็นข้อมูลราย Level ที่ admin ส่วนกลางตั้ง
  (staff role level_policy_admin ตาม DES-012) ค่าเริ่ม 70.000000 ช่วง 0..100
  เก็บเป็น revision immutable; proposal อ้าง revision ที่ใช้
- เงื่อนไข "สูงกว่าเกณฑ์" = strict > (เท่ากับเกณฑ์ไม่ผ่าน, AC-048-04)
- ประเมินตอนสิ้นเทอม มีผลเทอมถัดไปทั้งห้อง
- ไม่ถึงเกณฑ์: อยู่ Level เดิมอีกเทอม และแสดงส่วนที่ขาด
- ค่าเฉลี่ยนับนักเรียนทุกคนใน roster; กิจกรรมที่ไม่ส่ง/ไม่มีผลนับ 0
  (ใช้เฉพาะการเลื่อน Level; ส่งคะแนนไม่แปลงเป็น 0 ตาม DES-009)

ยังต้องยืนยัน:
- สูตรคะแนนรวมรายคน รอ OQ-014 (DES-010 formula_version);
  ก่อนอนุมัติ endpoint ตอบ 409 SCORING_FORMULA_NOT_CONFIRMED
- แหล่ง roster ของห้อง ณ สิ้นเทอม (สมมติฐาน — ยังไม่ยืนยัน: TstudentClassroomHistory
  ตาม source-review-004) และวันสิ้นเทอม/เทอมถัดไปจากข้อมูลเทอมเดิม — SA ตรวจ source ก่อน build
- สิทธิ์ยืนยันเมื่อ CourseRun ผูกหลายวิชา: ข้อเสนอ SA = ครูรายวิชาคนใดก็ได้ของ
  PlanCourseIds ของ CourseRun (DES-012) โดย If-Match กันยืนยันซ้ำ

## การคำนวณและ snapshot

total รายคน = คะแนนรวมหลักสูตร 0–100 ตาม ScoringPolicy revision และ formula_version
(DES-010) โดยกิจกรรมที่ไม่มีผลใช้ 0
ไม่ใช้ GetScore100 ของหลายวิชามาเฉลี่ยโดยเดา
average = Σ total / member_count; แต่ละคนมีน้ำหนักเท่ากัน
eligible = average > threshold
gap (เมื่อไม่ผ่าน) = threshold − average แสดงพร้อมข้อความว่าต้อง "มากกว่า" เกณฑ์
ต้องแสดง roster, จำนวนคนที่มีผลครบ/ไม่ครบ และตัวหาร

proposal เก็บ roster และผลของทุกคนเป็น immutable snapshot
รวม source result refs, scoring policy revision, formula_version,
promotion policy revision/threshold, current/target curriculum,
average, gap, effective context และ hash

ห้ามเสนอเลื่อนจากค่าเฉลี่ยเฉพาะผู้ที่มีคะแนนโดยซ่อนผู้ไม่มีผล

## Transition

ก่อน confirm/decline ตรวจใหม่ทั้ง roster, source results, policy revisions,
formula_version, current/target curriculum และสิทธิ์
เปลี่ยนแม้หนึ่งส่วนให้ PROPOSAL_STALE ต้องเสนอใหม่

confirm/decline/retained บันทึก proposal, successor CourseRun และ audit/idempotency
ใน School transaction เดียว
successor = CourseRun เทอมถัดไป (NYear/NTerm จากข้อมูลเทอมเดิม) ห้องเดิม
PlanCourseIds เดิม roster ทั้งห้องตาม snapshot; ScoringPolicy เริ่มจากค่าเริ่มของ curriculum ใหม่
เทอมถัดไปยังไม่มีในข้อมูลเดิม → 409 NEXT_TERM_NOT_AVAILABLE ไม่สร้าง successor
ไม่ย้ายผลเก่า/attempt เดิมและไม่ remap ช่อง PGGradeDB อัตโนมัติ (mapping ใหม่ทำตาม DES-008)

หนึ่ง run มี successor ได้หนึ่งรายการ
ห้ามข้าม Level หรือ downgrade โดยไม่มี business contract เพิ่ม

## ทางเลือกและการตรวจ

เลือก proposal snapshot + whole-room confirmation + เกณฑ์ราย Level แบบ revision
ปัดตก auto-promote และเลือกเฉพาะเด็กคะแนนสูง เพราะขัดมติ
ปัดตกเปลี่ยน CurriculumId ใน run เดิมเพราะทำลายประวัติ
ปัดตก threshold เป็นค่าคงที่ในโค้ด เพราะมติให้ตั้งราย Level ใน admin

ตรวจค่าเฉลี่ยเท่ากับเกณฑ์ (ไม่ผ่าน), 70.000001 ผ่าน, คนไม่ส่งงานนับ 0,
roster เปลี่ยน, ผลแก้ระหว่างรอยืนยัน, เกณฑ์เปลี่ยนหลังเสนอ (proposal ใช้ revision เดิม/stale),
ยืนยันซ้ำ, ครูสองคนยืนยันพร้อมกัน, Level สูงสุด, เทอมถัดไปยังไม่มี
และไม่มี partial promotion
