## Question contract

ชนิดรุ่นแรกตามมติ decisions-024: single_choice | boolean
ชนิดอื่น (รวม multiple_choice) เป็นงานถัดไปและต้องมี evaluator contract
ก่อน publish; server ตอบ QUESTION_KIND_UNSUPPORTED

Question={
question_key:U,kind:QuestionKind,prompt:Text,
options:[{option_key:U,text:Text}],
correct_option_keys:U[],max_score:DecimalString
}

single_choice มีตัวเลือก ≥2 และเฉลยหนึ่งตัว
boolean มีตัวเลือกสองตัวและเฉลยหนึ่งตัว
IDs ไม่ซ้ำ; correct keys ต้องอยู่ใน options; max_score > 0
ตอบถูกได้ max_score ตอบผิด/ไม่ตอบได้ 0 (ไม่มีคะแนนบางส่วนในสองชนิดนี้)

PublicQuestion ตัด correct_option_keys ออก
student response ไม่คืนเฉลยหรือ hidden scoring metadata ก่อนเวลา
ที่ policy อนุญาต ไม่มีการรับ earned/score จาก client

## Activity และ policy

quiz/test อยู่ที่ Activity ไม่ใช่ Curriculum.Mode
Config={
kind:"question-v1",bank_id:K,question_keys:U[],
default_policy:AssessmentPolicy
}
question_keys เป็นชุดแน่นอน; order ที่ใช้จริงเก็บใน Attempt
ไม่สุ่มจาก bank ปัจจุบันใหม่ตอน resume

AssessmentPolicy={
max_attempts:N|null,            (null = ไม่จำกัด)
selection:best|first|latest,
time_limit_seconds:integer>=1|null,
reveal:after_submit|after_close,
shuffle_questions:B,shuffle_options:B
}

ค่าเริ่มต้นที่ admin ส่วนกลางได้เมื่อสร้าง Activity (decisions-024):
- quiz: {max_attempts:null, selection:"best", time_limit_seconds:null,
  reveal:"after_submit", shuffle_questions:false, shuffle_options:false}
- test: {max_attempts:1, selection:"first", time_limit_seconds:<ต้องตั้งต่อ test>,
  reveal:"after_close", shuffle_questions:true, shuffle_options:false}
  shuffle_options ของ test (สมมติฐาน — ยังไม่ยืนยัน: มติระบุ "สุ่มข้อ" ไม่ระบุสุ่มตัวเลือก)
test ที่ไม่ตั้ง time_limit_seconds publish ไม่ได้

CourseRunActivity (ต่อห้อง) = {course_run_id, activity_id,
opens_at:D|null, closes_at:D|null, policy_override:AssessmentPolicy|null}
ครูรายวิชาตั้งได้; policy ที่มีผล = override ถ้ามี ไม่งั้น default_policy
ขอบเขตที่ครูปรับได้ยังไม่มีมติ (decisions-024 ยังไม่ตัดสิน): server ตรวจเฉพาะชนิด/ช่วงข้อมูล
ไม่ตั้งกรอบธุรกิจแทน; reveal after_close ต้องมี closes_at

ScoringPolicy (รายหลักสูตรที่เปิดใช้ = ต่อ CourseRun, REQ-047)={
quiz_counts:B,
activity_weights:[{activity_id:K,weight_bps:0..10000}],
formula_version:T64|null
}
quiz_counts=false บังคับน้ำหนัก quiz เป็น 0 และ quiz นั้นเป็น source ส่งคะแนนไม่ได้
น้ำหนักกิจกรรมที่นับคะแนนรวม 10000; กิจกรรม type instruction ไม่มีน้ำหนัก
ข้อเสนอ SA (รอ OQ-014 สูตรรวม): ผลคะแนนหลักสูตร (0–100) =
100 × Σ(weight_bps/10000 × earned/max ของผลที่ selection เลือก)
ใช้ได้เมื่อมนุษย์อนุมัติแล้วบันทึกเป็น formula_version; ก่อนนั้น
endpoint ที่ต้องใช้คะแนนรวม (DES-011) ตอบ SCORING_FORMULA_NOT_CONFIRMED
การส่งคะแนนรายช่อง (DES-009) ไม่ใช้คะแนนรวมนี้
ห้ามเฉลี่ยเฉพาะคน/กิจกรรมที่ส่งแล้วโดยไม่แสดงความไม่ครบ
ผลที่ขาดใช้ 0 เฉพาะการเลื่อน Level (DES-011); ส่งคะแนนไม่แปลงเป็น 0 (DES-009)

Policy เก็บ revision immutable; CourseRun ชี้ revision ที่ใช้
เปลี่ยน policy ต้องเป็น revision ใหม่ด้วย optimistic check
attempt/export ที่สร้างแล้วคง snapshot เดิม
preview ที่ยังไม่ยืนยันต้องสร้างใหม่เมื่อ policy ของ run เปลี่ยน

## สอบซ่อม (retake)

ครูรายวิชาเปิดสอบซ่อมรายคนได้ (decisions-024): หนึ่ง grant = สิทธิ์เพิ่ม 1 attempt
เกิน max_attempts สำหรับ learner/activity นั้น
ผลที่ใช้หลังสอบซ่อมและเพดานคะแนนยังไม่มีมติ จึงกำหนด contract ไว้
แต่ server ตอบ 409 RETAKE_RULE_NOT_CONFIGURED จนกว่าจะมีมติ

learner_id/sequence/deadline/score เป็น server-assigned
deadline_at = min(started_at + time_limit, closes_at) เมื่อมีค่า
body answers ต้องไม่มีคำถามหรือตัวเลือกนอก snapshot

ไม่ยอมรับ submission ที่เลย deadline โดยใช้เวลาจาก client
หมดเวลา: server finalize เป็น expired โดยตรวจคำตอบที่บันทึกล่าสุด (ข้อเสนอ SA)

## Transactions และผลลัพธ์

lock counter ของ learner/run/activity ตอนเริ่ม attempt
นับ started/submitted/expired ใน max_attempts (+ retake grant ที่ใช้แล้ว)
ห้ามเริ่ม attempt นอกช่วง opens_at–closes_at
void ต้องเป็น authorized correction พร้อม audit ไม่ใช้สร้างสิทธิ์สอบเพิ่ม
(สิทธิ์เพิ่มใช้ retake grant เท่านั้น)

submit ทำ validate/evaluate/freeze answers/result/audit/idempotency
ใน School transaction เดียว
การ submit ซ้ำคืนผลเดิม ไม่เพิ่มคะแนน
selection เลือกจาก attempt state submitted|expired ที่มี earned
ผลสำเร็จไม่เปลี่ยนด้วย policy หรือ bank revision ใหม่
การแก้ผลต้องมีเหตุผลและผล superseding ไม่ overwrite ประวัติ

project activity ใช้ Submission/Assessment เดิม โดยเพิ่ม
earned_score/max_score ที่มาจาก rubric/evaluator ที่อนุมัติ
ผลเดิมไม่มีตัวเลขให้ SOURCE_NOT_SCORABLE ไม่แปลงจาก outcome เอง

## ทางเลือกและการตรวจ

เลือก immutable attempt snapshot และ server grading
เลือกค่าเริ่ม policy อยู่ที่ Activity กลาง + override ราย CourseRun (decisions-024)
ปัดตกเก็บแค่ bank_id เพราะคำถาม/เฉลยอาจเปลี่ยน
ปัดตกใช้คะแนน client และผล local Guest เป็นผลทางการ
ปัดตกเปิด retake/ขอบเขต override/สูตรรวม ก่อนมีมติ เพราะเลือกแทนธุรกิจ
ปัดตก multiple_choice รุ่นแรก ตามมติ

ตรวจ publish revision ใหม่ระหว่างสอบ, สอง start พร้อมกัน,
submit ซ้ำ/เลยเวลา, หมดเวลาแล้ว finalize จากคำตอบที่บันทึก,
quiz ไม่จำกัดครั้งเลือกคะแนนสูงสุด, test ครั้งที่ 2 ถูกปฏิเสธ,
test สุ่มลำดับข้อแล้วเก็บลำดับจริง, เฉลย test ไม่รั่วก่อน closes_at,
ครู override แล้วค่าเริ่มกลางไม่เปลี่ยน, เปลี่ยน policy หลัง preview,
quiz ไม่นับคะแนน และผล project เดิมที่ไม่มี numeric score
