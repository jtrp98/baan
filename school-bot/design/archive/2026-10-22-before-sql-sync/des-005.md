## Content / criteria contract

Curriculum revision เป็นเนื้อหากลางของ SchoolBright (`SchoolId=null` ตาม decisions-020/026) สำหรับหนึ่ง `Level` และการเรียนประมาณหนึ่งภาคเรียน (บริบท 22 สัปดาห์เป็นกรอบเนื้อหา ไม่ใช่ค่าคงที่จำนวน Lesson ในโค้ด); โรงเรียนเลือกใช้ published revision แต่แก้เนื้อหากลางไม่ได้

**โครงสร้าง Level และ Activity (ยืนยันตาม decisions-020..026):**
- ถอน `Curriculum.Mode` ออกจาก `SchoolBotCurriculum`; `Mode` (`block|arm|code|null`) อยู่ที่ `SchoolBotActivity`
- `SchoolBotLevel` มี `LevelKey:U` ถาวร, `Code:T64` และ `Ordinal:N` เรียงลำดับตั้งแต่ Beginner ถึง Expert ที่จัดการผ่านข้อมูล
- `RecommendedGrades:T16[]` (ป.1–ม.6) เป็นคำแนะนำเริ่มต้นของแต่ละ Level ไม่ใช้เป็นข้อห้ามเข้าเรียน
- `Subjects:CurriculumSubject[]` (`{subject_key:U,code:T64,title:Text}`) เป็นรหัสวิชากลาง ไม่ใส่ `TPlane` หรือ `Pgtassessment` ของโรงเรียนในตารางหลักสูตรกลาง
- การนำเข้า Course Plan Sheet (REQ-045, decisions-020/023): นำเข้าทุกแถวเป็น `draft` (`ContentState=draft`), แถวที่คอลัมน์ `D=TRUE` ติดป้ายว่าผ่านการตรวจจากต้นทางแต่ไม่ publish อัตโนมัติ, คอลัมน์ `O` ไม่นำเข้า, คอลัมน์ `P–X` เป็นสื่อชุดที่ 2 ของหน่วยเดิม
- `LessonKey`, `MissionKey`, `ActivityKey` และ `IndicatorKey` เป็น `U` ถาวรข้าม revision; `Ordinal` เป็นลำดับภายใน curriculum revision เปลี่ยนลำดับได้โดยไม่เปลี่ยน key; row ID เป็น `K` ใหม่เมื่อสร้าง content revision ใหม่
- Published curriculum และ children (`Lesson`, `Mission`, `Criteria`, `Activity`) เป็น immutable snapshots; เปลี่ยนเนื้อหาหรือเกณฑ์ต้องสร้าง revision ใหม่ ไม่ย้อนแก้ผลเก่า

สัญญา `ActivityInput` และ `ActivityConfig`:
```text
ActivityInput={
  activity_key:U, ordinal:N, title:Text,
  type:instruction|project|quiz|test,
  mode:block|arm|code|null,
  indicators:[{indicator_key:U,code:T128,title:Text}],
  config:ActivityConfig
}

ActivityConfig =
  {kind:"instruction-v1", instructions:Text, media_refs:T2048[]}
| {kind:"project-v1", mission_id:K}
| {kind:"question-v1", bank_id:K, question_keys:U[], default_policy:AssessmentPolicy}
```
- `type=project` ต้องมี `mode` (`block|arm|code`); `instruction|quiz|test` ใช้ `mode=null`
- project mission อยู่ `Lesson` เดียวกันและมีเจ้าของ `Activity` เดียว; `Method` ของ mission ต้องตรง `Activity.Mode` (`block|code` → `automatic`, `arm` → `teacher`)
- ไม่เพิ่มชนิด `config` ที่ server ไม่มี validator/evaluator

`CriteriaRules` เป็น union:
- automatic: `{kind:"automatic-v1",combine:"all"|"any",rules:AutoRule[]}`
- teacher: `{kind:"teacher-v1",items:[{id:U,instruction:Text}]}`

`AutoRule` มี `id:U` และหนึ่งรูปแบบ:
`{type:"trace_equals",commands:Command[]}`;
`{type:"steps_at_most",maximum:integer1–100}`;
`{type:"uses_op",op:"move_right"|"move_left"|"jump",minimum:integer1–64}`

`Command={op:"jump"}` หรือ `{op:"move_right"|"move_left",value:integer1–10}`
`rules/items` 1–64, IDs ไม่ซ้ำ; combine/ค่าที่ตั้งต้องมี `SourceRef` และ `ApprovedBy/At` จากมนุษย์ก่อน publish

`SchoolBotAssessment` เพิ่ม `EarnedScore:numeric(18,6)?` และ `MaxScore:numeric(18,6)?` โดยต้อง `null` พร้อมกัน หรือ `0 <= EarnedScore <= MaxScore` และ `MaxScore > 0`; ค่าคะแนนตัวเลขต้องมาจาก numeric rubric/evaluator ที่ได้รับอนุมัติเท่านั้น ผลประเมินเดิมที่มีเฉพาะ `Outcome` (`passed|not_yet`) ยังคงอ่านได้ แต่ใช้เป็นแหล่งส่งคะแนนออกตาม DES-008/009 ไม่ได้

ชุดนี้ประเมิน trace ของ bounded DSL; ไม่อ้างตรวจฟิสิกส์ใน Phaser หากหลักสูตรต้องวัด world/obstacle goals ต้องออก evaluator contract เพิ่มก่อน publish เกณฑ์นั้น
- Question Bank, Attempt และ `ScoringPolicy` ตาม [DES-010](des-010.md)
- การแมพตัวชี้วัด/กิจกรรมกับช่องคะแนนและการส่งคะแนนตาม [DES-008](des-008.md) และ [DES-009](des-009.md)
- การเสนอและยืนยันเลื่อน Level ทั้งห้องตาม [DES-011](des-011.md)

## Grading / transitions / idempotence

Code/Block:
`queued → grading → evaluated` หรือ `error`
Arm:
`awaiting_teacher → evaluated`
การเปิด/ปิดบทเรียนไม่สร้าง submission หรือ passed

Server ตรวจว่า `Mission`/`Criteria`/`Activity`/`Curriculum` เป็น published global content (`SchoolId=null`) และโหลด snapshot จาก `ProjectRevision` ของนักเรียนใน `SchoolId` เดียวกับ session โดยตรวจว่า `Project.Mode` ตรงกับ `Activity.Mode` ของ project activity ที่อ้าง `Mission` นั้น (ไม่ใช้ `Curriculum.Mode`). Server ไม่รับ commands/score ที่ UI อ้าง; Code parse DSL ใหม่; Block compile normalized tree ใหม่ ใช้ bounds เดียวกับ DES-003 และ demo: 1–64 commands, ≤100 steps; ไม่ eval Python/JavaScript

Worker ใช้ durable `GradingJob`+lease; infrastructure รัน trusted bounded evaluator โดยไม่มีสิทธิ์ network/files ของ source นักเรียน ระบบต้องมี golden vectors เทียบ host/server เพื่อกัน semantics ต่างกัน ผล automatic บันทึก evaluator version และ rule results; `passed` และคะแนนตัวเลข (เมื่อมี approved numeric rubric) คำนวณตามเกณฑ์ที่อนุมัติ

Business validation ของโปรแกรมผิดคืน `400 PROGRAM_INVALID` ก่อนรับ submission; infrastructure grader ล้มเหลวเป็น `error` ไม่ใช่ `not_yet` เสนอ retry transient สูงสุด 3 ครั้งด้วย lease เดิม หลังนั้นให้ผู้ดูแล retry โดยไม่สร้าง submission ซ้ำ

Commit `Assessment`, `Submission.CurrentAssessmentId`, `GradingJob` และ audit ใน School DB transaction เดียว; unique submission/job/result ป้องกันผลซ้ำ เมื่อ response สูญหายใช้ `Idempotency-Key` เดิม

Arm ไม่ใช้ telemetry/write/timer เป็นผ่าน ครูตรวจผ่านหน้าเว็บใน `web-system` (`Channel=school_web`) เลือก `outcome` พร้อม `feedback` และ `rule_results` ครบ rubric; `AssessorId` มาจาก auth การแก้ผลสร้าง `Assessment` sequence ใหม่พร้อม `supersedes_id` และเหตุผล ไม่ overwrite ผลเก่า

Progress derive จากผลล่าสุดของแต่ละ activity/mission revision แสดง `awaiting_teacher`/`error` แยกจาก `passed` มี history ให้ตรวจย้อนกลับ ไม่รวมดาว/คะแนนหรือ carry-forward ต่าง revision โดยอัตโนมัติ

## Offline / Guest / errors

เสนอ signed published content bundle สำหรับ local lessons; local Code/Block result ระบุ `authority:"local"` ไม่เป็น Cloud assessment จน server ตรวจ snapshot ใหม่

การนำเข้าโครงงานและตรวจผลใหม่ของ Guest เมื่อ login ใช้สัญญาตาม REQ-040–042 และ DES-003/004 โดยไม่ผูก Guest กับนักเรียนอัตโนมัติโดยเดา

Errors: `403 FORBIDDEN, CHANNEL_NOT_ALLOWED, STAFF_ROLE_REQUIRED, SUBJECT_PERMISSION_REQUIRED`; `409 CONTENT_NOT_PUBLISHED, CRITERIA_NOT_APPROVED, FOUR_EYES_REQUIRED, ASSESSMENT_METHOD_MISMATCH, STATE_CONFLICT`; `412 VERSION_CONFLICT`; `503 GRADER_UNAVAILABLE`

## ทางเลือกและการตรวจ

เลือก global immutable curriculum (`SchoolId=null`) + แยก `Mode` ไปไว้ที่ `Activity` + server grading + four-eyes publish; ปัดตก client stars, run-success=passed, การผูก `Curriculum` กับโหมดเดียว และการแก้เกณฑ์ย้อนหลัง ทดสอบตัวอย่างผ่าน/ไม่ผ่านที่เจ้าของเนื้อหาให้, การนำเข้า Sheet เป็นร่าง, ผู้สร้างกด publish เองถูกปฏิเสธ (`FOUR_EYES_REQUIRED`), queue restart, duplicated submit, ครูสองคนตรวจชนกัน และ isolation ตาม AC-037–039 และ AC-043–045 ทุกข้อ
