## สรุปปัญหาจากข้อเท็จจริง

1. SchoolBot ต้องรู้ตัวตน/โรงเรียนจาก token ที่ตรวจได้ โดยไม่รับ school/user จาก client
2. token เว็บ revoke ไม่ได้ บางใบไม่มี exp และรับ handoff token ได้ถ้าตรวจแบบเดียวกับ gateway
3. การแชร์ HMAC key = ผู้ถือ key ปลอม token ใช้ได้ทั้ง SchoolBright ทุกโรงเรียน
4. DES-004 session ผูก DeviceJkt/License ใช้กับเว็บไม่ได้
5. ต้องแยกสิทธิ์ admin โรงเรียน / ครูรายวิชา / พนักงาน SchoolBright / นักเรียน Desktop

## ข้อเสนอ: C — token exchange + gateway introspection

### Flow หน้าครู/admin โรงเรียน (web-system)

1. browser → `POST /api/school-bot/v2/auth/web-sessions` (BFF) พร้อม header
   จาก `webSessionAuthHeaders()` และ body `{channel:"school_web"}`
2. BFF (route ใหม่ `src/app/api/school-bot/[...path]/route.ts`, upstream `schoolBot`,
   env `SCHOOL_BOT_API_URL` origin เท่านั้น) forward ไป SchoolBot
3. SchoolBot เรียก gateway introspection โดยส่ง header JabjaiWebKey เดิม
4. SchoolBot resolve ตัวตน/สิทธิ์จาก DB เดิม แล้วสร้าง SchoolBotSession channel school_web
5. browser เก็บ SchoolBot token ใน Zustand store แบบ memory เท่านั้น (ไม่ persist)
   แล้วเรียก `/api/school-bot/v2/*` ด้วย `Authorization: Bearer <token>`
6. ได้ 401 SESSION_EXPIRED → แลกใหม่หนึ่งครั้ง (token เว็บยังอยู่) แล้วส่งคำขอเดิมซ้ำ
   ด้วย Idempotency-Key เดิม

BFF forward เฉพาะ Authorization, JabjaiWebKey-* (เฉพาะ path web-sessions),
X-Request-Id, Idempotency-Key, If-Match, Content-Type, x-lang; ไม่ forward Cookie/Origin/Referer
(ต้องตรวจพฤติกรรม createUpstreamProxy ก่อน build)

### Gateway introspection — ขอเพิ่มใน G (ต้องอนุมัติ)

GET /api/school-bot/auth/web-principal
- authenticate ด้วย scheme `JabjaiWebLegacy` อย่างเดียว (ระบุ AuthenticationSchemes
  ตรง ไม่ใช้ SmartScheme เพราะ Bearer/X-Api-Key มาก่อน JabjaiWebKey)
- ปฏิเสธ token ที่มี claim `purpose` หรือ `aud` (handoff) → 401
- rate limit แบ่งตาม claim (school,user) ไม่ใช่ IP; Cache-Control no-store; ไม่ log token/claims
- 200 {school_id:I,user_id:I|null,admin_id:T64|null,is_admin:B,
  user_type:T16|null,expires_at:D|null}
- เปิดเฉพาะเครือข่ายภายใน SchoolBot → gateway (สมมติฐาน — deployment ยังไม่ยืนยัน)

### SchoolBot exchange

POST /v2/auth/web-sessions
header: JabjaiWebKey-*: <token>; body {channel:"school_web"|"staff_admin"}
ไม่ใช้ Idempotency-Key/raw response cache (ข้อยกเว้นเดียวกับ login ใน DES-004)

Cache-Control: no-store

ขั้นตรวจ (fail closed ทุกข้อ):
1. introspection สำเร็จภายใน timeout 3 วินาที (ข้อเสนอ) ไม่งั้น 503 AUTH_UNAVAILABLE

3. token ไม่มี exp: ปฏิเสธ 401 จนกว่ามนุษย์ตัดสิน (ประตู H2)

6. channel school_web: (ข้อเสนอ รออนุมัติ H7) โรงเรียนต้องมี SchoolBot License active
7. channel staff_admin: ต้องมี SchoolBotStaffRole active ของ (school_id, user_id)

school_id:S,profile:P|null,legacy_admin:B,expires_at:D,version:N}

### CORS / origin

- SchoolBot ไม่ส่ง Access-Control-Allow-* (ไม่มี CORS) → browser เรียกข้าม origin ไม่ได้
- request ที่มี header Origin ถูกปฏิเสธ 403 ORIGIN_NOT_ALLOWED เว้นแต่อยู่ใน allow-list
  (ค่าเริ่มว่าง); BFF ทั้งสองฝั่งต้องไม่ forward Origin; Desktop (Go host) ไม่ส่ง Origin
- `/v2/auth/web-sessions` และ `/v2/admin/*` เปิดเฉพาะเครือข่ายจาก pod ของ web-system/admin web
  ที่ ingress (defense-in-depth; สมมติฐาน deployment)

### CSRF

- web-system: ใช้ Bearer ใน header และไม่มี cookie ของ SchoolBot → ไม่มี ambient credential
- admin web: cookie SameSite=Strict + ตรวจ Origin = origin ของ admin ใน route handler/server action
  + mutation ต้องมี Idempotency-Key header (ฟอร์มข้ามเว็บตั้ง header ไม่ได้)
- token เว็บใน localStorage เสี่ยง XSS อยู่เดิม (auth-headers.ts:10–13) จึงไม่เก็บ SchoolBot token
  ลง storage

### อายุ token / revocation

| channel | อายุ (ข้อเสนอ) | refresh |
|---|---|---|
| school_web | 30 นาที absolute และไม่เกิน exp ของ token เว็บ | ไม่มี; แลกใหม่เงียบ ๆ |
| staff_admin | 8 ชม. absolute และไม่เกิน exp ของ token เว็บ | ไม่มี; login ใหม่ |
| desktop | 8 ชม. ตาม DES-004 | ไม่มี |

- เก็บ SHA-256 ของ token ใน SchoolBotSession; raw token ส่งครั้งเดียว (DES-004)
- revoke: logout; web-system เรียก logout แบบ best-effort ตอน logout/notifySessionExpired;
  staff_admin revoke ตามผู้ใช้; ถอนสิทธิ์/role/พนักงานพ้นสภาพมีผลตั้งแต่ request ถัดไป
- token เว็บเดิม revoke ไม่ได้ (session token ไม่มี jti) — SchoolBot จำกัดผลกระทบด้วยอายุสั้น
  และการ resolve สิทธิ์ใหม่ทุก request

### ทางสำรอง D (ใช้เมื่อ H1 ไม่อนุมัติ gateway endpoint)

SchoolBot ตรวจ HS256 ด้วย LegacyWebJwt:Secret เฉพาะตอนแลก ด้วยกฎเดียวกับ introspection
(ปฏิเสธ purpose/aud, exp ตาม H2, ไม่เชื่อชื่อ header); secret อยู่ secret store ของ SchoolBot
ต้องมีหนังสือรับความเสี่ยง Important (แชร์ signing key) และแผน rotation ร่วมกับ gateway/เว็บเดิม

## สิ่งที่ต้องมนุษย์อนุมัติ

- H1 เลือกทาง C และให้เจ้าของ G เพิ่ม `GET /api/school-bot/auth/web-principal`
- H2 token ที่ไม่มี exp (bypassgarde): ปฏิเสธ (ผู้ใช้ต้อง login ผ่าน gateway) หรือรับความเสี่ยงเป็นลายลักษณ์อักษร
- H3 นิยาม "admin โรงเรียน": IsAdmin=1 / Modify บน ScoreRecordSettings / เมนูใหม่เฉพาะ SchoolBot (ต้องเพิ่มข้อมูลเมนู)
- H4 schema: SchoolBotSession (channel ฯลฯ), SchoolBotStaffRole, CourseRun.PlanCourseIds → DBA
- H5 env/route ใหม่ใน W (R0 ของ repo) และ network/ingress ของ SchoolBot ↔ gateway
- H6 four-eyes ของการ publish และรายชื่อ staff_admin ตั้งต้น
- H7 ให้ session school_web ต้องมี SchoolBot License active ของโรงเรียนหรือไม่
- H8 breaking: `/v1/admin` static bearer → `/v2/admin` staff session
