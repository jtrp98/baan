## Ownership, Placement และ Concurrency

- ตารางทั้งหมด (`SchoolBotQuestionBank`, `SchoolBotCourseRun`, `SchoolBotScoringPolicy`, `SchoolBotCourseRunActivity`, `SchoolBotAttempt`, `SchoolBotRetakeGrant`) อยู่บน **SchoolBot DB (`10.0.0.128:9499`)** ตาม [decisions-027](../requirement/decisions-027.md)
- SchoolBright ส่วนกลางสร้าง/เผยแพร่ Question Bank และ Activity (`SchoolId=null`) ผ่านหน้า admin (Next.js ใน school-bot/web) ด้วย `staff_admin` session ตาม DES-012: role `content_author` สร้าง/แก้ draft, `content_approver` publish โดย**ต้องผ่านกฎ four-eyes** (ผู้สร้าง/แก้ร่างอนุมัติเองไม่ได้ คืน `409 FOUR_EYES_REQUIRED` ตาม [decisions-025](../requirement/decisions-025.md) และ [decisions-026](../requirement/decisions-026.md))
- ครูรายวิชาของ CourseRun (หน้าใน web-system ช่อง `school_web`) ตั้ง `ScoringPolicy`, ตั้งเวลา/override ของ `CourseRunActivity` และเปิด `RetakeGrant` รายคนได้ โดยต้องอ่านและ **re-check สิทธิ์ครูรายวิชาจาก School DB ผ่าน connection แยกด้วยบัญชี DB เดิม ([decisions-029](../requirement/decisions-029.md)) ณ จุดก่อน commit ใน SchoolBot DB**
- ไม่มีคอลัมน์ `Version`; การแก้ไขแถวเดิมใช้ `UpdateDate` (`clock_timestamp()`) เป็น opaque `ETag`/`If-Match` ตาม [decisions-030](../requirement/decisions-030.md)
- ใน `SchoolBotScoringPolicy` ถอนคอลัมน์ `CurriculumId` ออกตาม [db/review-005.md](../db/review-005.md) เพราะอ่านจาก `SchoolBotCourseRun.CurriculumId` ได้โดยตรง

## Question contract

ชนิดรุ่นแรกตามมติ decisions-024: `single_choice | boolean`; ชนิดอื่นตอบ `409 QUESTION_KIND_UNSUPPORTED`

Question={
question_key:U,kind:QuestionKind,prompt:Text,
options:[{option_key:U,text:Text}],
correct_option_keys:U[],max_score:DecimalString
}

single_choice มีตัวเลือก ≥2 และเฉลยหนึ่งตัว; boolean มีตัวเลือกสองตัวและเฉลยหนึ่งตัว; IDs ไม่ซ้ำ; correct keys ต้องอยู่ใน options; max_score > 0; ตอบถูกได้ max_score ตอบผิด/ไม่ตอบได้ 0
PublicQuestion ตัด `correct_option_keys` ออก ไม่คืนเฉลยก่อนเวลาที่ policy อนุญาต และไม่รับ earned/score จาก client

## Activity และ policy

quiz/test อยู่ที่ Activity (`Config={kind:"question-v1",bank_id:K,question_keys:U[],default_policy:AssessmentPolicy}`)
AssessmentPolicy={max_attempts:N|null,selection:best|first|latest,time_limit_seconds:integer>=1|null,reveal:after_submit|after_close,shuffle_questions:B,shuffle_options:B}

ค่าเริ่มต้นเมื่อสร้าง Activity (decisions-024):
- quiz: `{max_attempts:null, selection:"best", time_limit_seconds:null, reveal:"after_submit", shuffle_questions:false, shuffle_options:false}`
- test: `{max_attempts:1, selection:"first", time_limit_seconds:<ต้องตั้งต่อ test>, reveal:"after_close", shuffle_questions:true, shuffle_options:false}` (test ไม่ตั้ง `time_limit_seconds` publish ไม่ได้)

CourseRunActivity (ต่อห้อง) = `{course_run_id, activity_id, opens_at:D|null, closes_at:D|null, policy_override:AssessmentPolicy|null}`; ครูเปลี่ยนเฉพาะ time_limit_seconds และ opens_at/closes_at; field อื่นต้องเท่าค่าส่วนกลาง มิฉะนั้น 403 POLICY_OVERRIDE_NOT_ALLOWED; ตรวจ window ตาม [กฎผลเรียน](learning-rules-032-034.md)

ScoringPolicy (ต่อ CourseRun, REQ-047) = `{quiz_counts:B, activity_weights:[{activity_id:K,weight_bps:0..10000}], formula_version:T64|null}`
`quiz_counts=false` บังคับน้ำหนัก quiz เป็น 0 และใช้ส่งคะแนนไม่ได้; น้ำหนักรวม 10000; ใช้ weighted-normalized-v1 และ freeze CurrentPolicyId เมื่อเริ่ม CourseRun ตาม [กฎผลเรียน](learning-rules-032-034.md); NULL คือร่างเปิดรอบไม่ได้ ไม่ใช่รอมติ

## สอบซ่อม (retake — ยืนยันตาม decisions-025/026)

ครูรายวิชาเปิดสอบซ่อมรายคนได้ (`SchoolBotRetakeGrant`): 1 ใบ = สิทธิ์เพิ่ม 1 attempt เกิน `max_attempts` สำหรับนักเรียน/กิจกรรมนั้น
**ผลที่ใช้หลังสอบซ่อม (ยืนยันตาม [decisions-025](../requirement/decisions-025.md) และ [decisions-026](../requirement/decisions-026.md))**: การสอบซ่อม Test ใช้**คะแนนสูงสุด (`best`) ระหว่างครั้งจริงกับครั้งสอบซ่อม โดยไม่มีเพดานคะแนน**

## Transactions, Tenant Check และผลลัพธ์

- ฐานปัจจุบันในschoolbot_db.sqlคงเฉพาะPK ไม่มีSQL FK/UQ/CHECK; applicationต้องserializeความสัมพันธ์/ความไม่ซ้ำ/state/boundsด้วยtransactionlocksและตรวจเอง:
  1. ชั้น application ต้องตรวจว่า `CourseRun`, `ScoringPolicy`, `CourseRunActivity`, `Attempt`, `RetakeGrant` อยู่ `SchoolId` เดียวกับ session และ `Activity` อยู่ใน `CourseRun.CurriculumId`
  2. ก่อนสร้าง `Attempt` ต้อง re-check จาก **School DB** ว่านักเรียน (`P=student`, `LearnerId=sId`) อยู่ในห้องเรียน (`ClassroomId`/`NYear`/`NTerm`) ของ `CourseRun` จริง แล้วจึงเปิด **SchoolBot DB transaction** ล็อก counter/แถวของผู้เรียนสำหรับ `(SchoolId, CourseRunId, ActivityId, LearnerId)` เพื่อคำนวณ `Sequence` ถัดไป, ตรวจเพดาน `max_attempts` (และผูก `ConsumedAttemptId` ของ `SchoolBotRetakeGrant` หากเป็นการใช้สิทธิ์สอบซ่อม)
- ตอน `submit` ทำ validate/evaluate/freeze answers/result (`UpdateDate = clock_timestamp()`)/audit/idempotency ใน **SchoolBot DB transaction เดียว**

## Amendment 076 — 2026-10-26

อ้าง decisions-042:11–16 และ REQ-046 BR/AC-046-07; มี precedence เฉพาะผลหมดเวลา:
- ปิดด้วย state `expired` เดิม ตรวจอัตโนมัติจากคำตอบที่ server รับและบันทึกทันเวลา แม้ไม่กด submit; ข้อว่างได้ 0 ใช้คะแนนเต็มทั้งชุดตาม snapshot ไม่มีคำตอบได้ 0/เต็มทั้งชุด ไม่รับคำตอบย้อนหลัง
- นับครั้งตาม max_attempts/Sequence และใช้ RetakeGrant เดิมหากเป็นรอบซ่อม ไม่คืนสิทธิ์เพราะไม่กดส่ง และไม่ consume ซ้ำตอน finalize
- Mutation answers/submit หลังหมดเวลาไม่รับ answers เพิ่ม; mapping ใช้ `409 ATTEMPT_EXPIRED` เดิม ส่วน GET อ่าน outcome ได้ตามสิทธิ์เดิม ไม่ปฏิเสธการอ่านเพียงเพราะ expired; feedback/เฉลยยังขึ้นกับ reveal ของ snapshot ไม่เปิดทันทีเพราะหมดเวลา
- ผล expired ที่ตรวจเสร็จเข้า selection ตาม [กฎผลเรียน](learning-rules-032-034.md); Test ครั้งจริง/ซ่อมใช้ best ไม่มีเพดานลดคะแนน

หลักฐาน contract: dictionary/table-024.md:26–33, contract-002.md:34 และ contract-003.md:21,39–43 มี state/คะแนน/snapshot เดิม; ร่าง SQL ตาราง SchoolBotAttempt ใน ../db/schoolbot_db.sql อนุญาต expired กับ EarnedScore numeric(18,6) และ MaxScore เดิม จึงไม่เสนอ field/table/state/API ใหม่ ไม่ใช่หลักฐาน schema/runtime acceptance

As-built ที่อ่านจริง: target/school-bot/web/src/SchoolBot.Api/Program.cs:42–47,94–129 มี TimeProvider, management memory store และ logout แต่ไม่พบ Attempt route ในไฟล์นี้; ไม่ยืนยันว่ามี clock/finalizer/worker/transaction ของ expired แล้ว

รายละเอียดเทคนิคยัง PROPOSED และต้องตรึง/พิสูจน์: clock และขอบเส้นตาย, save/submit/expiry race, idempotent finalization, crash/retry/recovery, read ระหว่างยัง finalize ไม่เสร็จ และ reveal mapping; ไม่เลือกกลไกใหม่ใน amendment นี้ ไม่ใช้ NULL เป็นคะแนน 0 ที่ตรวจแล้ว

ทางเลือกที่ไม่ใช้: ไม่มีคะแนนเมื่อ expired ขัดมติ A; บังคับเปลี่ยนเป็น submitted หรือเพิ่ม storage ไม่จำเป็นต่อมตินี้
