## ปัญหาที่ร่างนี้แก้

ผู้ใช้ไม่มีทางรู้ว่าการวาง/สลับด้วยมือทำให้ออกห่างจากเป้าหมายระดับที่ตั้ง — เป้าหมายเป็น soft (ไม่ปฏิเสธ) จึงต้องแจ้งแบบไม่บล็อก ไม่เช่นนั้นระดับที่ตั้งจะรู้สึก "ไม่มีผล" (D12/R6)

## ขอบเขต

- รูปแบบ + ข้อความของคำเตือนหลังวาง/สลับ/ย้าย/ลบด้วยมือสำเร็จที่ทำให้ (ห้องเรียน, วัน) **เพิ่งกลายเป็น** ขัดเป้าหมายระดับ L ปัจจุบันของตาราง
- ช่องทางแสดงผล: toast ระบบเดิม (`react-hot-toast` position `top-right` ที่ `DashboardLayout` ติดตั้งไว้) แบบ warning

## ไม่อยู่ในขอบเขต

- การปฏิเสธ/ย้อนการวาง/เปลี่ยนกริด/บล็อกการบันทึก — **ห้ามทุกกรณี** (BR-80, AC-054)
- การกำหนดค่าเกณฑ์ — UX ไม่กำหนด: เกณฑ์คือ T_c = ⌈H_c / D_c⌉ ต่อห้องเรียนตาม BR-81a (ยืนยัน 2026-09-30) อ่านจาก config/ฟังก์ชันจุดเดียวของ FE-003

## ข้อกำหนด UI

- ทริกเกอร์ (ตาม design Rev 13 BR-80/BR-81a): หลังการ **วาง / สลับ / ย้าย / ลบ** ด้วยมือแต่ละครั้งที่ **สำเร็จ** ระบบคำนวณ T_c ใหม่ **ต่อห้องเรียน จากกริดปัจจุบัน** แล้วเทียบชุด (ห้องเรียน, วัน) ที่ละเมิด **ก่อน** กับ **หลัง** การแก้ครั้งนั้น:
  - เตือน **เฉพาะคู่ที่เพิ่งกลายเป็นละเมิด** (ละเมิดหลัง แต่ไม่ละเมิดก่อน) — รวมคู่ที่ "ตกเกณฑ์" เพราะ **T_c ลดลงหลังการแก้** (อาจเป็นห้อง/วันอื่นที่ไม่ได้ถูกแตะโดยตรง เช่น หลังลบคาบหนักทำให้ H_c ลดและ T_c ลด) — **ห้ามจำกัดเฉพาะห้อง/วันที่ถูกวางหรือลบ**
  - คู่ที่ละเมิดอยู่แล้วก่อนการแก้ **ไม่เตือนซ้ำ**
  - **L = 0: ไม่เตือนเลย** (ไม่มีเป้าหมาย) — ไม่มี toast ไม่มีข้อความ
  - **L = 1:** ละเมิด = `HeavyDayOverThreshold` (`nHeavy > T_c` ของห้องนั้น)
  - **L = 2:** ละเมิด = `HeavyDayOverThreshold` **หรือ** `ConsecutiveHeavy` (วิชาหนักติดกันในวันเดียวตาม BR-79 — คอลัมน์พัก/ช่องว่างตัดความต่อเนื่อง)
  - ห้องเรียนที่ H_c = 0 หรือ D_c = 0: ไม่มี `HeavyDayOverThreshold` (BR-81a)
  - UI ห้ามคำนวณสูตรเอง — เรียกฟังก์ชัน T_c/ตรวจละเมิดตัวเดียวกับ solver และสรุป (BR-81a Rev 13)
- การแสดง: toast warning 1 ชิ้นต่อการแก้ที่สำเร็จ (ไม่ทบต้น; ไม่มีคู่ใหม่ = ไม่มี toast) · หายเองหรือปิดเองได้ · **ไม่มี modal ไม่มี confirm** · ถ้ามีหลายคู่ใหม่: แสดงเป็นรายการใน toast เดียว **สูงสุด 3 คู่ แล้ว "และอีก {k} คู่"** / EN "and {k} more" (ผู้ใช้ตัดสิน 2026-09-30)
- ข้อความ — คำนำ **"แก้ไขตารางสำเร็จ"** (TH, ผู้ใช้ตัดสิน) / **"Timetable edited"** (EN — เลี่ยงคำว่า saved เพราะไม่ใช่การบันทึกตาราง) เพราะทริกเกอร์รวมการลบ/ย้าย และคู่ที่เตือนอาจไม่ใช่ช่องที่แก้ · ถ้อยคำส่วนที่เหลือเป็นข้อเสนอรอเซ็น:
  - `HeavyDayOverThreshold` — TH: "แก้ไขตารางสำเร็จ แต่ {sClassName} วัน{day} มีวิชาหนัก {n} คาบ เกินเป้าหมายระดับที่ตั้งไว้ ({T_c} คาบ)" · EN: "Timetable edited, but {sClassName} on {day} now has {n} heavy periods — above the set level's goal ({T_c})."
  - `ConsecutiveHeavy` (L = 2 เท่านั้น — **ไม่แสดงค่าเกณฑ์**, `nThreshold = null`) — TH: "แก้ไขตารางสำเร็จ แต่ {sClassName} วัน{day} มีวิชาหนักติดกัน" · EN: "Timetable edited, but {sClassName} on {day} now has consecutive heavy periods."
  - ถ้าการแก้ครั้งเดียวทำให้เกิดหลายคู่/สองชนิด: toast เดียว คำนำใช้ครั้งเดียวต้นข้อความ แล้วตามด้วยรายการคู่ (สูงสุด 3 + "และอีก {k} คู่")
- Accessibility: toast เป็น `role="status"` (`aria-live="polite"`) — ไม่ขโมย focus จากกริด · ต้องไม่ใช้สีอย่างเดียวสื่อระดับเตือน (มีไอคอน + ข้อความ) · อยู่นานพอให้อ่าน (ข้อเสนอ ≥ 6 วินาที หรือปิดเองได้) — ผู้ใช้เป้าหมายอายุ 30–60 ถนัดเทคโนโลยีกลาง–ต่ำ
- ชื่อวันแสดงตาม locale เดิมของกริด (คีย์ภายในภาษาอังกฤษ REQ-004)
- ต้องเปิด/ปิดผ่านค่า config เดียวกับเพดานของ solver (BR-78) — ห้าม hardcode เกณฑ์ใน UI
