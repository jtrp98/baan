## User Flow

1. **การตั้งค่าคาบต่อเนื่องและกลุ่มวิชา (`/timetable/subject-settings`):**
   - ผู้ใช้เปิดหน้า "เงื่อนไขวิชา" (Subject Settings)
   - แถบ "คาบต่อเนื่อง" (Class Continuity):
     - กำหนดรหัสวิชาและจำนวนคาบต่อเนื่อง N; N ≤ 1 ไม่มีข้อบังคับตาม BR-32 ไม่สร้าง validation ใหม่
     - หากจำนวนคาบ/สัปดาห์ไม่ลงตัวกับ \(N\) หรือ \(N\) เกินจำนวนคาบเรียนติดกันสูงสุดของวัน แสดง Warning ตอนบันทึกตาม BR-53; การเตือนทันทีระหว่างพิมพ์ยังไม่อยู่ในสัญญา
   - แถบ "กลุ่มวิชา" (Subject Groups):
     - กำหนดชื่อกลุ่มและเลือกวิชา; กลุ่มที่มีน้อยกว่า 2 รหัสไม่มีผลตาม BR-62 — ไม่สร้าง minimum-count validation ใหม่
     - มี Tooltip อธิบายชัดเจน: "วิชาต่างรหัสในกลุ่มเดียวกันไม่จัดชนเวลาข้ามห้องเรียน; รหัสเดียวกันชนเมื่อครูคนเดียวกันหรือไม่ทราบครู โดยตำแหน่ง Link Subject ที่ตรึงไว้คงเดิมพร้อมคำเตือน" (copy ที่อนุมัติ ให้ตรง G2)
   - กดบันทึก: ระบบ serialize เป็น object `{continuityRows, subjectGroups}`

2. **การแสดงผลและการปฏิเสธในหน้าจัดตารางสอน (`/timetable/manage-teaching-schedule`):**
   - **การวางเป็นบล็อก (Block Placement & Visual):**
     - เซลล์ที่อยู่ในบล็อกต่อเนื่อง \(N\) คาบ จะแสดงเส้นขอบเชื่อมโยง (border/badge บ่งบอกบล็อก เช่น "1/2", "2/2" หรือเชื่อมพื้นหลัง)
   - **การลบ (Block Deletion — AC-037c):**
     - เมื่อผู้ใช้กดปุ่มลบที่เซลล์ใดเซลล์หนึ่งในบล็อกต่อเนื่อง ระบบจะลบออกทั้งบล็อกพร้อมกัน (ไม่มีคำสั่งลบทีละช่องย่อย)
   - **การย้าย/สลับ (Drag & Drop / Swap — AC-037):**
     - ผู้ใช้ลากบล็อกไปวางในตำแหน่งใหม่: หากปลายทางมีช่องว่างไม่ครบ \(N\) คาบติดกัน หรือมีคาบพักคั่น ระบบจะปฏิเสธพร้อม Modal/Toast `continuityBroken`
   - **การชนกันของกลุ่มวิชา (Subject Group Overlap — AC-037 / DES-017):**
     - หากวางวิชาที่อยู่ในกลุ่มเดียวกันซ้อนกับห้องอื่นในช่วงเวลาเดียวกัน (รหัสต่างกันชนเสมอ; ข้อยกเว้นครูต่างกันใช้เฉพาะรหัสเดียวกัน — BR-64) ระบบปฏิเสธพร้อมข้อความ `subjectGroupOverlap`

3. **คำเตือนก่อนจัดตาราง (Generate Precheck / Warnings):**
   - ใน Precheck หรือรายการคำเตือนหลังจัดตาราง จะแสดงคำเตือน (ไม่บล็อก) หากพบกรณี:
     - `ContinuityQuotaNotDivisible`: โควตาไม่ลงตัวกับ \(N\)
     - `ContinuityExceedsTeacherCap`: เพดานคาบสอนต่อเนื่องของครูต่ำกว่า \(N\)
     - `SubjectGroupPinnedConflict`: วิชาในกลุ่มถูกตรึงด้วย Link Subject จนเกิดการชน

## Layout & Interaction

- **Subject Settings Table:**
  - เพิ่มคอลัมน์และ input ควบคุม \(N\) (จำนวนคาบต่อเนื่อง) และ modal จัดการกลุ่มวิชา
- **Timetable Grid:**
  - เซลล์ที่เป็นบล็อกต่อเนื่องมีตัวบ่งชี้ภาพชัดเจน
  - Drag interaction: เมื่อเริ่มลากเซลล์ในบล็อก ระบบจะ highlight และลากทั้ง \(N\) ช่องเป็นยูนิตเดียวกัน พร้อม ghost preview \(N\) ช่องก่อนวาง (ผู้ใช้เลือกข้อ ก วันที่ 2026-10-11)
  - Confirmation Modal: เมื่อกดลบเซลล์ จะมีข้อความระบุว่า "การลบจะนำวิชาออกทั้งบล็อก ({n} คาบ)"

## Accessibility

- รองรับการลบและย้ายด้วยคีย์บอร์ด
- เซลล์ในบล็อกต่อเนื่องมี `aria-label` เช่น `วิชาคณิตศาสตร์ คาบต่อเนื่อง 1 จาก 2`
- Modal แจ้งเตือนข้อผิดพลาดมี `role="alertdialog"` และ focus ถูกดักจับไว้ที่ปุ่มปิด
- ต้องตรวจ contrast ของเส้นขอบและตัวบ่งชี้ตาม WCAG 2.2 AA (≥ 3:1 สำหรับ UI components); ยังไม่ได้วัดจริง

### รายละเอียดประกอบ flow / states (อนุมัติทั้งฉบับ 2026-10-11)

- AC-036/037: บล็อกครบ N ช่องเรียนลำดับถัดกันตาม columnMetas ในวันเดียวกัน ไม่มีคอลัมน์พัก/lunch คั่น; ช่องว่างเวลาเปลี่ยนคาบที่ template ไม่ประกาศเป็นคอลัมน์พักยังนับเป็นต่อเนื่องตาม DES-012 BR-29. ย้าย/สลับสำเร็จต่อเมื่อผลทั้งสองฝั่งผ่านกติกาทั้งบล็อก; ไม่สำเร็จคงกริดเดิมและคืน focus จุดเริ่ม. ล็อก/ปลดล็อกช่องใด = ทั้งบล็อก; Regenerate เก็บ/ล้างทั้งบล็อก (BR-31). ลบจากช่องใดแสดงยืนยันทั้ง N คาบตามข้อเสนอเดิม; cancel คงกริด.
- AC-037a/b: โควตาไม่ลงตัวแสดงคำเตือนให้แก้โควตาหรือ N; Generate ยังไม่บล็อกด้วยเหตุนี้ วางเฉพาะบล็อกเต็ม ส่วนเหลือ shortfall. เพดานครูชนะเสมอ: รวมเวลาสอนติดกับบล็อกแล้วเกินเพดาน → ไม่วางทั้งบล็อก ไม่หด N.
- G2: เทียบทุกห้องในตารางปัจจุบันกับตารางอื่นใน conflict scope S1 รวม legacy NULL ตาม DES-009; ไม่รวม `/academic`. รหัสเดียวกันและไม่ทราบครูถือว่าชน พร้อมบอกเหตุ. link กลุ่มเดียวกันนับเป็นการวางเดียว; Link Subject ตรึงชนะและเตือน ไม่ปลด link อัตโนมัติ. ตารางเดิมเป็น snapshot ไม่ revalidate ทั้งตารางเพียงเพราะเปิดหน้า.
- VR-17 ตอน Submit: name ว่าง/ซ้ำ หรือ courseCodes ไม่ใช่ array string → ไม่ส่ง save, แสดง error รวมและชี้ field. Legacy array อ่านได้; writer คง continuityRows/subjectGroups ครบใน object ใหม่. ไม่สร้าง server validator.

วันที่ร่างจากผู้ใช้ 2026-10-11 · อ้าง DES-012 §37.2a และคำตอบ jtrp98 “ส่งผลคำเตือนผ่าน API กติกาวิชา (แนะนำ)”. ฐาน signed เรื่องบล็อก/ลาก/ย้าย/สลับ/ลบ/ล็อกและคำเตือนเดิมคงคำอนุมัติเดิม; การร่างส่วนนี้ไม่ขยาย sign-off เดิม.

**Flow:** โหลดเงื่อนไขวิชาพร้อมผลตรวจจาก API เดิม. เมื่อบันทึกสำเร็จ แสดงผลตรวจของค่าที่เพิ่งบันทึก พร้อมคำเตือนที่ตรวจพบ. การตรวจได้บางส่วน/ตรวจไม่ได้ไม่เปลี่ยนการบันทึกสำเร็จเป็นผิดพลาด และไม่เพิ่มเงื่อนไขบล็อก Save/Generate. ใช้กติกาบล็อก Generate เดิม. ไม่ร้องขอข้อมูลเพดานครูผ่าน Setting/Get.

| State | Copy ที่เสนอ | พฤติกรรม |
|---|---|---|
| กำลังโหลด/บันทึก | ใช้ spinner และข้อความโหลด/บันทึกเดิม | ระหว่างรอไม่อ้างว่าผลเตือนว่างคือไม่มีปัญหา; การบันทึกสำเร็จต้องมาจาก response ของการบันทึกจริง |

| บันทึกแล้ว + `unavailable` | “บันทึกเงื่อนไขวิชาแล้ว แต่ยังตรวจคำเตือนเพดานสอนต่อเนื่องของครูไม่ได้ กรุณาโหลดหน้าใหม่เพื่อตรวจอีกครั้ง ไม่ต้องบันทึกซ้ำ” | คงข้อมูลที่บันทึกแล้ว; แสดง warning ในหน้า ไม่แสดง Save failed และไม่บันทึกซ้ำอัตโนมัติ |

| แก้ N หลังผลตรวจล่าสุด | “มีการแก้ไขที่ยังไม่ได้บันทึก ผลตรวจเพดานครูเดิมยังไม่ครอบคลุมค่าที่แก้ไข” | ไม่ใช้ผล GET เก่าเป็นผลตรวจของ N ใหม่; ไม่แสดงผล response ล้าหลังเหนือค่าที่กำลังแก้ และไม่ล้างค่าที่แก้ |

รายการที่ตรวจไม่ได้ใช้ชื่อวิชา/แผน/ห้องจาก catalog ที่อ่านได้อยู่แล้ว; หากไม่พบชื่อใช้รหัสที่ยืนยันได้. เหตุผลแสดงเป็นภาษาผู้ใช้ เช่น “ข้อมูลสำหรับตรวจสิทธิ์ครูยังไม่พร้อม”, “อ่านข้อมูลสำหรับตรวจไม่สำเร็จ”, “ข้อมูลคาบต่อเนื่องหรือเพดานครูผิดรูป”, “ไม่พบวิชาในแผนของเทอมนี้”. ไม่แสดง teacher IDs, ค่าเพดานครู, H1, exception หรือรายละเอียดฐานข้อมูล.

**Layout / interaction:** reuse พื้นที่คำเตือนใต้การตั้งค่ากลุ่มวิชาและ `Alert` เดิม; ข้อความบันทึกสำเร็จแยกจาก warning ผลตรวจไม่ครบ. คำเตือนที่พบและรายการที่ตรวจไม่ได้แสดงครบ ชื่อ/เหตุผล wrap ในจอแคบ. ใช้ typography/tokens/8px spacing/12px radius เดิมตาม DESIGN.md และ School Bright skill; ไม่เพิ่มปุ่มบันทึกซ้ำหรือ flow ซ่อมข้อมูล. โหลดหน้าใหม่เป็นการตรวจข้อมูลที่บันทึกไว้เท่านั้น; ค่าที่กำลังแก้ยังต้องบันทึกก่อนจึงได้รับผลตรวจของค่านั้น.

**Accessibility:** ผลหลังบันทึกและการเปลี่ยนสถานะใช้ live region แบบ polite; เนื้อหาเป็นข้อความและ list ที่มีหัวข้อ “ผลตรวจเพดานสอนต่อเนื่องของครู”, ไม่อาศัยสีอย่างเดียว. คง focus บน action/editor เดิม ไม่ย้าย focus เพียงเพราะได้คำเตือน. Spinner มีชื่อเข้าถึงได้; รายการยาวและข้อความขยายยังอ่านได้. ต้องตรวจ contrast/keyboard/responsive ในงาน FE/reviewer/QA จริงภายหลัง ไม่อ้างว่าร่างเอกสารผ่าน runtime a11y แล้ว.
