## ปัญหาที่ร่างนี้แก้

หลัง Generate เสร็จ ผู้ใช้ไม่เห็นผลใด ๆ นอกจากปุ่มหยุดหมุน — วิชาที่วางไม่ลงผู้ใช้ต้องไล่หาช่องว่างเอง ขัด DES-020 §45.1 "ทุกครั้งที่ Generate/Regenerate จบ ผู้ใช้ต้องเห็นผลเสมอ … ห้ามจบเงียบ"

## ขอบเขต

- แผงผลลัพธ์หลัง Generate/Regenerate จบ บนหน้า `manage-teaching-schedule`
- แสดงร่วม: รายงาน shortfall (DES-020) + สรุปความเข้มข้น (DES-019) ใน **ผลเดียวกัน** (BR-84)
- การเปิดตารางเดิม (Flow D): แสดงเฉพาะ block สรุปความเข้มข้น

## ไม่อยู่ในขอบเขต

- `lstGenerateWarnings` (ของ DES-011 — ยังถูกประตู)
- การตรวจความครบก่อนบันทึก (§32.1 ไม่มี requirement) · การ persist รายงาน (client state เท่านั้น ไม่มี endpoint ใหม่)
- การเปลี่ยนตรรกะ solver / งบ attempt (REQ-008)

## ข้อกำหนด UI

### ตำแหน่งและพฤติกรรม

- แผง "ผลการจัดตารางอัตโนมัติ" ปรากฏด้านล่างแถบเครื่องมือของกริดทันทีที่ Generate จบ (เปิดกางไว้ ปิดได้)
- Regenerate แทนที่ผลเดิมทั้งชุด · การแก้ด้วยมือภายหลัง **ไม่คำนวณรายงานใหม่** (BR-85)
- ทุกสถานะต้องแสดงเวลาของผล `dFinishedAt` (BR-85 "ระบุเวลาของผลในรายงาน") + บรรทัดรอง "จัด {nAttemptsRun} รอบ"

### สถานะของแผง (ครบทุกสถานะ — ห้ามจบเงียบ)

| สถานะ | เงื่อนไข | การแสดงผล |
|---|---|---|
| จัดครบ | `nShortfallTotal = 0` และ `lstShortfall` ว่าง | badge เขียว **"จัดครบ"** (TH) / "All scheduled" (EN) |
| วางไม่ครบ | `lstShortfall` มีรายการ | badge เหลือง/ส้ม **"ยังวางไม่ได้ {nShortfallTotal} คาบ"** / "{nShortfallTotal} periods could not be placed" + ตารางรายการ (ด้านล่าง) |
| ตรวจผลไม่ได้ | exception ระหว่างคำนวณรายงาน | badge แดง **"ตรวจผลการจัดไม่ได้ — กรุณาตรวจกริด"** / "Result could not be verified — please check the grid" — **ห้ามแสดงเป็น "จัดครบ"** (§45.3) |
| Generate ล้มกลางทาง | attempt ไม่ถูก apply | **ไม่แสดงรายงานของ attempt ที่ไม่ถูก apply** (§45.3) — แผงคงสถานะก่อนหน้าหรือแสดงสถานะล้มตาม UX-005 |

### ตารางรายการขาด (lstShortfall)

จัดกลุ่มตามห้องเรียน (`sClassName`) · ภายในห้องเรียง `nMissing` มาก→น้อย (ข้อเสนอ) · คอลัมน์:
วิชา (`sCourseCode` + `sCourseName`) · ต้องการ (`nRequired`) · วางได้ (`nPlaced`) · ขาด (`nMissing`)

- **ห้ามมีคอลัมน์/ข้อความสาเหตุรายคู่** — solver ไม่บันทึก ห้ามแต่ง (BR-84)
- ช่องล็อก/link ที่ seed เข้าโควตานับเป็นวางได้ตาม BR-82 — ไม่มีสัญลักษณ์พิเศษในรายงาน

### หมวดตัดก่อนจัด (lstExcluded — BR-83)

ส่วนแยกหัวข้อ "วิชาที่ระบบไม่ได้ส่งเข้าการจัดอัตโนมัติ" / "Subjects excluded from auto-generation" + คำอธิบายหมวดเดียว (ไม่ระบุรายคู่):
TH "วิชาเหล่านี้ไม่ถูกส่งเข้า AI เพราะไม่พบครูผู้สอนที่มีคุณสมบัติ หรือไม่มีจำนวนคาบกำหนด (โควตาเป็น 0)"
EN "These subjects were not sent to the AI: no qualified teacher found, or zero required periods."

รายการ: `sCourseCode` (+ `nClassID` เมื่อมี) · หมายเหตุกำกับ: หมวดนี้จะว่างโดยโครงสร้างเมื่อ DES-011 (บล็อก Generate) เปิดใช้

### Block สรุปความเข้มข้น (DES-019 AC-055)

- badge ระดับของตาราง: **0 "ไม่กระจาย"** · **1 "พยายามกระจายวิชาหนัก"** · **2 "พยายามกระจาย + ไม่ให้หนักติดกัน"** (ตาม BR-78; ตาราง NULL แสดง 0 — ไม่ backfill)
- ชิปรายวิชาหนักจาก `lstHeavyCourseCodes`
- ตาราง `lstClassDays`: ครบทุกห้องเรียน × ทุกวันที่มีคาบ — คอลัมน์ ห้องเรียน · วัน (`sDay` แสดงตาม locale เดิมของกริด, คีย์ภายในเป็นภาษาอังกฤษตาม REQ-004) · หนัก (`nHeavy`) · เบา (`nLight`)
- สถานะพิเศษแทนตารางเมื่อเกิด: **"ไม่มีวิชาหนักตามสูตร"** / "No heavy subjects by formula" (BR-77 หน่วยกิตเท่ากันทั้งแผน) · **"จำแนกวิชาหนักไม่ได้"** / "Heavy-subject classification unavailable" (fallback เมื่อจำแนกหมวดจาก `TCourseGroup` ไม่ได้ — ห้ามเดา · SA-Q16 ปิดแล้ว หมวดมาจาก `TCourseGroup` จับคู่ `sCourseGroupDescTh` ดิบ; ค่าจริงยังรอตรวจ SA-Q18 จึงคง fallback ไว้)
- ข้อความกำกับ: "ข้อเสนอแนะเท่านั้น — ไม่บล็อกหรือเปลี่ยนกริด" (BR-81)
- Flow D (เปิดตารางที่บันทึกแล้ว): แสดงเฉพาะ block นี้ (รวมส่วนข้อเสนอแนะด้านล่าง) — รายงาน shortfall เป็นภาพ ณ เวลา Generate ไม่ persist

### ส่วนข้อเสนอแนะ (`lstRecommendations` — BR-81 / BR-81a, ยืนยัน 2026-09-30)

เกณฑ์ "หนักเกิน": `nHeavy > T_c` โดย T_c = ⌈H_c / D_c⌉ **ต่อห้องเรียน คำนวณใหม่จากกริดปัจจุบัน** (ไม่ตรึงจากตอน Generate — design Rev 13) ทุกครั้งที่สร้างสรุป รวมตอนเปิดตารางเดิมและหลังการแก้ด้วยมือ · UI แสดงค่าที่ได้ (`nThreshold`) เท่านั้น ห้ามคำนวณเกณฑ์เองใน UI (solver, คำเตือน UX-003 และสรุปเรียกฟังก์ชันเดียวกัน) · `nThreshold` เป็น `number | null`: ค่า T_c เฉพาะ `HeavyDayOverThreshold`, **`null` สำหรับ `ConsecutiveHeavy`**

| สถานะ | เงื่อนไข | การแสดงผล |
|---|---|---|
| ระดับ 0 | `L = 0` (รวม NULL) | **ไม่แสดงส่วนข้อเสนอแนะเลย** — ไม่มีหัวข้อ ไม่มีข้อความ "ไม่มีข้อเสนอแนะ" (ระดับ 0 = ไม่มีเป้าหมาย; `lstRecommendations = []` เป็นไปตามกติกา ไม่ใช่ "ผ่าน") · ตารางหนัก/เบาต่อวันยังแสดงครบ |
| ระดับ 1 มีรายการ | `L = 1` และมี `HeavyDayOverThreshold` | หัวข้อ **"ข้อเสนอแนะ"** + รายการต่อ (ห้องเรียน, วัน): `sClassName` · วัน · "หนัก {nHeavy} คาบ (เพดาน {nThreshold})" · ข้อความ `sSuggestion` |
| ระดับ 1 ว่าง | `L = 1` และ `lstRecommendations` ว่าง | บรรทัดเดียว TH "ไม่มีวันที่วิชาหนักเกินเป้าหมายระดับที่ตั้งไว้" / EN "No day exceeds the set level's heavy-subject goal." |
| ระดับ 2 มีรายการ | `L = 2` | รายการแบบเดียวกัน แต่มีได้ 2 ชนิดต่อ (ห้องเรียน, วัน): `HeavyDayOverThreshold` และ **`ConsecutiveHeavy`** (วิชาหนักติดกันในวัน ตาม BR-79) — จัดกลุ่มตามห้องเรียน แสดงชนิดด้วยป้ายกำกับข้อความ ("หนักเกินเพดาน" / "หนักติดกัน") ไม่ใช้สีอย่างเดียว |
| ระดับ 2 ว่าง | `L = 2` และว่าง | ข้อความเดียวกับ "ระดับ 1 ว่าง" (ปรับ EN/TH ให้ครอบคลุมทั้งเพดานและการติดกัน — ข้อเสนอ: "ไม่มีวันที่เกินเป้าหมายหรือมีวิชาหนักติดกัน") |
| จำแนกไม่ได้ / ไม่มีวิชาหนัก | สถานะพิเศษของ block สรุป | **ไม่แสดงส่วนข้อเสนอแนะ** (ห้ามแสดง "ไม่มีวันเกินเป้าหมาย" ที่อ่านเป็นผ่านทั้งที่ไม่ได้ประเมิน) |

- ถ้อยคำ `sSuggestion` (ข้อเสนอ — งาน UX ตาม BR-81a): `HeavyDayOverThreshold` TH "ย้ายวิชาหนัก {nHeavy − nThreshold} คาบไปวันที่ต่ำกว่า {nThreshold} คาบ" / EN "Move {n} heavy period(s) to a day below {nThreshold}" · `ConsecutiveHeavy` TH "สลับวิชาหนักที่ติดกันกับวิชาเบา" / EN "Swap adjacent heavy periods with light ones"
- ข้อเสนอแนะ **ไม่มีปุ่มแก้อัตโนมัติ/ปุ่มบังคับ** — ไม่บล็อก ไม่เปลี่ยนกริด (BR-81) · เปลี่ยนระดับของตารางแล้วผู้ใช้ต้อง Regenerate/เปิดใหม่จึงเห็นผลตามระดับใหม่ (คำนวณฝั่ง client จากกริดปัจจุบัน ไม่ persist)
- จำนวนรายการยาว: จัดกลุ่มตามห้องเรียน พับ/กางได้ (ข้อเสนอ) — ไม่ truncate ข้อความรายการ ให้ wrap

### สิ่งที่ห้ามแสดง

- ที่ระดับ 0: ห้ามแสดงส่วนข้อเสนอแนะหรือข้อความ "ไม่มีข้อเสนอแนะ" (BR-81a — `lstRecommendations = []` ตามกติกา)
- `ConsecutiveHeavy` ที่ระดับ 1: ห้ามแสดง (เฉพาะ L = 2)
- "ดัชนีเฉลี่ย" — ผู้ใช้ไม่ได้เลือก (BR-81, OQ-30)
