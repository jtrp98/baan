# REQ-017 — เพิ่มคอลัมน์ `stddev_score` ใน `compass_level_subject_stat` (รองรับ T-Score ของ `sb-compass-faculty-match REQ-013`)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `index.md` เท่านั้น

(ยืนยันโดยผู้ใช้ — ส่งต่อผ่าน coordinator relay ในรอบ `business-analyst` นี้, 2026-08-31)

**เหตุผลเชิงธุรกิจ**: `sb-compass-faculty-match REQ-013` ต้องคำนวณ **T-Score** ของคะแนนกลุ่มสาระ
ของเด็กเทียบกับฐานนักเรียนทั้งประเทศ ซึ่งต้องใช้ **ส่วนเบี่ยงเบนมาตรฐานระดับประเทศต่อ
(ระดับชั้น × กลุ่มสาระ)** แต่ตาราง `compass_level_subject_stat` ปัจจุบันเก็บแค่ `mean_score`
ไม่มีค่าเบี่ยงเบนมาตรฐาน — โมดูลนี้ (`sb-compass`) เป็นเจ้าของตารางนี้ จึงต้องมาเปิด requirement
ที่นี่แทน `sb-compass-faculty-match` ที่ไม่มีสิทธิ์แก้ schema ของโมดูลนี้เอง

- **เพิ่มคอลัมน์ `stddev_score`** ในตาราง `compass_level_subject_stat` แบบ **additive เท่านั้น** —
  ไม่แก้/ไม่ลบคอลัมน์เดิม (`mean_score`, `student_count`, `school_count`, `updated_at`, ฯลฯ
  คงเดิมทุกตัว) ไม่กระทบ consumer เดิมที่อ่านแค่ `mean_score` (REQ-004, REQ-005/REQ-006 — แม้
  REQ-005 จะถูกแทนที่แล้วตาม REQ-011 ข้างต้น แต่ตารางนี้ยังใช้ร่วมกับ REQ-004 ที่ยังทำงานอยู่)
- **รูปแบบการคำนวณ: ใช้ pattern เดียวกับ `mean_score` ที่มีอยู่แล้วในโค้ดจริง** — ยืนยันจาก
  `Helper/CompassRankingService.cs` (บรรทัด ~401 `TRUNCATE compass_level_subject_stat` และ
  ~411 `INSERT INTO compass_level_subject_stat (...)`) ว่าปัจจุบัน `mean_score` **ไม่ได้อัปเดตทีละ
  คะแนนแบบ incremental** แต่ถูกคำนวณใหม่ทั้งหมดในรอบ batch เดียวกันของ `recompute/national-stats`
  (REQ-010/REQ-014) แบบ **ล้างตารางทั้งหมดแล้วเขียนใหม่ทุกครั้งที่รัน** — `stddev_score` ต้อง
  คำนวณและเขียนพร้อมกันในรอบ batch เดียวกันนี้ ด้วยพฤติกรรมเดียวกันทุกประการ **ไม่ใช่ backfill
  ครั้งเดียวแยกต่างหาก และไม่ใช่การอัปเดตต่อเนื่องทุกครั้งที่มีคะแนนใหม่เข้ามา** — นี่เป็นข้อสรุป
  จากการอ่านโค้ดจริง ไม่ใช่คำถามที่ต้องรอผู้ใช้ตอบ
- **ผู้ใช้ปัจจุบันของค่านี้คือ `sb-compass-faculty-match REQ-013` เท่านั้น** — `sb-compass` เอง
  ยังไม่มีหน้าจอ/ฟีเจอร์ใดที่ต้องแสดงหรือใช้ `stddev_score` โดยตรงในรอบนี้ ถ้าต้องการในอนาคตต้อง
  กลับมา amend ข้อนี้เพิ่ม
- **ไม่กระทบพฤติกรรมอื่นของ REQ-010** (สถานะ `idle`/`running`/`done`/`failed`, กันสั่งซ้อน,
  โรงเรียนที่คำนวณพลาดไม่ทำให้ทั้ง batch ล้ม) — เพิ่มแค่คอลัมน์และค่าที่คำนวณเพิ่มในรอบเดิม

**ยังไม่ปิด (feasibility — ไม่บล็อกการส่งต่อ)**: สูตร stddev ที่แน่นอน (population stddev หรือ
sample stddev, และวิธีจัดการกลุ่มตัวอย่างเล็ก — REQ-004 ยืนยันแล้วว่าไม่มี minimum sample size
สำหรับ mean แต่ stddev ของกลุ่มตัวอย่าง 1 คนไม่มีความหมายทางสถิติ) **ยังไม่มีคำตอบจากผู้ใช้**
บันทึกเป็น **OQ-14** ให้ `system-analyst` เสนอแนวทางและตรวจ feasibility ก่อน implement จริง

**Acceptance criteria (ทดสอบได้)**
1. (AC-017.1) ตาราง `compass_level_subject_stat` มีคอลัมน์ `stddev_score` เพิ่มแบบ additive เท่านั้น — คอลัมน์เดิมทุกคอลัมน์คงเดิม และ consumer เดิมที่อ่านแค่ `mean_score` (REQ-004) ทำงานเหมือนเดิม
2. (AC-017.2) `stddev_score` ถูกคำนวณและเขียนพร้อมกับ `mean_score` ในรอบ batch `recompute/national-stats` เดียวกัน แบบล้างตารางแล้วเขียนใหม่ทั้งหมดทุกครั้งที่รัน — ไม่ใช่ backfill ครั้งเดียวและไม่ใช่ incremental update
3. (AC-017.3) การเพิ่ม `stddev_score` ไม่กระทบพฤติกรรมเดิมของ REQ-010 (สถานะ `idle`/`running`/`done`/`failed`, กันสั่งซ้อน, โรงเรียนที่คำนวณพลาดไม่ทำให้ทั้ง batch ล้ม)
