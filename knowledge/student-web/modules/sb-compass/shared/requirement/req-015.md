# REQ-015 — ปิดช่องโหว่ `SID` จาก client ให้ครบทุก endpoint (must-fix รอบนี้)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `index.md` เท่านั้น

endpoint กลุ่มแบบฝึกหัด/ใบรับรอง (`CompassApiController.cs` บรรทัด 643, 675, 729 ตามที่ระบุไว้
ก่อนหน้า) ยัง **รับ `SID` จากฝั่ง client โดยตรง** ต่างจาก endpoint หลักที่แก้ไปแล้ว (F3)
ผู้ใช้ยืนยันแล้วว่าต้องแก้ (ยกระดับจาก OQ-03 → requirement)
- ต้องเปลี่ยนไปใช้ **authenticated user ID จาก session** เหมือน REQ-009 ทุกจุด
- **ต้องปิดให้ครบทุกจุด ไม่ใช่แค่จุดเดียว** — เป็นช่องโหว่ค้างที่เปิดให้ดู/ส่งผลของเด็กคนอื่นได้
- ใช้กับ endpoint ใบรับรองด้วย แม้ตัว module ใบรับรองจะแยกไปทำภายหลัง (โค้ด stub อยู่ไฟล์เดียวกัน
  จึงต้องไม่ทิ้งช่องโหว่ค้างไว้)

**Acceptance criteria (ทดสอบได้)**
1. (AC-015.1) endpoint กลุ่มแบบฝึกหัด/ใบรับรองทุกจุด (บรรทัด 643, 675, 729) เปลี่ยนไปใช้ authenticated user ID จาก session เหมือน REQ-009 — ไม่รับ `SID` จาก client อีกต่อไป
2. (AC-015.2) ช่องโหว่ปิดครบทุกจุด รวม endpoint ใบรับรองด้วย — ไม่ทิ้งจุดค้างแม้ตัว module ใบรับรองจะแยกไปทำภายหลัง
