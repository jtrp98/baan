# มติที่ 044 — SQL constraints เหลือเฉพาะ Primary Key

วันที่ 2026-10-26 · ผู้ยืนยัน: ผู้ใช้ในแชต · ผู้บันทึก: นายช่าง

ผู้ใช้ยืนยัน “เหลือแค่ pk ก็พอ CONSTRAINT”. คง PRIMARY KEY ของ SchoolBot ทั้ง32ตาราง และถอน UNIQUE24 / FOREIGN KEY40 / CHECK80 รวม144รายการจากร่าง SQL รวมบล็อกเพิ่ม FK หลังสร้างตารางและส่วน DROP CONSTRAINT ที่คู่กันใน rollback

คง450คอลัมน์ ชนิดข้อมูล NOT NULL/NULL ค่าเริ่มต้น และ identity เดิม. คำสั่งถอน standalone indexes/GRANT ก่อนหน้ายังคงเดิม; backing indexes ที่ PostgreSQL สร้างให้ PK32ยังมี. ไม่แปลงกฎที่ถอนเป็น constraints รูปแบบอื่น

ความสัมพันธ์และกฎความไม่ซ้ำ/validation เดิมเป็นข้อมูลเชิงตรรกะของ application ไม่ใช่การบังคับในฐานข้อมูล. งานนี้ไม่ได้ implement หรือพิสูจน์การบังคับทดแทน และไม่ถือเป็นผล runtime. ปรับ DBML/คู่มือ/เกณฑ์ตรวจให้ตรงร่างใหม่โดยคง REQ/AC IDs และจำนวนเดิม

มตินี้แทนเฉพาะส่วนที่กำหนด UNIQUE/FK/CHECK ในแบบเดิม; ไม่เปลี่ยนชนิด PK int4 ชื่อคอลัมน์ กฎธุรกิจ หรืออนุญาตการรัน SQL บนฐานจริง
