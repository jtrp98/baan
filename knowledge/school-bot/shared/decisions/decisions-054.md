# มติที่ 054 — เลขอ้างอิงการอนุมัติและหลักฐาน release ยาวไม่เกิน 1,000 ตัวอักษร ไม่ขยายฐานข้อมูล

วันที่ 2026-11-03 · ผู้ตอบ: ผู้ใช้ในแชต · ผู้บันทึก: นายช่าง

## มติ

- `approval_ref` (เลขอ้างอิงการอนุมัติตอนเผยแพร่หลักสูตรหรือคลังข้อสอบ) และ `evidence_ref` (หลักฐาน CI ตอนเผยแพร่ release) รับได้**ไม่เกิน 1,000 ตัวอักษร** ให้ตรงกับช่อง `SchoolBotAuditEvent.Reason varchar(1000)` ที่มีอยู่ในฐานจริง
- **ไม่ขยายคอลัมน์ ไม่เพิ่มฟิลด์ ไม่มี migration** — โครงสร้างฐานคง 32 ตาราง / 450 ฟิลด์ตามที่ตรวจ catalog แล้ว
- ข้อความยาวเกิน 1,000 ตัว → API ตอบ `400 INVALID_INPUT` ห้ามตัดข้อความหรือเก็บเฉพาะ hash
- ถ้าภายหลังพบว่าต้องใช้ลิงก์ยาวกว่านี้จริง ค่อยเปิดเรื่องขยายใหม่ — ข้อเสนอขยายเป็น 2,048 ของ arch (2026-11-03) ไม่นำมาใช้

## ที่มา

vault พบว่าแบบให้สองช่องนี้ยาวได้ 2,048 ตัว แต่ช่องที่เก็บรับได้ 1,000 · arch เสนอขยายคอลัมน์ · ผู้ใช้ถามเหตุผล แล้วพบว่าแบบไม่เคยระบุว่าคนจะกรอกอะไรจริง ตัวเลข 2,048 ตั้งตามช่องอ้างอิงอื่น ไม่ได้มาจากความต้องการใช้งาน

ผู้ใช้ตอบ: "ไว้ 1000 ก่อนแหละ ไว้เจอปัญหาในอนาคต ค่อยคิด อย่าพึ่ง overengineer เลย"
