# TP-001 — ทางหลักการถือครองช่องคะแนนและจัดการ ScoreMapping

> Rev 1 · แก้ล่าสุด 2026-11-03 · แก้โดย inspect · ขอโดย ผู้ใช้ (ใบงาน 097 — เคส normal ของ BE-035 บน stub)

เอกสารนี้กำหนดเคสระดับ `normal` (ทางหลักและผลปฏิเสธหลักตามเกณฑ์ตรวจรับ) สำหรับงาน [BE-035 (ทำ GradeSlot/ScoreMapping ช่องเดิม)](../plan/extension/index.md) ใช้คู่กับ [ตาราง normal แยกตาม task](tp-001-normal-index.md) และ [ขอบเขต normal/full](tp-001-normal-scope.md) ทุกผลจริงยังเป็น NOT_RUN

คำย่อในเอกสาร: AC = Acceptance Criteria (เกณฑ์ตรวจรับ) · BR = Business Rule (กฎธุรกิจ) · API = Application Programming Interface · UUID = Universally Unique Identifier · UTC = Coordinated Universal Time · ETag = Entity Tag สำหรับตรวจข้อมูลชน · DB = Database (ฐานข้อมูล)

## Setup ร่วมบน stub (Setup G ต่อจาก Setup L และ C)

รันระดับ component/integration ในหนึ่ง host/process มีสอง service/adapter instances ต่อ backing store ของ SchoolBot ร่วมกัน แยกการทดสอบเป็นสองรอบต่อเคส: รอบแรกใช้ `MemorySchoolBotBackingStore` object เดียว และรอบที่สองใช้ `FileSchoolBotBackingStore` สอง object บน directory เดียวกัน อ่านตรวจ persisted state ผ่าน adapter ตัวที่สามหรือเปิด file store ใหม่โดยไม่พึ่ง cache ใช้ fake UTC clock `T = 2026-11-03T02:00:00Z`, fake cipher และตัวจำลองอ่านข้อมูลเดิม (School DB และ PGGradeDB read-only fakes) โดยนับจำนวนการเขียนลง PGGradeDB ต้องเป็น `0` ตลอดการทดสอบ BE-035 ทุกคำขอที่เปลี่ยนข้อมูลส่ง `X-Request-Id` และ `Idempotency-Key` เป็น UUID ใหม่ และส่ง `If-Match` ล่าสุดสำหรับการแก้ไขหรือยกเลิก

- **ข้อมูลโรงเรียนและรอบเรียนใน Setup G:**
  - โรงเรียน `S1` (`SchoolId = 1`, License สถานะ `Active`):
    - `CourseRun` `run1` (`Lifecycle = active`, `NYear = 101` ที่ resolve จาก `year = 2569`, `NTerm = "term-1"` ที่ resolve จาก `term = "1"`, `ClassroomId = 401`, `PlanCourseIds = [501, 502]`, `CurriculumId = cur1` สถานะ `published`) มีกิจกรรมในบทเรียน ได้แก่ `A1` (`type = project, mode = block, has_numeric_score = true`, มีตัวชี้วัด `ind1`), `A2` (`type = quiz, has_numeric_score = true`), `A3` (`type = test, has_numeric_score = true`) และ `A0` (`type = instruction, has_numeric_score = false`)
    - `CourseRun` `run2` (โรงเรียน `S1`, เทอมถัดไป `NYear = 101, NTerm = "term-2"`, `ClassroomId = 401`, `PlanCourseIds = [503]`, `CurriculumId = cur1`)
    - ช่องคะแนนเดิมใน PGGradeDB fake ของ `S1` เทอม 1 ที่ว่างและพร้อมถือครอง (`editable = true, owned = false`):
      - วิชา X (`plan_course_id = 501, course_id = 601, n_grade_id = 701`): ช่อง `SlotX` (`assessment_id = 801, score_identifier = "score_1", category = "before_midterm", max_score = "20", target_token = "tok-x"`) และช่อง `SlotZ` (`assessment_id = 803, score_identifier = "score_2", category = "midterm", max_score = "30", target_token = "tok-z"`)
      - วิชา Y (`plan_course_id = 502, course_id = 602, n_grade_id = 702`): ช่อง `SlotY` (`assessment_id = 802, score_identifier = "score_1", category = "before_midterm", max_score = "10", target_token = "tok-y"`)
  - โรงเรียน `S2` (`SchoolId = 2`, License สถานะ `Active`): `CourseRun` `runS2` (`NYear = 201, NTerm = "term-1"`, `ClassroomId = 409`, `PlanCourseIds = [509]`, `CurriculumId = cur1`) และช่องคะแนนของ `S2` แยกจาก `S1`
  - ผู้ใช้ช่องทาง `school_web` ตาม [DES-012 Rev9](../design/des-012.md): `schoolAdminS1` (`SchoolId = 1, IsAdmin = 1, sEmp = 901`), `schoolAdminS2` (`SchoolId = 2, IsAdmin = 1, sEmp = 902`) และ `schoolTeacherS1` (`SchoolId = 1, IsAdmin = 0, sEmp = 201` ครูผู้สอนรายวิชา `501` ใน `TPlanCourseTeacher`)

## TP001-069 (ส่วน normal ของ BE-035) — ดูบริบท สิทธิ์ผู้ดูแลกับครู การแยกบริบทโรงเรียน/เทอม และคู่ที่แมพตรงจริง

ระดับ: normal

อ้าง [AC-049-01 (admin เห็นโรงเรียน/เทอม คาบ/กิจกรรม/ตัวชี้วัด วิชา/ช่องเดิม; สร้างช่องใหม่ไม่ได้ ครูสร้าง/แก้ mapping ไม่ได้)](../../../schoolbright-web/modules/school-bot/shared/requirements/req-049.md), [AC-049-03 (สลับโรงเรียน/เทอมแล้ว mapping ไม่ถูกใช้ข้ามบริบทอัตโนมัติ)](../../../schoolbright-web/modules/school-bot/shared/requirements/req-049.md) และ [AC-049-04 (Preview ตรงคู่กิจกรรม–ช่องที่แมพ ไม่เพิ่มช่อง/เดาหมวดเอง)](../../../schoolbright-web/modules/school-bot/shared/requirements/req-049.md) · BE-035 · [DES-008 Rev6](../design/des-008.md), [HTTP API Rev6](../design/des-008-api.md), [ขอบเขตและผู้ใช้ Rev6](../design/des-008-ownership.md), [การตรวจข้อมูลและสิทธิ์ Rev6](../design/des-008-validation.md), [DES-012 Rev9](../design/des-012.md)

Setup และขั้นตอน: ใช้ Setup G; (1) `schoolAdminS1` เรียก `GET /v2/course-runs/{run1}/mapping-sources` และ `GET /v2/grade-targets?year=2569&term=1&classroom_id=401&plan_course_id=501` (และ `502`) เพื่อดูบริบทโรงเรียน/เทอม กิจกรรม/ตัวชี้วัด และช่องคะแนนเดิม; (2) `schoolAdminS1` ทดลองเรียก `POST /v2/course-runs/{run1}/grade-slots` โดยอ้าง `assessment_id = 999` ที่ไม่มีอยู่จริงใน PGGradeDB เพื่อตรวจว่าไม่สร้างช่องใหม่เอง; (3) `schoolAdminS1` ยืนยันถือครอง `SlotX` (`POST /v2/course-runs/{run1}/grade-slots` ด้วย `ownership_reason = "fixture:own-x"`) และสร้าง mapping `M1` ผูก `A1 → SlotX` (`POST /v2/course-runs/{run1}/score-mappings` ด้วย `sources = [{activity_id: A1, indicator_key: "ind1", weight_bps: 10000}]`) โดยปล่อย `A2` (Quiz), `A3` (Test) และ `SlotZ` (กลางภาค) ไว้ไม่แมพ; (4) `schoolTeacherS1` เรียก `GET` ดูแหล่งคะแนน ช่องคะแนนของวิชา `501` และรายการ mapping ของ `run1` จากนั้นทดลองเรียก `POST /grade-slots`, `POST /score-mappings`, `PUT /v2/score-mappings/{M1}` และ `POST /v2/score-mappings/{M1}/retire`; (5) สลับบริบทไปอ่าน `GET /v2/course-runs/{run2}/score-mappings` กับ `GET /v2/grade-targets` ของเทอม 2 (`term = "2"`) และให้ `schoolAdminS2` อ่านของ `runS2` (โรงเรียน `S2`) พร้อมเปิด file store ใหม่ตรวจข้อมูลที่บันทึกไว้

Response และ persisted state ที่คาด: (1) `schoolAdminS1` อ่านได้ 200 เห็นกิจกรรมพร้อม `indicator_keys`/`has_numeric_score` และเห็นช่องคะแนนเดิม `SlotX`, `SlotZ`, `SlotY` ที่ resolve `NYear = 101, NTerm = "term-1"` จริง; (2) การขอถือครองช่องที่ไม่มีในระบบเกรดเดิมถูกปฏิเสธด้วย `409 SLOT_UNAVAILABLE` ไม่สร้างหัวช่องใหม่และไม่เขียนลง PGGradeDB (`PGGradeDB writes = 0`); (3) การสร้าง `SlotX` และ `M1` ได้ 201 พร้อม ETag และเมื่ออ่าน `GET /v2/course-runs/{run1}/score-mappings` (ข้อมูลคู่แมพสำหรับแสดงและส่งให้ preview) คืนเฉพาะคู่ `A1 → SlotX` ที่แมพไว้รายการเดียว ไม่เพิ่ม `SlotZ` และไม่เดาหมวดจากชนิดกิจกรรม `quiz`/`test` (`A2`, `A3`); (4) `schoolTeacherS1` อ่านวิชาที่สอนได้ 200 แต่ทุกคำขอสร้าง/แก้/ยกเลิกช่องหรือ mapping ได้ `403 SCHOOL_ADMIN_REQUIRED` โดยไม่เปลี่ยนข้อมูล; (5) บริบทเทอม 2 (`run2`) และโรงเรียน `S2` (`runS2`) คืน `items = []` และช่องมี `owned = false` ไม่นำ `M1` ไปใช้ข้ามเทอมหรือข้ามโรงเรียนอัตโนมัติ ใน store หลัง reopen มี `SchoolBotGradeSlot = 1` (`TargetSnapshot` เก็บ `n_year = 101, n_term = "term-1"`), `SchoolBotScoreMapping = 1`, `audit = 2`, `ledger = 2`

## TP001-070 (ส่วน normal ของ BE-035) — กิจกรรมเดียวแมพหลายวิชา กันช่องซ้ำ และล็อกคู่ที่ส่งแล้วให้เปลี่ยนด้วยชุดใหม่

ระดับ: normal

อ้าง [AC-049-02 (กิจกรรม A แมพช่องวิชา X และ Y ได้; แมพ B ซ้ำช่องใดของ A ในบริบทเดียวกันถูกปฏิเสธ ทั้งแก้ชุดเดิมและสร้างชุดใหม่)](../../../schoolbright-web/modules/school-bot/shared/requirements/req-049.md) และ [AC-049-05 (mapping ที่ส่งแล้วแก้คู่เดิมไม่ได้; เปลี่ยนใช้ชุดใหม่ คู่/คะแนนที่ส่งแล้วคงเดิม และยังห้ามช่องซ้ำ)](../../../schoolbright-web/modules/school-bot/shared/requirements/req-049.md) · BE-035 · [DES-008 Rev6](../design/des-008.md), [HTTP API Rev6](../design/des-008-api.md), [การได้มาซึ่ง GradeSlot Rev6](../design/des-008-grade-slot.md), [กฎ mapping/export Rev1](../design/grade-rules-032-034.md)

Setup และขั้นตอน: ใช้ Setup G ตามลำดับโดยไม่มี race; (1) `schoolAdminS1` เรียก `POST /v2/course-runs/{run1}/grade-slots` ยืนยัน `SlotX` (วิชา X `plan_course_id = 501`) และ `SlotY` (วิชา Y `plan_course_id = 502`) แล้วเรียก `POST /v2/course-runs/{run1}/score-mappings` ผูกกิจกรรม `A1` เข้ากับ `SlotX` (`M1`) และผูกกิจกรรม `A1` เดียวกันเข้ากับ `SlotY` (`M2`) ด้วย `weight_bps = 10000`; (2) ทดลองผูกกิจกรรม `A2` ซ้ำลงในช่อง `SlotX` ของบริบทเดียวกันทั้งสองทาง: ทางแรกเรียก `PUT /v2/score-mappings/{M1}` เพื่อใส่ `sources = [A1, A2]` ในชุดเดิม และทางที่สองเรียก `POST /v2/course-runs/{run1}/score-mappings` สร้างชุดใหม่ชี้ `grade_slot_id = SlotX` ด้วย `sources = [A2]` รวมทั้งลองเรียก `POST /v2/course-runs/{run1}/grade-slots` ยืนยันช่อง `(SchoolId = 1, NGradeId = 701, AssessmentId = 801, ScoreIdentifier = "score_1")` ซ้ำ; (3) ใน fixture ที่ `M1` (`A1 → SlotX`) ถูกอ้างอิงใน `SchoolBotScorePreview` สถานะ `confirmed` และ `SchoolBotScoreExport` แล้ว (จำลองสถานะส่งคะแนนแล้วพร้อมค่าคะแนนเดิมในช่อง `SlotX`) ให้ `schoolAdminS1` ทดลองเรียก `PUT /v2/score-mappings/{M1}` (เปลี่ยนแหล่งเป็น `A2`) และ `POST /v2/score-mappings/{M1}/retire`; (4) จากนั้นให้ `schoolAdminS1` เปลี่ยนไปใช้ชุดใหม่โดยเรียก `POST /v2/course-runs/{run1}/grade-slots` ยืนยันช่องว่าง `SlotZ` และเรียก `POST /v2/course-runs/{run1}/score-mappings` สร้าง `M3` (`A2 → SlotZ`) พร้อมลองสร้างชุดใหม่ทับ `SlotX` ที่ล็อกแล้วอีกครั้ง แล้วเปิด file store ใหม่อ่านผล

Response และ persisted state ที่คาด: (1) การผูก `A1 → SlotX` (`M1`) และ `A1 → SlotY` (`M2`) ข้ามสองวิชาได้ 201 ทั้งสองรายการ; (2) การนำ `A2` มาใช้ช่อง `SlotX` ซ้ำถูกปฏิเสธทั้งการแก้ชุดเดิม (`409 MAPPING_SOURCE_COUNT_INVALID`) และการสร้าง mapping หรือถือครอง slot ซ้ำบนช่องเดิม (`409 STATE_CONFLICT` / `409 SLOT_ALREADY_OWNED`) โดย `M1` และ `M2` คงเดิม; (3) เมื่อ `M1` ถูกล็อกจากชุดส่งที่ยืนยันแล้ว ทั้ง `PUT /v2/score-mappings/{M1}` และ `POST /v2/score-mappings/{M1}/retire` ได้ `409 MAPPING_LOCKED` คู่ `M1` (`A1 → SlotX`, `RetiredAt = null, IsDelete = false`) และคะแนนเดิมในช่อง `SlotX` ไม่ถูกย้ายหรือล้าง; (4) การสร้างชุดใหม่บนช่องว่าง `SlotZ` ได้ 201 (`M3: A2 → SlotZ`) ส่วนการขอสร้างชุดใหม่ทับช่อง `SlotX` ที่ล็อกแล้วยังคงถูกปฏิเสธด้วย 409 หลัง reopen พบ `GradeSlot = 3` (`SlotX`, `SlotY`, `SlotZ`), `ScoreMapping = 3` (`M1`, `M2`, `M3` สถานะ active ทั้งหมด), `audit` และ `ledger` เพิ่มเฉพาะคำขอที่สำเร็จ และ `PGGradeDB writes = 0`

## รายการเคสระดับ full สำหรับ full pass

รายการด้านล่างบันทึกเป็นชื่อเคสบรรทัดเดียวตามกติการะดับ `normal` เพื่อให้ `check` ขยาย setup ในรอบ `full`:

- `TP001-069 (ส่วน full)` · ระดับ: full — ส่ง JWT/header ปลอม, ถอนสิทธิ์กลุ่มแอดมินหรือปิด License โรงเรียนก่อน commit (`403 SCHOOL_ADMIN_REQUIRED`/`LICENSE_REQUIRED`), ครูขอดูช่องคะแนนวิชาที่ตนไม่ได้สอน (`403 SUBJECT_PERMISSION_REQUIRED`), ผู้ดูแลข้ามโรงเรียนเข้าถึง `run1` (`403 SCHOOL_MISMATCH`/404), ใช้โทเคนช่องทาง `desktop` (`403 CHANNEL_NOT_ALLOWED`) และส่งแหล่งคะแนนที่เป็น `instruction` หรือ Quiz ที่ไม่นับคะแนน (`409 SOURCE_NOT_SCORABLE`) ตาม AC-049-01, AC-049-03 และ AC-049-04
- `TP001-070 (ส่วน full)` · ระดับ: full — สอง adapters/processes แข่งจอง `GradeSlot` หรือสร้าง `ScoreMapping` บนช่องเดียวกันพร้อมกันใต้ barrier เหลือผู้ชนะหนึ่งเดียว, ส่ง `If-Match` เก่าหรือขาดหาย (`412 VERSION_CONFLICT`/`428 PRECONDITION_REQUIRED`), พยายามหลบการล็อกด้วย soft-delete (`IsDelete = true`) หรือสร้าง `CourseRun` ใหม่มาผูกช่องเดิม, ส่ง `weight_bps != 10000` (`400 MAPPING_WEIGHT_INVALID`) และตรวจ idempotency replay/fault injection ตาม AC-049-02 และ AC-049-05
