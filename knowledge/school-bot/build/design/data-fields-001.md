# วิธีอ่านฟิลด์และคอลัมน์มาตรฐาน

> แก้ล่าสุด 2026-11-02 · แก้โดย arch · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

[กลับคู่มือ](data-model.md)

## วิธีอ่านฟิลด์ในคู่มือ

- **PK** คือรหัสแถวในตารางนั้น; SchoolBot ใช้ `integer` ที่ฐานข้อมูลสร้างให้
- **ความสัมพันธ์เชิงตรรกะ** คือการอ้างรหัสที่ application ต้องตรวจเอง; ร่าง SQL ไม่มี FK ทั้งภายใน SchoolBot และข้ามฐานข้อมูล
- **ว่างได้** หมายถึงเก็บ `NULL` ได้ ไม่ได้แปลว่าเป็นศูนย์หรือข้อความว่าง
- **JSON (`jsonb`)** คือชุดข้อมูลที่มีโครงสร้างด้านใน เช่น ข้อสอบ คำตอบ หรือ snapshot คู่มือมีลิงก์ไปนิยาม ไม่ได้หมายถึงใส่อะไรก็ได้
- ทุกตารางมี 6 ฟิลด์ร่วม: `IsDelete`, `CreateBy`, `CreateDate`, `UpdateBy`, `UpdateDate`, `SchoolId` และมีคำอธิบายซ้ำในหน้าตารางเพื่อเปิดอ่านแยกได้
- เนื้อหากลาง 8 ตารางบังคับ `SchoolId=NULL`; ตารางรายโรงเรียน 21 ตารางต้อง `SchoolId>0`; อีก 3 ตารางรองรับทั้งส่วนกลางและรายโรงเรียน ดูขอบเขตในแต่ละหน้า

CreateBy/CreateDate/UpdateBy/UpdateDate ทุกตารางเป็น nullable DEFAULT NULL; ถ้าไม่ส่งค่าจะเป็น NULL ไม่มี timestamp default อัตโนมัติ

## หกฟิลด์ที่มีทุกตาราง

| ฟิลด์ | ความหมาย |
|---|---|
| `IsDelete` | ระบุว่าแถวถูกลบแบบเก็บประวัติหรือไม่; false = ยังใช้, true = ซ่อนจากการอ่านตามปกติ ไม่ใช่การลบข้อมูลถาวร |
| `CreateBy` | รหัสนักเรียน sId หรือบุคลากร sEmp ผู้สร้างรายการ; NULL = ระบบ/ผู้ทำที่ไม่มีรหัส profile นี้ เลขอย่างเดียวไม่บอกชนิดคน ให้ดู Actor ใน AuditEvent ประกอบ |
| `CreateDate` | วันเวลาสร้างรายการตามเวลา UTC จาก server |
| `UpdateBy` | รหัสนักเรียน sId หรือบุคลากร sEmp ผู้แก้ล่าสุด; NULL = ระบบ/ผู้ทำที่ไม่มีรหัส profile นี้ ใช้กฎเดียวกับ CreateBy |
| `UpdateDate` | วันเวลาแก้ล่าสุด UTC จาก server; ใช้ตรวจว่ามีคนแก้แทรกก่อนบันทึกผ่าน ETag/If-Match แทนคอลัมน์ Version |
| `SchoolId` | รหัสโรงเรียนที่ข้อมูลแถวนี้สังกัด; ไม่ใช่รหัสผู้ใช้ ดูขอบเขตส่วนกลาง/รายโรงเรียนที่ต้นหน้านี้ |
