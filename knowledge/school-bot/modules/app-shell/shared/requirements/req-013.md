# REQ-013 — ขอบเขต sample/preview/mock

> แก้ล่าสุด 2026-11-02 · แก้โดย spec · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

## ต้องการอะไร/ทำไม

ให้ทดลองหน้าจอโดยไม่ตีความผลจำลองเป็นผลจากอุปกรณ์หรือการเรียนจริง. ผลจำลองต้องไม่ถูกใช้ยืนยันการทำงานกับอุปกรณ์หรือผลการเรียนจริง.

API (Application Programming Interface) คือช่องทางเรียกบริการ; USB (Universal Serial Bus) คือช่องทางเชื่อมต่ออุปกรณ์.

## Business Rules

- BR-013-01: Browser ที่ไม่มี native bridge ต้องไม่เปลี่ยนเป็น preview อัตโนมัติ
- BR-013-02: ผล mock ไม่ใช่สิทธิ์ครู ผลประเมิน การส่งคำสั่งจริง หรือ multi-project
- BR-013-03: ทุกเส้นทาง mock/preview ต้องทำให้ผู้ใช้ทราบว่าเป็นการจำลอง (ป้ายคงที่ตลอด session) — ยืนยันโดยผู้ใช้ 2026-10-24 ตาม [มติ 037 (ตรวจรับ AC-030-04..08 + UX Q5/Q9 + เกณฑ์ performance)](../../../../shared/decisions/decisions-037.md) (สถานะ implement ยังไม่พิสูจน์)

## Acceptance Criteria

- AC-013-01: เปิด browser โดยไม่มี `preview=1` และไม่มี bridge แล้วพบข้อผิดพลาด native bridge แทนผลสำเร็จจำลอง
- AC-013-02: ใน preview บันทึกงานได้ใน browser แต่ activate และตรวจอัปเดตไม่เรียก API จริง
- AC-013-03: ทดลอง LearnMap, Teacher restart/reset/console และ USB ตัวอย่างแล้วไม่มีคำสั่งไปอุปกรณ์ ไม่มีไฟล์ USB ที่ถูกคัดลอกจริง และไม่มีผลประเมินถาวร

## ยังไม่ยืนยัน

- เจตนาทางธุรกิจที่กลั่นจากฐานเดิมยังไม่ยืนยัน: ให้ทดลองหน้าจอโดยไม่ตีความผลจำลองเป็นผลจากอุปกรณ์หรือการเรียนจริง ต้องให้เจ้าของผลิตภัณฑ์ยืนยันเจตนานี้ โดยแยกจากกฎหรือเกณฑ์ที่มีมติยืนยันแล้ว
