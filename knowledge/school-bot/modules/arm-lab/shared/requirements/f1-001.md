# Arm Lab: Requirements (จาก role 1)

> นำเข้ารายละเอียดจากระบบเก่า (`Handoff/01_REQUIREMENT` v3.1 + ผลหลังจากนั้นถึง 2026-10-21) · **knowledge เป็นแหล่งความจริงแล้ว** ไม่ต้องเปิดโฟลเดอร์เดิม · ID เดิม (FR/NFR/EC/AC/DEC/ST/SCR) เก็บไว้ในวงเล็บเพื่อ grep ข้ามไฟล์ · ป้ายหลักฐาน (Confirmed/Observed/Proposed ฯลฯ) ดู `../../../../shared/context.md`
> R1–R11 ID เดิม ไม่เปลี่ยนความหมาย · R12–R17 เพิ่มวันนี้ (นำรายละเอียดฟังก์ชัน 6A ที่ผู้ใช้อนุมัติแล้ว และผล CR-11 เข้ามา) ดู CHANGELOG

## เป้าหมาย
นักเรียน ป.1–6 (UI เดียวกันทุกชั้น) สอนท่าแขนกล 6 ข้อต่อ (S0–S5) แล้วเล่นเป็นลำดับ กับหุ่นที่มีบอร์ด Raspberry Pi ผ่าน USB · ครูตั้งค่าขั้นสูงแบบ Zide ในโหมดครู · ฐานงานออกแบบ: frame 6A แขนกล (MainV6A) ที่ผู้ใช้อนุมัติแล้ว (รีดีไซน์จาก Zide)

## F1 ความต้องการเดิมจากทีมออกแบบ

## Requirements
ลำดับ: M = Must · ? = ยังไม่ยืนยัน (ดู OQ)

- R1 (M): ใช้ frame 6A แขนกล (MainV6A) เป็นฐานฟังก์ชันและ layout · **อนุมัติแล้ว (DEC-08)** แก้ผ่านใบสั่งแก้เท่านั้น ห้ามทำใหม่ทั้งหน้า · ฟังก์ชันและพฤติกรรมความปลอดภัยต้องครบตาม R5, R12–R16 หลังปรับให้เข้ากับ cloud, Raspberry Pi และ ป.1–6 · **ขนาดปุ่ม/ตัวอักษรคงตาม 6A เดิม ไม่ปรับให้ผ่านเกณฑ์ ≥16px/44px** (ผู้ใช้ตัดสิน 2026-10-21 · OQ20) · โน้ตเพื่อทบทวนอนาคต: ใน 6A มี control ต่ำกว่า 16px อยู่ 129 จาก 152 ตัว ไม่ผ่านเกณฑ์เด็กของ brand/context.md (ความเสี่ยงที่ยอมรับ ร่วมกับ RSK-04) · (FR-10, AC-07, DEL-04)
- R2 (M): ใช้กับแขนกลที่มีบอร์ด Raspberry Pi · โปรโตคอล "ใกล้เคียง Zide" (ผู้ใช้ตอบ 2026-10-20 → คง 6A เกือบทั้งหมด) · 6A สมมติ COM7 ที่ 115200, PWM 500–2500, คำสั่งรูปแบบ `{G0001#000P1500T3000!}` [Observed EV-03] · รายการค่าตั้งขั้นสูงยืนยันกับ firmware → OQ1, OQ12 · (FR-11, DEC-07)
- R3 (M): แขนกลบนจอ**ไม่ขยับไม่ว่ากรณีใด** (ไม่มีการจำลอง) ทั้งเล่นท่า ขยับข้อต่อ หรือทำอะไรก็ตาม · (FR-12, AC-08, CON-07)
- R4 (M): โหมดครูของ Arm Lab: การตั้งค่าขั้นสูงแบบ Zide · ครู**ของโรงเรียนเดียวกับนักเรียนที่ login อยู่** เข้าได้โดย login ด้วยบัญชี SchoolBright ของตัวเองใน dialog (แทน "ใส่รหัส") · (FR-13, AC-09, DEC-09, UJ-06) · การจบเซสชันครู → OQ9
- R5 (M): ปุ่มหยุดเห็นได้ตลอด · เตือนก่อนสั่งขยับไกลหรือเล่นวนไม่หยุด · ปิดปุ่มสั่งงานเมื่อหลุดการเชื่อมต่อ · (FR-14, NFR-04, AC-07)
- R6 (M): งานบันทึกบน cloud ผูกกับบัญชีเป็นค่าเริ่มต้น · (FR-22, AC-13, DEC-13) · รายละเอียดหน้ารวมงาน/sync อยู่ module `my-work`
- R7 (M): export งานเป็นไฟล์ .ini ได้ (Arm Lab = .ini ที่เปิดใน Zide ได้ · ผู้ใช้ตอบ 2026-10-20) · (FR-23, AC-13)
- R8 (M): กู้คืนงานสำรองที่อยู่ในเครื่องได้ (6A สำรองอัตโนมัติทุก 10 วินาที) · (FR-24, AC-13)
- R9 (?): นำท่าหรืองานจากไฟล์ .ini เข้ามาได้ · Inferred จาก frame (Ctrl+A) · frame ปัจจุบันทำปุ่ม "นำเข้าจากไฟล์ .ini…" แล้ว · → OQ4 · (FR-25)
- R10 (M): ใช้ UI เดียวกันทั้ง ป.1–6 ต้องอ่านและใช้ได้สำหรับ ป.1 · เป้า WCAG 2.2 AA + เกณฑ์เด็ก (`../../../../shared/context.md`) · ไม่มีตัวช่วยเพิ่มสำหรับ ป.1–3 ใน MVP (RSK-04 ยอมรับ) · frame เดิมสมมติผู้ใช้ ป.4–6 ต้องปรับข้อความ/ความซับซ้อน (CF-02) · **ยกเว้นขนาดปุ่ม/ตัวอักษร: คง 6A เดิมตาม R1 (ยังไม่ผ่านเกณฑ์ 16px/44px · ทบทวนภายหลัง)** · (NFR-02, DEC-06, DEC-19, EC-06, AC-15)
- R11 (M): เชื่อมต่อหุ่นผ่าน USB ในโปรแกรมติดตั้ง Windows/Mac · ไม่ต้องติดตั้ง driver (ฝังใน installer) · สถานะ: ยังไม่เชื่อม (ปุ่มสั่งงานปิด) / กำลังเชื่อมต่อ / เชื่อมแล้ว / หลุด · ชื่อหุ่นและการจับคู่ → OQ5 · (NFR-03, EC-03, FR-11, ST-19, ST-20)

### รายละเอียดฟังก์ชัน 6A (Observed EV-03 · frame อนุมัติแล้ว ต้องรักษาไว้)

- R12 (M) **ท่าและท่าชุด:** ท่ามีรหัส `G####` · ท่าชุด (action group) สีม่วง `K####` (tooltip เดิมเขียนสลับ = BUG-05) · ท่า 0 "แขนตั้งตรง" **แก้ไขไม่ได้** · ท่า 0 กับท่าพักเป็นคนละท่า · เพิ่มท่า · คัดลอก ตัด วาง ลบ · เลิกทำได้ **6 วินาที** · ลำดับท่าแสดงเป็นการ์ดหรือตาราง · เลือกท่าด้วยแถบ ‹ › หรือแตะจุด S0–S5 บนเวทีหุ่น · **เรียงลำดับท่าด้วยปุ่มขึ้น/ลงบนการ์ดท่า (ไม่ต้องลาก · WCAG 2.5.7) โดย UI ต้องไม่เทอะทะ** · **ท่าชุด K#### คงอยู่ใน MVP** Designer เสนอวิธีสร้าง/เล่นที่เด็ก ป.1–6 เข้าใจง่าย (ผู้ใช้ตัดสิน 2026-10-21 · OQ20) · (ENT-14, ENT-15)
