# 1. กติกากลางของ Labs (ข้อเสนอ)

> แก้ล่าสุด 2026-11-02 · แก้โดย int · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

[กลับint-002-labs](../../../../build/legacy-ux/int-002-labs.md) · ส่วนหนึ่งของ UX ชุดเดียวกับตาราง Sign-off ในไฟล์ทางเข้า


- วงจรสถานะหุ่นตาม [DES-006 (หุ่นจริง Windows/macOS)](../../../../build/design/des-006.md): `off → probing → connected → busy → connected | lost` — UI แสดง chip สถานะมุมบนตลอดเวลา: "ยังไม่เชื่อมต่อ / กำลังตรวจสอบบอร์ด / เชื่อมต่อแล้ว / กำลังทำงาน / การเชื่อมต่อขาด"
- **ป้ายโหมดทดลอง**: ทุกเส้นทาง preview/mock (เช่น `preview=1`) ติดป้ายคงที่ "โหมดทดลอง (จำลอง) — ผลลัพธ์ไม่ใช่คำสั่งจริง/ผลเรียนจริง" ตลอด session ([BR-013-03 (ทุกเส้นทาง mock/preview ต้องทำให้ผู้ใช้ทราบว่าเป็นการจำลอง (ป้ายคงที่ตลอด session) — ยืนยันโดยผู้ใช้ 2026-10-24 ตาม decisions-037 (สถานะ implement ยังไม่พิสูจน์))](../../../app-shell/shared/requirements/req-013.md) — ยืนยันแล้วตาม[มติ 037 (ตรวจรับ AC-030-04..08 + UX Q5/Q9 + เกณฑ์ performance)](../../../../shared/decisions/decisions-037.md), [AC-013-01 (เปิด browser โดยไม่มี `preview=1` และไม่มี bridge แล้วพบข้อผิดพลาด native bridge แทนผลสำเร็จจำลอง)](../../../app-shell/shared/requirements/req-013.md) ถึง [AC-013-03 (ทดลอง LearnMap, Teacher restart/reset/console และ USB ตัวอย่างแล้วไม่มีคำสั่งไปอุปกรณ์ ไม่มีไฟล์ USB ที่ถูกคัดลอกจริง และไม่มีผลประเมินถาวร)](../../../app-shell/shared/requirements/req-013.md), Q9 (ป้ายโหมดจำลองตลอด session))
- ห้าม mix: ผลจำลอง (dry-run/simulator) ไม่แสดงปะปนกับ telemetry จริง (DES-006)
- ปุ่ม "หยุด" (stop) ปรากฏคงที่ทุกสถานะ busy — เสนอขนาดใหญ่ สีแดง มุมขวาล่างของ workspace (Q8 (ปุ่มขอหยุดใหญ่สีแดงมุมขวาล่าง)) — copy ใช้คำ "ขอหยุด" ไม่ใช่ "หยุดแล้ว" เพราะ stop เป็นเพียงคำขอ ไม่มีเกณฑ์ latency/emergency ที่รับรอง ([BR-021-03 (ส่ง stop สำเร็จหมายถึงส่งคำขอ ไม่ใช่ physical stop หรือ emergency stop ที่รับรองแล้ว)](../../shared/requirements/req-021.md), [BR-021-04 (ยังไม่มีเกณฑ์ความหน่วงหรือวิธีหยุดฉุกเฉินที่มนุษย์รับรอง ดู OQ-008)](../../shared/requirements/req-021.md), [OQ-008 (ขอบเขตหุ่นและการยอมรับความปลอดภัย)](../../../../shared/open-questions/oq-008.md))

## 2. Arm Lab

### 2.1 ค้นหาและเชื่อมต่อหุ่น — [REQ-014 (ค้นหาและเชื่อมต่อหุ่น)](../../shared/requirements/req-014.md) · [DES-006 (หุ่นจริง Windows/macOS)](../../../../build/design/des-006.md)

เข้า Arm Lab = เริ่มที่ "ยังไม่เชื่อมต่อ" เสมอ ไม่แสดงเชื่อมต่ออัตโนมัติ ([AC-014-01 (เปิด native ใหม่แล้วไม่แสดงว่าหุ่นเชื่อมต่ออยู่โดยอัตโนมัติ)](../../shared/requirements/req-014.md))

| State | UI + คำ copy (ข้อเสนอ) |
|---|---|
| loading (กำลังค้นหา) | "กำลังค้นหาบอร์ด…" + ปุ่ม "ค้นหาใหม่" |
| empty (ไม่พบ) | "ไม่พบอุปกรณ์ — ตรวจสอบสาย USB หรือพอร์ต แล้วกดค้นหาใหม่" (การค้นพบ ≠ เชื่อมต่อ — [BR-014-01 (ค้นพบอุปกรณ์ไม่เท่ากับเชื่อมต่อสำเร็จ)](../../shared/requirements/req-014.md)) |
| พบรายการ | รายการ "ชื่ออุปกรณ์ · ชนิด: HID/Serial" (path เป็นค่าภายในของ OS — **ไม่มีช่องให้ผู้ใช้พิมพ์ path** ตาม DES-006) ต้องเลือกอุปกรณ์ก่อน ([AC-014-02 (เมื่อไม่เลือกอุปกรณ์หรือไม่ยืนยันโปรไฟล์ การกดเชื่อมต่อไม่สำเร็จ)](../../shared/requirements/req-014.md)) |
| ยืนยันโปรไฟล์ | ต้องยืนยันโปรไฟล์ก่อนกดเชื่อมต่อ — ไม่เลือก/ไม่ยืนยัน = ปุ่มเชื่อมต่อ disabled (AC-014-02) |
| probing | "กำลังตรวจสอบบอร์ด… (ส่ง board.info อย่างเดียว ไม่มีคำสั่งเคลื่อนไหว)" ([BR-014-03 (การเชื่อมต่อไม่ส่งคำสั่งเคลื่อนไหว)](../../shared/requirements/req-014.md)) |
| error: probe ไม่ตอบ | ไม่เข้าสถานะ connected: "บอร์ดไม่ตอบสนอง — ลองเสียบสายใหม่ หรือเลือกอุปกรณ์อื่น" ([AC-014-03 (ใช้ test device ที่ไม่ตอบ probe แล้วไม่เข้าสถานะ connected)](../../shared/requirements/req-014.md)) |
| connected | เข้า workspace · chip "เชื่อมต่อแล้ว: <ชื่ออุปกรณ์>" |
