# REQ-009 — 5b. รีวิวแยกทีละมิติ (per-dimension review — เพิ่มเข้ามาทีหลัง แก้จากที่เคยออกแบบเป็นการตัดสินใจเดียวทั้งเคส)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `index.md` เท่านั้น

หน้าคิวตรวจสอบ (review-queue) ต้องแสดงผลจำแนกทั้ง 3 มิติแยกกัน (เมนู / ประเภทเคส / ความรุนแรง) และให้คนเลือกทีละมิติอิสระจากกัน ไม่ใช่ตัดสินใจเดียวสำหรับทั้งเคส แต่ละมิติมี 3 ตัวเลือก:
- **ใช้** — ผลจำแนกของ AI ถูกต้อง ยืนยันตามเดิม
- **ใช้แต่แก้ไข** — ผลจำแนกใกล้เคียงแต่ต้องแก้ค่า คนระบุค่าใหม่แทน
- **ไม่ใช้** — ผลจำแนกผิดทั้งหมด ไม่ใช่แค่ใกล้เคียง: มิติเมนู/ความรุนแรง ปล่อยเป็น NULL ได้เลย (ไม่ผูกเมนูไหนชัดเจน/ไม่มีความเสียหายเชิงเทคนิคจริง) แต่ **มิติประเภทเคสต้องระบุค่าที่ถูกต้องแทนเสมอ** (ทุกเคสต้องมีประเภท) พร้อม**เหตุผลที่ถูกต้องแบบบังคับกรอก** (ต่างจาก "ใช้แต่แก้ไข" ที่เหตุผลเป็นทางเลือก) — เพื่อใช้เป็นสัญญาณสอน AI ว่าเคสแบบนี้ AI เข้าใจผิดทิศทางไปเลย ไม่ใช่แค่ใกล้เคียง

**Acceptance criteria:**
- AC-009.1: หน้าคิวตรวจสอบ (review-queue) แสดงผลจำแนกทั้ง 3 มิติ (เมนู / ประเภทเคส / ความรุนแรง) แยกกัน และคนตรวจเลือกทีละมิติอิสระจากกัน
- AC-009.2: แต่ละมิติมี 3 ตัวเลือก: ใช้ (ยืนยันตามเดิม) · ใช้แต่แก้ไข (ระบุค่าใหม่แทน) · ไม่ใช้
- AC-009.3: เมื่อเลือก "ไม่ใช้" มิติประเภทเคสต้องระบุค่าที่ถูกต้องแทนพร้อมเหตุผลแบบบังคับกรอกเสมอ ส่วนมิติเมนู/ความรุนแรงปล่อยเป็น NULL ได้
