## Findings — Phase 3 & Phase 5

### SEC-01 — Token_Secret plaintext committed ใน repository

- **Location:** `AITimeTableBackend/appsettings.json:13`
- **Attack:** ผู้ใดก็ตามที่เข้าถึงซอร์สโค้ด (developer, git log, backup, CI/CD artifact) สามารถนำ HMAC-SHA256 `Token_Secret` ไปสร้าง JWT token ปลอม โดยกำหนด claims `NCompany`, `user_id`, หรือ `admin_id` ใด ๆ ได้เอง ทำให้สามารถ bypass authentication และเข้าถึงข้อมูลของทุกโรงเรียนในระบบ SchoolBright
- **Fix:** หมุนเวียน secret (Rotate secret) ทั้งระบบ SchoolBright; ย้าย secret ออกจาก `appsettings.json` ไปยัง Environment Variables หรือ Cloud Secret Store (e.g. Azure KeyVault, Huawei KMS); ห้าม commit secret ลง git
- **Status:** open (ผู้ใช้รับความเสี่ยงชั่วคราวระดับ dev 2026-09-29 ตาม R33/D49; คงเป็น Human Gate บังคับก่อน deploy production) · **คำตัดสินล่าสุด:** jtrp98 วันที่ 09/10/2026 เลือก 1C — ทำงาน dev ต่อ พัก production deploy ไว้ก่อน; ไม่ใช่การรับความเสี่ยงสำหรับ production

### SEC-02 — สภาพแวดล้อม Dev ถือ Signing Key ของ Production (R32)

- **Location:** Deployment architecture / `appsettings.json:13`
- **Attack:** เนื่องจาก frontend production ถูกตั้งค่าให้ชี้มายัง backend dev ทำให้ backend dev ต้องใช้ `Token_Secret` ร่วมกับ production หากสภาพแวดล้อม dev ถูกเจาะหรือมีการเข้าถึงฐานข้อมูล/คอนฟิก dev ผู้โจมตีจะได้กุญแจที่สามารถเข้าถึง production ได้โดยตรง
- **Fix:** แยก secret และ signing authority ระหว่าง dev และ production ให้เด็ดขาด หรือ promote backend ขึ้น production พร้อมกัน
- **Status:** open · **คำตัดสินล่าสุด:** jtrp98 วันที่ 09/10/2026 เลือก 2C — พักการตัดสินเรื่อง production ให้ทำ dev ต่อ; ไม่ใช่การรับความเสี่ยงสำหรับ production

### SEC-03 — Package vulnerability advisories (NU1904, NU1903 / BL-004)

- **Status:** fixed — security re-audit 2026-10-09 ตามคำอนุมัติ 3A ของ jtrp98 วันที่ 09/10/2026; ประวัติ finding ก่อนปิดเก็บ verbatim ที่ `security/archive.md`
- **Fix verified:** `AITimeTableBackend/AITimeTableBackend.csproj:14` ใช้ direct Newtonsoft.Json 13.0.4; ลบ package Dynamic.Core และ using ที่ไม่ใช้จาก MenuController, WebAPIController, HTTPHeaderParseService โดยไม่เปลี่ยน API/auth logic
- **Evidence:** security อ่าน manifest/ตรวจ restored `obj/project.assets.json` จริง — Newtonsoft.Json/13.0.4, ไม่มี Dynamic.Core; production rg ของ namespace/parser symbols ไม่พบ; `review/round-9.md` PASS; `qa/round-8.md` tests 125/125, runtime output metadata 13.0.4, NuGet vulnerability audit backend/tests ไม่พบ vulnerable packages ตาม sources ปัจจุบัน
- **Advisory basis:** [GHSA-5crp-9r3c-p9vr](https://github.com/advisories/GHSA-5crp-9r3c-p9vr) ระบุ patched Newtonsoft.Json 13.0.1; [maintainer release 13.0.1](https://github.com/JamesNK/Newtonsoft.Json/releases/tag/13.0.1) ตั้ง default MaxDepth 64 · เวอร์ชันที่ resolve จริง 13.0.4 อยู่หลัง patch
- **Limitations:** เป็นการปิด dependency finding ใน working tree/build artifacts; ไม่ได้ deploy หรือทดสอบ live production payload/shared DB และไม่ใช่การปิด SEC-01/SEC-02 หรือรับความเสี่ยง production
