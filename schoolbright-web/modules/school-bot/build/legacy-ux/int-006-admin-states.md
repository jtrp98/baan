# int-006 — state และ accessibility (a11y — การเข้าถึงสำหรับผู้ใช้ทุกกลุ่ม) ของ admin

> แก้ล่าสุด 2026-11-02 · แก้โดย int · ขอโดย ผู้ใช้ (เรียบเรียงตามกติกาเอกสารใหม่ ความหมายไม่เปลี่ยน)

กำหนดทุกสถานะของหน้าจัดการหลักสูตร นำเข้า และคลังข้อสอบ รวมฟอร์มผิดและคำขอที่ยังไม่ทราบผล

## S1. กติกาทุกพื้นที่ข้อมูล

ครอบรายการ/รายละเอียดหลักสูตร ตัวแก้ Lesson หน้าตรวจเผยแพร่ import preview/result และ bank/policy ไม่ถือ error เป็น empty หรือถือข้อมูลเก่าว่าเป็นข้อมูลล่าสุด

| State | คำและพฤติกรรมที่เสนอ |
|---|---|
| loading | Spinner เฉพาะส่วน + “กำลังโหลดหลักสูตร…” / “กำลังตรวจข้อมูลนำเข้า…” / “กำลังโหลดคลังข้อสอบ…”; aria-busy=true ปิดการกระทำที่พึ่งข้อมูลนั้น |
| empty | “ยังไม่มีหลักสูตรในรายการนี้” / “ยังไม่มีบทเรียนในฉบับร่าง” / “ไม่พบแถวข้อมูลสำหรับนำเข้า” / “ยังไม่มีข้อสอบในฉบับร่าง”; ข้อความอย่างเดียว ไม่มี CTA ในพื้นที่ empty |
| error อ่านข้อมูล | “โหลดข้อมูลไม่ได้ — ตรวจสอบอินเทอร์เน็ตแล้วลองใหม่” พร้อม “ลองใหม่” สำหรับการอ่าน; คงบริบทเดิมและป้าย “ข้อมูลที่แสดงอาจยังไม่ล่าสุด” หากเก็บข้อมูลเดิมไว้ |
| disabled | อธิบายเหตุผลข้างปุ่ม เช่น “กำลังบันทึก” “ยังไม่ได้ตรวจข้อมูล” “ต้องให้ผู้ตรวจอีกคนเผยแพร่”; ไม่ใช้สีจางอย่างเดียว |
| read-only | ฉบับเผยแพร่แล้ว/ผู้ไม่มีสิทธิ์แก้ แสดงข้อความกำกับ ไม่ทำให้ช่องเหมือนแก้ได้ |
| สำเร็จ | inline “บันทึกฉบับร่างแล้ว” หรือ “เผยแพร่แล้ว” จากผลยืนยันจริง; toast เป็นตัวเสริม ไม่ใช้เป็นหลักฐานผลเพียงแห่งเดียว |

ปุ่มสร้าง/นำเข้าใน toolbar เป็นทางเข้าของหน้าปกติ ไม่วางเพิ่มใน empty card ไม่สร้าง filter ฝั่ง server ที่สัญญายังไม่มี

## S2. ฟอร์มและข้อมูลผิดปกติ

Submit แล้วแสดงสรุปข้อผิดพลาดบนฟอร์มพร้อมลิงก์ไปช่องผิด label ข้าง field บนเว็บ มี * และคำ “จำเป็น” ช่องเดิมไม่ถูกล้าง

| บริบท | ข้อเสนอการจัดการ |
|---|---|
| Lesson key/ordinal ซ้ำ หรือ key หาย | “รหัสหรือลำดับบทเรียนไม่ถูกต้อง — ตรวจรายการที่ระบุ”; ปิดบันทึก/เผยแพร่ ไม่สร้าง key จากเลข Unit |
| ข้อมูลเก่ามีลำดับผิด/ชื่อยาว | ไม่เรียงแก้แล้วบันทึกเงียบ ชื่อและคำอธิบาย wrap; รหัสยาวตัดเฉพาะรายการและมีทางเปิดดูเต็มด้วย keyboard |
| Activity ผิด mode/config | ชี้กิจกรรมและชนิดที่ผิด ไม่แก้ mode ให้อัตโนมัติ ไม่แปลงสื่อเป็น project |
| เกณฑ์ไม่มีหลักฐานอนุมัติ | “ยังเผยแพร่ไม่ได้ — ขาดหลักฐานอนุมัติเกณฑ์”; คงร่าง ห้ามใช้ผลจำลองเป็นหลักฐาน |
| ข้อสอบผิดชนิด/เฉลย/คะแนน | “ตรวจชนิดข้อ ตัวเลือก เฉลย และคะแนนเต็มก่อนบันทึก”; ชี้ข้อผิด ไม่ใช้ 0 แทนคะแนนเต็มที่หาย |
| Test ไม่มีเวลา | “ระบุเวลาสอบก่อนเผยแพร่”; ไม่กำหนดจำนวนนาทีแทนเจ้าของเนื้อหา |
| สื่อเปิดไม่ได้ | “เปิดสื่อนี้ไม่ได้ — ตรวจลิงก์ต้นทาง”; คง Lesson และแสดงสื่ออื่นได้ ไม่รายงานว่าไม่มีสื่อทั้งหมด |
| ข้อมูล response ผิดรูป/ไม่ครบ | “ยังยืนยันข้อมูลนี้ไม่ได้ — ลองโหลดใหม่หรือติดต่อผู้ดูแล”; ปิด mutation ที่พึ่งข้อมูล ไม่โชว์ JSON หรือ exception ดิบ |

## S3. ผล mutation และ retry — Q42 (ตรวจผลคำขอเดิมและข้อมูลชน)

ใช้กับสร้าง/บันทึก content/เผยแพร่ curriculum/bank และ import เมื่อสัญญาส่วนหลังพร้อม

1. ก่อนส่งเก็บบริบทคำขอและ Idempotency-Key เดิม พร้อม If-Match ของ resource ที่แก้ ปิดปุ่มซ้ำระหว่างรอ ไม่เปลี่ยน key เพื่อหลบผลค้าง
2. สำเร็จเฉพาะเมื่อได้ผลยืนยันตามสัญญา การปิด modal/เปลี่ยนหน้าไม่แปลว่า server ยกเลิกหรือ rollback
3. timeout/เครือข่ายขาด/502/504 หลังส่ง: แถบค้าง “ยังไม่ทราบว่าบันทึกสำเร็จหรือไม่ — ตรวจสอบผลก่อนทำรายการใหม่” คงบริบท ไม่แสดง “นำเข้าไม่สำเร็จ ไม่มีข้อมูลเปลี่ยน” โดยไม่มีหลักฐาน
4. เมื่อสัญญารองรับ replay ให้ “ตรวจสอบผลคำขอเดิม” ด้วย key/body เดิมภายใต้สิทธิ์ปัจจุบัน ไม่มี auto-retry mutation หรือปุ่มส่งชุดใหม่ ระหว่างยังไม่ทราบผล
5. ถ้าคำขอเดิมหมดอายุ แสดง “ตรวจสอบรายการเดิมก่อนเริ่มใหม่” ใช้ resource_id เฉพาะเมื่อ server เปิดเผยและมีสัญญาอ่านรองรับ ไม่สร้าง status endpoint/poll เอง
6. import ปฏิเสธก่อน commit ตามสัญญา atomic ที่ต้องเติม: เสนอข้อความ “ยังไม่นำเข้าข้อมูล — แก้แถวที่ระบุก่อน” ใช้ได้เมื่อ server ยืนยันว่าไม่มีการเปลี่ยนข้อมูลเท่านั้น ห้ามปกปิด partial result หากพบความผิดปกติ
