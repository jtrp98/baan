# REQ-015 — วิชาคาบต่อเนื่อง (Class Continuity) เป็น hard constraint บังคับจริง (แก้ REQ-003(a), ปิด OQ-2 **บางส่วน — เฉพาะ Class Continuity**; ส่วน `nCourseIntensity` ของ OQ-2 ยังเปิด)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น


**การตัดสินใจทางธุรกิจที่ยืนยันแล้ว:** ค่า "คาบต่อเนื่อง N คาบ" ของวิชา (REQ-003(a)) เปลี่ยนจาก as-built เดิมที่ **เก็บไว้เฉยๆ ไม่มีผลต่อการจัด** (D12, AC-007) เป็น **hard constraint ที่ตัวจัดตารางต้องบังคับจริง** — วางวิชานั้นต้องต่อเนื่องกัน N คาบเสมอทั้งตอน Generate อัตโนมัติและตอนวางมือ/สลับมือ ถ้าวางแล้วทำให้ไม่ต่อเนื่องครบ N คาบต้องถูกปฏิเสธเหมือนกติกาอื่น (เทียบ AC-019)

**Acceptance criteria:**

- AC-036 — วิชาที่ตั้งค่าคาบต่อเนื่อง N คาบ ถูกวางติดกัน N คาบเสมอ ทั้งจาก Generate อัตโนมัติและวางมือ · **แก้ 2026-09-28 (ปิด OQ-14 (ก)):** ต้องติดกันจริงตามเวลา ห้ามข้ามคอลัมน์พัก/lunch — ถ้าคาบก่อน/หลังพักไม่ติดกันจริง ไม่นับเป็นคาบต่อเนื่อง
- AC-037 — การวาง/สลับมือที่ทำให้วิชาคาบต่อเนื่องไม่ครบ N คาบ (หรือแยกวัน) ถูกปฏิเสธพร้อมข้อความอธิบายเหตุผล เช่นเดียวกับ AC-019
- **AC-037a (ใหม่, ปิด OQ-14 (ข))** — ถ้าโควตาคาบ/สัปดาห์ของวิชาไม่ลงตัวกับ N (เช่น โควตา 3 คาบ/สัปดาห์ แต่ N=2) ระบบถือเป็น**การตั้งค่าผิด** ต้องแสดงคำเตือนให้ผู้ใช้แก้ค่าใดค่าหนึ่ง — ไม่ auto-split เป็น 1 บล็อก + 1 คาบเดี่ยว
- **AC-037b (ใหม่, ปิด OQ-14 (ค))** — ถ้า N (คาบต่อเนื่องของวิชา) มากกว่าเพดาน "คาบต่อเนื่องไม่พัก" ของครูคนที่สอน (BR-9) **เพดานของครูชนะเสมอ** ห้ามวางเกินเพดานครูแม้จะทำให้วิชาวางไม่ครบ N คาบ
- **AC-037c (ใหม่, ปิด OQ-14 (ง))** — บล็อกคาบต่อเนื่องที่วางแล้ว **ลบได้เฉพาะทั้งบล็อกพร้อมกันเท่านั้น** ห้ามลบทีละช่องเดียวของบล็อก
- **ยกเลิกสถานะ "เก็บไว้เฉยๆ" ของ D12 เฉพาะส่วน Class Continuity** — ส่วน `nCourseIntensity` (ความหนักตาราง) ยังไม่ถูกแตะ คงเป็น as-built เดิม (ยังไม่ตอบ OQ-2 ส่วนนั้น)

**`subjectGroups` (กลุ่มวิชา) — ยืนยันธุรกิจ 2026-09-28, ปิด OQ-21:** เป็น requirement จริง ไม่ใช่ dead field — **มีผลต่อการจัดตารางจริง**: วิชาที่อยู่ในกลุ่มเดียวกันห้ามถูกจัดชนกันเอง (เวลาเดียวกัน) เพิ่มเป็น hard constraint ใหม่ต่อจาก Class Continuity — system-analyst ต้องออกแบบสัญญาเพิ่มสำหรับกติกานี้แยกจาก DES-012 · *แก้ 2026-09-29:* สัญญารองรับมีแล้วที่ **design.md Rev 6 §42 DES-017** (`Contract:SubjectGroupSeparation.v1`) — ฉบับก่อนหน้าเขียนว่า "ยังไม่มีสัญญารองรับใน Rev 5" · SA พบว่าการอ่านตรงตัว "ห้ามชนกันภายในห้องเรียนเดียว" ไม่มีผลจริง เพราะกริดของห้องเรียนหนึ่งมีได้ 1 วิชาต่อช่องอยู่แล้ว (§42.1) ขอบเขตที่มีผลจริงจึงยังต้องให้ product owner ตอบที่ **OQ-25 (เปิด)** · ระหว่างรอ design.md ระบุ fallback ว่ายังไม่บังคับกติกานี้ (ข้อมูลคงไว้) — เป็นข้อกำหนดของการออกแบบ ไม่ใช่คำตอบทางธุรกิจ

**หมายเหตุความเสี่ยงทางเทคนิค (ส่งต่อ system-analyst):** โค้ดฝั่ง frontend ที่ยังไม่ commit เปลี่ยนรูปแบบข้อมูล `jSetSubjectsClassContinuity` จาก JSON array เป็น object `{continuityRows, subjectGroups}` — *ผลตรวจของ SA (design.md §37.2, EVD-045/047, Rev 5):* backend เก็บ/คืน blob เป็นสตริง verbatim ไม่ parse จึงเข้ากันได้แล้ว ไม่ต้องแก้ backend
