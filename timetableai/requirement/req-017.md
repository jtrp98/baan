# REQ-017 — เพดานการสอนของครู: หน่วยเป็นชั่วโมงจริง + เพดานรายสัปดาห์เป็น hard constraint (แก้ REQ-002)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น


**การตัดสินใจทางธุรกิจที่ยืนยันแล้ว 3 ข้อ:**

1. **หน่วยของเพดาน "ไม่เกิน N/วัน" และ "ไม่เกิน N/สัปดาห์" คือชั่วโมงสอนจริง** (นับตามความยาวเวลาจริงของคาบ) ไม่ใช่จำนวนคาบ (as-built เดิมนับเป็นคาบ, `nMaxTeachingPeriodPerDay/Week`) — ต้องแก้ตรรกะการนับใน generator และตอนวางมือให้แปลงเป็นชั่วโมงจริงตามความยาวคาบของ template ที่ใช้ ไม่ใช่นับหัวคาบ
2. **เพดาน "ไม่เกิน N/สัปดาห์" ต้องบังคับจริงเป็น hard constraint** เทียบเท่าเพดานรายวันเดิม ทั้ง Generate และวางมือ · *แก้ข้อเท็จจริง 2026-09-28 (ผลตรวจโค้ดของ SA — design.md §39.2, D38, EVD-054/EVD-055):* ฉบับก่อนหน้าเขียนว่าค่านี้ "บันทึกได้แต่ยังไม่มีใครอ่านใช้" ซึ่งไม่ตรง — ค่ารวม /สัปดาห์ **ไม่เคยถูกบันทึกเลย** เพราะ frontend ส่ง `nMaxTeachingPeriodPerWeek` แต่ backend (`RequestSetting`) ไม่มีฟิลด์นี้และทิ้งค่าเงียบ ๆ ตั้งแต่ต้น จึงไม่มีค่าเดิมของ /สัปดาห์ให้ย้ายข้อมูล (ค่าเดิมที่ต้องตัดสินเรื่อง migration มีเฉพาะ /วัน — OQ-16)
3. **ลำดับความสำคัญเปลี่ยน:** UI ใหม่เอา checkbox "ใช้กับครูทุกคน / ยกเว้นครูที่เลือก" ออก — ลำดับที่ถูกต้องคือ **"กำหนดเวลาการสอนรายบุคคล" (ค่ารายคน) ชนะ "กำหนดเวลาการสอนใช้สำหรับครูทุกคน" (ค่ารวม) เสมอ** เมื่อครูคนนั้นมีค่ารายคนตั้งไว้ —ไม่มีขั้น "ยกเว้น" แยกอีกต่อไป (ต่างจาก BR-8 เดิมที่มี 3 ระดับ: รายคน > รวม-หักยกเว้น > ไม่จำกัด)

**Acceptance criteria:**

- AC-041 — เพดาน/วันและ/สัปดาห์ถูกคำนวณและบังคับเป็น**ชั่วโมงสอนจริง** ไม่ใช่จำนวนคาบ ทั้ง Generate และวางมือ · **แก้ 2026-09-28 (ปิด OQ-16 (ก)):** ผู้ใช้กรอกเพดานเป็น**จำนวนเต็มชั่วโมงเท่านั้น** ไม่รับทศนิยม/เศษนาที
- AC-042 — เพดาน/สัปดาห์ถูกบังคับเป็น hard constraint เทียบเท่า AC-003 เดิม (ที่เดิมมีแค่/วัน)
- AC-043 — ครูที่มีค่ารายบุคคลตั้งไว้ ใช้ค่ารายบุคคลเสมอ โดยไม่ต้องพึ่ง flag "ยกเว้น" ใด ๆ — ครูที่ไม่มีค่ารายบุคคลใช้ค่ารวมของทุกคน · **AC-043a (ใหม่, ปิด OQ-16 (ค)):** ครูที่ตั้งค่ารายบุคคลเฉพาะ "/วัน" (ไม่ได้ตั้ง "/สัปดาห์") — เพดาน/สัปดาห์ของครูคนนั้น**ใช้ค่ารวมของทุกคนแทน** ไม่ใช่ถือว่าไม่จำกัด
- **แก้ BR-8 / AC-003 เดิม**: ลำดับความสำคัญใหม่คือ **รายคน > รวม** (2 ระดับ) แทน **รายคน > รวม-หักยกเว้น > ไม่จำกัด** (3 ระดับ)
- **AC-043b (ใหม่, migration gate — ปิด OQ-16 (ข)):** ค่าเพดาน/วันเดิมที่โรงเรียนบันทึกไว้แล้ว (หน่วย "คาบ") **ไม่แปลงเป็นชั่วโมงอัตโนมัติ (M1)** — ถือว่าไม่จำกัดจนกว่าผู้ใช้จะกรอกค่าใหม่เป็นชั่วโมงเอง ไม่มีการคำนวณแปลงจากความยาวคาบของ template (M2) หรือการตีความเลขเดิมตรงๆ เป็นชั่วโมง (M3) — ค่ารวม/สัปดาห์ไม่มีข้อมูลเดิมอยู่แล้ว (ดูข้อ 2 ด้านบน) จึงไม่ต้องตัดสิน migration ส่วนนั้น

**หมายเหตุสำคัญ — ต้องส่งต่อ system-analyst:** การแปลง "คาบ" เป็น "ชั่วโมงจริง" กระทบตรรกะ hard constraint หลักของ REQ-008/REQ-009 โดยตรง (BR-8, BR-9) — ต้องออกแบบว่าจะเก็บค่าที่ผู้ใช้กรอกเป็นหน่วยชั่วโมงในฐานข้อมูล (schema change) หรือเก็บเป็นคาบแล้วแปลงตอนคำนวณ (logic-only) — เป็นการตัดสินใจทางเทคนิคที่ระบบ (ไม่ใช่ BA) ต้องเลือก · migration ของค่า/วันเดิมปิดแล้ว (M1, AC-043b) ไม่ต้องรอคำตอบเพิ่ม
