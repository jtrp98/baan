# REQ-016 — ห้องเรียนประจำวิชา (Subject Room) + กันห้องชนเวลาเดียวกัน — **ใหม่**

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น


**การตัดสินใจทางธุรกิจที่ยืนยันแล้ว:** UI ใหม่แสดงห้อง (เช่น "ห้องทดลองวิทยาศาสตร์ 1") ต่อเซลล์วิชาบนกริด ซึ่งเป็นข้อมูลที่ระบบ as-built เดิมไม่มี — ผู้ใช้ยืนยันว่านี่คือข้อกำหนดใหม่ในขอบเขตของโมดูลนี้ **พร้อมกติกากันห้องชน** (คล้ายกติกากันครูชนของ REQ-008 BR-17 แต่เป็นมิติ "ห้อง" แทน "ครู")

- *ถ้อยคำฉบับ 2026-09-23 (เก็บไว้เป็นประวัติ — ถูกแทนแล้ว ไม่ใช่กติกาปัจจุบัน):* "ห้องเรียนพิเศษ/ห้องปฏิบัติการหนึ่งห้อง ต้องไม่ถูกใช้สอนวิชาอื่นซ้อนเวลาเดียวกัน" (แบบไบนารี — 1 ห้อง 1 การสอนต่อช่วงเวลา)
- **กติกาปัจจุบัน (ยืนยันธุรกิจ 2026-09-28, ปิด OQ-15 (ก)(ง); แก้ข้อความให้ตรง 2026-09-29):** ห้องมี **ความจุ (capacity)** — ห้องหนึ่งใช้พร้อมกันได้หลายวิชา/กลุ่มห้องเรียน **ตราบที่ไม่เกิน capacity ของห้องนั้น** ในเวลาเดียวกัน โดยนับรวมทุกตารางสอนของปีเดียวกัน และการใช้ห้องในระบบ `/academic` — รายละเอียดดู AC-038a และ AC-039 · ห้องมี "ครูผู้ดูแลห้อง" ด้วย ผลของครูผู้ดูแลต่อการจัดตารางและที่ตั้งค่า capacity/ครูผู้ดูแล **ยังเปิดอยู่ที่ OQ-26**

**Acceptance criteria:**

- AC-038 — ผู้ใช้กำหนดห้องเรียนประจำวิชาได้ **ต่อวิชา — ความสัมพันธ์ 1 วิชา : 1 ห้อง เท่านั้น ไม่มี pool หลายห้อง** (ยืนยันธุรกิจ 2026-09-28, ปิด OQ-15 (ข)) และเป็นค่าคงที่ตายตัวของวิชา **เปลี่ยนห้องรายเซลล์ตอนวางมือไม่ได้** (ยืนยันธุรกิจ 2026-09-28, ปิด OQ-15 (ค)) · ตั้งค่าที่**หน้า `/timetable/subject-settings` (กติกาวิชา)** (ยืนยันธุรกิจ 2026-09-28, ปิด OQ-15 (จ)) · **แก้ 2026-09-28 (ปิด OQ-24):** ทะเบียนห้องที่เลือกได้ต้อง**อ้างอิง `TRoom` ของ school DB เดิม** (ชุดเดียวกับที่ `/academic` ใช้) ไม่ใช่รายการห้องที่โมดูลนี้สร้างเอง — system-analyst ต้องยืนยัน schema จริงของ `TRoom` เพิ่ม (SA-Q5) และแก้ proxy `ClassroomList/*` เดิมที่ชี้ endpoint ไม่มีจริงให้สอดคล้องกับแหล่งข้อมูลนี้
- **AC-038a (ใหม่, 2026-09-28, ปิด OQ-15 (ก)) — `TRoom` มี capacity ไม่ใช่กติกา "ชนแบบไบนารี":** ผู้ใช้ยืนยันว่าทะเบียนห้องต้องมีฟิลด์เพิ่มอย่างน้อย **(1) ความจุ/จำนวนกลุ่ม-ห้องเรียนที่เข้าร่วมพร้อมกันได้ (capacity)** และ **(2) ครูผู้ดูแลห้อง** — ห้องพิเศษหนึ่งห้องจึงรองรับได้ **มากกว่า 1 วิชา/กลุ่มห้องเรียนพร้อมกัน ถ้ายังไม่เกิน capacity** (เช่น ห้องแล็บ capacity 3 = ป.1/1+ป.1/2+ป.1/3 เรียนพร้อมกันในคาบเดียวได้โดยไม่ถือว่าห้องชน) — เปลี่ยนแบบจำลอง AC-039 จาก "ห้องเดียวใช้ได้ 1 วิชา/ครั้ง" เป็น "นับจำนวนการจองพร้อมกันเทียบกับ capacity" **schema/รายละเอียด field ให้ system-analyst ออกแบบต่อ**
- AC-039 — ห้องเดียวกันต้องไม่ถูกจัดสอนเกิน **capacity** ของห้องนั้นในเวลาเดียวกัน (แก้จาก "ห้ามซ้อนเวลาเดียวกันเลย" เป็น "ห้ามเกิน capacity" ตาม AC-038a) **ข้ามตารางสอนทุกชุดของปีเดียวกัน** (ไม่ใช่แค่ภายในตารางชุดที่กำลังแก้) ทั้งตอน Generate อัตโนมัติและวางมือ — เทียบเท่าขอบเขตกันครูชนของ BR-17 (ยืนยันธุรกิจ 2026-09-23, ปิด OQ-9) — ละเมิดต้องถูกปฏิเสธเหมือน AC-019 · **แก้ 2026-09-28 (ปิด OQ-15 (ง)):** การตรวจนี้ต้อง**นับรวมการใช้ห้องในระบบตารางสอนเก่า `/academic` ด้วย** (cross-system check) ไม่ใช่แค่ภายในโมดูลนี้ — ห้องเดียวกันถูกจองใน `/academic` แล้วจึงถือว่าห้องนั้นไม่ว่างสำหรับโมดูลนี้ด้วย
- AC-040 — วิชาที่ไม่ได้กำหนดห้อง (เช่น สอนในห้องเรียนประจำของนักเรียนเอง) ไม่ถูกบังคับกติกานี้

**หมายเหตุสำคัญ — ต้องส่งต่อ system-analyst ก่อน implement:** เป็น **schema change** (ไม่มีคอลัมน์/ความสัมพันธ์ "ห้องต่อวิชา" ใน as-built ปัจจุบัน — design.md §12 DES-004) เข้าเงื่อนไข "Adds or alters a field/table/relation" ของ pipeline routing (system-analyst amend → test-planner → engineer → qa-engineer +security) · ตรรกะกันชนห้องต้องตรวจข้ามตารางสอนทุกชุดของปี **และข้ามระบบไปยัง `/academic`** (เทียบ BR-17) — เพิ่มภาระ query/index และการเชื่อมต่อข้ามระบบ ให้ system-analyst ออกแบบ query path และวิธีอ่านข้อมูลการจองห้องจาก `/academic` (cross-backend read)

**ข้อค้นพบจากโค้ดที่ยังไม่ commit (SA — design.md §38, D42, EVD-048/050/051; บันทึก 2026-09-28):** โครง "ห้อง" ในหน้า generate ค้างอยู่ครึ่งทาง — proxy `/api/classroom-list/get|set` ชี้ไป endpoint `ClassroomList/*` ที่**ไม่มีอยู่จริง**ใน backend และฟิลด์เดิม `nClassroomID` เป็น `int` ซึ่งชนิดไม่ตรงกับคีย์ `sRoomID` (varchar) ของทะเบียนห้อง `TRoom` ใน school DB · ~~SA เสนอให้ "ห้อง" = แถวของ `TRoom` — ข้อเสนอเท่านั้น ยังไม่ใช่การยืนยันทางธุรกิจ~~ · *แก้ 2026-09-29:* ข้อเสนอนี้**ยืนยันธุรกิจแล้ว 2026-09-28** — ทะเบียนห้องอ้าง `TRoom` (ปิด OQ-24, AC-038) และกติกาย่อยของห้องปิดแล้ว (ปิด OQ-15, AC-038/AC-038a/AC-039) · ที่ยังเปิด: schema จริงของ `TRoom` = SA-Q5 (technical) · คำถามธุรกิจต่อเนื่อง = OQ-26

**หมายเหตุข้อเท็จจริงจากการออกแบบ (design.md Rev 6 §38 DES-013, D46, D47, EVD-072..EVD-075 — ไม่ใช่ requirement ใหม่ ไม่เปลี่ยน AC ใด):**

- `TRoom` (จาก dump ที่ล้าสมัย — D24) มีเพียง `sRoomID`, `sRoomName`, `cDel`, `SchoolID` + audit — **ไม่มีคอลัมน์ความจุหรือครูผู้ดูแลห้อง** (EVD-072) · ฟิลด์ที่ AC-038a ต้องการจึงยังไม่มีที่เก็บใน school DB ที่ทราบ — ที่เก็บเป็นคำถามเทคนิค/อำนาจอนุมัติ SA-Q9
- `TSchedule` ของ `/academic` (dump) **ไม่มีคอลัมน์ห้อง** ขณะที่ Service Academic รับ/คืน `roomId` — ที่เก็บห้องจริงของ `/academic` ยังไม่ทราบ (D46)
- Service Academic ที่มีวันนี้ **ไม่มี endpoint อ่านการใช้ห้องตาม `roomId`** — รวบรวมด้วย API ปัจจุบัน = N+1 ต่อแถวของเทอม ซึ่ง SA ไม่ยอมรับ (D47) · read path ของการนับห้องข้าม `/academic` (AC-039) จึงต้องรอเจ้าของระบบยืนยันที่ SA-Q10
- ผลต่อผู้อ่าน requirement: AC-038a/AC-039 **ยังเป็นข้อกำหนดเดิมครบ** แต่ implement ได้ต่อเมื่อประตูเทคนิค SA-Q5/SA-Q9/SA-Q10 + schema confirmation ปิด (design.md §38 สถานะสัญญา) · ค่า default "ห้องที่ไม่ได้ตั้งความจุ → K = 1" ใน design.md BR-54 เป็น**ข้อเสนอของ SA** ที่รอยืนยันพร้อม schema confirmation — ยังไม่ใช่คำตอบทางธุรกิจ
