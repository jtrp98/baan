## ทำไมเป็นไฟล์ใหม่ ไม่รวมใน UX-004

UX-004 = ข้อความที่ผู้ใช้เห็นเมื่อ **API** ตอบ 401/403 (toast / Alert / สถานะ error ของหน้า) · UX-006 = **component ของ Sidebar** ที่ไม่แสดงข้อความ 401/403 เลย และมีวงจรสถานะของตัวเอง (hook: `loading` / `ready` / `checkFailed` → รายการ: enabled / noPermission / loading / checkFailed) จึงเซ็นแยกได้ — ผู้ใช้อาจแก้ copy 403 ใน UX-004 โดยไม่กระทบหน้าตาเมนู และกลับกัน · UX-004 อ้าง UX-006 ในหัวข้อ "การปรับให้สอดคล้องกับเมนูปิด"

## ปัญหาที่ร่างนี้แก้

ผู้ไม่มีสิทธิ์เห็นเมนูแล้วกดเข้าไปโดน 403 (D53) — ตัดสินแล้วให้แสดง **ปิดใช้งาน ไม่ซ่อน ไม่ใช่กดแล้ว 403** ร่างนี้กำหนดหน้าตา ข้อความอธิบาย คีย์บอร์ด/a11y และสถานะ loading/error ให้ผู้ใช้ (ครู/ฝ่ายวิชาการ อายุ 30–60 ถนัดเทคโนโลยีกลาง–ต่ำ) เข้าใจว่า "เมนูนี้มีอยู่แต่ใช้ไม่ได้เพราะอะไร" ไม่ใช่ระบบเสีย

## ขอบเขต

- รายการย่อย 5 รายการของส่วน Teaching Schedule (ลำดับและชื่อป้ายตาม as-built — **ไม่เปลี่ยนชื่อ/ลำดับเมนู**) : `/timetable` (401) · `/timetable/manage-timetable` (402) · `/timetable/settings` (403) · `/timetable/create-class-period` (404) · `/timetable/subject-settings` (422) — map เป็นของ BR-86 (config จุดเดียว) UX ไม่กำหนด
- สถานะของรายการ: เปิด · ปิดเพราะไม่มีสิทธิ์ · ปิดระหว่างโหลด · ปิดเพราะตรวจสิทธิ์ไม่สำเร็จ

## ไม่อยู่ในขอบเขต

- เงื่อนไขการแสดง **ส่วน** Teaching Schedule (กลุ่ม Academic "22" — คง as-built ตาม BR-89) · เมนูกลุ่มอื่น
- การซ่อน/ปิดปุ่มเขียนในหน้า (เมนูเปิด = สิทธิ์อ่าน; สิทธิ์เขียนถูก 403 ตาม BR-75 — ดู UX-004; การแสดงปุ่มเขียนอยู่นอกสัญญา DES-022)
- การขอสิทธิ์/ขั้นตอนของผู้ดูแล (ไม่มีกติกาธุรกิจรองรับ — ห้ามแต่ง)
- การพาไป SessionExpired จาก Sidebar (ห้ามตาม §47.3)

## ข้อกำหนด UI

### สถานะของรายการ (ทั้ง 5 รายการมีครบทุกสถานะ)

| สถานะรายการ | เงื่อนไข (DES-022 §47.3) | หน้าตา | พฤติกรรม |
|---|---|---|---|
| เปิด (`enabled`) | hook `ready` · HTTP 200 `status === 1` body ครบ 5 MenuID · `isRead === true` ของ MenuID นั้น | เหมือนรายการเมนูปกติที่มีอยู่ (ไม่แก้ style เดิม) | คลิก/Enter นำทางตามเดิม |
| ปิด — ไม่มีสิทธิ์ (`noPermission`, `disabledReason: "noPermission"`) | hook `ready` · HTTP 200 · `isRead === false` ของ MenuID นั้น — **รวมผู้ใช้ที่ไม่มีสักเมนู** (200 + `isRead:false` ทุกตัว) | ดู "หน้าตาสถานะปิด" + **ไอคอนกุญแจ** ท้ายบรรทัด · ไม่มี spinner/ไอคอนเตือน | ไม่นำทาง · tooltip "ไม่มีสิทธิ์" |
| ปิด — กำลังตรวจสิทธิ์ (`loading`, `disabledReason: "loading"`) | hook `loading` (ยังไม่ได้ผลของการโหลดหน้านี้) | หน้าตาปิดเดียวกัน ไม่มีกุญแจ/ไอคอนเตือน · **spinner เล็กที่หัวกลุ่ม** (`headerIndicator: "loading"`) | ไม่นำทาง · tooltip "กำลังตรวจสอบ" |
| ปิด — ตรวจสิทธิ์ไม่สำเร็จ (`checkFailed`, `disabledReason: "checkFailed"`) | hook `checkFailed`: HTTP 401, **HTTP 403**, 5xx, network, timeout, `status !== 1`, body ผิดรูป, **ขาด MenuID ใดใน 5 ตัว** | หน้าตาปิดเดียวกัน + **ไอคอนเตือน** (รูปทรงต่างจากกุญแจ ไม่ใช้สีแดง) **ที่ทุกรายการ และที่หัวกลุ่ม** (`disabledReason` รายรายการ + `headerIndicator: "checkFailed"` — ผู้ใช้ตัดสิน 2026-09-30) — **ต้องแยกแยะจาก noPermission ได้ทั้งด้วยรูปทรงไอคอนและข้อความ ไม่พึ่งสีอย่างเดียว** | ไม่นำทาง · tooltip ให้โหลดหน้าใหม่ · **ไม่ retry อัตโนมัติ** |

- **HTTP 403 จาก `MenuPermissions/Get` = checkFailed ไม่ใช่ noPermission** (Rev 14: endpoint เป็น authenticated-only; "ไม่มีสิทธิ์" มาจาก 200 + `isRead:false` เท่านั้น) — ห้ามแสดงกุญแจ/ข้อความ "ไม่มีสิทธิ์" เมื่อเจอ 401/403/error
- สถานะทั้งกลุ่มมาจากผลเดียวของการโหลดหน้า: `loading` และ `checkFailed` ปิด **ทั้ง 5 รายการ**; `enabled`/`noPermission` ตัดสินรายรายการ · หัวกลุ่มมีตัวบ่งชี้เฉพาะ `loading` และ `checkFailed` (ไม่มีตัวบ่งชี้ตอน ready)

Fail-closed: ห้ามมีสถานะใดที่รายการ "เปิด" ก่อนรู้ผล หรือเมื่อผลผิดปกติ (§47.3, BR-88)

### หน้าตาสถานะปิด (ใช้ token ของ design system เท่านั้น — ไม่สร้างสีใหม่)

- ข้อความ + ไอคอนรายการ: `Text/Tertiary` `#7B8F9C` บนพื้น Sidebar `#1F262D` (รายการเปิดยังใช้สีข้อความเดิมของ Sidebar) — **ต้องตรวจ contrast จริงบน Sidebar ให้ ≥ 4.5:1 ตามเกณฑ์ AA ของ skill** (ค่านี้ประมาณ 4.5:1 คำนวณมือ ไม่ได้วัดด้วยเครื่องมือ — ถ้าไม่ผ่านให้แจ้ง UX ก่อนเลือกสีอื่น ห้ามสร้างสีนอก token) — ผู้ใช้ต้องอ่านชื่อเมนูที่ปิดได้ เพราะเป็นข้อมูล ไม่ใช่ของตกแต่ง
- ไม่มีพื้น hover; ตัวชี้เมาส์ `cursor: not-allowed` · **ข้อยกเว้น "หน้าปัจจุบัน"** (ผู้ใช้ตัดสิน 2026-09-30): รายการปิดที่ตรงกับหน้าที่เปิดอยู่ (เข้าด้วย URL ตรง) แสดง highlight "คุณอยู่หน้านี้" แต่ยังคลิกไม่ได้ — ใช้ตัวบ่งชี้หน้าปัจจุบันแบบเดียวกับรายการ Sidebar เดิม (ข้อเสนอ: แถบ/พื้นด้วย token `Border/Secondary` `#09C6DD`; ตรวจรูปแบบจริงกับ as-built) + `aria-current="page"` · สีข้อความยังเป็นสีสถานะปิด และมีไอคอนกุญแจ/tooltip "ไม่มีสิทธิ์" ครบ (ไม่ให้ highlight ถูกอ่านว่าใช้งานได้)
- ไอคอนกุญแจ (ไอคอนต้องมาจากชุดที่ Sidebar ใช้อยู่ — skill ไม่ระบุ icon set) ขนาดเดียวกับไอคอนรายการ วางท้ายบรรทัด **จองพื้นที่ไว้ทุกสถานะ** เพื่อกันเลย์เอาต์ขยับเมื่อผลโหลดเสร็จ · ความหมายไม่พึ่งสีอย่างเดียว (ไอคอน + tooltip + `aria-disabled`)
- ไม่ซ่อนชื่อรายการ ไม่ตัดคำด้วย `…` ถ้าป้ายยาวให้ wrap ในความกว้าง Sidebar 348px (ทดสอบ extreme text: ป้าย TH ยาวสุด และ EN)
- ไม่มี animation/transition ตกแต่ง (skill §16); เปลี่ยนสถานะทันที (`prefers-reduced-motion` เคารพโดยปริยาย)
- Touch target ≥ 48px สูงเท่ารายการเดิม

### Tooltip / ข้อความอธิบาย (ถ้อยคำเป็น **ข้อเสนอ** รอเซ็น)

| สถานะ | TH | EN |
|---|---|---|
| ไม่มีสิทธิ์ | ไม่มีสิทธิ์ใช้งานเมนูนี้ | You don't have permission for this menu. |
| กำลังตรวจสอบ | กำลังตรวจสอบสิทธิ์… | Checking permissions… |
| ตรวจสอบไม่สำเร็จ | ตรวจสอบสิทธิ์ไม่สำเร็จ — โหลดหน้าใหม่เพื่อลองอีกครั้ง | Couldn't check permissions — reload the page to try again. |

- "ไม่มีสิทธิ์" ใช้ถ้อยคำเดียวกับ 403 ของ **หน้า/action** ใน UX-004 โดยตั้งใจ (ผู้ใช้เห็นเหตุผลเดียวกันไม่ว่าจะเจอที่เมนูหรือที่หน้า) — ที่ Sidebar ข้อความนี้มาจาก 200 + `isRead:false` เท่านั้น ไม่ใช่จาก HTTP 403 — ถ้าผู้ใช้แก้ copy ใน UX-004 ให้แก้ที่นี่ตาม
- ข้อความ "ตรวจสอบไม่สำเร็จ" บอกสาเหตุ + วิธีแก้ ตามกติกา Error ของ skill §14 · ไม่แสดงรหัส/สถานะ HTTP/MenuID แก่ผู้ใช้ปลายทาง · **ไม่แยกข้อความ 401 กับ 5xx** (401 ในสถานะนี้ให้หน้าที่เปิดอยู่จัดการเอง ตาม UX-004)
- ไม่แสดง toast/Alert/modal จาก Sidebar ในทุกสถานะ — ความล้มเหลวของการตรวจสิทธิ์ไม่ขัดจังหวะงาน (เมนูปิดคือสัญญาณ) · ระบบ log ฝั่ง engineering ตาม §47.3

### Loading (โหลดสิทธิ์ครั้งเดียวต่อการโหลดหน้า (full page load) — BR-89 Rev 14)

- ผลเก็บในหน่วยความจำตลอดอายุหน้า: Sidebar remount / เปลี่ยน route / เปลี่ยนภาษา ใช้ผลเดิม **ไม่กลับไปแสดง loading ซ้ำ** และไม่มี refetch — UI ต้องไม่ออกแบบรอบ "ลองใหม่" ใด ๆ
- แสดงรายการครบ 5 ทันทีในสถานะ "ปิด — กำลังตรวจสิทธิ์" (ไม่ซ่อน ไม่ว่างเปล่า) เพื่อกันเลย์เอาต์กระโดด; ส่วนหัวของกลุ่ม Teaching Schedule มี Spinner ขนาดเล็กท้ายหัวข้อ (`headerIndicator: "loading"`; skill §14 "Loading = Spinner") จนกว่าจะรู้ผล และตั้ง `aria-busy="true"` ที่ container ของ 5 รายการ · spinner มีข้อความสำหรับ screen reader ("กำลังตรวจสอบสิทธิ์") · เมื่อผู้ใช้ตั้ง `prefers-reduced-motion` spinner ที่หัวกลุ่ม **เปลี่ยนเป็นตัวบ่งชี้แบบนิ่ง** (เช่น ไอคอนนาฬิกาทรายหรือจุดสามจุด) ไม่มีการเคลื่อนไหว (ผู้ใช้ตัดสิน 2026-09-30)
- เมื่อรู้ผล: รายการสลับสถานะทันที **ไม่ประกาศ** การเปลี่ยนแก่ screen reader (ไม่ใช่ข้อมูลเร่งด่วน) — ยกเว้น tooltip/คำบรรยายของรายการที่ผู้ใช้โฟกัสอยู่ให้ปรับตามสถานะใหม่
- ผู้ใช้ที่มีสิทธิ์จะเห็นรายการปิดชั่วครู่ก่อนเปิด (ยอมรับตาม design "Compatibility") — ไม่ใส่ delay/animation เพื่อกลบ

### Error state

- ตามตารางสถานะรายการ (`checkFailed`): ทั้ง 5 ปิด + ไอคอนเตือนที่ **หัวกลุ่มและทุกรายการ** + tooltip "ตรวจสอบสิทธิ์ไม่สำเร็จ — โหลดหน้าใหม่…" · หยุด Spinner
- ไม่มีปุ่ม "ลองใหม่" ใน Sidebar และไม่ retry อัตโนมัติ (Rev 14: ความพยายามครั้งถัดไป = ผู้ใช้ reload หน้าเท่านั้น) — คำแนะนำ "โหลดหน้าใหม่" อยู่ใน tooltip
- **ผู้ใช้ที่ไม่มีสักเมนูไม่ใช่ error state** — Rev 14: backend ตอบ 200 + `isRead:false` ทุก MenuID → แสดง `noPermission` (กุญแจ) ทั้ง 5 · ส่วน HTTP 401/403 จาก endpoint นี้ = `checkFailed` (ไม่ใช่ "ไม่มีสิทธิ์") — **แก้ข้อความเดิมของร่างนี้ที่เคยตีความ 403 เป็น "ไม่มีสิทธิ์"**

### คีย์บอร์ด / Accessibility (WCAG 2.1 AA)

- รายการปิด **ยังอยู่ใน tab order และรับ focus ได้** (รูปแบบ `aria-disabled="true"` ไม่ใช่ attribute `disabled` ที่ข้ามรายการ) — เพื่อให้ผู้ใช้คีย์บอร์ดและ screen reader ทราบว่ารายการมีอยู่และรับเหตุผลได้
- ไม่มี `href` ที่ใช้งานได้ (BR-89): เรนเดอร์เป็นองค์ประกอบที่ไม่ navigate (ข้อเสนอ: `role="link"` + `aria-disabled="true"` + `tabIndex={0}` เพื่อคงความหมาย "ลิงก์ที่ใช้ไม่ได้" ให้ screen reader) · Enter/Space/คลิก/แตะ = ไม่ทำอะไรนอกจากแสดงคำอธิบาย (`preventDefault`)
- เหตุผลผูกด้วย `aria-describedby` ไปยังข้อความตามตาราง tooltip (screen reader ได้ยิน: ชื่อเมนู · ปิดใช้งาน · เหตุผล) — ต้องไม่พึ่ง tooltip เมาส์อย่างเดียว
- Tooltip แสดงเมื่อ **hover และ keyboard focus** ทั้งคู่; ปิดด้วย `Esc` โดยไม่ย้าย focus; บนแท็บเล็ต/จอสัมผัส การแตะรายการปิดแสดงคำอธิบายเดียวกัน (ไม่ต้อง hover)
- Focus ring มองเห็นได้บนพื้นเข้ม: เส้นขอบ `Border/Secondary` `#09C6DD` ≥ 2px มุมโค้ง 12px — ใช้กับทั้งรายการเปิดและปิด (ความเปรียบต่างของ ring ต้องตรวจจริง ≥ 3:1 ตาม WCAG 1.4.11)
- ห้ามใช้สีอย่างเดียวสื่อสถานะ (มีไอคอน + ข้อความคำอธิบาย + `aria-disabled`) · ข้อความ Tooltip: ตัวอักษร Body S1 14/28 ขึ้นไป (ผู้ใช้ 30–60 ปี — ข้อเสนอ Body Regular 16/32) ฟอนต์ TH Sarabun New
- ลำดับ tab ตามลำดับเมนูเดิม ไม่ถูกสลับตามสิทธิ์

### Edge cases

- เปิดหน้าด้วย URL ตรงของหน้าที่รายการเมนูปิดอยู่: หน้าโหลดแล้วได้ 403 จาก API → แสดงตาม UX-004 · รายการนั้นใน Sidebar ยังปิด (คลิกไม่ได้) แต่ไฮไลต์เป็น "หน้าปัจจุบัน" + `aria-current="page"` (ผู้ใช้ตัดสิน 2026-09-30)
- ผู้ใช้ที่สิทธิ์ถูกถอนขณะใช้งาน: เมนูคงสถานะจากตอนโหลดหน้าจน reload หน้า (ผลอยู่ในหน่วยความจำ ไม่ refetch; ห้าม cache ลง `localStorage` — BR-89) · action ที่โดน 403 ใช้ UX-004
- response ขาด MenuID ใดใน 5 ตัว → `checkFailed` ทั้งกลุ่ม (§47.3 Rev 14) · MenuID ที่ backend ไม่มีใน `TMenu` (SA-Q14) → backend คืน `isRead:false` → `noPermission` เฉพาะรายการนั้น (Fallback ของ DES-022)
- endpoint ยังไม่ deploy (404) → `checkFailed` (ไม่ใช่ "ไม่มีสิทธิ์" และไม่ใช่ "เปิดทั้งหมด")
- Sidebar แบบหุบ/ไอคอนล้วน (ถ้ามีใน as-built — **ยังไม่ได้ตรวจโค้ดเอง**): tooltip ต้องแสดงชื่อเมนู + เหตุผล และรายการปิดต้องมีสัญญาณต่างจากรายการเปิด

## Decided by user 2026-09-30 (ตอบในแชต — ยังเป็นร่าง ไม่มีผู้เซ็น)

- รายการปิดที่ตรงกับหน้าปัจจุบัน (URL ตรง): **ไฮไลต์เป็น "คุณอยู่หน้านี้" แต่คลิกไม่ได้** (ดู "หน้าตาสถานะปิด" และ Edge cases)
- tooltip "ไม่มีสิทธิ์": **ไม่มีบรรทัด "ติดต่อผู้ดูแลระบบ"** (ตามตารางข้างบน)
- **Loading:** ทุกรายการปิด + Spinner ขนาดเล็กที่หัวกลุ่ม (ตามที่ร่างไว้)
- **ตรวจสิทธิ์ไม่สำเร็จ:** ปิด + ไอคอนเตือน + tooltip ให้โหลดหน้าใหม่ · **ไม่ retry อัตโนมัติ** (ตามที่ร่างไว้)

- **`prefers-reduced-motion`:** spinner ที่หัวกลุ่มเปลี่ยนเป็นตัวบ่งชี้ **แบบนิ่ง** (เช่น นาฬิกาทราย หรือจุดสามจุด) ไม่มีการเคลื่อนไหว
- **`checkFailed`:** ไอคอนเตือนที่ **ทั้งหัวกลุ่มและทุกรายการเมนู** (ตรง `headerIndicator` + `disabledReason` รายรายการของ Rev 14)

## Open for user

2. **ไอคอนกุญแจ/เตือน**: ยืนยันชุดไอคอนของ Sidebar จริง (skill ไม่กำหนด icon set) · ยืนยัน contrast `#7B8F9C` บน `#1F262D` ด้วยเครื่องมือก่อน implement (ยังไม่ได้วัด)
