# REQ-012 — 8. การแทรกคิวงานเร่งด่วน — `TCrmQueueInterrupt`

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `index.md` เท่านั้น

ไม่ห้ามแทรกคิว แต่ต้องแสดงต้นทุนก่อนอนุมัติเสมอ: มูลค่า/ความเสี่ยงทางธุรกิจ (`BusinessJustification`), งานที่ถูกเบียดออกพร้อมจำนวนโรงเรียนที่รอ (`BumpedItems` เก็บเป็น JSON snapshot), ผลกระทบเป็นจำนวนวันที่ล่าช้า (`EstimatedDelayDays`) — การอนุมัติต้องมีชื่อผู้อนุมัติกำกับเสมอ (`ApprovedBy` บังคับ NOT NULL) พร้อม `Decision` (`APPROVED`/`REJECTED`) + เหตุผล และสรุปเป็นรอบ (เช่นรายไตรมาส) เพื่อใช้ขอทรัพยากรเพิ่ม/กันเวลาแก้ tech debt — ผูกกับ `TCrmIssue` ที่ถูกขอแทรกคิว

**Acceptance criteria:**
- AC-012.1: คำขอแทรกคิวทุกรายการแสดงต้นทุนก่อนอนุมัติเสมอ: เหตุผล/ความเสี่ยงทางธุรกิจ (`BusinessJustification`), งานที่ถูกเบียดออกพร้อมจำนวนโรงเรียนที่รอ (`BumpedItems`), และผลกระทบเป็นจำนวนวันที่ล่าช้า (`EstimatedDelayDays`)
- AC-012.2: การอนุมัติทุกครั้งมีชื่อผู้อนุมัติ (`ApprovedBy` บังคับกรอก) พร้อม `Decision` (`APPROVED`/`REJECTED`) และเหตุผล — ไม่มีคำขอใดอนุมัติได้โดยไม่ระบุผู้อนุมัติ
- AC-012.3: คำขอแทรกคิวทุกรายการถูกผูกกับ `TCrmIssue` ที่ถูกขอแทรกคิว
