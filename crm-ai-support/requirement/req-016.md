# REQ-016 — 12. บทบาทหน้าที่ — `TCrmStaffRole`

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `requirement\index.md` เท่านั้น

ตารางแยกสำหรับติดตาม "ใครทำหน้าที่อะไร" ในฟีเจอร์นี้ (`FunctionalRole`: `CS`/`SA`/`UX_UI`/`PM`/`DEV`/`SALES`) — หนึ่งคนถือได้หลายแถว (multi-role) ใช้เพื่อ**การมอบหมายงาน/แสดงผลรายชื่อ** (เช่น SA คนไหนบ้างที่มอบหมาย Issue ให้ได้) **ไม่ใช่กลไกตรวจสิทธิ์เข้าถึง API** — การตรวจสิทธิ์ยังใช้ `PERMISSIONS.CRM_AI_*` ที่มีอยู่แล้วเหมือนเดิม (สองระบบทำงานคนละหน้าที่ ไม่ทับซ้อนกัน)

**Acceptance criteria:**
- AC-016.1: หนึ่งคนถือได้หลายบทบาทพร้อมกัน (หลายแถวต่อคน) โดย `FunctionalRole` เป็นหนึ่งใน `CS`/`SA`/`UX_UI`/`PM`/`DEV`/`SALES`
- AC-016.2: `TCrmStaffRole` ใช้เพื่อการมอบหมายงาน/แสดงผลรายชื่อเท่านั้น — การตรวจสิทธิ์เข้าถึง API ยังใช้ `PERMISSIONS.CRM_AI_*` เดิม (ไม่ใช้ตารางนี้ตรวจสิทธิ์)
- AC-016.3: มอบหมายงานให้ผู้ใช้ที่ยังไม่มีสิทธิ์ CRM AI ไม่ได้ — ต้องให้สิทธิ์ก่อนเสมอ (ผลที่ยอมรับแล้วของการ derive จากสิทธิ์)

> Core Feature เดิมข้อ 9 "Case Monitor Dashboard & Analytics" ถูกย้ายออกไปเป็น module ใหม่ `crm-case-dashboard` แล้ว — ดู § Change Log (เลขข้อ Core Feature ใหม่ข้างบนนี้ไม่ชนกันเพราะเลขเดิมข้อ 9 ถูกปลดไปแล้ว)

## Scope

**(แก้ 2026-08-16) ไม่มีการแบ่ง MVP/Later อีกต่อไป — ผู้ใช้ยืนยันให้ปลดล็อคทุกตาราง/บทบาท/ฟีเจอร์ตาม `hkt-5-crm-ai-script.txt` พร้อมกันหมด** ครอบคลุมทั้งหมดนี้:
- AI จำแนกเคส 4 ประเภท (BUG/FEATURE/TASK/QA) + เมนู + ความรุนแรง พร้อมเหตุผล+ความมั่นใจ (§ Core Feature 2, 4b)
- กลไกบังคับความปลอดภัย (safety-keyword override) (§ 3)
- คิวตรวจสอบโดยคนแบบ per-dimension (§ 5b)
- Backfill เคสเก่า ~70k เคส (§ 4c)
- Audit log ของทุกการตัดสินใจ AI
- ทุกบทบาท: CS, SA, PM, UX/UI, Dev, Sales
- กลไกเรียนรู้เบื้องหลังเต็มรูปแบบผ่าน `TCrmAiSuggestion` (§ 7)
- การแทรกคิวงานเร่งด่วนผ่าน `TCrmQueueInterrupt` (§ 8)
- แคตตาล็อกฟีเจอร์กลางผ่าน `TCrmProductFeature` (§ 9)
- ความสัมพันธ์ระหว่างเมนูผ่าน `TCrmMenuRelation` (§ 10)
- คำสัญญาลูกค้าผ่าน `TCrmCustomerPromise` (§ 11)
- บทบาทหน้าที่ผ่าน `TCrmStaffRole` (§ 12 — เสริม ไม่แทนที่ระบบ permission เดิม)
- AI provider: Gemini
- **Gate ก่อนเปิดใช้งานจริง**: cleanup ข้อมูล Request เดิมที่สะสมไว้ ~500 รายการให้เสร็จก่อน launch เพื่อให้ "ค้นไม่เจอ = ไม่มีจริง" เชื่อถือได้ 100% ตั้งแต่วันแรก (ยอมรับการเปิดใช้งานช้าลงเพื่อแลกกับความน่าเชื่อถือนี้)
- ไม่มีกำหนดเส้นตายตายตัว

**ยังไม่เอาเข้า scope นี้ (จากเอกสารต้นฉบับเต็มที่ไม่ใช่ `hkt-5-crm-ai-script.txt`)**: ตาราง SLA/Contract-tier แบบ configurable, `TCrmCaseSubType`, `IsDuplicate` flag — ดู § Declined / Not Pursuing (ยังยืนกรานตามเดิม ไม่เปลี่ยน)

## Constraints & Assumptions

- Dev ต้องไม่เปลี่ยนวิธีทำงาน — ยังทำงานในระบบ Backlog เดิม ระบบ CRM sync ข้อมูลเข้าออกให้เอง (ผลกระทบนี้อยู่ใน Phase 2+ เมื่อเปิดสิทธิ์ให้ Dev)
- ข้อมูลเมนูที่ใช้ค้น/แสดงผลต้องกรองเฉพาะเมนูที่ "เปิดใช้งานจริง" เท่านั้น — มีคอลัมน์ชื่อคล้ายกันในระบบเดิมที่สะกดผิดอยู่ ต้องระวังไม่ใช้ผิดตัว (รายละเอียดคอลัมน์จริงให้ system-analyst ตรวจกับ schema-map ก่อนล็อก design)
- AI provider ล็อกที่ Gemini สำหรับ Phase 1
- ช่วงเปลี่ยนผ่านของ CS: เปิดฟีเจอร์ที่ให้ประโยชน์กับ CS ก่อน (คำตอบที่เตรียมไว้ให้) แล้วค่อยเพิ่มขั้นตอนขอให้ CS ตรวจสอบ/ยืนยันทีหลัง เพื่อลดการต่อต้าน
- ทีม CS ควรมีส่วนร่วมออกแบบหมวดหมู่ย่อยของเคสตั้งแต่ต้น

## Declined / Not Pursuing

- **ตาราง SLA/Contract-tier แบบ configurable** (`TCrmSlaSetting`/`TCrmSeverityLevel`/`TCrmContractTier`/`TCrmCompanyContract`) จากเอกสารต้นฉบับเต็ม `School-Bright-CRM-AI-Design-Summary (4).md` — ผู้ใช้ยืนยันวันที่ 2026-08-16 ว่า**ยึด `_docs/hkt/hkt-5-crm-ai-script.txt` เป็น scope เดียวเท่านั้น ไม่เพิ่มตารางจากเอกสารต้นฉบับเต็ม** สูตร priority score จึงยังเป็น code constant (`crm-sla-rule.constant.ts`) ต่อไป ไม่แปลงเป็นตาราง — ระดับสัญญาลูกค้า (contract tier) ยังไม่มีแหล่งข้อมูลจริงเหมือนเดิม (multiplier คงที่ 1.0) — **ตามมาด้วยมติ 2026-08-18: เลิกใช้ตัวคูณระดับสัญญาในสูตร priority ถาวร แทนด้วยตัวคูณจำนวนโรงเรียน (§ Core Feature 2b)** ถ้าวันหนึ่งมีแหล่งข้อมูลระดับสัญญาจริง ต้องเปิดเป็น requirement ใหม่ ไม่ใช่ย้อนสูตรเก่ากลับมาเงียบ ๆ
- **`TCrmCaseSubType` (root cause ย่อยกว่า category) และ `IsDuplicate`/`DuplicateOfCaseId` flag** จากเอกสารต้นฉบับเต็มเดียวกัน — ผู้ใช้ยืนยันให้ยึด `hkt-5-crm-ai-script.txt` เป็น scope เดียวกันเช่นกัน ไม่เพิ่มสองแนวคิดนี้เข้า MVP ตอนนี้
