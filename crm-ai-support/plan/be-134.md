# BE-134 — apply การตัดสินใจรายมิติ

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

Original Task ID: `BE-crm-ai-support-P1-22`

## Goal

แก้ `review-queue.service.ts`/`review-queue.repository.ts` ให้ apply การตัดสินแต่ละมิติอิสระต่อกัน อัปเดต `TCrmSupport`/`TCrmCaseAiAssessment` เฉพาะมิติที่เปลี่ยน เขียน `TCrmAiDecisionLog` แยกต่อมิติที่ถูกรีวิว (ไม่รวมเป็นก้อนเดียวเหมือนเดิม) — คนตัดสินเฉพาะมิติที่เห็นปัญหา — ถ้า apply รวมก้อนเดียวจะทับมิติอื่นที่คนยังไม่ได้ตัดสิน

## References

REQ-009, AC-009.1, AC-009.2, DES-003, DEC-003

## Scope

apply เฉพาะมิติที่ส่งมา — มิติที่ไม่ส่งคงค่าเดิมทุกคอลัมน์ · log แยกแถวต่อมิติที่ถูกตัดสิน

- Security-sensitive: yes

## Out of Scope

มิติที่ไม่ได้ส่งใน request (ห้ามเขียนทับ) · `*ReviewedBy`/`*ReviewedAt` ของกลไกอัตโนมัติ · แถว log เดิม

## Expected Output

none

## Acceptance

AC-009.1: การตัดสินแต่ละมิติ apply อิสระ — มิติอื่นไม่ถูกแตะ
AC-009.2: ทุกมิติที่ถูกตัดสินมี log แยกของตัวเอง — audit ต่อมิติได้จริง

## Dependencies

—

## Handoff

ตรวจ AC-009.1/AC-009.2 ด้วยการส่งการตัดสินบางมิติแล้วเทียบ DB ว่ามิติอื่นคงเดิม + log แยก — สถานะ verified ตามแถวเดิม หลักฐานรอบตรวจเก็บอยู่กับโมดูล (review.md/review/ และ Change Log)
แก้ service/repository เดิม — revert ได้ (ข้อมูลที่ apply แล้วเป็นการตัดสินของคน ไม่ย้อนอัตโนมัติ)
ส่งต่อ reviewer
