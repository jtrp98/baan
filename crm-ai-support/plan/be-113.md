# BE-113 — PATCH /review-queue/[id] confirm/override

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

Original Task ID: `BE-crm-ai-support-P1-13`

## Goal

เพิ่ม `PATCH /api/v2/support/crm-ai/review-queue/[id]` — คนยืนยัน (`CONFIRMED`) หรือแก้ไข (`OVERRIDDEN`) ผลจำแนก เขียน `ReviewedBy`/`ReviewedAt` + แถวใหม่ลง `TCrmAiDecisionLog` (คอลัมน์ append-only เดิมห้ามแก้) — การตัดสินใจของคนต้องมีตัวตน+เวลา+audit คู่ทุกครั้ง และห้ามแก้ประวัติเดิม — คิวตรวจจึงเชื่อถือได้

## References

REQ-009, AC-009.1, DES-001, DEC-001, DES-003, DEC-003

## Scope

endpoint ตัดสินใจของคน — เขียน `{Dim}ReviewStatus` + `{Dim}ReviewedBy` + `{Dim}ReviewedAt` พร้อมกัน · กลไกอัตโนมัติห้ามเขียน `*ReviewedBy`/`*ReviewedAt` (DEC-003)

- Security-sensitive: yes

## Out of Scope

แถว decision log เดิม (append-only) · การให้กลไกอัตโนมัติเขียน `*ReviewedBy`/`*ReviewedAt` แทนคน

## Expected Output

none

## Acceptance

AC-009.1: คนตรวจตัดสินผลจำแนกบนคิวได้จริง — ทุกการตัดสินมีผู้รีวิว/เวลา/audit คู่กัน

—

## Handoff

ตรวจ AC-009.1 ด้วย dev server: CONFIRMED/OVERRIDDEN เขียนสถานะ+ผู้รีวิวถูกต้อง + decision log มีแถวใหม่ — สถานะ verified ตามแถวเดิม หลักฐานรอบตรวจเก็บอยู่กับโมดูล (review.md/review/ และ Change Log)
endpoint ใหม่ additive — revert รายไฟล์ได้ (การตัดสินที่บันทึกแล้วเป็นข้อมูลของคน ไม่ย้อนอัตโนมัติ)
