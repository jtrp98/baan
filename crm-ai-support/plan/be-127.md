# BE-127 — ค่า REJECTED ทุกคอลัมน์ review status

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `project-manager` · Owner/Phase/Depends/Status → `plan\index.md` (index ชนะ)

Original Task ID: `BE-crm-ai-support-P1-15`

## Goal

เพิ่มค่า `REJECTED` ในทุกคอลัมน์ review status (`ReviewStatus`/`MenuReviewStatus`/`SeverityReviewStatus` บน `TCrmCaseAiAssessment`) — คง VARCHAR เดิม ไม่ต้องแก้ schema แค่ app-layer รับค่านี้เพิ่ม — ตัวเลือก ไม่ใช้ ของการรีวิวรายมิติต้องมีค่าสถานะของตัวเอง ไม่ปนกับ OVERRIDDEN (แก้ไข) — ค่า NULL จึงยังหมายถึง ยังไม่เคยตัดสิน เท่านั้น

## References

REQ-009, AC-009.2, AC-009.3, DES-003, DEC-003

## Scope

app-layer enum เท่านั้น — ไม่แตะ schema (VARCHAR รับค่าใหม่ได้ทันที) · ค่าใหม่ต้องไหลผ่าน schema/service ของ review-queue ด้วย

- Security-sensitive: yes

## Out of Scope

schema/ตาราง · ความหมายค่า NULL · ค่า enum เดิม (CONFIRMED/OVERRIDDEN/PENDING_REVIEW/NEEDS_HUMAN)

## Expected Output

Contract:CrmAiPerDimensionReview.v1

## Acceptance

AC-009.2: มิติรีวิวมีตัวเลือก ไม่ใช้ (REJECTED) ครบทั้ง 3 มิติ — ค่าถูกรับและเก็บได้จริง
AC-009.3: ค่า REJECTED แยกจาก OVERRIDDEN และจาก NULL — ความหมายไม่ปนกัน
