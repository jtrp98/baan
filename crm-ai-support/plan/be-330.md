## Goal

แก้ `ai-suggestion.service.ts`/`.repository.ts` ให้ accept **มีผลจริง** (ของเดิมเป็นการตีความอนุรักษ์นิยม) — ทุกข้อในทรานแซกชันเดียวกับ `Status=ACCEPTED` + แถวคู่ log (ข้อ 4) ล้ม = rollback ทั้งก้อน ตาม design § ข้อ 6: MERGE_ISSUE/MERGE_REQUEST อ่าน `Payload.evidence_case_ids` (ว่าง → 422) เขียน `IssueId=subject_id` ตามกติกา 4 กลุ่ม (ไม่มี assessment → ข้าม / NULL → เขียน / ตรงอยู่แล้ว → ไม่ทำ / ชี้เรื่องอื่น → ห้ามเขียนทับ) สรุปผลนับลง AiOutput+response รวมได้ 0 → 422 · NEW_KNOWLEDGE สร้าง DRAFT (ห้าม APPROVED อัตโนมัติ, Title/AnswerBody จาก body ก่อน fallback Payload, เกิน 300 ตัวอักษร → 422, ห้ามรับ subject_id จาก request) · STALE_KNOWLEDGE เฉพาะ APPROVED → NEEDS_REVIEW (DRAFT/ARCHIVED → 422, NEEDS_REVIEW ซ้ำ idempotent) · ขอบร่วม: Payload parse ไม่ได้/type นอก 5 ค่า → 422 ไม่มี default branch เงียบ · สิทธิ์ก่อนทรานแซกชัน → 403 · อัปเดต update-spec ให้ตรง — การ accept ต้องเปลี่ยนระบบจริงพร้อม audit ในทรานแซกชันเดียว — กติกา 4 กลุ่มกันการเขียนทับการผูกเรื่องที่คนตั้งใจไว้แล้ว
