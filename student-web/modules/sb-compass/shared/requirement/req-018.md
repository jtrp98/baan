# REQ-018 — เกณฑ์การถอด REQ-005/REQ-007 ออกจากระบบ (trigger-based ไม่ใช่วันที่ตายตัว)

> Budget ≤ 4 KB (`policies\documentation.md` §4) · เขียนโดย `business-analyst` · ไฟล์นี้ = 1 REQ + AC ของมัน · สถานะอยู่ที่ `index.md` เท่านั้น


(ยืนยัน 2026-09-02 — ปิด **OQ-22** ที่ `system-analyst` เปิดไว้ใน `design.md`; ผู้ใช้ตอบ
"ตามคำแนะนำ" คือรับข้อเสนอของ `business-analyst` เป็นการตัดสินใจธุรกิจ)

REQ-005 (จัดอันดับสายการเรียน 8 สาย) และ REQ-007 (แบบทดสอบบุคลิกภาพ 10 ข้อ) ถูกแทนที่แล้วโดย
`sb-compass-faculty-match REQ-011`/`REQ-012` ตามที่บันทึกไว้ในหัวข้อทั้งสองข้างต้น — สิ่งที่ยังไม่เคย
ตัดสินใจมาก่อนคือ **"จะถอดโค้ด/ตาราง/endpoint ของเดิมออกจริงเมื่อไหร่"**

- **ไม่ใช้วันที่ตายตัว ใช้ trigger-based**: ถอด REQ-005/REQ-007 ออกจริง (endpoint ที่เกี่ยวข้อง,
  `TCompassMbtiResult`, `CompassMbtiStore.cs` และจุดอื่นตามที่ `sb-compass/design.md` ระบุไว้)
  ภายใน **N สัปดาห์หลังจาก `sb-compass-faculty-match REQ-011` และ `REQ-012` ขึ้น production จริง**
  (นับจากวัน deploy จริง ไม่ใช่วัน merge โค้ดหรือวันผ่าน QA)
- **N = 4 สัปดาห์ เป็นค่าเริ่มต้นทางวิศวกรรมที่ `business-analyst` เสนอเอง — ผู้ใช้ไม่ได้ระบุจำนวน
  สัปดาห์** (ตอบ "ตามคำแนะนำ" โดยไม่ให้ตัวเลข) → บันทึกเป็น **(assumption — unconfirmed)**
  ใน `## References` ไม่ใช่ค่าที่ผู้ใช้ยืนยัน — ถ้าต้องการเปลี่ยนจำนวนสัปดาห์ ต้องกลับมา amend ข้อนี้
- **เหตุผลของ trigger-based แทนวันที่ตายตัว**: ณ วันที่บันทึกนี้ ของเดิม (REQ-005/REQ-007) ไม่มี
  production traffic แล้ว แต่ของใหม่ (REQ-011/REQ-012) ก็ยังไม่ได้ deploy เช่นกัน — กำหนดวันที่ตายตัว
  ล่วงหน้าเสี่ยงผูกกับ timeline การ deploy ที่ยังไม่แน่นอน ในขณะที่ trigger ที่ผูกกับเหตุการณ์ deploy
  จริงยังคงความปลอดภัยไว้ได้เสมอ (ของเดิมจะไม่ถูกถอดจนกว่าของใหม่พร้อมใช้งานจริงมาแล้วอย่างน้อย N สัปดาห์)
- การติดตามเงื่อนไขนี้และดำเนินการถอดจริงเป็นงานของ `project-manager`/`devops` (ผูกกับ `status.md` ของ
  `sb-compass-faculty-match`) ไม่ใช่การตัดสินใจทางธุรกิจที่ต้องรอผู้ใช้เพิ่มเติมอีก

**Acceptance criteria (ทดสอบได้)**
1. (AC-018.1) REQ-005/REQ-007 ถูกถอดออกจริง (endpoint ที่เกี่ยวข้อง, `TCompassMbtiResult`, `CompassMbtiStore.cs` และจุดอื่นตามที่ `sb-compass/design.md` ระบุ) ภายใน N สัปดาห์หลังจาก**วัน deploy จริง**ของ `sb-compass-faculty-match REQ-011`/`REQ-012` (ไม่นับจากวัน merge โค้ดหรือวันผ่าน QA) — N = 4 สัปดาห์เป็นค่าเริ่มต้นที่ยังไม่ยืนยัน (assumption — unconfirmed)
2. (AC-018.2) ก่อน trigger ถึงเวลา ของเดิม (REQ-005/REQ-007) ยังไม่ถูกถอดออก — การถอดไม่ผูกกับวันที่ตายตัว
